查看后台进程 

### 查看后台进程的常用命令

- 查看当前终端会话的后台任务

```bash
jobs
# 显示详细信息
jobs -l

```

- 查看所有进程（常用组合）

```bash
# 查看所有进程，显示命令
ps aux

# 查看特定用户进程
ps aux | grep $USER

# 查看进程树
ps auxf

# 只显示进程名和 PID
ps -eo pid,comm,args

```

- 查找特定进程（按名称）

```bash
# 查找包含 "vllm" 的进程
ps aux | grep vllm

# 或使用 pgrep
pgrep -af vllm

```

- 实时查看进程

```bash
# 基础版
top

# 更友好的版本（需安装）
htop

```

- 查看进程详细信息

```bash
# 查看进程的完整命令行
ps -p <PID> -o pid,cmd

# 查看进程的环境变量
cat /proc/<PID>/environ | tr '\\0' '\\n'

```

- 查看进程的资源使用

```bash
# 查看进程的 CPU 和内存使用
ps -p <PID> -o pid,%cpu,%mem,cmd

# 查看所有进程的资源使用（按 CPU 排序）
ps aux --sort=-%cpu | head -20

```

### 实用示例

```bash
# 查找并查看 vLLM 相关进程
ps aux | grep -E "vllm|python.*api_server"

# 查看所有 Python 进程
ps aux | grep python

# 查看进程树（更直观）
pstree -p | grep vllm

```

### 终止后台进程

```bash
# 终止当前终端的后台任务
kill %1  # %1 是 jobs 显示的编号

# 或使用 PID
kill <PID>

# 强制终止
kill -9 <PID>

```

### **字段含义**

- user: 进程所有者
- 522303: 进程 ID (PID)
- 0.0: CPU 使用率（当前约 0%）
- 0.3: 内存使用率（约 0.3%）
- 1986528: VSZ（虚拟内存，约 1.9GB）
- 109576: RSS（物理内存，约 107MB）
- pts/16: 终端（伪终端 16）
- Sl+: 状态
- S: 可中断睡眠（等待 I/O 或事件）
- l: 多线程
- +: 前台进程组
- 11月05: 启动日期（11 月 5 日）
- 0:00: CPU 累计时间（约 0 分钟）
- 后面是完整命令

进程检查：

- 正常：Sl+ 表示在运行（可能正在加载模型或等待请求）
- CPU 0.0%：可能处于等待状态（加载中/空闲）
- 内存 107MB：可能仍在初始化，或已加载到 GPU 显存

```bash
# 查看进程的详细状态
ps -p 522303 -o pid,stat,etime,cmd

# 查看进程打开的文件（包括 GPU）
lsof -p 522303 | grep -E "cuda|nvidia"

# 查看 GPU 使用情况（如果进程在使用 GPU）
nvidia-smi

# 查看进程的线程
ps -T -p 522303

# 查看进程的网络连接（如果服务已启动）
netstat -tlnp | grep 522303
# 或
ss -tlnp | grep 522303
```

杀掉vllm进程的时候，只杀掉主进程uv run vllm的不行，还得杀掉 VLLM::EngineCore

服务后台运行方式：

uv运行方式

- 方法 1：使用 `nohup`（简单）

```bash
nohup uv run --with vllm vllm serve /home/user/llm/models/Qwen-14B-Chat/ \\
  --trust-remote-code --gpu-memory-utilization 0.8 \\
  --tensor-parallel-size 2 --max-model-len 8192 \\
  > vllm.log 2>&1 &

```

- 输出会写入 `vllm.log`，进程在后台运行，退出终端后继续。
- 方法 2：使用 `screen`（推荐，可交互）

```bash
# 安装 screen（如未安装）
sudo apt install screen  # Debian/Ubuntu

# 创建新会话
screen -S vllm

# 在 screen 中运行命令
uv run --with vllm vllm serve /home/user/llm/models/Qwen-14B-Chat/ \\
  --trust-remote-code --gpu-memory-utilization 0.8 \\
  --tensor-parallel-size 2 --max-model-len 8192

# 按 Ctrl+A 然后按 D 来 detach（分离会话）
# 退出终端后，进程继续运行

# 重新连接会话
screen -r vllm

```

- 方法 3：使用 `tmux`（功能更强）

```bash
# 安装 tmux（如未安装）
sudo apt install tmux  # Debian/Ubuntu

# 创建新会话
tmux new -s vllm

# 在 tmux 中运行命令
uv run --with vllm vllm serve /home/user/llm/models/Qwen-14B-Chat/ \\
  --trust-remote-code --gpu-memory-utilization 0.8 \\
  --tensor-parallel-size 2 --max-model-len 8192

# 按 Ctrl+B 然后按 D 来 detach
# 退出终端后，进程继续运行

# 重新连接会话
tmux attach -t vllm

```

- 方法 4：后台运行 + `disown`

```bash
# 后台运行
uv run --with vllm vllm serve /home/user/llm/models/Qwen-14B-Chat/ \\
  --trust-remote-code --gpu-memory-utilization 0.8 \\
  --tensor-parallel-size 2 --max-model-len 8192 \\
  > vllm.log 2>&1 &

# 记录 PID
PID=$!

# 从当前 shell 的作业表中移除，使其不受 SIGHUP 影响
disown $PID

```

- 方法 5：使用 `setsid`（创建新会话）

```bash
setsid uv run --with vllm vllm serve /home/user/llm/models/Qwen-14B-Chat/ \\
  --trust-remote-code --gpu-memory-utilization 0.8 \\
  --tensor-parallel-size 2 --max-model-len 8192 \\
  > vllm.log 2>&1 &

```

- 方法 6：systemd 服务（生产环境推荐）
创建服务文件 `/etc/systemd/system/vllm.service`：

```
[Unit]
Description=vLLM Service
After=network.target

[Service]
Type=simple
User=user
WorkingDirectory=/home/user/llm
Environment="PATH=/home/user/.local/bin:/usr/local/bin:/usr/bin:/bin"
ExecStart=/home/user/.local/bin/uv run --with vllm vllm serve /home/user/llm/models/Qwen-14B-Chat/ --trust-remote-code --gpu-memory-utilization 0.8 --tensor-parallel-size 2 --max-model-len 8192
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target

```

然后：

```bash
sudo systemctl daemon-reload
sudo systemctl enable vllm
sudo systemctl start vllm
sudo systemctl status vllm

```

### 推荐

- 临时测试：`nohup ... &` 或 `screen`/`tmux`
- 长期运行：systemd 服务（自动重启、日志管理）
