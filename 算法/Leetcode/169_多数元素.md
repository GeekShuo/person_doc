# [169] 多数元素 (Majority Element)

## 题目描述
给定一个大小为 `n` 的数组 `nums` ，返回其中的多数元素。多数元素是指在数组中出现次数 **大于** `⌊ n/2 ⌋` 的元素。
你可以假设数组是非空的，并且给定的数组总是存在多数元素。
**进阶**：尝试设计时间复杂度为 `O(n)`、空间复杂度为 `O(1)` 的算法解决此问题。

## 解题思路
- **Boyer-Moore 投票算法 (最优解)**：由于多数元素的出现次数不仅多，而且比其他**所有元素加起来还要多**。
- 这就像是在打擂台，我们维护一个候选人 `candidate` 和一个计数器 `count`。
- 遍历数组：
  - 如果 `count == 0`，我们将当前人设为候选人 `candidate = num`。
  - 如果 `num == candidate`，我们给当前候选人投票，`count += 1`。
  - 如果 `num != candidate`，我们用当前人抵消候选人一票，`count -= 1`。
- 因为多数元素的票数超过总票数的一半，即使其他所有人联合起来抵消他，最后剩下的一定是他。

## 代码模版 (Python)

```python
class Solution:
    def majorityElement(self, nums: list[int]) -> int:
        count = 0
        candidate = None
        
        for num in nums:
            if count == 0:
                candidate = num
            
            if num == candidate:
                count += 1
            else:
                count -= 1
                
        return candidate
```

## 边界条件与易错点
1. **是否存在多数元素**：题目明确保证“给定的数组总是存在多数元素”。如果没有这个保证，找到 `candidate` 后还需要再遍历一遍数组确认它的真正出现次数是否大于 `n/2`。
2. **初始化**：`count` 初始为 0 可以保证第一个元素顺利上位成为 `candidate`。
3. 哈希表法（`Counter`）、排序取中间值（`sorted(nums)[len//2]`）也算常见思路，但空间/时间复杂度达不到进阶的 `O(n)` 且 `O(1)` 空间的最优标准，面试尽量首选投票法。
