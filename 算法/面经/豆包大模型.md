2️⃣说说Qwen2的模型结构吧，Qwen2相比Qwen1做了哪些改进？

🚤Qwen2是标准的 Decoder - only Transformer 架构，采用了 SwiGLU 激活函数、 RoPE 位置编码、 RMSNorm 等主流技术。相比Qwen1，一是注意力机制采用了 GQA，在保证性能的同时提升了推理效率；二是支持更长的上下文窗口；三是显著提升了多语言处理和代码能力；四是开源了更多尺寸的模型，覆盖从0.5B到72B的范围。

3️⃣为什么现在 Decoder - only 成为大模型的主流架构，相比于 Encoder - Decoder 的架构好在哪里？

🔶核心原因： Decoder - only 架构统一了自然语言处理的范式，将所有任务（如分类、问答）都视为"下一个词预测"的生成任务，极大简化了模型设计和训练流程。

🔶优点：架构统一：训练和推理流程简化，无需处理复杂的 Encoder - Decoder交互；擅长上下文学习：天然适合 In - Context Learning （上下文学习）和 Few - shot / Zero - shot 任务；生成效果好：在续写、对话等开放式生成任务上表现更自然。

4️⃣讲一下 RoPE 吧，目前常用的位置编码还有哪些， RoPE 有什么优点，如何进一步外推？

✨RoPE （旋转位置编码）：通过对词向量在高维空间中进行旋转来引入绝对位置信息，同时通过旋转的性质巧妙地实现了相对位置的表。

✨其他位置编码：绝对位置编码（如BERT中的learned PE、Transformer中的Sinusoidal PE)、 ALiBi （注意力偏置）。

✨RoPE 优点：相对位置感知：天然具备相对位置编码特性；无长度限制：理论上可以处理任意长度的序列；外推性好：相比绝对位置编码，在处理比训练时更长的序列时性能衰减较慢。

✨外推方法：通过NTK-aware Scaling、YaRN等方法调整旋转矩阵的基频（base frequency)，使其能更好地泛化到未见过的长序。

5️⃣了解 RAG 吗， GraphRAG 的做法。

🔘RAG （检索增强生成）:当模型遇到需要外部知识的问题时，先用一个检索器（ Retriever ）从知识库（如向量数据库）中检索出相关的文本片段，然后将这些片段作为上下文（ Context ）连同原始问题一起输入给生成器（ Generator )，让模型基于这些信息来生成答案。这有效缓解了模型知识过时和幻觉问题。

🔘GraphRAG （图检索增强生成）:是 RAG 的演进。它不仅检索独立的文本块，而是利用知识图谱（ Knowledge Graph ）来检索。通过在图上进行推理和路径查找，可以检索到结构化更强、关系更明确的知识，从而生成逻辑更严谨、更具深度的答案。

6️⃣开放题：如果要提升大模型的多轮对话能力，你有哪些可以改进的点？

1.构建高质量多轮对话数据：增加对话深度，确保逻辑连贯，引入对话状态（如用户意图变化）。

2.负样本构造：构造逻辑断裂、重复回答、遗忘前文等负样本，让模型学会避免这些问题。

3.优化位置编码：使用能更好处理长距离依赖的位置编码方法。

4.引入记忆机制：设计显式的记忆模块或使用类似 RAG 的方法，在对话过程中检索历史关键信息。

2️⃣大模型的灾难性遗忘问题怎么解决？

🔘 重放（ Replay )：在微调数据中混入一部分预训练数据，让模型在学习新知识的同时"复习"旧知识。

🔘参数高效微调( PEFT )：如 LORA 、 QLORA 。只微调模型的一小部分参数（适配器），冻结大部分原始参数，从而最大程度保留预训练知识。

🔘正则化方法：如 EWC （弹性权重巩固），对预训练阶段重要的参数增加一个正则项，限制其在微调时发生剧烈变化。

3️⃣场景题：目前有一些专业领域知识，比如医疗知识或者法律条文，准备做一个智能助手，要让你搭建一个 RAG 链路，会怎么做？

1.数据处理与索引：

■数据清洗：收集医疗／法律领域的文档，进行格式清洗和预处理。

■文本切块( Chunking ):将长文档切分成有意义的小块（ chunk )，如按章节、段落或固定长度切分。

■向量化与建库：使用领域相关的文本嵌入模型（如 BERT 或专门微调的模型）将每个 chunk 转换为向量，存入向量数据库（如FAISS , ChromaDB ）建立索引。

2.检索模块( Retriever ):

■当用户提问时，同样使用嵌入模型将问题转换为向量。

在向量数据库中进行相似度搜索（如余弦相似度），召回 Top - K 个最相关的文本 chunk 。

■（可选）可以加入重排（ Re - ranking ）模型，对召回的 chunk 进行二次排序，提高精准度。

3.生成模块( Generator ):

■构建 Prompt :将召回的 Top - K 个文本 chunk 作为上下文，和用户的原始问题一起，整合成一个清晰的 Prompt 。

■调用大语言模型（ LLM )，输入构建好的 Prompt ，生成最终答案。可以对 LLM 进行 SFT ，使其更擅长利用上下文回答问题。

4.迭代优化：建立评估机制，根据 bad case 不断优化切块策略、嵌入模型、重排模型和 Prompt 模板。

4️⃣讲一下 FlashAttention 的思想和做法。

✨思想：解决标准 Attention 计算中因N2量级的 Attention 矩阵（ N 为序列长度）读写 HBM （高带宽内存）而导致的 IO 瓶颈。FlashAttention 的核心是 IO - aware ，即减少 GPU 内存之间的读写。

✨做法：

■Tiling（分块）：将巨大的 Attention 矩阵切分成较小的块（ tile )，使其可以完全放入 SRAM ( GPU 片上高速缓存）中。

■KernelFusion：将 Attention 计算的多个步骤（矩阵乘、 softmax 、 dropout 、与 V 相乘）融合成一个单一的 CUDA kernel 。

■在线 Softmax ：在分块计算过程中，通过一种数值稳定的方法，在不访问完整输入的情况下计算出正确的 Softmax 结果。

5️⃣除了刚刚说到的这些，还了解过哪些模型训练推理优化的方法。

1.ZeRO （零冗余优化器）:将模型参数、梯度和优化器状态分片到不同 GPU 上，极大降低单卡显存占用。

2.Offload :将一部分数据（如优化器状态）卸载到 CPU 内存或 NVMe。  

3.并行策略：

■数据并行（ DP ):每张卡复制一份完整模型，训练不同数据。

■张量并行（ TP )：将模型层的权重矩阵切分到不同 GPU 上，进行协同计算。

■流水线并行（ PP )：将模型的不同层分配到不同 GPU 上，形成流水线作业。

4.推理优化：模型量化（如INT8/INT4)、模型剪枝、机采样（ Speculative Decoding )。
