Python 代码从源文件到最终执行，主要经历编译（Compilation）和解释执行（Interpretation/Execution）两个大阶段。虽然我们常说 Python 是“解释型语言”，但它实际上是先编译、后解释的混合模式。

以下是标准的 CPython（官方默认的 Python 实现）从读取你的 .py 文件到运行出结果的完整过程：

## 第一阶段：编译阶段（由源代码到字节码）
当你在命令行输入 python script.py 时，Python 解释器首先会做编译工作。这个阶段发生在内存中，目的是把人类能读懂的源代码变成机器（Python 虚拟机）能读懂的形式。

### 1. 词法分析（Lexical Analysis / Tokenizing）
做了什么：读取 .py 源文件的内容（纯文本），把一长串字符串切分成一个个的词法单元（Tokens）。
例子：a = 2 + 3 会被切分为标识符 a、操作符 =、数字 2、操作符 +、数字 3。同时它还会识别缩进、换行等 Python 特有的语法标志。
### 2. 语法分析（Syntactic Analysis / Parsing）
做了什么：把刚刚生成的 Tokens 组合起来，结合 Python 的语法规则，构建出一棵抽象语法树（AST - Abstract Syntax Tree）。
意义：这一步会检查你的代码有没有“语法错误”（SyntaxError）。比如你的括号没闭合，或者 if 后面漏了冒号，AST 就无法成功构建，程序在此直接报错退出。
### 3. 编译成字节码（Bytecode Generation）
做了什么：一旦 AST 生成，编译器会遍历这棵树，将其翻译成字节码（Bytecode）。字节码是一组偏底层的、平台无关的指令集（后缀一般是 .pyc 文件里的内容，存在 __pycache__ 目录下）。
它长什么样：你可以把它理解为“Python 虚拟机的汇编语言”。比如两数相加，字节码会包含 LOAD_NAME（加载变量）、LOAD_CONST（加载常量）、BINARY_ADD（执行加法）等指令。
注意：这一步并没有真正运行你的代码，它不关心你的变量 a 现在到底是什么类型，只负责把逻辑翻译好。
## 第二阶段：执行阶段（在虚拟机中运行字节码）
生成字节码后，这些字节码就会被送入 Python 虚拟机（PVM - Python Virtual Machine） 中开始真正执行。

### 4. Python 虚拟机（PVM）评估循环
做了什么：PVM 是一个庞大的 C 语言写成的 while 循环大机器（在 CPython 源码中叫 ceval.c）。它一条接一条地读取刚才生成的字节码指令，并调用背后的 C 语言底层实现去执行。
栈帧（Stack Frame）机制：PVM 是一个“基于栈的虚拟机”。执行时，你的每一层函数调用都会创建一个“栈帧”（Frame）。这个 Frame 里保存了当前函数的局部变量、全局变量引用、以及执行到了哪一条字节码。
运行时报错：像 TypeError（比如拿字符串和数字相加）、NameError（变量没定义就使用）等所谓的运行时异常，全都是在这一步抛出的。编译器在第一阶段不管这些，只有 PVM 真正跑到这一行指令时才会发现问题。
### 5. 内存分配与垃圾回收
在 PVM 执行字节码的过程中（比如执行了 a = [1, 2, 3]），它会在底层的 C 语言堆内存中调用 malloc 申请内存空间，并创建对应的对象实体（在这个例子里是 PyListObject）。
同时，Python 的**引用计数（Reference Counting）和垃圾回收机制（Garbage Collection）**启动：当一个对象没有任何变量指向它时，PVM 会立刻释放它占用的内存。
## 总结：整个过程的生命周期
写代码：你保存了 main.py
启动：输入 python main.py
词法/语法分析器：检查代码语法，没问题就生成 AST 树。
编译器：将 AST 树转化为字节码（缓存到 __pycache__/main.cpython-3x.pyc，下次运行时如果你没改源码，这前 4 步直接跳过以提升速度）。
虚拟机（PVM）：加载字节码，一条条翻译成当前 CPU 系统（Mac/Win 等）能执行的底层机器码，操作内存并输出最终结果。
