# docker
启动docker

systemctl start docker

# 拉取镜像：

查找目标镜像 

docker search 镜像名称

可以看到大概信息，但是镜像标签等信息。

拉取镜像的时候，很多时候镜像没有标签，docker会默认使用lastest标签，但具体的标签可能不是，此时就会拉取失败，要在dockerhub查看具体的镜像标签

查看镜像信息

docker inspect 镜像id   ｜｜ docker images inspect 镜像id

上面命令是本地的，远程要docker manifest inspect 

可以看到系统和指令集架构，暴露的端口，

运行容器：

docker run ubuntu:15.10 /bin/echo "Hello world"

# 运行交互式容器

docker run -it ubuntu:15.10 /bin/bash

平台 （镜像制作时确定了架构是arm/amd，拉取的时候需要确定

- it 交互 有此选项才可以执行类似/bin/bash的命令
- d 后台运行
- P 网络端口随机映射
- p （主机ip:）主机port：容器port 端口映射
- -name=xxxx 容器名称
- v 主机目录：容器目录 挂载容器目录到主机目录

exit退出容器

**以后台进程方式运行容器**

docker run -itd ubuntu:15.10 /bin/sh -c "while true; do echo hello world; sleep 1; done"

显示在运行的容器

**docker ps**

显示容器的输出

docker logs 容器id

显示容器ip映射

docker port id

停止容器

docker stop id

查看容器内部运行的进程

docker top id

启动已停止的容器

docker start b750bbbcfd88

docker restart id 重启容器

打开后台的容器

docker attach 此时退出会导致容器停止

**docker exec** 此时退出会不会导致容器停止，推荐用这个

导出容器

docker export 1e560fca3906 > ubuntu.tar

导入容器

cat docker/ubuntu.tar | docker import - test/ubuntu:v1

或

docker import [http://example.com/exampleimage.tgz](http://example.com/exampleimage.tgz) example/imagerepo

删除容器

docker rm -f 1e560fca3906

docker 数据卷

docker volume create 数据卷名 #创建数据卷（自动生成一个目录）

docker volume ls #列出已有数据卷

docker volume inspect 数据卷名 #查看某个数据卷（包括它的目录）

docker volume rm 数据卷名 #删除数据卷（先删使用该卷的容器）

## 创建镜像

当我们从 docker 镜像仓库中下载的镜像不能满足我们的需求时，我们可以通过以下两种方式对镜像进行更改。

- 1、从已经创建的容器中更新镜像，并且提交这个镜像
- 2、使用 Dockerfile 指令来创建一个新的镜像

更新镜像

先编辑一个修改好的镜像

docker commit -m="has update" -a="runoob" e218edb10161 runoob/ubuntu:v2

- **m:** 提交的描述信息
- **a:** 指定镜像作者
- **e218edb10161：**容器 ID
- **runoob/ubuntu:v2:** 指定要创建的目标镜像名

之后就可以用这个镜像启动容器了

dockerfile构建镜像

dockerfile每条指令前缀必须大写

**docker build -t runoob/centos:6.7 .**

- **t** ：指定要创建的目标镜像名
- **.** ：Dockerfile 文件所在目录，可以指定Dockerfile 的绝对路径

docker tag 860c279d2fec runoob/centos:dev

为镜像设置标签

### 分阶段构建

dockerfile构建镜像的时候，有时候需要用一些编译器等工具，得到编译结果后，容器运行的时候不需要这些编译器，此时可以用分阶段编译的方式，分bulider、runner两个阶段

## docker-compose

- 使用 Dockerfile 定义应用程序的环境。
- 使用 docker-compose.yml 定义构成应用程序的服务，这样它们可以在隔离环境中一起运行。
- 最后，执行 docker-compose up 命令来启动并运行整个应用程序。
