# apt与snap

Owner: xqer

`apt` 和 `snap` 都能在 Linux（尤其是 Ubuntu/Debian 系）上装软件，但它们的机制和特点差别很大

- **apt**
    - 传统的 **Debian 包管理工具**，安装 `.deb` 包。
    - 软件从 **系统仓库**下载，安装后依赖由系统统一管理。
    - 例如：
        
        ```bash
        sudo apt update
        sudo apt install go
        ```
        
- **snap**
    - **Canonical 推出的新一代包管理**，软件打包成独立的 **snap 镜像**，带上自己的依赖。
    - 从 **Snap Store** 下载。
    - 例如：
        
        ```bash
        sudo snap install go --classic
        
        ```
        

---

## 2. **依赖处理**

- **apt**：依赖由系统统一管理，多个程序共享同一份库，省空间，但可能遇到依赖冲突。
- **snap**：每个应用几乎自带所有依赖，隔离性好，但占用空间大。

---

## 3. **更新机制**

- **apt**：你需要 `apt update && apt upgrade` 才会更新。
- **snap**：默认 **自动更新**，后台每天检查。

---

## 4. **运行环境**

- **apt**：直接跑在宿主机系统环境里。
- **snap**：运行在 **沙箱** 中（基于 `AppArmor` 等机制），安全性更高，但可能会有权限限制或性能开销。

---

## 5. **使用体验**

- **apt**：
    - 启动快，占用小。
    - 但不同发行版的仓库版本可能比较旧。
- **snap**：
    - 应用更新快（开发者自己打包推送），可以很快用到新版本。
    - 但启动慢（尤其是第一次运行），体积大，可能出现桌面环境兼容问题。

一般系统核心软件（比如gcc、libc）建议用**apt**，而桌面应用、需要快速更新的工具（比如docker、postman）可以用**snap**
