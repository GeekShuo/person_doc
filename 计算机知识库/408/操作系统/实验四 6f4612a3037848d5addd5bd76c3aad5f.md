# 问题二：

在 Linux 内核中，定时器是通过仿照时间轮算法实现的红黑树，被挂载在内核的定时器链表中来维护；内核任务定时器主要有两种方式修改： 直接修改 timer 的 expires 字段并重新添加到队列中：这种方式需要手动修改 timer 的 expires 字段，然后再将该 timer 重新添加到定时器队列中。这种方式可以利用已有的 timer 结构，在修改定时器时节省了旧的定时器结构释放和新的定时器结构分配的开销。 通过 modtimer() 函数更改定时器唤醒时间：modtimer() 函数是包含在内核头文件 中的函数，目的是将当前 timer 重新调度到内核定时器链表上，更新其定时器到期时间。这种方式更加方便，只需要在新到期时间上计算并传递 timer 即可，系统会自动更新其下次将要到期的时间，同时防止了可能出现的链表遍历和操作的不一致情况。 两种方式有以下区别： 频繁更改定时器：在定时器需要频繁添加/删除的情况下，直接修改 timer 的 expires 更加高效，因为不需要重复分配和释放定时器结构体，降低了内存的开销。 修改定时器的到期时间：通过修改 expires 字段的方式更直观，易于理解和维护；通过 mod_timer() 函数更为优雅，容易扩展，并且更加健壮。 需要注意的是，直接修改 timer 的 expires 字段可能会破坏内核定时器链表的数据结构，从而导致定时器调度不准确，产生 Bug。而使用 mod_timer() 函数，则能保证内核定时器链表数据结构的完整性。 因此，我们需要根据使用场景，选择适合的方式来修改定时器。
