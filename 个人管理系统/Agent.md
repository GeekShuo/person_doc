# 个人管理系统长期规则

此文件是维护本文件夹的约定。用户用自然语言报告任务、进度、学习情况或计划变化时，按以下规则更新 Markdown 文件。

## 边界

1. 本文件夹只管理目标、状态、行动、时间、进度、复盘与笔记链接。各板块的具体学习内容、论文摘录、作品资料等留在原有文件夹。
2. 未经用户要求，不读取或改写其他文件夹中的笔记。用户提供具体路径时，可以将其作为链接；不要猜测链接目标。
3. 所有管理数据保持为普通 Markdown，可直接在 Obsidian 中阅读；不依赖 Dataview、Tasks 等插件或自动运行脚本。
4. 保留历史记录。完成任务时勾选原条目；调整日期时记下改期，不要无痕删除已报告的进展。

## 信息口径

1. 日期与周次按中国标准时间（Asia/Shanghai），周一至周日为一周，周文件使用 ISO 周次 `YYYY-Www`。用户习惯凌晨睡觉、中午起床；凌晨临睡前说“明天”，通常指同一公历日期的白天。优先采用用户明确说出的日期，不能机械地加一天。
2. 用户没有提供的目标、截止日期、进度、时长或成果写「待录入 / 待确认」，不要把未知当作 0%、未完成或逾期。
3. 进度优先使用可核对的里程碑或用户明确给出的比例。若有明确百分比，可在 Dashboard 写为 `60% ██████░░░░`（10 格）；没有依据则保持「待录入」。
4. 状态统一使用「未开始 / 进行中 / 等待中 / 已暂停 / 已完成」。遇到不确定的状态，先记录原话并标记「待确认」。
5. 学习掌握按照 [[学习掌握追踪]] 的等级和实际表现判断。学习时长、阅读数量只是投入，不直接证明掌握。

## 收到自然语言更新时

1. 识别板块、行动、发生日期、截止时间、预计/实际时长及完成证据。没有明确日期的「今天 / 明天 / 本周」按消息发生时的中国标准时间解释。
2. 新任务写入对应 `每日/YYYY-MM-DD.md`；跨日任务同时放到 [[本周计划]]。任务应是可执行的动作，能确定时写明结果与时间。
3. 更新 [[Dashboard]] 的目标、状态、进度、下一步和最近时间点；学习变化同步到 [[学习掌握追踪]]。
4. 完成、延期或取消任务时，保留原任务记录，并同步更新本周计划。必要时在当周 `周复盘/YYYY-Www.md` 记下原因与后续安排。
5. 用户新增板块时，在 Dashboard、本周计划和当周复盘增加对应行；若属于学习，也加入学习追踪。不要为新板块自动创建内容文件夹。
6. 每次更新后检查即将到期、已逾期和长期未更新的事项，给出具体下一步。没有截止日期或最近进展时标为「待确认」，不推断逾期。
7. 规划时间时先看用户提供的可用时间和固定安排。控制每日重点最多 3 项；计划超过可用时间时，先调整优先级或提出需要用户选择的取舍。
8. 新的一天或一周需要记录时，按现有每日/周复盘文件的结构新建对应文件，并更新 Dashboard 快速入口。本周计划滚动更新到当前周；上一周的完整复盘保留。

## 沟通与督促

- 当前优先级：找工作是用户明确指定的主线。排计划时先保护求职投递、面试准备与面试时间，再安排其他可调整事项；用户改变优先级时同步更新本规则与 Dashboard。
- 分类规则：钢琴归入「音乐与舞蹈」。钢琴仅在 2026 年 11 月 2–8 日有学校免费练习机会；此后不要自动安排钢琴。长期跟踪唱歌/声乐和 K-pop 舞蹈，频率依据用户实际可用时间调整。
- 用户回报每日完成情况后，核对计划与实际时长、任务产出和仍卡住的问题；给出具体评估与下一步调整，不只按是否打勾评价。对 2026 年 11 月 2 日的小红书面试准备，重点看自我介绍、项目讲述和追问应答。
- 更新后简要告诉用户改了什么、接下来最值得做的一步，以及哪些关键信息仍待确认。
- 对停滞或时间冲突给出明确提醒与现实可行的建议；不要凭空制造紧迫感。
- 这些 Markdown 文件不会自行发送定时通知。需要主动推送提醒时，另行配置提醒工具。
