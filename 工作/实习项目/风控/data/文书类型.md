

## 处理流水线

```

  │
  ▼ run_ocr_pipeline.py (experiments/doctype/0807/)
  │   1. 下载图片 (download API: 9.147.113.141:13173)
  │   2. v6 OCR (无旋转检测, ~269ms/条)
  │   3. cls_wl 白名单分类
  │   4. 未命中 → VL 1.6 兜底 (~12.6s/条)

  │
  ▼ review_server.py --port 8767
```

### 1. 下载图片

- API: http://9.147.113.141:13173/file/download
- 参数: bucketName=authority, destPath=<fpath>
- Header: AppId/LoginName/RequestId/Token (MD5签名)
- 返回: base64 编码的文件内容
- 速度: ~367ms/条

### 2. v6 OCR (PP-OCRv6_medium, 无旋转检测)

- Pipeline: pipelines/v6_ocr.yaml (det=PP-OCRv6_medium_det, rec=PP-OCRv6_medium_rec)
- 已关闭旋转检测 (PP-LCNet doc_ori + textline_ori)，原因: 旋转检测模型对正常文档误判率较高
- 真正旋转的文档由 VL 1.6 兜底处理
- 速度: ~269ms/条 (XPU, 单worker)

### 3. cls_wl 白名单分类

核心分类逻辑，在 utils.py 和 review_server.py 中保持一致:

匹配策略 (最长匹配优先):

1. norm_loose 归一化: 繁→简转换 (50+字映射) + ASCII字母数字剥离 + 同义词归一 (商靖/请求/呼请/呈请→请)
2. 编辑距离模糊匹配: k 按标题长度自适应 (<=6字精确, 7-12 k=1, 13-20 k=2, >20 k=3), band DP + n-gram seeds 锚点优化
3. 锚点顺序匹配: 标题按连接词切分成2-4个锚点片段(每个≥4字), 检查锚点按序出现且间隔≤30字, 处理并图/水印中文插入
4. 两种方式都收集命中, 返回归一化长度最长的 title
5. 冻结/解除冻结混排: 统一归为「协助冻结/解除冻结财产通知书」, 不按案号细分

白名单类型 (27条):

- 协助查询财产通知书
- 协助冻结财产通知书 / 协助冻结/解除冻结财产通知书
- 关于商请协助对有关涉案账户紧急止付的函
- 关于商请协助对紧急高危预警对象有关账户采取保护性止付措施的函
- 调取证据通知书
- 协助紧急止付通知书
- 等
