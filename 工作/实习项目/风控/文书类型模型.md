## 一、链路总览

两级级联：v6 OCR 白名单分类 → VL 1.6 兜底。

```
输入数据 (CSV: appid/fpath/category)
    │
    ▼
┌──────────────────────────────────────────────┐
│ Step 1: 下载图片 (download API)                │
│  http://9.147.113.141:13173/file/download      │
│  bucket=authority, MD5 签名, base64 响应        │
│  ~367ms/条, 按 stem 断点续传                     │
└──────────────┬───────────────────────────────┘
               ▼
┌──────────────────────────────────────────────┐
│ Step 2: v6 OCR (无旋转检测)                    │
│  PP-OCRv6_medium_det + PP-OCRv6_medium_rec     │
│  pipeline: pipelines/v6_ocr.yaml              │
│  ~269ms/条 (XPU 单 worker)                     │
└──────────────┬───────────────────────────────┘
               ▼
┌──────────────────────────────────────────────┐
│ Step 3: cls_wl 白名单分类 (核心)               │
│  norm_loose 归一化 → 最长匹配优先                │
│  ed≤k 模糊 + ngram 锚点 + 锚点顺序匹配           │
│  冻结/解除冻结混排分支                           │
└──────────────┬───────────────────────────────┘
               │ 未命中
               ▼
┌──────────────────────────────────────────────┐
│ Step 4: VL 1.6 兜底 (未命中 case)              │
│  PaddleOCR-VL-1.6-0.9B + PP-DocLayoutV2       │
│  + UVDoc + PP-LCNet doc_ori                    │
│  ~12.6s/条, 自带方向分类+去扭曲                  │
└──────────────┬───────────────────────────────┘
               ▼
  ocr_results.csv / review_data.csv → review_server 人工审核
```

## 三、白名单分类逻辑 (cls_wl)

24 条白名单类型 (止付函 / 通知书 / 审批表 / 凭证说明):

- 协助查询财产通知书 / 协助冻结财产通知书 / 协助解除冻结财产通知书 / 协助冻结/解除冻结财产通知书
- 调取证据通知书 / 协助紧急止付通知书
- 关于商请协助对紧急高危预警对象有关账户采取保护性止付措施的函
- 关于商请协助对有关涉案账户紧急止付的函 (及"请/请求"变体、"采取紧急止付措施"变体)
- 关于商请协助对受害人保护性紧急止付的函 / 关于商请协助对资金预警受害人账户紧急止付的函
- 电信网络诈骗受害人银行结算账户保护性止付通知书
- 涉赌账户呈请查询审批表 / 公安部电信诈骗案件侦办平台呈请查询审批表
- 接警止付平台无凭证说明 / 关于接警止付平台无汇款凭证的工作说明
- 紧急止付情况说明 / 诈骗接警紧急止付的情况说明 / 受案登记表
- 等

匹配策略 (最长匹配优先):

1. norm_loose 归一化: 繁→简转换 (60+ 字映射) + ASCII 字母数字剥离 + 同义词归一 (商请/请求/呼请/呈请→请, 的函→函)
2. 编辑距离模糊匹配: k 按标题长度自适应 (≤6字精确, 7-12 k=1, 13-20 k=2, >20 k=3), band DP + n-gram seeds 锚点优化
3. 锚点顺序匹配: 长标题按连接词 (对有关涉案账户/账户 等) 切成 2-4 个锚点片段, 检查锚点按序出现且跨度≤80字, 处理并图/水印中文插入
4. 两种方式都收集命中, 返回归一化长度最长的 title
5. 冻结/解除冻结混排: 统一归「协助冻结/解除冻结财产通知书」, 不按案号细分 (有案号时区分冻结/解冻)

> ⚠️ 注意: review_server.py 内的 cls_wl 是最新版 (ed≤k band-DP + ngram-seeds + 锚点匹配 + 冻结分支),
> 
> utils.py 内的 cls_wl 是稍旧版 (仅 ed≤1 模糊匹配)。跑批脚本 run_v6_ori_full.py / run_ocr_pipeline.py
> 
> 通过 import utils 用的是 utils.py 版本; review 服务用 review_server.py 版本。
> 
> 两版白名单标题列表一致, 主要差异在模糊匹配的编辑距离预算 (ed≤1 vs ed≤k)。

```

  PP-OCRv6_medium_det/         60MB   (文本检测)

外部服务:
  文件下载: http://9.147.113.141:13173/file/download
            (bucket=authority, AppId/LoginName/RequestId/Token MD5 签名, base64 响应)

运行:
  cd scripts/doctype
  ./run_xpu.sh run_v6_ori_full.py --device xpu:0     # 全量 OCR 跑批
  python3 review_server.py --port 8767               # review 服务 /proxy/8767/

环境变量 (run_xpu.sh 已内置):
  PADDLE_PDX_DISABLE_DEV_MODEL_WL=1  # 绕过 XPU 白名单 (v6 未官方 XPU 认证但能跑)
```

## 七、已知问题与改进方向

1. VL 1.6 速度偏慢 (12.6s/条 vs 理论 6.5s/条): 无 warmup + 部分大图触发长生成; 可用 warmup 缓解
2. 旋转检测已关闭: PP-LCNet doc_ori 对正常文档误判率高, 真正旋转文档依赖 VL 兜底
3. [u](https://doc.weixin.qq.com/smartpage/utils.py%20%E4%B8%8E%20review_server.py%20%E7%9A%84%20cls_wl%20%E4%B8%8D%E5%90%8C%E6%AD%A5)[: utils.py 为 ed≤1 旧版, review_server.py 为 ed≤k 新版, 跑批与 review 判定可能不一致, 建议统一](https://doc.weixin.qq.com/smartpage/:%20utils.py%20%E4%B8%BA%20ed%E2%89%A41%20%E6%97%A7%E7%89%88,%20review_server.py%20%E4%B8%BA%20ed%E2%89%A4k%20%E6%96%B0%E7%89%88,%20%E8%B7%91%E6%89%B9%E4%B8%8E%20review%20%E5%88%A4%E5%AE%9A%E5%8F%AF%E8%83%BD%E4%B8%8D%E4%B8%80%E8%87%B4,%20%E5%BB%BA%E8%AE%AE%E7%BB%9F%E4%B8%80).py 为 ed≤k 新版, 跑批与 review 判定可能不一致, 建议统一
4. 冻结/解除冻结混排[: 不按案号细分 (utils.py 的](https://doc.weixin.qq.com/smartpage/:%20%E4%B8%8D%E6%8C%89%E6%A1%88%E5%8F%B7%E7%BB%86%E5%88%86%20\(utils.py%20%E7%9A%84) _freeze_branch 会按案号区分, review_server.py 归混排), 由人工标注修正
5. 未命中 0.70%: 大部分为 OCR 乱码 / 非白名单类型, VL 兜底救回有限
