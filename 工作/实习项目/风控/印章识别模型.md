# 印章检测链路 (Seal Detection Pipeline)

文件路径 /apdcephfs_tj3/share_303745403/mikeypeng/sealandtype/experiments/seal/seal_pipeline_20260816.tar.gz

公安/法院法律文书印章有无判定

## 一、链路总览

三阶段级联架构，逐步消解不确定样本：

```
输入文档 (PDF/JPG/PNG)
    │
    ▼
┌──────────────────────────────────────────────┐
│ Stage 1: 三模型三分类 (seal_classify_online)   │
│  下载 → 渲染全部页 → 逐页跑 3 模型 → v5 规则    │
│  PP-DocLayoutV2 + PP-DocLayout-L + seal_det   │
│  + HSV 颜色 blob 检测                          │
│  输出: HAS_SEAL / NO_SEAL / UNSURE / ERROR    │
│  (高长宽比 H/W>2.0 自动分块推理)               │
└──────────────┬───────────────────────────────┘
               │ NO_SEAL + UNSURE 进入二阶段
               ▼
┌──────────────────────────────────────────────┐
│ Stage 2: 8块切分 (run_0804.py --stage 2)      │
│  每页切 8 块(15%重叠) → 每块重跑三模型         │
│  找回整页缩放导致漏检的小印章                   │
└──────────────┬───────────────────────────────┘
               │ 仍 UNSURE
               ▼
┌──────────────────────────────────────────────┐
│ Stage 3: VLM 多页判定 (run_vlm_unsure_0804_v2)│
│  渲染全部页 → 每批 5 页发 VLM → 逐页判定       │
│  任一页有印章 → HAS_SEAL; 全无 → NO_SEAL      │
└──────────────┬───────────────────────────────┘
               ▼
  合并 combined_results.json → review_server 人工审核
```

## 三、三个模型的必要性

|模型|架构|参数量|作用|实测贡献|
|---|---|---|---|---|
|PP-DocLayout-L|RT-DETR-L, 640x640|32.3M|版面检测(23类含seal)|主力: 承担 98.5% HAS_SEAL 检出|
|PP-DocLayoutV2|RT-DETR+PointerNet, 800x800|53.1M|版面检测+阅读顺序|补充: 0.2% 独立检出 + 交叉验证降低漏检|
|PP-OCRv4_server_seal_det|ResNet+FPN(PSE), 动态输入|28.5M|印章弯曲文本检测|辅助: 1.3% 中分区间(0.12~0.25)的颜色/圆度确认|
|detect_color_seal_blobs|OpenCV HSV (非模型)|-|红/蓝/黄彩色斑块检测|辅助: 与 seal_det 共同提供中分确认信号|

classify_v5 决策规则 (为什么需要多信号):

|条件|判定|
|---|---|
|V2≥0.25 或 L≥0.25|HAS_SEAL (高分直接判)|
|V2/L∈[0.12,0.25) + seal_det或颜色blob确认|HAS_SEAL (中分需辅助)|
|V2/L<0.15 + seal_det全否决 + 无blob|NO_SEAL (hard_no/soft_no)|
|其他|UNSURE → 进入 Stage2/3|

# 模型调研与端到端融合可行性分析

## 一、三个模型技术规格

|属性|PP-DocLayoutV2|PP-DocLayout-L|PP-OCRv4_server_seal_det|
|---|---|---|---|
|架构|RT-DETR + Pointer Network|RT-DETR-L|ResNet + FPN (PSE)|
|参数量|53.05M|32.26M|28.49M|
|文件大小|202.3 MB|123.0 MB|108.7 MB|
|输入尺寸|800x800 (固定resize)|640x640 (固定resize)|动态 (resize_long=736)|
|检测类别|23类 (含seal)|23类 (含seal)|仅印章弯曲文本|
|训练数据|论文/杂志/合同/书籍/试卷/研究报告|同左|500张圆形印章测试集|
|精度|未公开mAP|90.4% mAP@0.5|98.21% Hmean|
|预处理|resize到800x800, 不归一化|resize到640x640, 不归一化|resize_long=736, ImageNet归一化|
|后处理|NMS + 框分类|NMS + 框分类|DBPostProcess (多边形)|
|原始用途|通用版面分析+阅读顺序|通用版面分析(23类)|印章内弯曲文本检测|

关键发现：三个模型原本都不是专门做"印章有无判定"的。

- layoutV2 / layoutL 是通用版面分析模型，seal 只是 23 个类别之一，训练数据以论文/杂志/合同为主，法律文书占比未知
- seal_det 本质是"印章内文本检测"模型，检测的是弯曲文字而非印章本身，对无文字的纯图案印章无效

---

## 二、当前链路中各模型的实际贡献

基于 0804 法院数据 (24831 条) 的统计：

### HAS_SEAL 判定来源

|来源|数量|占比|说明|
|---|---|---|---|
|V2+L 都高分 (≥0.25)|12137|50.9%|两模型一致，最可靠|
|仅 L 高分|11337|47.6%|L 是主力，V2 漏检|
|仅 V2 高分|48|0.2%|V2 几乎不独立贡献|
|辅助特征驱动 (V2,L<0.25)|305|1.3%|靠 seal_det + 颜色blob|

### 核心发现

1. layoutL 承担了 98.5% 的 HAS_SEAL 检出（单独或与V2联合），V2 几乎不独立贡献
2. V2 和 L 在 46% 的文档上分歧严重（11385/24831），说明两个模型对印章的判断标准不一致
3. UNSURE 中 68% (415/607) 双模型完全无信号 (V2<0.01 且 L<0.01)，模型彻底漏检
4. VLM 在双模型零信号的 UNSURE 中找回 24 个有印章，这些是模型完全看不到的

### 各模型不足

#### layoutV2 (PP-DocLayoutV2)

|不足|数据证据|根因|
|---|---|---|
|对印章检出率极低|仅 0.2% 独立检出|训练数据中印章样本少，主要拟合论文/杂志版面|
|输入固定 800x800|大图缩放后小印章丢失|不保留原始分辨率|
|与 L 分歧率高|46% 文档分歧|两个模型检测标准不一致|
|额外参数浪费|53M 但 Pointer Network(阅读顺序)对印章无用|阅读顺序模块占 ~20M 参数，印章场景完全不需要|

#### layoutL (PP-DocLayout-L)

|不足|数据证据|根因|
|---|---|---|
|输入固定 640x640|比 V2 更小，小印章更容易丢|640 分辨率对 A4 文档，印章可能只占 20-30px|
|90.4% mAP 是 23 类平均|seal 单类精度未知|23 类均摊，印章可能远低于平均|
|仍有 2.5% 漏检 (607/24831)|UNSURE 中 68% 双模型零信号|非法律文书专用，对法院/公安文书泛化不足|
|无颜色感知|黑白印章和彩色印章一视同仁|纯视觉特征检测，不利用 HSV 颜色先验|

#### seal_det (PP-OCRv4_server_seal_det)

|不足|数据证据|根因|
|---|---|---|
|本质是文本检测不是印章检测|检测弯曲文字碎片|只能找有文字的印章，纯图案印章无效|
|后处理复杂|需聚类+颜色/圆度/Hough辅助判定|输出碎片而非完整印章框|
|辅助特征规则手工设计|classify_v5 中大量硬编码阈值|规则不可学习，难以泛化|
|贡献有限|仅 1.3% 的 HAS_SEAL 依赖它|大多数情况 layoutL 已能判定|
|98.21% Hmean 是 500 张测试集|实际法律文书表现未知|测试集可能与实际场景分布不同|

#### classify_v5 规则系统

|不足|说明|
|---|---|
|硬编码阈值|V2>=0.25, L>=0.25, 0.12, 0.15 等全是人工调参|
|规则不可学习|颜色blob、圆度、Hough 等特征的组合逻辑固定|
|无法端到端优化|模型训练和规则设计完全分离|
|场景过拟合|阈值针对当前数据调优，换场景可能失效|

## 三、端到端融合方案分析

### 方案 A: 微调单一 layout 模型 (最轻量)

思路: 用 layoutL (检出率最高) 做基础模型，在法律文书印章数据上微调

做法:

1. 收集法律文书 + 印章标注 (框标注，不是分类标签)
2. 用 PaddleDetection/RT-DETR 微调 layoutL
3. 只保留 seal 类别 (或加少量其他类别防止灾难遗忘)
4. 输出: seal 框 + 置信度，单阈值判定

优点:

- 改动最小，只需微调
- 单模型推理，速度快
- 保留 RT-DETR 的检测能力

缺点:

- 仍是固定分辨率输入 (640x640)，小印章问题不解决
- 需要框级标注数据 (当前只有文档级标签)
- 无法利用颜色等先验知识

预估数据需求: 2000-5000 张带印章框标注的法律文书

### 方案 B: 印章专用检测模型 (中等)

思路: 训练一个只做印章检测的专用模型，替换三个模型

做法:

1. 用当前 24831 条数据 (HAS_SEAL=24021) 的文档作为训练集
2. 标注印章位置 (框级)，训练 RT-DETR / YOLO 等检测器
3. 输入用更高分辨率 (1280x1280 或动态)
4. 多尺度推理 (原始 + 切块) 作为测试时增强

优点:

- 专注印章检测，精度可以做得更高
- 可选用更高分辨率输入
- 单模型替代三模型，简化部署

缺点:

- 需要大量框级标注 (当前只有文档级 yes/no 标签)
- 训练成本和时间

预估数据需求: 5000+ 张框级标注

### 方案 C: 二分类端到端模型 (最彻底)

思路: 直接训练一个"输入文档图片 → 输出有印章/无印章"的二分类模型

做法:

1. 用现有数据 (24831 条, HAS_SEAL=24021, NO_SEAL=765) 作为训练集
2. 采用多实例学习 (MIL) 或注意力机制:
    - 文档逐页/逐块提取特征 (CNN backbone)
    - 注意力聚合各页/块特征
    - 输出二分类

3. 不需要框级标注，只需文档级标签

优点:

- 完全端到端，无需手工规则
- 直接优化目标 (有无印章)
- 可学习颜色、形状、位置等综合特征
- 无需框级标注

缺点:

- 正负样本极不平衡 (24021 vs 765, 去重后 16847 vs 222)
- 需要设计多页聚合机制
- 黑盒模型，可解释性差
- 可能过拟合当前数据分布

预估数据需求: 当前数据量足够 (需去重后使用)

### 方案 D: 模型蒸馏 + 规则学习 (折中)

思路: 用 VLM 作为教师模型，蒸馏到轻量检测器

做法:

1. 用 VLM 对所有 UNSURE 和部分 HAS_SEAL/NO_SEAL 做精细判定
2. 用 VLM 的判定结果 + 现有三模型输出作为特征
3. 训练一个轻量分类器 (XGBoost/小MLP) 做最终判定
4. 输入特征: V2分数, L分数, seal_det碎片数, 颜色blob面积, 圆度, 页数等

优点:

- 无需框级标注
- 可解释 (特征重要性)
- 训练快
- 融合所有信号

缺点:

- 仍依赖三个基础模型推理
- 不是真正的端到端
- 特征工程仍需人工设计

## 四、推荐路线

### 短期 (1-2周): 方案 D — 模型蒸馏 + 规则学习

- 用 VLM 跑一批精细标注 (已有 559 条 UNSURE 的 VLM 结果)
- 提取三模型 + 颜色 + 几何特征
- 训练 XGBoost 替代 classify_v5 规则
- 预期: UNSURE 从 2.4% 降到 1% 以下，消除手工阈值

### 中期 (1-2月): 方案 B — 印章专用检测模型

- 标注 2000-5000 张法律文书的印章位置 (可用半自动: 模型预标注 + 人工校正)
- 训练高分辨率 (1280+) 印章检测器
- 替换三个模型，单模型推理
- 预期: 漏检率从 2.4% 降到 1% 以下，推理速度提升 2-3x

### 长期: 方案 C — 端到端二分类

- 积累更多去重后的文档级标注数据
- 设计多页注意力聚合网络
- 完全端到端，无需手工规则和辅助特征
- 预期: 最简洁的部署形态，精度持平或更好

## 五、关键瓶颈

1. 训练数据标注成本: 当前只有文档级标签 (有/无印章)，缺乏框级标注。短期可用方案 D 绕过，中期需要标注投入
2. 正负样本不平衡: 去重后 16847 vs 222 (98.7% vs 1.3%)，需要过采样或 focal loss
3. 小印章检测: 固定分辨率输入是根本问题，需要高分辨率输入或多尺度推理
4. 多页文档: 需要设计页级特征聚合机制 (max-pooling / attention)
5. 颜色多样性: 印章有红/蓝/黑/紫等颜色，模型需对所有颜色有效
