# 业务价值

在查冻扣业务中，司法机关会每日会传来上千万的业务单据，其中，有相当大的一部分的电话号码有格式混乱、乱填、缺少分隔符，以及缺区号或者区号错误的情况。这部分数据，一方面不符合监管部门要求的所有单据都要正式，不能随便处理用户的原则，另一方面，用户处理这些单据的时候，无法打通这些无效号码，经常出现投诉财付通的情况，大大增大了用户摩擦。

因此，设定一个行之有效的方案，校验号码的格式合理性与有效性（确认属于这个法院） 有很高的业务价值。

# 技术方案

## 格式合理性

首先考虑了大模型+prompt规则的形式，该方案有如下弊端

1.每天数十万条数据，用大模型废时废算力

2.大模型输出不可控，无法甄别幻觉问题，与业务对齐后，当前还是满足司法机构要求为第一准则，不能有误拦截，大模型无法控制幻觉

3.后期发现业务规则非常复杂，判断标准不是电话号码能不能打通，而是”是不是看起来像号码？“ 全部提示词加入会比较冗余，可能提高幻觉概率。

最终，采用硬规则的方式，主要依靠正则匹配加数据库匹配

经统计，硬规则的单条响应速度在1~1.4 ms左右

# 电话号码有效性判断规则（v2.1）

## 1. 这份文档回答什么

一个号码字符串进来，什么情况判有效（最终是否有效=True）、什么情况判无效（False）。

- 输入：CSV 文件，默认取第 1 列为法院名称、第 3 列为电话（可用环境变量 NAME_COL / PHONE_COL 改列号）。空电话行直接丢弃，不产生结果行。
- 处理链：process_contact.py（阶段 1，提取号码 + 第一轮判定）→ fix_areacode.py（阶段 2，补区号 + 区号一致性 + 出最终结论）。
- 结论列：fix_areacode.py 输出的 最终是否有效 是唯一结论，只有 True / False，不留空。

总原则：判无效必须 100% 准确，能放过的都放过。 只要号码本身可用，即使格式脏、缺区号、带分机，都尽量判有效；只有确认不是可用号码，才判无效。

高无效率日期全部落在 5 月和 6 月上旬，低无效率日期全部落在 7 月下旬之后，与旬度趋势一致。

## 10. 结论与建议

1. 整体质量良好：94.95% 有效率，无效仅 5.05%，且无效项经核验均为真实的垃圾数据（占位符、身份证号、位数错误号码），无误杀。
2. 质量持续改善：无效率从 5 月的约 10% 降至 8 月的 1.50%，7 月下旬起显著改善。
3. 无效集中在录入质量：85.6% 的无效来自"非法号码"和"占位符短号"，建议在录入端加位数/号段前置校验，可直接消除大部分无效数据。
4. 区号缺失普遍：42% 的有效号码是无区号本地号，虽按规则判有效并自动补区号，但建议录入端强制要求填写区号，避免依赖推断。
5. 粘连录入需规范：27 行"座机+手机"连写虽已被规则救回，仍建议在表单层面拆分为两个字段。



# 机构联系电话合规校验函数 - 接口文档（tRPC）

## 概述

在现有 tRPC 服务的 proto 中新增两个函数，按机构类型区分：

|函数|用途|org_name 传入内容|
|---|---|---|
|CourtPhoneCheck|法院电话号码合规校验|法院名称，如「莆田市荔城区人民法院」|
|GonganPhoneCheck|公安电话号码合规校验|公安局/分局/支队名称，如「四川省成都市公安局锦江分局刑警大队」|

- 每次调用只处理一条数据，批量场景由调用方循环/并发调用
- 两函数输入输出结构完全一致，仅区号推断等内部规则有差异（见「两函数差异」）
- 号码有效性规则两函数共用同一套，见《号码合规判断规则说明.md》

## proto 定义

```
// 两个 rpc 方法加入现有 service
service <现有服务名> {
  rpc CourtPhoneCheck(PhoneCheckReq) returns (PhoneCheckRsp);   // 法院
  rpc GonganPhoneCheck(PhoneCheckReq) returns (PhoneCheckRsp);  // 公安
}

// 请求：两函数共用
message PhoneCheckReq {
  string business_id = 1;  // 批次/案件编号，原样返回
  string org_name = 2;     // 机构名称（法院或公安机关），用于推断应属区号
  string phone = 3;        // 原始号码字符串
}

// 响应：两函数共用
message PhoneCheckRsp {
  string business_id = 1;         // 原样返回
  string org_name = 2;            // 原样返回
  string phone = 3;               // 原始号码，原样返回
  bool is_valid = 4;            // 号码是否有效："True" / "False"
  repeated string invalid_code = 5;  // 无效号码的类型（错误码 P1001~P1006，有效时为空）
  string number_type = 6;         // 号码类型（可选）
  int32 error_code = 7;           // 处理时报错返回码：0=处理成功，非0=处理异常
  string fixed_number = 8;        // 修复后的号码，供参考
  string region = 9;              // 推测的号码归属地，供参考
}
```

## 请求字段

|字段|类型|必填|说明|
|---|---|---|---|
|business_id|string|是|批次/案件编号，原样返回|
|org_name|string|是|机构名称。法院函数传法院名称，公安函数传公安局/分局/支队名称。用于推断应属区号（地级市直配 > 区县 > 市名词干 > 省会兜底）|
|phone|string|是|原始号码字符串，允许脏格式（分隔符、文字备注、多号码连写、国际前缀等），最长 200 字符|

## 响应字段

|字段|类型|必填|说明|
|---|---|---|---|
|business_id|string|是|批次/案件编号，原样返回|
|org_name|string|是|机构名称，原样返回|
|phone|string|是|原始号码，原样返回|
|is_valid|bool|是|号码是否有效："True" / "False"，唯一结论，不留空|
|invalid_code|list[string]|是|无效号码的类型（错误码，见下表），有效时为空列表|
|number_type|string|否|号码类型，见 number_type 取值表|
|error_code|number|否|处理时报错返回码：0=处理成功；非 0=处理异常（见「error_code 取值」）|
|fixed_number|string|否|修复后的号码（E164，如 +865942212345；多个用英文逗号分隔；无修复/无法修正为空），供参考|
|region|string|否|推测的号码归属地（无法确定为「未知」），供参考|

## invalid_code 错误码

判定原则：判无效必须 100% 准确，能放过的都放过。 只有命中下表错误码才判 is_valid=False。区号与机构所在地冲突不判无效（不参与返回）。

错误码与《号码合规判断规则说明》§4「判无效的完整清单」6 类一一对应：

|错误码|含义|触发条件|例子|
|---|---|---|---|
|P1001|位数不足|去非数字后 1~6 位（特服号除外），不可能是任何有效号码，补区号也修不了。阶段一直接定案，不进入区号判断（对应 §4 第 1 类）|123456、12345|
|P1002|已解析但非法|能解析成 E164 但无效，且不属于缺区号形态（对应 §4 第 2 类）|非法手机号 1783716058、UNKNOWN 长号|
|P1003|无法切出确定号码|提取不到号码（空串、纯文字、人名），或脏数据命中 4 条硬约束：单段数字 >12 位；含非电话特征（字母/金额/全角数字/信用代码/网址）；候选切法不唯一；兜底截取数字量超限（对应 §4 第 3 类）|""、承办人座机号码(必填)、209734403722097344|
|P1004|本地号首位为 0|补全区号后本地号第一位是 0（对应 §4 第 4 类）|05583093→0558+05583093|
|P1005|区号+残缺本地号|源号已带区号（0XX/0XXX-开头）但本地号残缺，不重复补区号（对应 §4 第 5 类）|0316-123|
|P1006|案号/非电话号码|含案号关键词（民初/执保/财保/刑初等）且非「号码+备注」形态（对应 §4 第 6 类）|（2025）豫1002执891号|

> 注：机构名无法推断区号的记录不单设错误码——逐条核查此类记录本身即无效（人名/邮箱/长号/区号+残缺），按号码形态归入 P1002/P1003/P1005。无区号 7/8 位本地号不受此影响：阶段一已判有效，定位不到区号只是 fixed_number 为空，不影响 is_valid。

## error_code 取值（处理返回码）

|值|含义|调用方处理|
|---|---|---|
|0|处理成功|按 is_valid / invalid_code 取业务结果|
|1|参数错误（缺字段、phone 超 200 字符等）|修正后重传|
|2|内部处理异常|稍后重试，不需要修改请求|

error_code 非 0 时，is_valid/invalid_code 等业务字段无意义，以 error_code 为准。

## number_type 取值

|值|含义|
|---|---|
|FIXED_LINE|固话（含带区号放宽判定）|
|MOBILE|手机号|
|SERVICE_LINE|特服号（白名单内，如 12368/96110/10086）|
|LOCAL_NO_AREA_CODE|无区号 7/8 位本地号（位数完整、省略区号，判有效）|
|TOLL_FREE|800 免费电话|
|SHARED_COST|400 等分摊付费号码（含被库按信息台模式识别的带区号号码，按库判定放行）|
|TOO_SHORT|位数不足（1~6 位，判无效 P1001）|
|UNKNOWN|无法归类|

## 两函数差异

号码有效性规则完全相同，差异仅在机构名 → 应属区号推断及少量修复策略
