2.知道 deepspeed 和 megatron 吗，分别介绍一下
**解答**：都在大规模分布式训练中常被用到：
- **DeepSpeed**：微软开源的库。它的核心杀手锏是 ZeRO（零冗余优化器）系列。通过将优化器状态、梯度和模型参数这三者沿着数据并行（DP）的维度进行切片和分发（即ZeRO 1、2、3），从而降低了单卡的显存吃紧问题，让较少的显卡也能训千亿模型。
- **Megatron-LM**：NVIDIA开源的模型并行框架。它除了数据并行，主打的是**模型的高效模型并行**，尤其是张量并行（Tensor Parallelism，把一个大矩阵乘法切给多个GPU算）和流水线并行（Pipeline Parallelism，把模型的不同层分给不同GPU算）。

3.Decoder 文本生成有哪几种方法
**解答**：大模型生成文本（Decode算法）主要有以下几类：
1. **贪心搜索 (Greedy Search)**：每一步总是选转移概率最大的那一个词。容易陷入局部最优或者无限循环死胡同。
2. **束搜索 (Beam Search)**：每一步保留Top-K个最高概率的局部序列（紫宽K即为束宽），并在下一步拓展，最后选出一条全局概率得分最高的路径（适合翻译等追求高质量唯一答案的任务）。
3. **随机采样 (Sampling)**：以概率分布随机扔骰子选词。加入`Temperature`参数（大于1更随机，趋近0更贪心）。
4. **Top-K 采样 / Top-P 采样(Nucleus)**：为了避免采样到低概率狗屁不通的单词，截断只从累计概率最高的前K个或累计概率达到P的词库里进行采样。（适合需要创造性的对话或文章生成）。

4.Attention 为什么要做scaled ，不做会怎么样，为什么用根号 d _ k
**解答**：在缩放点积注意力（Scaled Dot-Product Attention）中，$QK^T$ 的结果必须除以 $\sqrt{d_k}$。
**为什么做**：如果不缩放，当词向量维度 $d_k$ 变大时，$QK^T$ 点积结果的绝对值会暴涨。当把这些绝对值的数字送进Softmax函数时，会落在指数函数的严重饱和区。这会导致计算出的梯度趋近于0（梯度消失），模型根本没法训练更新。
**为什么是除以根号 $d_k$**：因为假设 $Q$ 和 $K$ 向量里每个元素是均值为0、方差为1的独立同分布独立随机变量，那么它们内积结果的高斯分布的方差就是 $d_k$。为了把方差缩放回 1（让Softmax拿到一个方差在1附近的平滑输入），就要让整个结果除以标准差，也就是 $\sqrt{d_k}$。

5.说一下 Decoder 的因果注意力， QKV 分别来自哪
**解答**：因果注意力（Causal Attention / Masked Self-Attention）是指在自回归生成时，模型在时刻 $t$ 只能看到 $1 \dots t$ 这个时间步之前的Token，绝不能偷看未来的Token，通过加上一个下三角的Mask掩码矩阵来实现。
以Transformer的自回归Decoder为例：
- **如果是 Masked Self-Attention**：Q（Query）、K（Key）、V（Value）全部来自于当前Decoder层本身的输入（上一层输出或自身Embedding），自己和自己做Attention。
- **如果是 Decoder 中的 Cross-Attention（交叉注意力，常见于机器翻译的Encoder-Decoder结构）**：Q 依然来自于Decoder内部自身当前的隐向量；而 K 和 V 则来自于**Encoder最后的输出表示信号**，通过 Q 去 Encoder 那边查找并加权提取相关的记忆和信息。

6.深挖多模态大模型论文用的video - llama ，讲一下大模型的结构
**解答**：Video-LLaMA 主要用于视频理解。它的核心结构分为两部分，旨在将音视频模态对齐到文本模态（LLaMA/Vicuna）：
1. **Video Q-former 桥接层**：先使用冻结的ImageBind或CLIP作为视觉/音频编码器提取帧特征。接着利用Q-Former（Query Transformer）结合固定的Learnable Queries，将帧级别的长特征压缩汇聚成少数代表性的向量表示。
2. **Audio Q-former**：原理类似，提取音频模态特征。这些视听压缩后的向量经过一个线性投影层（Projection Layer），被对齐转换成和大语言模型Word Embedding维度一致的Token输入，直接拼接给后端的语言模型去理解输出回答。

7.LoRA 初始化怎么做的，用的秩是多少，为什么不选其他的数
**解答**：LoRA利用两个低秩矩阵相乘（A*B）来代替整个大矩阵 $\Delta W$ 的微调。
- **初始化**：矩阵 A 通常采用正态分布（随机高斯分布）或者Kaiming初始化进行随机权重初始化；矩阵 B **全部采用零初始化（Zero Initialization）**。这么做是为了保证刚开始训练的第一轮前向传播时，旁路 $B \times A = 0$。即模型原本的行为和没加上LoRA之前是一模一样的。
- **秩（Rank r的大小的选择）**：通常设置 $r = 8, 16, 64$ 等。选得太小（如$r=1$或$2$）会导致信息压缩过度，新矩阵表达能力不足，无法学握到复杂微调任务的空间容量；选得太大（如$r=768$）会导致可训练参数激增，不但失去了高效微调的省显存初衷，在小数据集上还反倒容易产生过拟合，且作者论文里证明低秩带来的效果已趋近饱和。

8. 介绍一下 ALBEF 、 BLIP
**解答**：ALBEF和BLIP都是非常经典的多模态图文研究模型：
- **ALBEF**：在早期的多模态中，强调了先通过图像和文本各自独立的编码器编码，然后再利用 **Cross-Attention** 进行深层的多模态融合（图文匹配）。其最大的创新在于引入了**动量蒸馏（Momentum Distillation）**，即利用动量模型生成伪目标，来处理网络图文数据集中充满噪声的弱对齐问题。
- **BLIP**：在ALBEF的架构基础上进一步发展，使用了一个集成了单向、双向、交叉注意力的统一新架构（Multimodal Mixture of Encoder-Decoder, MED）。它不仅能做图文理解匹配，还能做图文生成任务。另一大贡献是使用Captioner生成高质量图像字幕并使用Filter剔除坏样本（被称为CapFilt的Bootstrapping算法），大幅搞定了训练图文质量较差的短板。

2.论文用了CoT，讲一下论文的CoT是怎么样的
**解答**：在多模态方向的CoT（思维链，Chain of Thought），往往不能单纯靠大语言模型自导自编，而是要结合图像特征步步为营。比如一种设计是：第一轮先强制模型输出对图片的详细底层文本描述（Caption，找实体），第二轮再基于这些描述加逻辑指引去推理他们间的关系方位（理解空间语义），最后一步再推导出核心的行动判定或者高维常识结论。这就是结合多模态观测的Step-by-step。

3.介绍transformer 架构
**解答**：Transformer是纯基于Attention的Encoder-Decoder网络结构，抛弃了RNN/LSTM。
- 内部核心组件包括：多头自注意力层（Multi-Head Self Attention，捕捉全局上下文的长距离依赖）、前馈神经网络层（FFN/MLP，负责非线性特征提取扩维映射）、残差连接（Add/Residuals，防止深层网络梯度消失）加上层归一化（LayerNorm，保证训练稳定性）。
- 因为抛弃了RNN没有时序概念，所以在输入端需强行加上位置编码（Positional Encoding）来提供词汇先后顺序。

4.BLIP2的结构是什么，两阶段怎么训练的，有哪些损失
**解答**：核心结构：BLIP-2抛弃了全参微调大模型，使用一个轻量级的 **Q-Former（Querying Transformer）** 来连接冻结的先进视觉模型（Image Encoder例如ViT）和冻结的先进大语言模型（LLM 例如 Flan-T5 / OPT）。
共分两阶段训练：
- **阶段一（多模态表示学习）**：连接视觉编码器和Q-Former，语言模型没参与。Q-former通过与图文联合训练学习把视觉特征提炼为最切合语言的向量。计算三种Loss：ITC（图文对比损失）、ITM（图文匹配二分类损失）、ITG（图文生成语言模型损失）。
- **阶段二（多模态生成对齐学习）**：这会儿才把Q-Former对接到巨大的冻结LLM前面，加个全连接映射层（Linear Projection）。让Q-Former扮演Soft Prompt的作用，仅训练一小部分参数，利用纯语言建模损失促使LLM根据Q-former压缩出来的视觉Query去生成准确的答案结果。

5.知道 PEFT 吗，讲一下 LoRA
**解答**：PEFT 即参数高效微调（Parameter-Efficient Fine-Tuning）。为了不动辄训几百亿参数而搞出的省钱技术丛林。最典型的代表就是LoRA（参见第一面第7题）。

6.LoRA 是什么，有什么好处
**解答**：通过在原来模型的全连接层旁边，挂上一个低秩的旁路矩阵乘积 $W_{new} = W_0 + \Delta W = W_0 + B \times A$。微调时冻结 $W_0$，只更新小规模的 $A$ 和 $B$ 矩阵。
**好处**：
1. 幅度省显存和算力。
2. 因为模块化拆分，你可以训出来N个几十MB的LoRA权重文件插拔对应不同的下游垂类任务业务。
3. 推理0延迟：推理部署阶段，因为线性代数的分配律，可以方便地把旁路算出来的增量矩阵 $\Delta W$ 直接“加等”进（Merge）原矩阵 $W_0$ 里，推理速度和原始模型一模一样，完全没有额外开销。

7.Transformer 怎么做加速训练，训练和推理有什么区别
**解答**：
- **加速训练措施**：系统级用到并行（Tensor Parallelism，Pipeline，ZeRO系列切分）；显存级使用混合精度（AMP fp16/bf16），激活重计算（Activation Checkpointing）；算子级使用FlashAttention（在SRAM缓存平铺计算避免HBM内存墙瓶颈）。
- **训练和推理的本质区别**：
  - **训练时**：所有的标签答案我们都有了，可以用Teacher Forcing。这时候通过Mask掩码矩阵屏蔽未来信息，我们可以一次性完全**并行**把整句话一秒钟前向和后向计算出来，算力的吞吐利用率极高。
  - **推理时**：由于本质是**自回归**（Auto-regressive），后面的词生成依赖前面还没蹦出的词，所以必须**循环串行**一步步计算。这时候主要性能瓶颈在于计算KV Cache时的显存带宽IO问题，算力很难喂饱跑满。

**解答**：比如在典型的多模态问答（Visual Instruction Tuning）项目里使用的是类似于LLaVA的结构：

3.讲一下multi-head attention，用pytorch手撕一下，要可以实现cross attention的
**解答**：
```python
import torch
import torch.nn as nn
import math

class MultiHeadAttention(nn.Module):
    def __init__(self, d_model, num_heads):
        super(MultiHeadAttention, self).__init__()
        assert d_model % num_heads == 0
        self.d_k = d_model // num_heads
        self.num_heads = num_heads
        
        # 定义投影层，若要做Cross-Attention，q和(k,v)可能输入不一样，所以要分开独立映射
        self.W_q = nn.Linear(d_model, d_model)
        self.W_k = nn.Linear(d_model, d_model)
        self.W_v = nn.Linear(d_model, d_model)
        self.W_o = nn.Linear(d_model, d_model)
        
    def forward(self, query, key, value, mask=None):
        batch_size = query.size(0)
        
        # 1. 线性映射并切分成多头: [batch, seq_len, d_model] -> [batch, seq_len, num_heads, d_k] -> [batch, num_heads, seq_len, d_k]
        Q = self.W_q(query).view(batch_size, -1, self.num_heads, self.d_k).transpose(1, 2)
        K = self.W_k(key).view(batch_size, -1, self.num_heads, self.d_k).transpose(1, 2)
        V = self.W_v(value).view(batch_size, -1, self.num_heads, self.d_k).transpose(1, 2)
        
        # 2. Scaled Dot-Product Attention
        # scores: [batch, num_heads, tgt_len, src_len]
        scores = torch.matmul(Q, K.transpose(-2, -1)) / math.sqrt(self.d_k)
        
        if mask is not None:
            # mask 可以用来做 Padding 屏蔽，或者 Causal Masking
            scores = scores.masked_fill(mask == 0, -1e9)
            
        attn_weights = torch.softmax(scores, dim=-1)
        
        # context: [batch, num_heads, tgt_len, d_k]
        context = torch.matmul(attn_weights, V)
        
        # 3. 拼接多头并经过最终的线性映射输出
        # context -> [batch, tgt_len, d_model]
        context = context.transpose(1, 2).contiguous().view(batch_size, -1, self.num_heads * self.d_k)
        output = self.W_o(context)
        return output
```

4.大模型训练为什么不用SFT
**解答**：（这里的考点应该是问为什么要脱离单纯的SFT发展出RLHF强化学习或者为什么只用SFT不够）。
1. **数据构建极贵且长尾**：高质量人工示范对话数据昂贵，而且很多隐式推理边界或者微小语气的纠正很难通过大量收集数据完全覆盖。
2. **“打分比自己撰写容易”**：人类专家自己去写一个涵盖百家之长的天花板式好作文非常难（SFT的模仿天花板就是人类能给出的样本的智商天花板）；但是给模型自己生成的两篇作文去评比谁好谁坏很容易。强化学习可以通过Reward上限超越人类原有的显式撰写能力，激发模型的内驱逻辑优化。
3. **缓解幻觉与贴合反馈**：纯SFT让大模型只学会了生搬硬扯的“克隆语气”，如果没见过这个知识点就非常容易产生“编造式幻觉”；而引入人类偏好奖励可以让它知道在不懂的时候承认“我不知道”。

5.知道RLHF吗，讲一下训练流程
**解答**：RLHF（基于人类反馈的强化学习流程），主流框架分为三大核心步骤：
1. **SFT阶段（指令微调）**：先积累一批高质量（几万条级别）人工撰写好的QA数据集，把基座模型预训练过一遍，让它初步具备能正常像人类一样回答的能力。
2. **RM阶段（奖励模型训练）**：给同一个Prompt指令，让Step1里SFT后的模型输出产生A、B、C、D好几个不同回答。人类标注人员不对回答重写，而是按照喜爱程度给A、B、C、D排序打分。拿这些排序好的配对数据，训练出一个类似于裁判员打分的分类器网络——Reward Model。
3. **PPO强化学习阶段（策略微调优化）**：固定Reward Model裁判员的权重不动。现在发一个指令给正在被优化的生成动作模型（Actor），让它生成一段文本，那去过裁判员RM那里拿一个得分（Reward）。通过PPO算法，用这个分数返回去去梯度更新指导Actor去化总期望得分，但同时加入一个跟原来旧SFT模型对比的KL散度惩罚，避免生成结果离正常人类语言偏移太远导致出现“得分Hacking但语句不通”的情况。

6.问了几个电商相关的场景题，用大模型解决 prompt 应该怎么设计，怎么处理prompt的输出，怎么过滤错误格式的输出
**解答**：
- **怎么设计Prompt**：利用电商特定的架构套路。1. 定义电商专家角色系统提示（“你是一个擅长提炼商品卖点的电商营销专家经理”）。2. 上下文补齐：在问题周边填补这个商品的Title、类目标签、前序历史销售特征等结构化基础数据。3. 提供优秀的少量打样样本（Few-shot机制），告诉它标题得有“促销词+核心词+属性词”的强硬要求。4. 命令如果遇到算数类推荐价格时生成推理的思路（CoT思维链）。
- **处理输出与排雷错乱格式**：大模型很容易“说废话”即不服从纯JSON字段约束。处理办法包括：
  1. Prompt约束：“仅输出合格和合法的JSON字典片段信息，不要附加上下任何解释废话”。
  2. 后处理侧用贪婪正则表达式匹配大括号内的有效内容提取或使用健壮的JSON容错解析库尝试读取。
  3. 通过循环控制+Self-Correction调用：如果解析异常挂掉，系统后台截取Error日志配合原输入再问大模型一次“你刚才输出的格式解析报错了为XXX，请修复以JSON输出”。
  4. 工程底层：换用vLLM或SGLang框架在推理引擎Decode抽样环节强制使用JSON Schema掩码强制规范引导生成（Guidance / Outlines约束解码策略）。
