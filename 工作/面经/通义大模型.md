## 2．Qwen 的模型结构怎样？相比 LLaMA、DeepSeek 有什么区别

**解答**：Qwen 各版本细节不同，整体属于 Decoder-Only Transformer，常使用 RoPE、RMSNorm、SwiGLU 和 GQA，部分版本带 QKV Bias，并使用覆盖中文、多语言和代码的较大词表。LLaMA 的基础结构相近，差异主要在 Tokenizer、训练数据、注意力配置和上下文策略。DeepSeek-V2/V3 的代表性差异是 DeepSeekMoE 与 MLA：前者用稀疏专家扩大容量，后者把 KV 压缩为潜在表示以降低 KV Cache。比较时必须指定版本，不能把整个模型家族视为单一架构。

## 3．Attention 怎么做？Encoder 和 Decoder 的 Attention 一样吗

**解答**：

\[
\operatorname{Attention}(Q,K,V)=\operatorname{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}+M\right)V。
\]

Encoder Self-Attention 通常是双向的，只屏蔽 Padding；Decoder Self-Attention 使用 Causal Mask，位置 \(i\) 不能访问未来位置。Encoder-Decoder 模型的 Decoder 还有 Cross-Attention，其中 Q 来自 Decoder，K/V 来自 Encoder。Decoder-Only LLM 没有独立 Encoder 和 Cross-Attention。

## 4．MoE 相比 Dense 的训练难点是什么

**解答**：MoE 用 Router 为每个 Token 选择少量专家，可在激活计算量相对可控时扩大总容量。难点包括专家负载不均和路由坍缩、专家容量溢出、Top-k 路由不稳定、跨设备 All-to-All 通信、专家并行与数据/张量/流水线并行的组合，以及部署时仍需保存全部专家参数。常用手段有负载均衡辅助损失、Router Z-Loss、容量控制、共享专家、合理初始化和通信计算重叠。

## 6．怎么缓解大模型幻觉

**解答**：先区分事实错误、上下文不一致和推理错误。数据侧清洗错误和冲突语料；训练侧加入高质量 SFT、偏好和拒答样本；知识侧使用结构化查询或 RAG，并优化召回、重排、时效性和权限；生成侧要求逐条引用证据、证据不足时拒答；高风险结果可用规则、检索、NLI 或人工复核。降低 Temperature 只能减少随机性，不能保证事实正确。

## 7．RLHF 流程是什么？PPO 和 DPO 的思想及损失表达式

**解答**：经典 RLHF 先做 SFT，再收集偏好对训练标量奖励模型，最后在线采样并用 PPO 更新策略，同时通过参考模型 KL 约束防止偏移。PPO 概率比为

\[
r_t(\theta)=\frac{\pi_\theta(a_t\mid s_t)}{\pi_{old}(a_t\mid s_t)}，
\]

裁剪目标为

\[
L_{PPO}=-\mathbb E_t\left[\min(r_t\hat A_t,
\operatorname{clip}(r_t,1-\epsilon,1+\epsilon)\hat A_t)\right]，
\]

完整目标通常还包括价值损失、熵项和 KL 约束。

DPO 直接使用偏好对 \((x,y_w,y_l)\)：

\[
L_{DPO}=-\mathbb E\log\sigma\left(\beta\left[
\log\frac{\pi_\theta(y_w\mid x)}{\pi_{ref}(y_w\mid x)}-
\log\frac{\pi_\theta(y_l\mid x)}{\pi_{ref}(y_l\mid x)}
\right]\right)。
\]

DPO 不显式训练奖励模型，也不需要在线 rollout 和 Critic，但依赖固定偏好数据覆盖。

## 10．代码：Transformer Encoder

**解答**：

```python
import torch
from torch import nn

class TransformerEncoderBlock(nn.Module):
    def __init__(self, d_model: int, num_heads: int, d_ff: int, dropout: float = 0.1):
        super().__init__()
        self.norm1 = nn.LayerNorm(d_model)
        self.attn = nn.MultiheadAttention(
            d_model, num_heads, dropout=dropout, batch_first=True
        )
        self.norm2 = nn.LayerNorm(d_model)
        self.ffn = nn.Sequential(
            nn.Linear(d_model, d_ff),
            nn.GELU(),
            nn.Dropout(dropout),
            nn.Linear(d_ff, d_model),
        )
        self.dropout = nn.Dropout(dropout)

    def forward(self, x: torch.Tensor, padding_mask: torch.Tensor | None = None):
        h = self.norm1(x)
        h, _ = self.attn(h, h, h, key_padding_mask=padding_mask, need_weights=False)
        x = x + self.dropout(h)
        x = x + self.dropout(self.ffn(self.norm2(x)))
        return x
```

这是 Pre-Norm Encoder Block。实际模型还需在输入中加入位置编码，并确保 `padding_mask` 中 `True` 表示需屏蔽的位置。

## 2．超长上下文业界一般怎么做？Qwen 怎么做

**解答**：长上下文方法包括位置插值、NTK-aware Scaling、YaRN 等 RoPE 扩展；使用长序列数据继续训练；FlashAttention、分块/滑窗或稀疏注意力降低计算与显存；通过 GQA/MQA、KV 量化和缓存管理降低 KV Cache。Qwen 不同版本采用的策略不同，应依据具体模型技术报告说明，不能只说“RoPE 天然外推”。评估还应关注长文检索、跨段推理和不同位置的有效利用，而非只看最大输入长度。

## 3．讲讲 DeepSeekMoE、MLA 和 LoRA

**解答**：DeepSeekMoE 使用细粒度路由专家与共享专家，每个 Token 只激活部分路由专家；总参数量大，但激活计算较低，训练需处理负载均衡和跨卡通信。MLA 将 K/V 的主要信息联合压缩到低维潜在向量，推理缓存潜在表示，再恢复各注意力头所需表示，从而降低 KV Cache。LoRA 冻结基座权重并训练低秩增量 \(\Delta W=(\alpha/r)BA\)，显著减少可训练参数对应的梯度和优化器状态。

## 4．除了 Qwen，还了解哪些模型：LLaMA、DeepSeek、GLM

**解答**：LLaMA 是 Meta 的 Decoder-Only 模型家族，常用 RoPE、RMSNorm、SwiGLU 和 GQA；DeepSeek-V2/V3 的代表性设计是 MLA 和稀疏 MoE，R1 系列侧重推理后训练；GLM 系列源于 General Language Model 预训练框架，后续 ChatGLM/GLM 版本在架构、双语对话、长上下文和工具能力上持续演进。比较必须指定版本、参数规模和任务，重点看数据、架构、训练方法、部署成本与许可证。

## 5．Attention 怎么做？Encoder 和 Decoder 的 Attention 一样吗

**解答**：计算公式与一面第 3 题一致。关键区别是 Encoder 通常使用双向 Self-Attention，Decoder 使用 Causal Self-Attention；Encoder-Decoder 架构的 Decoder 还使用 Cross-Attention。不能只回答 Q、K 相乘，还要说明缩放、Mask、Softmax 和对 V 的加权。

## 6．了解 DeepSpeed 吗？ZeRO-1、2、3 分别做了什么

**解答**：DeepSpeed 提供分布式训练、混合精度、Offload 和推理等能力。ZeRO-1 分片优化器状态；ZeRO-2 再分片梯度；ZeRO-3 再分片参数，并在计算时按需 All-Gather。阶段越高，单卡静态显存越低，但通信和调度开销通常越大。CPU/NVMe Offload 是可选能力，不等同于某个 ZeRO 阶段。

## 7．FP16、BF16、FP32、INT8 有什么区别，训练时怎么选

**解答**：FP32 有 8 位指数和 23 位尾数，范围和精度高但显存与计算成本大；FP16 有 5 位指数、10 位尾数，精度较高但动态范围小，训练常需 Loss Scaling；BF16 有 8 位指数、7 位尾数，动态范围接近 FP32，通常更适合大模型训练；INT8 是整数表示，主要用于量化推理，也可在特定方案中参与训练。支持 BF16 的硬件上通常优先 BF16 混合精度，并对归一化、损失等敏感操作保留更高精度。最终取决于硬件、框架和数值稳定性验证。

## 8．看过 LLaMA 源码吗？对 Prompt 微调了解多少

**解答**：LLaMA 前向核心包括 Token Embedding、若干 Pre-Norm Decoder Block、RoPE、因果注意力、SwiGLU FFN 和输出头。Prompt Tuning 冻结基座模型，只学习若干连续软提示向量，并把它们拼接到输入 Embedding 前；Prefix Tuning 通常在各层注入可学习的 K/V 前缀。它们参数量小、便于多任务切换，但小模型或复杂任务上效果可能弱于 LoRA，软提示也可能占用有效上下文或增加缓存。

## 9．Qwen 相比其他开源模型好在哪里

**解答**：不能做无条件结论。可结合具体版本说明其中文、多语言、代码、工具调用、长上下文、模型尺寸覆盖和工程生态等优势，再用同一评测集比较准确率、格式遵循、时延、显存和许可证。不同任务上 LLaMA、DeepSeek、Mistral 等也可能更合适，选型应以目标场景实测为准。

## 10．除了 DeepSpeed，训练和推理显存不足还有什么办法

**解答**：训练侧可用 FSDP、张量/流水线并行、混合精度、梯度检查点、梯度累积、LoRA/QLoRA、8-bit Optimizer、序列并行与 CPU Offload。推理侧可用 INT8/INT4 量化、GQA/MQA、KV Cache 量化或分页管理、连续批处理、张量并行、上下文截断/压缩和投机解码。应区分减少显存、提高吞吐和降低延迟，它们并不总能同时改善。

## 11．FlashAttention 具体怎么做

**解答**：标准 Attention 会把完整 \(N\times N\) 分数矩阵写入显存，HBM 读写开销大。FlashAttention 将 Q、K、V 分块搬入片上 SRAM，在块内计算分数，并利用 Online Softmax 维护每行最大值和归一化因子，从而无需物化完整注意力矩阵；反向也通过重计算减少中间量存储。它计算结果是精确 Attention（允许浮点舍入差异），时间复杂度仍为 \(O(N^2d)\)，但 I/O 更少，显存复杂度由注意力矩阵的 \(O(N^2)\) 降到近似线性中间存储。

## 12．代码：岛屿数量（LeetCode 200）

**解答**：

```python
def num_islands(grid: list[list[str]]) -> int:
    if not grid or not grid[0]:
        return 0
    m, n = len(grid), len(grid[0])

    def dfs(i: int, j: int) -> None:
        if i < 0 or i >= m or j < 0 or j >= n or grid[i][j] != "1":
            return
        grid[i][j] = "0"
        dfs(i + 1, j)
        dfs(i - 1, j)
        dfs(i, j + 1)
        dfs(i, j - 1)

    ans = 0
    for i in range(m):
        for j in range(n):
            if grid[i][j] == "1":
                ans += 1
                dfs(i, j)
    return ans
```

每个格子最多访问一次，时间复杂度 \(O(mn)\)，递归栈最坏为 \(O(mn)\)。超大网格可改为显式栈避免递归深度限制。

## 13．Linux：给定单词，统计各字母数量并按数量倒序返回

**解答**：若只统计英文字母且忽略大小写：

```bash
printf '%s' "$word" | tr '[:upper:]' '[:lower:]' | grep -o '[[:alpha:]]' | sort | uniq -c | sort -k1,1nr -k2,2
```

`grep -o .` 会把标点也统计进去；以上命令用字符类过滤字母，并在计数相同时按字母排序。不同区域设置下字符范围可能不同，只需 ASCII 时可改用 `grep -o '[A-Za-z]'`。
