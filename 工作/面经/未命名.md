2.如何做 embedding 微调的，如何构造正负样例，训练的 loss 是什么
**解答**：微调通常使用 Contrastive Learning（对比学习）。正样本：Query和人工标注/点击的Doc。负样本：In-batch Negative（批次内其他Query的Doc）和 Hard Negative（用BM25召回但未点击的易混淆Doc）。Loss：InfoNCE Loss。

3.sft的 loss 是什么，怎么实现的
**解答**：SFT使用 Causal Language Modeling 的 Cross-Entropy Loss。实现上只对 Target（回答）部分的Token计算Loss，对Prompt部分的Token做Mask屏蔽不计入梯度。

4.NLP任务常用的损失函数有些
**解答**：交叉熵损失（Cross-Entropy）、对比损失（InfoNCE/Triplet Loss）、DPO Loss（偏好优化）、KL散度。

5. pretrain 和 sft 有什么区别
**解答**：Pretrain是无监督的“海量完形填空/文字接龙”，学的是世界知识和语言规律；SFT是极少量的“格式化问答对”有监督微调，学的是如何听懂人类指令并以人类喜欢的口吻回答问题。

6.RAG有哪些可优化的地方
**解答**：召回侧：混合检索（BM25+Dense）、加入Re-ranker重排；索引侧：Query改写、文档多级无损切块；生成侧：加入Prompt反思或知识图谱双路召回。

7.意图分流的 agent 怎么做微调的，用了多少数据
**解答**：通过收集真实场景下用户Query和所需调用的API作为问答对，构造包含系统思考约束的JSON格式集进行SFT，几千到上万条高质量数据即可。

8.做 sft 时是怎么做数据配比的，参数具体怎么设置的， loss 如何变化
**解答**：一般保持10%通用知识+80%垂类应用+10%安全拒答。学习率设置得很小（如1e-5），Loss前期快速下降，后期平缓，若反弹需用Early Stopping。

9. 说一下 vllm 部署8*7B的 MOE 模型每秒大概能推多少token
**解答**：依赖于GPU型号。8x7B MoE实际激活用到的参数只有10多B。在单张A100上利用PagedAttention一般能达到数千Tokens/s的吞吐。

10. 如果显存不够了，有哪些常用的优化手段
**解答**：训练：LoRA、DeepSpeed ZeRO、Gradient Checkpointing、混合精度训练。推理：vLLM（KV Cache按页分配）、INT8/AWQ量化。

**解答**：LeetCode 206。定义prev=null, curr=head，循环里保存next=curr.next, curr.next=prev, prev=curr, curr=next，返回prev。

5.你的 RAG 项目中用到了 agent 吗，一般 agent 会用在RAG 链路中的哪些部分
**解答**：用到了。Agent通常用于前置的意图识别（决定需不需要去查库），以及路由Router（该查哪个库），还有后置的反思打分模块（Critic）评估捞回的文档能不能回答。

7.在知识库中召回回来的文本没有好结果该怎么办 
**解答**：设置相似度阈值拦截。如果都低于阈值，或者大模型读完后发现无答案，触发“不知道”的兜底回复，严防编造幻觉。

8. KL散度的表达式，它和交叉熵的区别
**解答**：$D_{KL}(P||Q) = \sum P(x) \log\frac{P(x)}{Q(x)}$。KL散度衡量两个分布的差异；交叉熵是 $H(P,Q) = H(P) + D_{KL}(P||Q)$。由于目标真实分布因任务固定，$H(P)$是常数，所以优化交叉熵基本等价于优化KL散度，但交叉熵好算很多。

9 .code ：手写一个多分类的公式，并用代码实现
**解答**：也就是Softmax。`exp_x = torch.exp(x - x.max()); return exp_x / exp_x.sum(dim=-1)`。

10.🎨智力题：抛硬币，正反概率都是0.5，如果是正面则继续抛，求抛硬币次数的期望
**解答**：期望 $E = 1 + 0.5 \times E$ （如果第一次是正，继续抛的期望依然是 $E$；如果第一把反，结束了就是0）。解得期望次数为 2 次。

4. 为什么不拿 KL 散度作为 loss
**解答**：因为算交叉熵的时候，真实标签是One-Hot的（极其简单），交叉熵只需要把非0项对数求和即可。而算KL的话，还要减去真实目标的熵（虽然是0常数），工程上算交叉熵比算完整KL公式更快。如果是模型蒸馏，两个都是软标签时，就必须用KL了。

5.LLM哪个环节最重要，为什么呢
**解答**：高质量数据管线（Data Pipeline）最重要。“Garbage in, garbage out”，不论是预训练还是SFT，高质量配比的数据决定了模型的聪明天花板。

**解答**：浅层：LR、GBDT。深度：Wide&Deep、DeepFM、DIN（关注序列）。

7. deepseed 的原理，zero1,2,3怎么做的
**解答**：将大模型训练时的显存占用切片分布到各个GPU上。ZeRO-1切分Optimizer States（优化器状态）；ZeRO-2进一步切分Gradients（梯度）；ZeRO-3彻底将模型Parameters（参数权重）也切分，用到哪层播报到哪层，显存极致压缩。

8.🎨智力题：54张扑克牌，分成三等份，求大小王在同一组的概率
**解答**：大王一定在三份中的一份里（这份里有18个坑位，大王占1个，剩17个）。其余53张牌竞争这剩的17个坑位，小王也在里面的概率是 $17/53$。

9.🔘code ：实现rand5到rand7.
**解答**：利用 `(rand5() - 1) * 5 + rand5() - 1` 生成 0到24 均匀分布的数。遇到 $>20$ 的数就丢弃（拒绝采样），对于 $0\sim 20$ 返回 `val % 7 + 1` 即可。

2.现在主流大模型架构有什么变化？ 
**解答**：从纯Dense模型走向MoE（混合专家模型）以打破参数性能瓶颈；Attention架构从MHA走向MQA/GQA以及DeepSeek的MLA（多头潜在注意力）以极致压缩KV Cache占用；微调与对齐技术从PPO逐渐被更轻量的DPO、以及去掉Critic的GRPO所取代；模态上从纯文本走向原生多模态（如Omni统一架构）。

3.grpo的改进方法有哪些？了解gspo吗？
**解答**：
- **GRPO改进**：抛弃传统PPO庞大的价值网络Critic，转而对同一个Prompt生成多个不同回答构建组（Group），在组内对Reward求相对的分数（Z-Score标准化）直接作为Advantage基线，省下一半以上的显存。
- **GSPO了解**：GSPO (Group Swapped Preference Optimization) 是一种结合了偏好对比和组内相对打分的进阶变体，进一步降低对由于打分器绝对分不准带来的方差问题。

4.transformer结构介绍？
**解答**：分为Encoder和Decoder。核心是Self-Attention（自注意力机制），捕捉全局上下文。通过多头机制提取不同子空间特征。加上FFN（前馈神经网络）引入非线性，配上LayerNorm和残差连接稳定深层梯度，还有Positional Encoding注入序列位置信息。

5.hrbp业务理解题：你觉得实习项目中某个点有什么更好的实现方式？这样做优缺点是啥？  
**解答**：比如在RAG引入时，更好的方式是从“单纯外挂”变为“知识召回+大模型自身逻辑推理结合的多Agent架构”。优点是减少幻觉上限极高，缺点是多次调用LLM导致响应时间极大拉长。

6.deepseek r1有的什么注意力优化？  
**解答**：采用了 **MLA (Multi-head Latent Attention)**。核心在于它把巨大的KV张量进行低秩压缩（经过一个极小的Latent隐层池子），并且把RoPE（旋转位置编码）给彻底独立解耦摘出来。这样在推理计算时不仅算得快，而且显存占用只有传统MHA的一小部分。

7.有了解什么kv优化方法吗？  
**解答**：
1. 架构级：MQA、GQA、MLA压缩KV体积；
2. 系统工程级：PagedAttention（vLLM）按页动态非连续分配显存，零碎片；KV Cache量化（INT8/FP8）；
3. 算法级：滑动窗口注意力（Sliding Window）、或者对历史KV做Token丢弃（如Heavy-Hitter Oracle选留高分KV）。

8.code：手撕mha，进一步问在哪加masked矩阵。
**解答**：`scores = torch.matmul(q, k.transpose(-2, -1)) / math.sqrt(d_k)`。在算完scores之后，送入Softmax之前加Mask：`scores = scores.masked_fill(mask == 0, float('-inf'))`。

2.多任务建模梯度冲突如何解决
**解答**：
1. **梯度正交投影 (PCGrad)**：如果两个任务的梯度夹角为负（互相打架），就把其中一个梯度投影到另一个梯度的法平面上。
2. **PCGrad的进化：CAGrad**：在一定邻域内寻找一个平均梯度方向最大的去优化。
3. **动态权重调整 (如 Uncertainty Weighting, DWA)**：针对不同任务Loss量级不同动态给不同的大权重。
4. **底层架构隔离**：采用PLE架构隔离共享参数和私有参数。

3.线上排序的融分公式
**解答**：
传统的粗暴公式会是线性加权 $Score = W_1 \times CTR + W_2 \times CVR$。
或者幂乘积非线性加权 $Score = CTR^\alpha \times CVR^\beta \times \text{视频时长}$。这个通常由一个上层的强化学习微调Agent或者黑盒超参搜索（如Grid Search）在线打AB实验试出来。

4.项目中的GAUC是如何设计的，有没有更合理的设计方法
**解答**：
设计：GAUC = $\frac{\sum_{i=1}^n \text{曝光量}_i \times AUC_i}{\sum_{i=1}^n \text{曝光量}_i}$，在用户级别内算AUC再加权。
更合理方法：引入时间衰减机制或者用户的上下文活跃状态特征进行软加权，惩罚那些全点/全不点的无效用户分母噪音；或者使用更贴合线上排序位置打分的NDCG指标辅助验证。

5.大模型中的moe结构优化是如何实现的
**解答**：
- 结构上，将传统的巨大的FFN换成一个Router（如Gating Network）控制的多个细分的小FFN（特种专家）。
- 优化上，使用`Top-2`稀疏路由，为了防极化，Loss里强行加Load Balancing Loss平衡分配概率，并通过专家级并行（EP）配合模型并行（TP）跨显卡解决通讯瓶颈。

6.如何避免学偏的模型上线
**解答**：
三道防线：
1. 离线多维度死磕：看全局AUC还要死盯GAUC和各个细分长尾用户群体的切片AUC，防止模型骗分（只对高活用户拟合）。
2. Replay/影子回放机制：导入昨天的真实线上流量离线压测它的打分是否有显著倒挂。
3. 线上AB Test：绝对的最终试金石，严格开3%、5%的小流量灰度实验组看CTR、CVR再全量。

7.实习中某个项目选择改策略而不是改模型的考量
**解答**：
ROI（投入产出比）的考量。改模型牵一发而动全身，需要大改训练管道、耗时几周且线上容易崩（模型迭代不稳）。而加一个兜底、熔断或特征策略强插规则，几行代码就能当天上线立马止血（如针对大促临时提权的粗暴规则）。

8.📚手撕：auc
**解答**：将List中`(predict, label)`按predict从小到大排序。设rank为当前下标(1开始)。求所以label为1的样本的rank之和S。`AUC = (S - M*(M+1)/2) / (M*N)`，其中M为正样本数，N为负样本数。

3. 介绍一下多任务建模的纠偏方法
**解答**：比如在转化率CVR预估中，由于线上推断只能看到曝光到点击，但训练时用的是点击到购买的样本，存在极大样本选择偏差（Sample Selection Bias）。纠偏方法是使用 **ESMM (Entire Space Multi-Task Model)** 算法，引入曝光到购买的完整概率 $pCTCVR = pCTR \times pCVR$，在全样本空间进行联合优化。

4.多专家网络极化问题
**解答**：即路由坍缩（Routing Collapse），所有任务全都指向某个“明星专家”，别的专家变死神经元。详见前文，通过 Load Balancing Loss（强制均摊）、或者 Noisy Gating（给门控预测加高斯小噪声）、或者使用全隔离的 PLE架构处理。

5.多任务建模为什么选择ctr和cvr而不是ctr和cpm
**解答**：CTR（点击率）和CVR（转化率）是反映用户真实对物品极度感兴趣内生欲望的指标（模型能学会）。CPM（千次展现成本/收益）不仅取决于点击，更取决于广告主的动态出价、大盘的竞争激烈程度甚至运营的人为调节。CPM太受环境波动影响且具有“异质性”，模型很难纯靠自身直接进行准确拟合。

6.提高pcoc的方法
**解答**：PCOC = (Predict CTR) / (真实点击率)。如果PCOC偏高（高估），说明正样本里混入了易骗人的标题党，或者负样本压制力不够。提高/校准PCOC的方法有：使用 Platt Scaling 或者 Isotonic Regression（保序回归）在模型输出结果后对概率分布做一层保序平滑校准校正。

7.📚手撕：业务场景题
**解答**：例如实现一个TopK商品过滤、或者基于规则的推荐合并策略，用优先队列（堆）即可。

2.transformer计算的时间复杂度和空间复杂度，deepseek对transformer主要做了哪些改进？
**解答**：
- 计算时间/空间复杂度正比于序列长度的平方 $O(L^2)$。
- **DeepSeek改进**：主要就是 MLA (Multi-head Latent Attention)。将原本需要天量显存来单独存储的每个计算层巨大的 Key, Value 矩阵，浓缩经过一个低维的隐变量（Latent Vector），大幅压扁极减小 KV-Cache 开销。

3.为什么要在推荐系统中引入rqvae？
**解答**：RQ-VAE（残差量化变分自编码器）常用于生成式推荐（Generative Retrieval）。推荐系统中商品ID是离散正交且缺乏语义的。RQ-VAE能像生成图片离散Token一样，把千千万万没有关系的商品压缩编码成一段有层次感、带有语义信息的离散ID串。然后就能让大模型通过“续写生成这段ID”直接命中召回商品。

4.如何解决坍缩问题？
**解答**：对于VAE中的“后验坍缩（Posterior Collapse）”，指Decoder极其强大直接无视了隐空间向量，$KL$散度降为0死机。解决方法：对KL散度加上一个随步数逐步拉升的温和的权重系数（KL退火，KL Annealing），或设定一个容忍下界（Free Bits）。

5.对rankmixer了解吗？介绍一下？
**解答**：由于直接采用全连接做特征交叉会受限于显存爆满。RankMixer是受到计算机视觉MLP-Mixer启发的轻量级架构，它直接抛弃笨重的Attention架构，采用两组全连接层：一层做Token-mixing（在特征通道上交换信息横向切），一层做Channel-mixing（在每个通道内独立做非线性映射纵向切），实现极其高效的极低延迟用户特征混合推荐。

6.详细介绍一下Moe？优缺点各自是啥？
**解答**：
- 详解：即混合专家。将大前馈网络拆散成N个独立的小网络，前置一个Router（路牌）。一个Token过来，路牌给出得分，激活得分最高的2个专家做运算，其余的装死睡觉。
- 优点：解除了参数量和推理算力的死绑。模型能堆到极夸张甚至万亿参数规模吞噬海量知识，但推理时FLOPs极低甚至快于小模型。
- 缺点：门控极易陷入极化偏科（所有活给一个人干）；训练和推理工程极端复杂，极度依赖多卡并行通讯矩阵调优。

7.训练模型如果loss不稳定，如何解决？
**解答**：
1. 检查数据里是否混入了带有脏乱字符或极端值的劣质刺客样本，加强裁剪或清洗。
2. 将Learning Rate的学习率适当降低，并强上 Warm-up（预热）策略缓慢爬坡拉高。
3. 检查梯度是否爆炸，强开 Gradient Clipping (梯度裁剪截断)。
4. 如果是推荐模型，更换更大平滑的Loss函数（比如Huber Loss防飞逸）。

8.了解lora吗？
**解答**：Low-Rank Adaptation（低秩微调）。核心是在预训练大矩阵的旁边外挂两个长相奇特的低维分解矩阵A和B。冻结老祖宗矩阵权重不动，只练A和B。训练完后只要把 $A \times B$ 变回去加到老公公身上即可。能把一个几十G的模型的微调显存直接爆降只需修改几百兆小文件。

9.代码:手撕mha
**解答**：多头自注意力。步骤：把 $x$ 过全连接层后切分成 `[batch, num_heads, seq, head_dim]`；进行点乘 `qk / sqrt(d) `；加上mask过softmax；乘上 $v$；利用 `transpose` 再变回原始厚度 `[batch, seq, embed_dim]` 连接后输出。

4. DP和DDP区别
**解答**：
- **DP (DataParallel)**：单进程多线程模式。主卡不仅承担自己那份计算，还要作为中枢不断把切成块的数据、全量模型权重撒给子卡，算完还要汇总子卡的梯度。**存在极其严重的单卡通信与显存瓶颈负荷过重问题。**
- **DDP (DistributedDataParallel)**：多进程模式。每张卡都是一个独立并行的诸侯国。大家都各自带一份独立模型权重和数据跑前向反向，最后在算完梯度时，通过NCCL后端的 **Ring-AllReduce（环形同步）**机制极其高效地互换和平均化梯度，彻底解决单卡中枢拥堵死机问题。

5. t维度的rope是怎么做的？ 
**解答**：指在视频生成（或多模态3D空间）中引入时间序列(Time)上的旋转位置编码 (RoPE)。将文本一维的RoPE扩充到三维空间，不仅给宽高$(H, W)$赋予频域旋转角度，也对视频帧的时间轴 $T$ 赋予单独的频域旋转因子，让模型感知到连续画面的绝对先后与相对距离关系。
