# 一面

## 1．怎么解决 LLM 幻觉问题

**解答**：先区分事实性幻觉、上下文不一致和推理错误。数据侧清理错误、重复和冲突语料；训练侧加入高质量 SFT、偏好和拒答样本；知识侧对实时或私域事实使用结构化查询或 RAG，并优化切块、召回、重排、时效性和权限；生成侧要求引用证据、证据不足时拒答；高风险场景再用检索、规则、NLI 或人工逐条核验。降低 Temperature 只能减少随机性，不能保证事实正确。

## 2．DPO 的训练过程怎样，正负概率怎么算

**解答**：数据为偏好三元组 \((x,y_w,y_l)\)，其中 \(y_w\) 优于 \(y_l\)。策略模型和冻结参考模型分别计算整段回答的条件对数概率；通常只累加 Assistant 有效 Token，并正确处理 Padding。损失为：

\[
L_{DPO}=-\mathbb E\log\sigma\left(\beta\left[
\log\frac{\pi_\theta(y_w\mid x)}{\pi_{ref}(y_w\mid x)}-
\log\frac{\pi_\theta(y_l\mid x)}{\pi_{ref}(y_l\mid x)}
\right]\right)。
\]

DPO 不显式训练奖励模型，也不需要在线 rollout 和 Critic，但仍需参考模型或等价实现，效果依赖固定偏好数据的质量和覆盖。

## 3．MoE 架构原理

**解答**：MoE 通常把 Transformer 的部分 FFN 替换为多个专家。Router 为每个 Token 计算门控分数，只选择 Top-k 专家，并将专家输出加权合并：

\[
y=\sum_{i\in\operatorname{TopK}(g(x))}g_i(x)E_i(x)。
\]

这样可在单 Token 激活计算量相对可控时扩大总参数量和容量。代价是所有专家仍占存储，且会产生负载不均、容量溢出、路由不稳定和 All-to-All 通信开销，因此需要负载均衡损失、容量控制和专家并行。

## 4．RAG 有噪声怎么办

**解答**：数据侧清洗重复、过期和低可信文档，并维护版本、来源和权限；召回侧使用 BM25 与向量混合检索、元数据过滤和 Query 改写；排序侧用 Cross-Encoder Reranker、相关性阈值和去重；上下文侧使用 Parent-Child 切块、压缩和证据聚合；生成侧要求只依据可引用证据回答。资料不足时拒答，资料冲突时列出来源与时间并明确不确定性。用 Recall@K、Context Precision/Recall、Faithfulness 和引用正确率分环节评估。

## 5．了解哪些新的强化学习和偏好优化技术

**解答**：可介绍 PPO/GRPO 等在线策略优化，DPO、IPO、KTO、ORPO、SimPO 等直接偏好优化，可验证奖励强化学习，以及过程监督。GRPO 对同一问题采样一组回答，使用组内相对奖励估计优势并省去独立 Critic，但仍包含策略采样、概率比裁剪与 KL 控制。数学和代码任务可使用答案校验器或单元测试提供奖励。闭源模型未公开的训练流程不能武断断言采用 MCTS。

## 6．DeepSeek GRPO 的原理和后续改进

**解答**：对问题 \(q\) 从旧策略采样一组回答 \(o_1,\ldots,o_G\)，计算奖励 \(r_i\)，组内优势可写为：

\[
A_i=\frac{r_i-\operatorname{mean}(r)}{\operatorname{std}(r)+\epsilon}。
\]

再用 \(\rho_{i,t}=\pi_\theta(o_{i,t}\mid q,o_{i,<t})/\pi_{old}(o_{i,t}\mid q,o_{i,<t})\) 构造 PPO 式裁剪目标，并加入相对参考模型的 KL 正则。组内标准化值是优势估计，不是“Baseline”本身。后续优化主要处理全同奖励组无学习信号、长度偏置、裁剪稳定性、采样效率、奖励投机和 rollout 吞吐。

## 7．召回索引怎么优化

**解答**：根据规模、更新频率、召回率和延迟选择 HNSW、IVF、PQ/OPQ 或混合索引，并调节 `efSearch`、`nprobe` 等参数。数据侧做切块、去重和向量归一化，保留标题、时间、权限等元数据；检索侧采用分区过滤、冷热分层和 BM25+Dense 混合召回；再用 Reranker 精排。HNSW 查询并非在所有数据与参数下严格 \(O(\log n)\)，必须以 Recall@K、P95 延迟、内存和构建/更新成本实测。

## 8．意图识别时 LLM 输出格式不好怎么优化

**解答**：优先使用 API 原生 JSON Schema、Function Calling/Tool Calling，或 vLLM、SGLang、Outlines 等的 Grammar 约束解码；Prompt 中明确字段类型、枚举、必填项并提供少量示例；输出后使用标准 JSON 解析器和 JSON Schema/Pydantic 校验，失败时有限重试并回传具体校验错误。不要用正则解析嵌套 JSON，因为字符串转义、数组和嵌套对象会导致误截取。

## 9．代码：三数之和

**解答**：

```python
def three_sum(nums: list[int]) -> list[list[int]]:
    nums.sort()
    ans = []
    for i in range(len(nums) - 2):
        if nums[i] > 0:
            break
        if i > 0 and nums[i] == nums[i - 1]:
            continue
        left, right = i + 1, len(nums) - 1
        while left < right:
            total = nums[i] + nums[left] + nums[right]
            if total == 0:
                ans.append([nums[i], nums[left], nums[right]])
                left += 1
                right -= 1
                while left < right and nums[left] == nums[left - 1]:
                    left += 1
                while left < right and nums[right] == nums[right + 1]:
                    right -= 1
            elif total < 0:
                left += 1
            else:
                right -= 1
    return ans
```

排序后固定一个数，再用双指针查找另外两个数并跳过重复项。时间复杂度 \(O(n^2)\)，除排序外额外空间 \(O(1)\)。

# 二面

## 1．RAG 常用的检索方式

**解答**：稀疏检索如 BM25 擅长关键词、型号和专名；Dense Retrieval 用 Embedding 表达语义，适合措辞不同但含义相近的问题；混合检索同时召回两路结果，常用 RRF 或归一化分数融合，再交给 Cross-Encoder Reranker 精排。还可结合元数据过滤、知识图谱和结构化数据库。哪种最好取决于语料和评测，不存在固定“最稳”方案。

## 2．知道哪些 Embedding 模型

**解答**：常见开源模型有 BGE、GTE、E5、Jina Embeddings 和 Sentence-Transformers 生态模型，商业 API 包括 OpenAI Embeddings 等。选型应关注目标语言与领域、最大长度、向量维度、是否支持 Query/Document 指令、MTEB/C-MTEB 等基准，以及目标语料上的 Recall@K、延迟和成本；不能只按历史榜单名次选择。

## 3．一般通过什么渠道了解新技术

**解答**：优先阅读论文原文、官方技术报告、代码仓库、Release Notes 和模型卡；再用 Papers with Code、Hugging Face Trending、arXiv 分类与学术会议追踪工作。对二手解读要回到原始实验核验，并通过最小复现记录版本、数据、指标和限制。

## 4．RAG 遇到模型缺失电商知识一般怎么做

**解答**：库存、价格、活动规则等实时事实优先通过数据库查询或 RAG 提供；术语、语气、任务流程可通过领域 SFT 学习；语料规模足够且基座领域差距明显时，才考虑持续预训练。三种方式可组合，是否需要训练应由“仅 RAG、RAG+SFT、RAG+持续预训练”等消融实验决定，不存在唯一方案。

## 5．Qwen3 的技术原理

**解答**：应明确具体版本和官方技术报告，避免沿用“尚未发布”的过时表述。概括时可从 Decoder-Only 基础架构、Dense/MoE 版本、GQA、RoPE、Tokenizer、多语言与代码数据、长上下文、思考/非思考模式和后训练方法展开。面试中应区分官方披露事实与个人推测，并与同规模模型在相同配置下比较。

## 6．怎么防止客服 LLM 串台

**解答**：后端必须按租户和 Session 隔离消息、缓存、向量检索过滤条件与工具权限，禁止共享可变全局历史；每次请求校验用户身份和数据 ACL；缓存键包含租户、权限、模型及知识版本，避免语义缓存跨用户命中；长期记忆需记录归属、来源和有效期；日志脱敏并做并发、重放和越权测试。System Prompt 只能辅助角色约束，不能替代服务端隔离。

## 7．代码：字符串解码

**解答**：

```python
def decode_string(s: str) -> str:
    stack = []
    current = ""
    repeat = 0
    for ch in s:
        if ch.isdigit():
            repeat = repeat * 10 + int(ch)
        elif ch == "[":
            stack.append((current, repeat))
            current, repeat = "", 0
        elif ch == "]":
            prefix, count = stack.pop()
            current = prefix + current * count
        else:
            current += ch
    return current
```

每个输入字符处理一次；若把输出拼接成本计入，时间与空间复杂度均为 \(O(|output|)\)。
