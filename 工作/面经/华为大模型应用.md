2、强化学习中onpolicy和offpolicy的区别什么？grpo是onpolicy的吗？如何实现真正的onpolicy? 
**解答**：
- **On-policy（同策略）**：产生样本数据的策略（Policy）和当前正在被优化更新的策略是同一个。也就是说，模型必须自己去环境里探索产生数据来进行这一轮的训练。代表算法是 PPO。
- **Off-policy（异策略）**：产生样本数据的策略和正在被优化的策略不是同一个。可以用旧策略甚至其他随机策略收集的数据放在经验回放池（Replay Buffer）里供现在的模型训练。代表算法是 DQN。
- **GRPO（Group Relative Policy Optimization）**：是**On-policy**的。它是DeepSeek提出的一种基于PPO的改进算法。GRPO摒弃了原来PPO中和Actor差不多同样大小的Critic模型，而是对同一个Prompt用当前策略采样多个输出（形成一个Group），利用这些输出在这个Group内部的相对Reward来作为baseline计算优势（Advantage），极大节省了显存。
- **如何实现真正的On-policy**：在每次更新完策略网络的参数后，必须清空之前收集的轨迹数据，用这套刚刚更新后的最新参数重新与环境（Reward Model等）交互来采集新的数据，才能进行下一次梯度更新。

3、解释一下为什么GPT可以并行计算，而rnn不能。
**解答**：
- **GPT并行计算**：GPT基于Transformer的自注意力机制。在**训练阶段**（Teacher Forcing），由于序列中每一位预测目标所依赖的历史真实的Token都已经完整输入，Transformer可以通过一个下三角的Mask矩阵，在矩阵乘法的一步前向传播中同时计算出整个序列所有位置的Attention结果，这就是所谓的并行训练。
- **RNN串行计算**：RNN的网络结构本质决定了第t步的隐状态 $h_t$ 的计算必须依赖第 t-1 步的隐状态 $h_{t-1}$ 的计算结果。所以无论如何它都必须顺着时间轴一步一步串行算完，无法进行时间维度上的并行操作。

4、qwen系列纯文本模型每一代的改进点是什么？
**解答**：
- **Qwen 1/1.5**：奠定了强大的多语言和中文基础能力。1.5版本在对齐上放弃了繁琐的PPO转而使用DPO，大幅提升了模型的Chat指令遵循能力。
- **Qwen 2**：架构上全面引入GQA（Grouped Query Attention）以提高推理效率降低内存抓取；引入了Tie Embedding，并在长上下文处理上采用了YARN/双重RoPE缩放；模型的数据上大幅增强了代码和数学能力。
- **Qwen 2.5**：在2的基础上进行了远比过去更大规模的高质量数据预训练，大幅度强化了指令遵循、长文本理解和多语言能力，是同等规模下目前业界最强的开源全能模型系列之一。

5、在计算attentionscore时如何对padding做mask操作？
**解答**：在Transformer中，批量计算时为了对齐长度较短的序列，会补齐（Padding）一些无意义的Token。
**Mask操作法**：在计算出原始的Attention Score矩阵（$QK^T/\sqrt{d}$）后，在送入Softmax之前，使用一个Padding Mask矩阵，将那些属于Padding token的位置的值替换为一个极大负数（比如$-1e9$ ）。这样在进行Softmax归一化时，$e^{-1e9}$ 会趋近于0。最终在乘上Value矩阵时，这些Padding部分就不会对当前Token的注意力求和产生任何权重的实质影响。

6、valuemodel和rewardmodel的区别？
**解答**：在RLHF的框架下：
- **Reward Model (RM，奖励模型)**：是静态的打分模型。它接受一个环境状态和动作（比如一个Prompt和模型的Response），输出一个标量评分，表示这个回答绝对质量的好坏。
- **Value Model (Critic，价值模型)**：是动态更新的模型。它用来预测在当前状态下，由当前策略一直往后执行，能获得的“未来折现总回报（Expected Return）”。在PPO算法中它负责提供一个基准线（Baseline），从而计算出优势函数（Advantage），帮助Actor模型判断某个动作好于平均预期的程度。

7、moe架构是什么？ds如何平衡每个专家学到的token数量？
**解答**：
- **MoE（混合专家，Mixture of Experts）架构**：将标准Transformer中的前馈神经网络层（FFN）替换为多个并行的“专家”网络，并引入一个门控路由（Router网络）。针对每个输入的Token，Router计算概率并动态将它分配给少数几个专家（比如Top-2）处理，最后将它们的输出加权求和。这样可以在极小增加算力的前提下大幅扩张模型的总参数规模。
- **专家负载均衡（Load Balancing）**：如果任由模型自由学习，Router很容易陷入“马太效应”，把所有Token都倾向于发给某几个“明星专家”，导致其他专家“饿死”。通常这会通过在总Loss中加一项**辅助损失（Auxiliary Loss）**来解决。这项辅助损失会监控所有Batch内Token分配给专家的比例，并促使其逼近均匀分布；或者像DeepSeek-V2/V3中采用无辅助Loss的Router级偏置（bias）等策略来直接在路由逻辑上保证分配均匀。

8、解释一下ds的MLA和MTP。
**解答**：这是DeepSeek（DS）提出的两大核心技术优势：
- **MLA (Multi-head Latent Attention)**：用于极大地解决推理时的KV Cache显存占用瓶颈。它的做法是不再对每一层的大量Key和Value做单独的长序列缓存，而是将KV共同投影压缩成一个低维的隐向量（Latent Vector），并在计算Attention时将RoPE位置编码做解耦提取。这样能让长文本推理的KV显存占用大幅度减少。
- **MTP (Multi-Token Prediction)**：除了预测下一个Token外，模型额外长了几个轻量级的预测头（Prediction Head），在训练前向时不仅预测 $x_{t+1}$，还同时预测 $x_{t+2}, x_{t+3}$等等。这相当于在训练期给模型提供了更密集的监督信号，提高了学习效率。同时在推理阶段，MTP自带的头可以充当免费的“草稿模型”（Draft Model），天然支持极其高效的投机解码（Speculative Decoding），大幅提升生成速度。

9、prompt工程，你在实践中有什么trick?什么时候给fewshot？什么时候逻辑引导？
**解答**：
- **常用的Trick**：结构化约束（用Markdown、XML等标签包裹指令以免混淆）；赋予特定的Persona角色（“你是一个资深专家”）；通过清晰标明输入/输出的分隔符和强制格式（如“只能用JSON回答”）。
- **什么时候给 Few-Shot（少样本）**：当你的任务用抽象语言难以完美描述（比如判断一种主观情感风格、提取隐式规律或者要求特别非标的格式）时，给模型提供2-3个包含正例和反例的上下文，让它直接学习Pattern，会比长篇大论的指令有效得多。
- **什么时候逻辑引导（CoT，思维链）**：当遇到多步数学推导、逻辑判断、复杂决策时，要在Prompt里强制它“请一步一步分析（Let's think step by step）”或者你先给它个思考模板结构。多思考的Token意味着多分配了算力，能显著减少直接输出最终结果带来的幻觉。

10、市面上的大模型分别有什么优势，如何选择合适的大模型？
**解答**：
- **GPT-4o / Claude 3.5 Sonnet**：两家是闭源通用模型的巅峰，代码能力和复杂问题解决能力最强。如果项目对准确率要求极高且有预算，或者需要超写码能力，直接调API选这俩。
- **Qwen系列（通义）**：中文开源与闭源生态的绝对强手。如果做国内本地部署，且需要长文本、优异的中文对齐能力，Qwen是第一选择。
- **Llama 3系列**：全球开源标杆。如果你想在海外市场或英语场景做自己的垂类SFT或者Base衍生，社区资源最好。
- **DeepSeek**：超高的推理极客能力（代码、数学能力并肩最强者）极低的API价格。如果是大量文本的离线跑批处理或需要重度RAG的逻辑总结，DeepSeek是性价比首选。

11、多维旋转位置编码是如何改进的？ 
**解答**：**RoPE（Rotary Position Embedding）**相较于绝对位置编码和传统的相对位置编码的改进点在于：
它通过在复平面上对词向量进行旋转变换来表征位置信息。它给出的词嵌入虽然是绝对位置的表达，但是当计算Attention中的内积时，两个位置的内积结果中会自动包含相对位置之差（也就是一种退化或者旋转相加的相对体现）。
这让它既有绝对位置编码的高效性，又具备相对位置编码的外推能力，同时还能很方便地通过直接修改旋转弧度底数做长文本外推扩展（比如YARN、位置插值 PI）。

12、mcp和fc是什么，在你的项目中你是如何使用这两个功能的？
**解答**：
- **FC (Function Calling，函数调用)**：是大模型输出结构化参数能力的一种体现。模型不是输出闲谈文本，而是根据用户的问询，判断需要调用哪一个外部函数，然后准确提取所需的参数用JSON等格式输出。这样就可以联动后端代码真正执行诸如查询数据库、调用天气API的动作。
- **MCP (Model Context Protocol)**：这是一种连接大模型与本地、远程外部数据源及工具箱的标准协议栈。它标准化了模型与上下文数据的通信方式。
- **项目使用**：（可以结合实际场景）比如我利用FC让大模型判断用户意图，当遇到查询最新数据时，模型输出函数名和参数，接着通过代码后端拦截并去调用搜索API，再把抓回来的结果挂回上下文，实现Agent的自动化决策。

13、现场手撕接雨水。
**解答**：LeetCode核心经典题（42题）。
核心思路是利用**双指针**：
```python
def trap(height):
    if not height: return 0
    left, right = 0, len(height) - 1
    left_max, right_max = height[left], height[right]
    res = 0
    while left < right:
        if left_max < right_max:
            left += 1
            left_max = max(left_max, height[left])
            res += left_max - height[left]
        else:
            right -= 1
            right_max = max(right_max, height[right])
            res += right_max - height[right]
    return res
```
