3．为什么多头注意力能提升表达能力？
**解答**：
类比于卷积神经网络利用不同的“卷积核”去抓取图像的不同纹理边缘；**多头注意力（Multi-Head Attention）**的原理在于将同一句话的隐层向量映射投射到多个绝对相互独立且平行的线性子空间中。
- **防止特征冲撞淹没**：如果只用一个大头，遇到像“苹果”这个词时，模型既想表达它和“好吃”的物理关联，又想表达它和前文“公司财报”的金融关联，特征容易揉在一起搅糊。而分成多头后，有的专门学词性指代，有的专门学情感状态，有的看物理空间。
- 最后将它们所有头的果子拼起来（Concat）再融合。它地提升了模型在同质化的字层面中抽丝剥茧捕捉不同视角语义联系的容错率。

4．为什么要在大模型中使用 RMSNorm ？和 LayerNorm 有什么差异？
**解答**：目前绝大多数开源百亿/千亿模型（如Qwen, Llama）标配全是 RMSNorm。
- **差异（砍了均值操作）**：传统的 `LayerNorm` 标准流程有两步死板：先求均值让特征归位到 0 中心（减均值），再求方差让它们统一步伐缩放（除以标准差）。而 `RMSNorm` （Root Mean Square Normalization）非常激进地把**“求均值并做中心化平移”这一步彻底给剁了**。它直接拿特征向量算其原始平方和平方根（RMS）去当缩放分母就行。
- **为什么更优**：作者和工业界无数人发现，LayerNorm 里的平移操作对神经网络的高级表征表现基本毫无增益卵用，纯纯浪费算力。剁掉它之后，不仅显存开销小了，训练速度直接起飞提升几成（大概快10%~30%计算），且在保持了不亚于甚至超越原版平稳收敛性的基础上，是绝对的极致工程降本神手。

5．KV Cache 是怎么起作用的？为什么对长上下文推理很关键？
**解答**：
- **作怎么起作用**：大模型生成文本是“自回归”的，只能像挤牙膏一样一次蹦个字。当它要预测第101个字时，要把前100个字的 $Q, K, V$ 矩阵算完；预测第102个字，按理要把101个字全重算。但实际上那前100个词自己本身的 $K$ 向量和 $V$ 向量天荒地老都不会变了！所以系统就在显存里开辟一大块空间把这些老员工的值存下（这就是KV Cache）。新字蹦出来，只算它自己的新 $Q$，然后拿 $Q$ 跑去仓库里跟存好的几百个老 $K,V$ 走一遍 Attention 累加即可，不再算旧人。
- **对长文的关键性**：救命恩人。如果不存，每次都在里面重新从头暴力点乘，每次新吐一个字的运算量会呈恐怖的 $O(L^2)$ 指数级雪崩，如果长文本有10万字，一张卡大概预测1个字要卡死几分钟。有了 KV Cache，推流的计算时间复杂度硬生生被砍到了呈线性受限于显存带宽读取的 $O(L)$。让即时生成超长小说成为活的可能。

6．大模型推理时的加速思路？
**解答**：
面试高频八股，从不同层级切面拆解：
- **架构与模型压缩侧**：使用相对低精度的 **量化部署**（KV Cache INT8/AWQ/GPTQ压权重），用小幅度的性能降低换取两三倍的带宽和显存腾空。
- **算子与内存调度侧**：引入 **FlashAttention** 大幅减缓 Attention 阶段 SRAM 和 GPU 大显寸之间的反复横跳；一定要部署 **vLLM (PagedAttention)** 这个划时代的架构来彻底消灭请求句子长短不一带来的那超过 50%的严重显存缓存碎片空洞。
- **算法前沿生成侧**：如果追求生成单个请求的极致速度，引入 **投机解码（Speculative Decoding）**。用一个超级轻巧的百兆残废小模型在前面先替大哥飞速盲猜几个词打成草稿发给大哥，重型大模型大哥只在一瞬间对草稿进行一揽子校验，由于通常能命中，所以成倍榨出了生成加速时间。

7．模型微调时遇到过过拟合吗？怎么处理的？
**解答**：
SFT 中极易过拟合，它的症状是**“灾难性遗忘（Catastrophic Forgetting）”**，即大模型只会呆板回答某种业务格式，原本跟它聊天吹牛问物理公式的基础灵气被全部洗没遗忘掉。
**应对良方**：
1. **防爆隔离的参数壁垒（用LoRA）**：坚决不上全参（Full-Tuning）。只用LoRA给大模型的某一层挂一个小参数插件训，相当于只教给它新外挂技能，完全冻死了基座几百亿的大本营盘参数，让它天然就没有作乱推翻原本常识的土壤。
2. **数据掺沙子（Data Mixing）**：这也是正牌大厂作法。如果放 80% 的专业死板客服医考问答语料，一定不能忘了在剩余 20% 里塞满类似于 ShareGPT / Alpaca 等最高质量的杂学通用闲聊指令对，甚至放几道深渊数理逻辑题作为抛锚点，用这批通用语料保佑它的人格和基础结构不散架。
3. **老传统训练调参**：调低一点学习率配置、提早设立验证集Loss回升早停规则、提升Weight Decay。

8．✨算法题手撕：
**解答**：
- **1️⃣字符串的全排列**：LeetCode 46/47 经典深度优先回溯模板（Backtracking）。字符串先转成排序数组。搞个布尔类型数组 `used` 记录位置，for循环里选一个推进去，到底后撤回，遇到同层邻居一样且没被使用过的 `nums[i] == nums[i-1] && !used[i-1]` 果断 `continue` 剪枝防重复序列。
- **2️⃣二叉树序列化与反序列化**：LeetCode 297（Hard）。序列化常用前序遍历甚至由于层级关系BFS也行。递归走到空了就记下个特殊符号 `"#"` 并用逗号打断。反序列化时拿着一个由逗号崩出来的迭代器或队列列从前往后抠，第一拿到的就是根节点，接下来左右顺藤摸瓜递归挂节点即可重塑真身。

3．大模型生成内容如何做去重过滤？
**解答**：
这主要是考查预训练大模型语料管线工程（Data Pipeline）。如果把高度雷同的重复段落几十次喂给大模型，它的那一块记忆神经突触就会被畸形撑大进而严重发生活记死背，在生成时出现诡异无聊的“复读机现象”。
- **篇章/文档级大过滤**：不能用 $O(N^2)$ 的两两字面对比，那个算力太贵。绝对主流方案是用 **MinHash + LSH (局部敏感哈希)** 这一对黄金搭档。对几十亿的网页每篇抓一把稀疏签名，相同签名的丢到一个桶里看做全重复丢弃。
- **段落级/词组级高频过滤**：用 **N-Gram 重合度比对 或者 布隆过滤器（Bloom Filter）** 定向狙击。如果有几百个词的局域连续重合块比如“侵权必究/免责声明”这类重复污染源头，必须清洗扣去。

4．如果词表特别大（10w+ token ), Softmax 加速通常有哪些实现？
**解答**：
在10万词表（Vocab）的输出层，要从最后一层超大尺寸隐变量投射算出这10万个词的概率，最后那个庞大的 Softmax（尤其要求全部分母指数之和）拖累且浪费计算规模。
- **分层 Softmax（Hierarchical Softmax）**：彻底把平顶的一维大数组拍成一棵高的**哈夫曼二叉树 (Huffman Tree)**。遇到大概率常见的词直接走上头那几步到了。整体需要计算的激活层直接从绝对的 $100000$ 次暴降到只有对数级别的十几、几十次的二分类分叉路口概率计算，降维打击。
- **负面采样估算流（Negative Sampling） / 噪音对比估计（NCE）**：在训练求梯度阶段用的障眼法。正所谓“我哪有时间在10万人里比大小”，只要每一次训练，除了拿唯一的正确答案做正样本，我只从另外10万词里可怜巴拉地随机抽5到10个词出来临时拉壮丁充当算分母的错误靶子。大大稀释了梯度的爆炸规模却能逼近原有宏观表现。
- 此外还有工业级别的：Triton 自定义 Kernel 将减法计算和矩阵乘算术操作就近合并优化。

5．如果要在中文领域做Instruction Tuning ，需要注意哪些数据问题？
**解答**：
中文SFT是非常深的坑，主要有以下三点雷区：
1. **翻译腔/排版错乱（不可看重外文强翻）**：很多开源中文SFT集是把英语的ShareGPT这类高质量洋文集用烂翻译器强行翻过来的，充斥大量的“噢我的老天爷！”甚至奇怪的半角中英标点乱用。如果不找原生高质量大模型用纯正国人口吻进行深加工润色（Rewrite），做出来的模型一开口也是阴阳怪气的老外味。
2. **安全与中国特色合规红线对齐（Safety & Red Teaming）**：中文土壤有着严苛的政治、法律规范以及公序良俗红线（黑产、暴力）。必须要构建包含大量引诱犯罪句式的极高质量“拒答样本对（Refusal Examples）”进行打底，确保模型学会如何严肃大义凛然地制止和说不。
3. **格式与模板污染板结**：所有的指令人工配对，不要统统都是形如“人类：你该怎样。模型：好的，如下：第一...”。这种单一的套路会让模型变成死板回答的智障机。要注入扮演各类角色（如暴躁老哥、严谨科研人、写诗诗人）格式和多重样板的指令源。

6．LoRA 和 Prompt Tuning 有何区别，分别适于什么场景？
**解答**：
这两者可以说是完全两种“改造战术”。
- **Prompt Tuning（软提示大魔法）**：模型的庞大结构连碰都不会碰（冻结彻底）。它只是在人类原本的指令问答文字前方，用代码偷偷摸摸往里面塞入一段可以更新反向求导的“隐形魔法乱码张量向量”。然后让它根据任务自己去更新。
  - **适用**：适合做**千人千面的超级云计算平台（多租户冷启动）**。因为模型核心驻留基座就那百来G不占地方永远不变，但对于甲乙丙不同公司，服务器只要给他们加载前头那几KB隐形小张量就直接可以变身专业人，省钱之神。但缺点是长期挤占珍贵的语言上下文长度。
- **LoRA（旁路骨盆介入微调）**：在模型原本密布的那几十上百层大脑皮层深处（Linear结构边上），全焊进去几个廉价的小骨架旁路 $A$ 和 $B$ 矩阵进行真实权重的梯度变化，最后还能加法无损合并揉进大脑里。
  - **适用**：**绝对主流统治级方案，适合对于单个开源模型进行专属精细化的垂域和企业级改造**。它推理根本不占任何长度，不增加一丝推理阻力。知识的改变下限和天花板也是远超过上面的外挂提示流，属于降维打击。
