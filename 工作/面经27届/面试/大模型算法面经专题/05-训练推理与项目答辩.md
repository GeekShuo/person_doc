# 预训练、推理优化与项目答辩

## 一、预训练与训练系统

### 数据与目标

- Tokenizer 训练、词表大小、中文/代码/多语言配比。
- 数据清洗、去重、质量评分、污染检测和课程学习。
- Causal LM 目标、Scaling Law、Chinchilla-style 计算与数据配比。
- Dense 与 MoE：路由、负载均衡、Expert Parallel 和通信。

### 并行训练

| 技术 | 切分对象 | 关键追问 |
|---|---|---|
| DP/DDP | 数据 | All-Reduce 通信量、梯度同步时机 |
| ZeRO/FSDP | 参数/梯度/优化器状态 | Stage 1/2/3 分别切什么，通信和重算代价 |
| TP | 层内张量 | Column/Row Parallel、通信位置 |
| PP | 模型层 | Bubble、Micro-batch、1F1B |
| EP | MoE 专家 | Token dispatch、All-to-All、负载不均 |

### 显存估算

至少拆成：参数、梯度、优化器状态、Master Weights、激活、Attention 中间量、通信 Buffer、CUDA Context、Workspace、缓存与碎片。要说明序列长度和 batch 增大为何主要推高激活与 Attention 显存，以及 Gradient Checkpointing 如何用计算换显存。

## 二、推理优化

### 核心路径

```text
请求调度
→ Prefill
→ KV Cache 分配
→ Decode
→ Continuous Batching
→ 输出与回收
```

### 高频问题

- Prefill 是算力密集还是访存密集？Decode 呢？
- KV Cache 如何估算？为什么长上下文和高并发会成为瓶颈？
- PagedAttention 如何减少碎片并支持动态请求？
- MHA/MQA/GQA/MLA 如何影响 KV Cache 与质量？
- Prefix Cache 在什么请求模式下收益最大？
- Continuous Batching 与静态 batching 的差异。
- FlashAttention 为什么减少 HBM 读写，而不只是“把复杂度降为线性”？
- AWQ、GPTQ、FP8、INT8/INT4 的校准、速度与精度取舍。
- 投机解码何时有效？Acceptance Rate 如何影响收益？
- vLLM、SGLang、TensorRT-LLM 如何选型？

指标需同时考虑 TTFT、TPOT、P50/P95/P99、吞吐、并发、显存、每 Token 成本和质量损失。

## 三、模型模块手撕

优先级从高到低：

1. Stable Softmax、Scaled Dot-Product Attention、带 Mask 的 MHA。
2. RoPE、RMSNorm、SwiGLU、GQA。
3. KV Cache 的 Prefill/Decode 更新。
4. SFT Loss Mask、DPO Loss、GRPO 组内 Advantage。
5. LoRA Linear、Top-k/Top-p Sampling。
6. Batch 推理、Padding/Attention Mask、dtype/device 和边界测试。

小红书 2026 字节 Coding 统计帖反复提到 MHA、RoPE、知识蒸馏、量化感知训练、梯度裁剪、Warmup 和 RMSNorm。此类频次只能作为复习线索，不能当作官方题库。

## 四、项目答辩模板

### 90 秒版本

```text
业务问题与用户
→ 数据规模和难点
→ Baseline
→ 我的核心改动
→ 离线指标与消融
→ 线上/系统指标
→ 最大 Bad Case 与下一步
```

### 深挖清单

- 数据：来源、授权、清洗、去重、泄漏、难例、版本。
- 模型：为什么选、替代方案、参数量、训练资源。
- 实验：控制变量、消融、随机种子、显著性。
- 指标：为什么该指标与业务目标一致，是否存在代理指标偏差。
- 失败：错误归因、复现路径、修复和回归测试。
- 工程：延迟、吞吐、成本、监控、灰度、回滚和安全。
- 贡献：你亲自写了什么、决定了什么、否掉了什么。

### 常见危险回答

- “调了几个参数效果就好了”，但没有实验表。
- “用了最新模型”，但说不清为什么适配任务。
- “准确率提高很多”，但没有基线、测试集和置信区间。
- “用了 Agent/RAG”，但说不清检索、工具、评测和失败恢复。
- “训练过大模型”，但说不清卡数、显存、数据量、step 和 loss 曲线。
