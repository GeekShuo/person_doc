# 虾皮一面

## Q: 什么是数据泄漏？

**一句话定义**：训练时用到了**预测时刻拿不到的信息**，导致离线指标虚高、上线直接崩。

### 常见类型

1. **特征工程泄漏（最经典）**
   - 在全量数据上 fit（标准化、缺失值填充、特征选择、PCA、Target Encoding、SMOTE），再切训练/测试集
   - 正确做法：先切分，只在训练集上 fit，再 transform 测试集（用 sklearn `Pipeline` 封装防手滑）

2. **目标泄漏（Target Leakage）**
   - 特征隐含 label 的"未来结果"
   - 例：预测"是否逾期"却用了"催收次数"（催收发生在逾期之后）；预测"是否患病"用了"已开药记录"

3. **时间序列泄漏**
   - 随机切分而不是按时间切（用"未来"预测"过去"）
   - 正确做法：`train < valid < test` 按时间序切，验证集与训练集之间留 embargo 间隔

4. **分组 / ID 泄漏（含切分前未去重）**
   - 重复样本或同一实体的多条记录同时落在训练集和测试集 → 模型"背答案"
   - 来源：埋点重复上报、join 产生笛卡尔积、爬虫重复、重采样后未去重
   - 正确做法：**先去重、再切分**；同一用户/实体的记录用 `GroupKFold` 按组切分；近重复用 MinHash/感知哈希处理

### 怎么发现

- 离线 AUC > 0.98，线上腰斩（最直接的红旗）
- 单特征 AUC 就 0.9+，或特征重要性"一家独大" → 该特征大概率泄漏
- 离线 ↔ 线上 gap 巨大
- 核心检查方法 **time-travel check**：对每个特征问"在模型真正做预测的那一刻，这个值我真的能拿到吗？"

### 怎么避免（标准答法）

> 严格区分 as-of time，所有 transform 只 fit 训练集；用 `Pipeline` 封装；时序任务按时间切并加 embargo；同一实体用 `GroupKFold` 聚组切分；切分前按业务主键去重；上线后建立离线/在线一致性监控。

### 补充（被追问时）

"模型泄漏"还有第二层含义——**模型对训练数据的信息泄露**（偏安全/大模型方向）：成员推断攻击（MIA）、训练数据提取、模型提取攻击；防护手段有差分隐私（DP-SGD）、正则化/早停、不暴露置信度、API 限流等。
