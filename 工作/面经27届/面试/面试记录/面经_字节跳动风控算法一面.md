## 二、腾讯 CDG 项目

#### Q2 · 五级质量标准里，OCR 不可辨比例、边缘强度、拉普拉斯方差分别是怎么算的？ ⚠️
**我的回答**：
- OCR 不可辨比例：调用专用小 OCR 模型，它对每个文本框给出置信度，**置信度 < 0.9 就认为该框文字不可辨**（场景对精准要求高），再结合**框大小、框内字数加权**，汇总出整份文书可辨/不可辨文字的比例；
- 拉普拉斯方差：**承认"具体计算公式没细看"**，只说了原理——看文字边缘与背景的像素差异，模糊文书的字"没那么黑"、与背景差异小。

**失分点**：拉普拉斯方差是**一行公式**的常识，答"没细看公式"在算法面里是明显失分。

**更优回答**（公式 + 边界，一次答完）：
```
# OpenCV 标准实现
lap = cv2.Laplacian(gray, cv2.CV_64F)      # 3x3 核 [[0,1,0],[1,-4,1],[0,1,0]] 卷积
score = lap.var()                          # 取方差，值越大越清晰
```
- **原理**：拉普拉斯算子是二阶导数，对**边缘/突变**响应强；模糊图像的边缘被平滑，二阶响应趋于 0 → 方差小；
- **三个必须说的边界**（说出这些就是"用过"而不是"听说"）：
  1. 必须**只在文字 ROI 上算**（全局方差会被大面积空白背景稀释，也常被印章/表格线污染）；
  2. 对**噪声敏感**（噪点会抬高方差），必要时先做轻微去噪；
  3. **它只衡量成像锐度，不等于"能不能读懂"**——字很小但成像清晰、或藏文/手写体，锐度高但 OCR 读不出；**这正是要再引入"OCR 可辨比例"做语义侧补充的原因**（把两维指标的设计动机讲出来，直接加分）；
- **边缘强度**：Sobel/Prewitt 梯度幅值的均值或高分位（如 P95），与拉普拉斯方差互补；同样只在 ROI 上算。

#### Q3 · 漏检率的 GT 是人工标注还是模型给的？ ❌
**我的回答**：先说"简历上写的漏检率，我应该写的是精准率"（现场纠正口径）→ 测试时取约 1 万条数据、过一遍校验链路 → 有问题的样本占比不到 5% → 找**产品同学人工标注**确认这些判定没问题 → 所以能保证**精准率**；召回只能抽样看一部分数据。

**失分点**：被问"GT 是谁给的"时**先慌着改口**；且口径仍不完整（没说抽样方案、样本量、置信区间）。

**更优回答**（先定口径，再给 GT 与抽样方案）：
- **口径三连**（被问任何指标都这么答）：
  1. **精准率** = 链路判"不合规"中真不合规的比例；
  2. **漏检率/漏放率** = 真不合规中被放过的比例，**召回 = 1 − 漏检率**；
  3. 工程上我们的硬指标是**精准率 ~100%**（误拦代价极高），召回是次级目标；
- **GT 从哪来（分层标注，成本可控）**：判"不合规"的样本**全量**送人工复核（量小、优先级最高）；判"合规"的样本**按模型分数分桶抽样**复核（重点抽边界桶），用**分层/重要性抽样**无偏估计漏检率；标注方是产品/审核同学，需先做**标注一致性**（双人标注 + Kappa/QWK）；
- **样本量与置信度**：1 万条里问题样本 <5%（约几百条）→ 要补一句"在该样本量、95% 置信度下精准率区间是 xx~xx"，**敢报区间比报单点更专业**；
- **主动补一句**："线上没有真值，所以我们把**补材料后重提 / 放弃重提**当作弱监督信号来交叉验证"（这一句是风控岗的通用加分点，建议固化）。

#### Q4 · SFT 为什么用 CE + KL，而不是只用 CE？ ✅
**我的回答**：预标签有误差，人工复核也有分歧（同一份文书有人判 2 档、有人判 3/4 档）→ 对硬标签做**高斯分布平滑**（把 one-hot 的概率按高斯展开到相邻档）→ 标签变成**软分布**而不是固定 token → 只用 CE 学不了这个分布 → 加 KL 散度联合训练。
**面试官确认**："所以是因为你们的标签不是一个固定值。"✅ 这题答到位。

**更优回答**（补形式化与延伸）：
- **形式化**：设人工众标注的均值 μ、方差 σ，构造软标签 `q ∝ exp(−(i−μ)²/(2σ²))` 归一化到 5 档；loss = `CE(q, p)` 或 `CE + λ·KL(q‖p)`（用 KL 的好处是**可单独调 λ 和温度**，控制"允许模型偏离多少"）；
- **三重收益**（说清为什么值得）：① **吸纳标注噪声**，避免模型被个别争议样本带偏；② **注入序数先验**（相邻档惩罚小，符合清晰度的连续本质）；③ **天然做概率校准**，缓解过度自信，便于后面按阈值切"后两类"；
- **配套设计**：输出目标用 `excellent / good / fair / poor / bad` 这类**语义 token**，借预训练词序拿到序数关系（可与本条一起讲，是同一套设计的两面）。

#### Q5 · 印章识别：三路模型分别解决什么问题？怎么融合？ ✅（本场最佳）
**我的回答**：
1. **HSV 颜色 + 连通性形状**：检测红色圆形区域、把断裂笔画连起来 → **失败点**：真实样本有很多**绿色/黄色章**、**极小的章**、**背景反光/彩色墨水**干扰，纯颜色+形状会误判为无章；
2. **百度开源小模型**（几百兆，专做表格/抬头/印章检测）两个模型，各自出打分，成为两路信号（一个激进、一个保守）；
3. 三路信号（颜色形状 + 两个模型分）→ 自建**约 1000 条困难样本集**（极小章、异色章等）→ 搜**几百组阈值组合**，**先保精准再保召回**；
4. **中间档送大模型**：分很低 → 直接判无章；分很高 → 判有章；**中间分（小印章等）交给 27B 千问 VL 模型**判，识别较准；
5. **成本账**：链路总耗时要求 3~5 秒，小模型链路 <1 秒，只有极少量 case 走大模型，成本可接受。

**评价**：✅ 有 ROI 分层、有阈值搜索方法、有成本账，是全场最完整的一题，**固定下来当模板用**。

**更优回答**（补三处）：
- **融合形式说清楚**：不是简单加权，而是**级联 gate（三分档）+ 阈值投票**：`score = w1·s_shape + w2·s_modelA + w3·s_modelB`，在 1000 条困难集上**网格/随机搜索**权重与上下阈值，约束 `precision ≥ 目标` 再最大化 `recall`；也可直接用小逻辑回归/XGB 学融合权重，比手工阈值更稳；
- **为什么要分层**（一句话点题）："**80% 的样本小模型就能定死，只有边界档才值得花大模型的钱**"——这就是中台最看重的成本意识；
- **可补的追问**：困难集怎么维护（线上低置信回流）、大模型判错怎么办（结果进下一轮困难集、持续迭代）、延迟/超时降级策略（大模型超时则回退小模型结论）。

#### Q8 · 三个奖励（拦截 / 误杀 / 格式）的权重怎么定的？ ❌
**我的回答**：先说"具体比例我一般调整"，被面试官追问"是算法手段调的还是经验拍的"后，承认是"跑下来一些经验"。

**更优回答**（给系统性方法，别再说"经验"）：
1. **先归一化**：三个奖励量纲不同（格式 0/1、拦截 0/1、误杀 -1/0），**必须先各自归一化**（如 z-score 或缩到 [0,1]），否则大模型奖励会主导——这本身也是你答 GDPO 的论据，前后呼应；
2. **搜索**：网格/随机搜索权重组合 → 得到**帕累托前沿**（精确率 vs 召回 vs 格式合规率），由业务在曲线上选点；
3. **课程式调权**：早期给格式奖励更高权重（先学会可解析输出），后期降低格式、提高业务奖励；
4. **监控**：训练中画**每个奖励分量**的曲线（不看聚合值），一旦某分量暴涨而其他不动就是 reward hacking 的信号；
5. **诚实兜底**："最终确实有业务拍板的成分，但**拍板是在帕累托曲线上选点**，不是拍权重数值"——这句话能把"经验"说得专业。

#### Q9 · 为什么用 GDPO 而不是 GRPO？ ✅
**我的回答**：GRPO 是**先把多个奖励相加、再做归一化**；我们的场景里**格式奖励很容易拿高分**（一开始就高），而风险拦截/误杀奖励很低 → 相加后高分奖励主导 → 长期训练后模型**只学会遵循格式**（reward hacking）。GDPO 是分别归一化再聚合。✅ 动机讲清楚了。

**更优回答**（更严谨的版本，背下来）：
- **GRPO 的问题**：多目标奖励直接求和后再做 group-wise advantage 归一化，会出现 **"优势塌缩"**——量级/方差大的目标吃掉梯度，其他目标（往往是真正的业务目标）几乎不更新，表现为 **reward hacking**（你说的 "high hiking" 口误，正确说法是 **reward hacking**）；
- **GDPO 的做法**：对**每个目标分别做 group 内归一化**，再按权重聚合 advantage，使各目标的梯度量级可比、各目标都真实参与优化；
- **顺带**：这也是 Q8 权重问题的答案——**先归一化再加权**，两题可以互相引用，显得体系化。

#### Q10 · 89 万条数据 SFT 后，怎么**评估**通用知识遗忘？怎么缓解？ ⚠️
**我的回答**：只答了缓解——在 SFT/RL 损失里加惩罚项，让更新后模型与初始模型的**概率分布（KL）**或参数差异不要太大，类似 RLHF 里相对 reference model 的约束。面试官认可："有点像 RLHF 每一步限制相对于 reference model 的偏离程度。"✅
**失分点**：面试官问的是**两件事**（评估指标 + 缓解方法），**评估那一半没答**。

**更优回答**：
- **评估（你漏的部分）**：
  1. **通用集**：MMLU / C-Eval / CMMLU（或内部通用评测集），再**按领域拆**（语言、知识、推理、数学、代码），定位掉的是哪一块；
  2. **遗忘率指标**：`Forgetting = (acc_base − acc_ft) / acc_base`，按领域分别算；
  3. **表示层**：CKA / 表征相似度、logits 分布 KL、attention 模式变化；
  4. **trade-off 曲线**：横轴通用能力、纵轴任务能力，取不同数据量/LR/epoch 画点，选拐点；
  5. **顺序**：先定义"掉多少算不可接受"（如通用掉 >5% 需干预），再谈缓解。
- **缓解**（你答到的 + 补充）：
  1. **replay 混合通用数据**（最有效，5~20%）；
  2. **KL 正则到 base**（你答的，正确）；
  3. **LoRA / 只训部分层 / 冻结 embed 与 LM head**；
  4. **小 lr + 少 epoch + early stop**；
  5. **权重插值 WiSE-FT**：`θ = α·θ_ft + (1−α)·θ_base`，**一行代码**换回通用能力，且常常还能涨任务指标——这条是面试官最爱听的"低成本工程解"。

#### Q11 · 手算 LoRA 节省多少参数（矩阵 d×d、rank r） ⚠️
**我的回答**：先卡在维度表述上（反问"长跟宽是什么"），后答 **d² − 2·d·r**（节省量）。
**评价**：公式方向对，但**被维度追问卡住 + 没给具体数字**，显得不熟。

**更优回答**（一次给全，含推导与实例）：
- 通用形式：原矩阵 `W ∈ R^{m×n}` → 参数 `mn`；LoRA `B∈R^{m×r}, A∈R^{r×n}` → 参数 `r(m+n)`；
- **节省** = `mn − r(m+n)`，**压缩比** = `mn / (r(m+n))`；
- 实例（必背）：`d = 4096, r = 16` → 原 `16,777,216`，LoRA `2×4096×16 = 131,072`，**压缩 128 倍，节省 99.2%**；
- 顺带报**显存账**（面试官常追）：可训练参数少了 → **优化器状态大幅省**（Adam 每参数约 16 字节），全参微调 7B 需 ~112GB 优化器状态，LoRA 只需几十 MB 级；
- 补充：只对哪些层挂（一般 q/v 或所有线性层）、`scale = α/r`、rank 选择的经验（8/16/32）。

#### Q12 · LoRA 微调后，部署时外挂参数怎么处理？ ⚠️
**我的回答**：意思是"原参数也保存，用的时候把 LoRA 插到某一层，用的时候再插入"，但表达混乱、术语不准。

**更优回答**（三种方式 + 取舍，一条不漏）：
1. **合并权重（merge）**：`W' = W + (α/r)·BA`，**推理零额外开销**，与原生模型部署方式完全一致；缺点是一个模型只能带一个 LoRA；注意 **bf16/fp16 合并可能有数值掉点**，需合并后回归评测；
2. **运行时旁路（不合并）**：推理框架（vLLM / SGLang / TensorRT-LLM）支持把 LoRA 作为旁路 kernel 注入，可**同 batch 内混合多个 adapter**（不同任务共享底座），延迟几乎无损；
3. **多 LoRA 服务（S-LoRA / Punica）**：把大量 adapter 权重分页存放、按需加载，一张卡同时服务成百上千个 LoRA；
- **选择依据**：单任务固定 → 合并；多任务/多租户热插拔 → 运行时旁路。
- 另：产物只需存 A、B（几 MB~几十 MB），**分发/回滚成本极低**，这也是你"多任务共用底座"的工程卖点。

#### Q13 · 什么时候用 SFT，什么时候用强化学习？ ✅
**我的回答**：有固定标准答案、学特定表达 → SFT；没有标准答案的复杂任务（写作文、风控里给拒答理由）→ 只需要奖励信号，用 RL。面试官追问"**如果有规则奖励函数，那跟 SFT 有什么区别？**"→ 我补：SFT 是 **teacher forcing**，推理时前面 token 没有标准答案，会基于自己的错误前缀继续生成（分布偏移），RL 让模型按自己的历史回答做回归（提到 DPO 也是针对这一点）。✅ 后半段答得好。

**更优回答**（三点说全）：
1. **监督粒度**：SFT 是 **token 级**的"照抄答案"，RL 是**序列级**的"结果打分"，能学 SFT 数据里没有的解；
2. **曝光偏差 / exposure bias**（你答到的点，用术语）：teacher forcing 造成训练-推理分布不一致 → 缓解手段有 **scheduled sampling、DPO、RL**；
3. **成本与稳定性**：RL 贵且不稳，工程顺序通常是 **SFT 打底 → (Rejection Sampling / RFT) → DPO / GRPO(GDPO) 精调**；其中 **rejection sampling + SFT（RFT）** 是性价比最高的中间态，值得主动提一句。

#### Q14 · 传统 OCR 还是直接用大模型？CTC 怎么解决可变长度输出？ ❌
**我的回答**：项目里都用传统 OCR 模型；**CTC 直接说"没太接触"**。

**更优回答**（必须背死，这是 OCR 岗最基础的一题）：
- **问题**：输入图片编码出 T 个时间步，目标文本长度 L 未知，且 **T 与 L 无对齐标注**；
- **CTC 四步解法**：
  1. 引入 **blank 占位符 `-`**，允许 `T ≥ L`，每步输出 `词表 ∪ {blank}` 的分布；
  2. 定义**多对一映射** `B(π)`：先合并重复字符，再删掉 blank（如 `a-ab-` → `ab`）；
  3. **对所有能折叠成 y 的路径求和**：`P(y|x) = Σ_{π: B(π)=y} Π_t P(π_t | x)`；
  4. 用**前向-后向动态规划**（类似 HMM）在 O(T·L) 内算出该概率及梯度 → **无需对齐即可端到端训练**；推理用 greedy 或 beam search（可外挂语言模型纠偏）。
- **局限**（说出来才像真懂）：条件独立假设（每步独立，无语言模型）、输出呈**尖峰（peaky）**、对二维/弯曲文字不友好 → 所以工业界常用 **检测 + 识别**两阶段（PP-OCR 系列：DB 检测 + SVTR/CRNN 识别），而端到端 VLM 虽然天然不定长，但**成本高 + 会幻觉**，这正是你们仍用传统 OCR 的原因（**把技术选型和自己的项目连起来，一题两得**）。

#### Q15 · 千问3-VL 的架构？DeepStack 是怎么做的、为什么这样设计？ ❌
**我的回答**：不了解；面试官提示"在 LLM 每一层 input 都把图片特征注入进去，类似传统 CV 的特征金字塔"后仍未接住，最后说接触少。

**更优回答**（**你 SFT 的就是这个模型，这题必须补到能讲 40 秒**）：
- **DeepStack（深层特征堆叠）**：不再只把 ViT **最后一层**的视觉 token 拼到 LLM 输入层，而是取 **ViT 多个不同深度层的特征**，分别注入到 LLM 的**不同层**（浅层视觉特征 → LLM 浅层，深层语义特征 → LLM 深层），机制上类似 CV 的 **FPN / 特征金字塔**与"跨层残差注入"；
- **为什么**：① ViT **浅层保留细节/纹理/边缘**（小字、模糊笔画、印章这类细粒度信息），深层是语义；只用末层会**丢细节**，对 OCR/小字/清晰度判断极不友好；② 只在输入层注入时，视觉信息在深层会被**稀释**；逐层注入让 LLM 在每个深度都能"再看一眼图"；③ 配合**动态分辨率/窗口注意力**控制 token 数，不显著增加算力；
- **配套知识点**（顺手补齐，避免二次被问）：**Interleaved-MRoPE**（把位置编码拆成时间/高度/宽度三段交错，支持任意分辨率与视频）、视频的**时间戳对齐**；
- **与你的项目连起来**："我做的清晰度分级恰恰依赖**细粒度视觉细节**，这也是 DeepStack 这类设计对这类任务有价值的原因"——**把不会的题接回自己的项目，是最优止损话术**（记下来，比硬说"没接触"强得多）。

## 五、Coding：Top-K（Quickselect） ⚠️

### 题目还原
> 给定长度 n 的**无序数组**，求第 k 大（或第 k 小）的数。**不允许做一次完整排序后返回下标 k−1**，要求在快排切分过程中只对前 k 个排序/输出。

### 我的表现
**思路说对了**（"做快排时先切分，只对前 k 个数字排序"），但**代码没写出来**，自述"C++ 好久没写，跟 Python 有点记混"。面试官虽然说"不是说一定要调通才行"，但**算法题写不出代码在字节这种场是硬伤**。

### 正确解法（背到能默写）

```python
import random

def quickselect(nums, k):           # 第 k 小（k 从 1 开始）
    def select(l, r, k):            # 在 nums[l:r+1] 中找第 k 小
        if l == r:
            return nums[l]
        p = random.randint(l, r)
        nums[p], nums[r] = nums[r], nums[p]
        pivot = nums[r]
        i = l
        for j in range(l, r):       # 三路切分
            if nums[j] <= pivot:
                nums[i], nums[j] = nums[j], nums[i]
                i += 1
        nums[i], nums[r] = nums[r], nums[i]
        left_len = i - l            # 左段（<= pivot）元素个数
        if k <= left_len:
            return select(l, i - 1, k)
        elif k == left_len + 1:
            return nums[i]
        else:
            return select(i + 1, r, k - left_len - 1)
    return select(0, len(nums) - 1, k)
```
- 第 k 大 ⇔ 第 `n − k + 1` 小；若只要"前 k 个有序"，选出第 k 小后再对前 k 个做一次 O(k log k) 排序即可；
- 面试官原话要求"只对前 k 个排序"就是**Quickselect + 局部排序**，不要写成堆。

### 复杂度与追问（必背）
- **平均 O(n)**、最坏 O(n²)；证明：每轮期望砍掉一半 → `n + n/2 + n/4 + ... < 2n`；
- **随机化 pivot** 避免最坏；**BFPRT（中位数的中位数）**可保证最坏 O(n)，但常数大，工程少用；
- **替代方案**：大小为 k 的堆 `heapq.nsmallest` → **O(n log k)**，适合**流式/内存受限**；`numpy.partition`（introselect）是工业界常用；
- **海量数据放不进内存**：分桶/计数（值域小）、外排、分片 TopK 再归并；
- **常考变体**：第 k 大、Top-K 的频率（堆 + 哈希）、无序数组中位数。
