## 二、逐场复盘

### 1. 腾讯 CDG 支付风控算法面（68 min）——表现最好的一场

**做对的（这套讲法可以直接复用）**

- **业务约束先讲清楚**：低成本（日均 37 万单）+ 零误判（法院公安单据不能误拒）+ 低延迟——这三句开场定住了整场基调。
- **按 ROI 拆解任务**：把"单据有效性校验"拆成清晰度检测 / 电话号码校验 / 标题校验 / 盖章校验，先啃投入产出比最高的那块。这是面试官最认可的框架。
- **技术演进讲出因果**：不是罗列技术，而是"发现问题 → 解释为什么原方案不行 → 给出改法"：
  - xgboost 二分类在难样本上准确率低 ⇒ 因为真实样本不是二分类问题
  - ⇒ 改成**五分类**，用 OCR 可辨识次数做主指标分档，再用图像综合特征补充
  - ⇒ 直接用大模型分类效果差（预训练没学过"清晰度"这个任务）
  - ⇒ **OCR 规则预标注 → 大模型后训练**，人工只 check 少量 uncertain 样本
  - ⇒ 软标签 + KL 散度优化，把人工标注的不确定性写进标签
- **结论有数**：精确率 ~100%，召回 60%+；部分模块已上线，灰度顺序明确（先拒第五类）。

**被问住 / 答得含糊的**

- SQL `WHERE` vs `HAVING`：直接说"接的比较少，…永远记不过来" ❌ 这是送分题，必须补
- 代码题（有序数组合并 / 双指针）：**没写出来**，只讲了思路，最后用"时间到了、代码有点 debug 不出来"收场 ❌ 本场最大失分点
- 两渠道转化率差异：直觉对了（看分布重叠 / 差异概率），但没说出"双比例 z 检验 / p 值 / 显著性水平"这些关键词 ⚠️
- 生成器 `yield`：能说出惰性产出，但没点出"省内存 / 数据流式处理"这个核心动机 ⚠️
- 面试官点破岗位错配：现有经历偏 OCR 内容审核 / 安全，与纯风控算法不完全对口

## 三、短板清单（按优先级）

### P0 · 下次面试前必须解决

1. **代码题必须写出来**。本场唯一明确失分。建议按专题刷到"白板无 IDE 也能写"：双指针、滑动窗口、归并/有序数组merge、堆/topK、二分、二叉树遍历、LRU。每天 2 题限时 20 min，手写。
2. **KV Cache / 显存手算**（见附录）——被问到就不能错。
3. **SQL 基础**：`WHERE` vs `HAVING`、窗口函数、`GROUP BY` 后过滤、join 类型、去重。这是风控/数据岗的必考，不能说"用得少"。
4. **Python 基础口述**：`yield`、深浅拷贝、装饰器、GIL、`__new__` vs `__init__`、可变默认参数坑。

### P1 · 高频机考机器学习/统计

-  ROC 曲线与阈值选择要结合**业务目标**讲（风控=卡精确率，内容审核=看漏放成本），你答通用版可以再贴业务
- 假设检验要能说出：原假设 / 备择、**双比例 z 检验**、p 值、**显著性水平 α**、两类错误（风控尤其强调第二类：漏判）
- 样本不均衡的处理（分层分析只是诊断，还要会给解法：重采样、改 loss、换阈值、分层指标）
- L1 vs L2 的**几何解释 + 为什么 L1 稀疏**（你答到"绝对值 vs 平方和"就停了，可以补一句菱形 vs 圆的等高线切点）

### P2 · 表达与策略

- **自我介绍按岗位定制**：面 CDG 风控 → 主推"单据校验 / 有效性判定 / 零误判约束"；面内容安全 → 主推"审核标准制定 / SFT / 数据构建"；面游戏 → 主推"AIGC 生图评测 + UGC 治理"
- **业务场景题四步法**（这条是你自己总结的血泪教训，务必变成肌肉记忆）：
  1. 复述需求并对齐目标（什么叫"摆烂/挂机"，判定口径是什么）
  2. 明确约束（实时还是离线？误判成本？有没有标签？规模多大）
  3. 给**最简 baseline**（规则/统计阈值：伤害占比、移动距离、断线时长）
  4. 再升级（行为序列建模、突变点切分、对比学习），并给出评估方式
- 减少"嗯/呃/一个一个"这类填充词：录 1 分钟自我介绍回放，目标是把填充词压到 5 次以内
- 反问环节提前准备 3 个高质量问题（不要只问"你们喜欢什么候选人"）

## 五、附录：KV Cache 手算（必须背下）

13B 模型，隐藏层 4096 维，40 层，FP16（2 bytes）：

```
单个 Token 的 KV Cache
  = K 和 V 两份 × 层数 × 隐藏维度 × 每参数字节
  = 2 × 40 × 4096 × 2 B
  = 655,360 B ≈ 640 KB / token

模型权重    = 13e9 × 2 B ≈ 26 GB
seq_len=2048 时单并发 KV ≈ 640 KB × 2048 ≈ 1.28 GB
```

关键点要能说出来：

1. KV Cache **与 prompt 长度有关，与"训练长度"无关** —— 这句你说对了
2. 层数、隐藏维、份数（K/V）是乘数，缺一不可
3. 若用 **GQA / MQA**（如 Llama-2 70B），要按 `kv_heads` 而非 `hidden_size` 算：
   `2 × layers × kv_heads × head_dim × 2 B`
4. FP16=2B / INT8=1B / FP32=4B，量化能线性砍显存

> 你面试时把 k 矩阵维度答成了 1014×3096（正确应为 4096），属于数字记错，不是思路错。把公式背死即可。
