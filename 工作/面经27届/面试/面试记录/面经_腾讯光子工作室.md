#### Q3 · 准确率和召回，站在哪一边怎么判断？ ✅
**我的回答**：（自评）"问准确这是站在哪怎么判断的，这个还好。"
**正确回答**：这类题的通用答法是**先问成本，再定指标**：① 误判成本高的场景（查封单据、封号处罚）→ **精确率优先**，甚至可以牺牲召回；② 漏放成本高的场景（内容涉政/暴恐、盗刷首笔）→ **召回优先**，靠人工复核兜精确率；③ 目标不是二选一而是**给方案**：定业务目标（如精确率 ≥ 80%）→ 在此约束下最大化召回 → 中间档走人工审核队列 → 上线后按 PSI 动态调阈值。能说出"中间档转人工"这一点，比单纯答指标定义高一个层次。

#### Q4 · 印章识别用的到底是什么模型？为什么用这个模型？你做了什么工具/工作？ ❌
**我的回答**：（自评）"这里其实我没有打好，我就说我是那个调到那个别人的模型，就那个 TB light 跟 LC light。"
**正确回答**：这是典型的**把自己说成调包侠**。同一件事换个讲法就是加分项：
- **选型理由**（为什么是它）：边缘/CPU 部署、延迟要求在 xx ms 内、显存受限、印章是小目标 + 风格混杂，通用大模型 ROI 不划算；
- **为什么不用替代方案**：直接用通用 VLM/GPT-4V 判清晰度效果差（预训练没学过"清晰度"这个任务），且成本/延迟撑不住日均几十万量级；
- **我做了什么**：难样本集构造（难在哪：极小字体、手写体、灰度低、糊/证件件的边界样本）、评测口径定义（由 PM 确认）、规则 + 模型级联、不确定样本回流。
> 提示：模型名 TB light / LC light 请先核对真实名字，面试说错模型名很伤。

#### Q5 · 京东 AI 安全部：deep research 接入知乎 / B站 / 小红书，成本会不会很高？延迟很长？ ❌
**我的回答**：（自评）回答偏含糊，只说到做了 OCR、视频转文字这类环节。
**正确回答**：这类题考的是**系统设计 + 成本意识**，按"拆解预算 → 控制手段"回答：
- **成本拆解**：每轮 query 的检索返回文档数 × 平均 token + 精排 rerank + 大模型阅读 token 数 + 多轮 hop 的乘数效应；
- **控制手段**：① **分级模型**——小模型做初筛/过滤，大模型只精读 top-k；② **token 预算**与截断/摘要；③ **缓存命中**（同 query、同 URL 内容）与 **prompt caching** 复用前缀；④ **去重**（多源同一条新闻只算一次）；⑤ 限制最大 hop 数与检索宽度，证据充分即**提前终止**；
- **延迟**：多源检索并行、流式返回首字（先把已确认结论吐给用户）、异步预取下一步查询；
- **回答要点**：承认"确实有成本"，然后给出量化口径（每千次调用 xx 元、P95 延迟 xx 秒）——能量化本身就是答案。

#### Q6 · OCR 与视频转文字这条链路的细节 ⚠️
**我的回答**：答了做了 OCR 和视频转文字。
**更优回答**：把这条链路讲成**完整 pipeline**：视频 → 抽帧/关键帧去重（不必每帧都 OCR）→ ASR 字幕（可用本地轻量 ASR）→ OCR 文本 → 多模态向量化 → 与 ASR 时间轴对齐 → 结构化摘要。省成本的抓手就是**关键帧去重**（同一镜头只取代表帧）和**只在检测到文本区域的帧上跑 OCR**（先过一遍轻量文本检测避免全图 OCR）。

#### Q7 · long term memory 长期记忆是怎么做的？ ⚠️
**我的回答**：提到这块"最后还能再优化一点"。
**更优回答**：标准四层架构，直接套：① **短期窗口**：最近 N 轮对话全量塞进上下文；② **滚动摘要**：窗口溢出时把早期对话压缩成 summary 保留；③ **外部向量库**：把历史事实 embedding 后检索召回 top-k 再拼回 prompt（重要的会话/用户偏好）；④ **结构化用户画像表**：性别/兴趣/业务线等稳定字段单独存表，System Prompt 直接注入。**关键三问必须答**：写入触发时机（何时值得存）、遗忘/过期策略（时间衰减 + 去重 + 冲突消解）、一致性（新事实与旧事实冲突时以时间新的为准）。

#### Q8 · 13B、隐藏层 4096 维、FP16、40 层，每个 token 的 KV 矩阵多大？ ❌
**我的回答**：答"k 矩阵的维度是 1014 乘上 3096"，并说"跟训练长度没有关系"——后半句对，**数字错了**。
**正确回答**（必须背死）：
```
单 token KV Cache = K 和 V 两份 × 层数 × 隐藏维度 × 每参数字节
                  = 2 × 40 × 4096 × 2 B
                  = 655,360 B ≈ 640 KB / token
```
- 单个 token 在每层产生的 **k 向量、v 向量各 4096 维**（不是答错时说的 1014×3096）；
- KV Cache 与**序列长度成正比、与"训练长度"无关** ✅ 这句你说对了；
- 若用 **GQA/MQA**（如 Llama-2 70B），要按 `kv_heads` 而非 `d_model` 算：`2 × layers × kv_heads × head_dim × 2 B`；
- seq_len=2048 时单并发 KV ≈ 640 KB × 2048 ≈ **1.28 GB**。

#### Q9 · 整个模型的权重大概多少？ ⚠️
**我的回答**：被追问权重多大，答得不够干脆。
**正确回答**：`13B 参数 × 2 B(FP16) ≈ 26 GB`。延伸三个换算必须会：① INT8 量化 ≈ 13 GB（线性砍半）、INT4 ≈ 6.5 GB；② FP32 训练时还要算优化器状态：权重 4B + 梯度 4B + Adam 的 m/v 各 4B ≈ **每参数 16 字节**，13B 全参微调需 ~208 GB 显存（所以才有 LoRA / ZeRO）；③ 推理显存 ≈ 权重 + KV Cache + 激活。

#### Q13 · 业务场景题：王者里很多队伍摆烂/挂机，怎么设计算法把这些人抓出来关小黑屋？ ⚠️
**我的回答**：先说拿用户行为轨迹、预设一批问题玩家做分类模型；被面试官提示"每秒交互行为非常多、这么做很低效"后，改口说先做突变点切分/令牌化（每 4~5 秒聚合一次行为再喂给传统方法或模型）。
**自评**（这句完全正确）："这个问题答的是我们太思考太深入。我应该先吃饱菜生肉，然后再跟他讲的。"
**正确回答**：业务题四步法，开口顺序比炫技重要：
1. **复述并对齐口径**：先反问"摆烂/挂机"怎么定义？判定证据来自举报还是行为？要处理的是**单局**还是跨多局的惯犯？误封的申诉机制如何？
2. **明确约束**：实时（局中踢出）还是离线（赛后处罚）？误伤成本极高（封号直接影响留存）→ **精确率优先**；标注从哪来（举报弱监督）；数据规模（每秒百万级行为）。
3. **先给最简 baseline**（这一步你跳过了，所以被面试官打断）：规则版——单局有效操作率、移动距离、伤害/承伤占比、经济获取速率、断线重连次数、连续 N 秒无输入；再用阈值 + 多局累计次数做分级处罚。
4. **再升级到模型**：先把行为序列**聚合降采样**（按秒/按 5 秒窗口统计）再建模，或用 LSTM/Transformer 做序列分类；也可用**对比学习/ anomaly detection**（正常玩家聚类，离群即嫌疑）。最后一定给评估：精确率优先 + 人工复核队列 + 处罚梯度（先扣分/限时禁赛，而非直接封）。
- 加分项：提到**防对抗**（作弊者会模拟操作，要用操作时序随机性和生理特征做检验）、**冷启动**（先用举报数据弱监督起量）。
