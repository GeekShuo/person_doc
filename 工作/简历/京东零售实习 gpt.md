四、重点项目一：数据清洗，怎么讲得像算法项目
1. 项目背景
不要说：

领导让我清洗一批图。

应当说：

团队需要训练商品主图生成模型，但原始电商图片中包含商详图、低分辨率图、文字过密图、白边图、水印图、模糊图和视觉组件残缺图。如果直接进入训练，会导致模型学习到低质构图、文字乱码和错误营销元素。因此需要构建高精度的训练数据筛选链路。

2. 你的核心思路
你可以把流程概括成三个层次。

第一层：低成本规则过滤
分辨率
宽高比
对比度
锐度
白边
OCR 字数和面积占比
目的：

用低成本特征优先过滤明显无效样本，避免后续 OCR、VLM 和人工标注资源浪费。

第二层：模型过滤
文字贴片检测
PaddleOCR 识别
模糊、水印和文本框贴边检测
Qwen3-VL 美学评分
商品主体抠图
目的：

处理单纯规则无法表达的语义和美学问题，例如是否存在有效营销主体、文字布局是否合理、视觉组件是否完整。

第三层：人工校验
优质单图标注
文本准确性标注
边界 Case 回流
更新标注规范或自动过滤规则
目的：

将人工标注不只作为最终审核，还作为规则和模型迭代的反馈信号。

3. 最适合强调的算法思维
这套流程本质上是一个级联分类器：越靠前的步骤成本越低、召回优先；越靠后的步骤成本越高、精度优先。通过漏斗设计，把昂贵的 VLM 推理和人工标注集中在更有价值的候选数据上。

这句话很重要，它能让“数据清洗”从写脚本变成“算法系统设计”。

4. 项目结果
可以讲：

最终形成了自动清洗、人工标注和问题回流的闭环。优质单图人工通过率达到 86%，文本准确性标注通过率达到 76%，说明自动化链路已经过滤掉了大部分明显低质数据，同时保留了较高比例的有效候选。

注意不要把“最终只保留 0.75%”孤立地写在简历上，因为面试官可能误以为误删严重。面试中被问到再解释：

原始底库并不是专门为主图生成训练准备的，包含大量商详图和非目标图片，因此低漏斗率主要来自目标数据本身稀缺，并不代表模型性能差。

五、重点项目二：OCR 选型与部署
这个项目很适合算法岗，因为它包含完整的：

任务定义 → GT 构建 → 指标设计 → 模型对比 → Bad Case 分析 → 部署接入。

1. 为什么通用 OCR 指标不够
你可以这样讲：

营销海报中既有营销贴片文字，也有商品包装上的小字。两类文字的重要程度不同：营销贴片必须完整且准确；包装上的微小文字可以适当忽略。因此不能简单地把所有文字当成同等权重，需要根据业务语义设计评测和标注规则。

2. 你怎么构建 GT
可以讲以下细节：

人工修正 OCR 文本作为 GT
统一全角和半角
统一中英文标点
保留标点差异，避免过度宽松
支持多个 GT 合并为一个预测框的 merge 情况
支持一个 GT 被拆成多个预测框的 split 情况
小字单独标记，不对完全漏识别的小字强行计算 FN
编辑距离较小的错误作为 substitution 单独分析
这些细节非常能证明你真正做过评测。

3. 为什么选择 PaddleOCR-VL 1.5
可以这样回答：

PaddleOCR v5 的 Recall 略高，但容易把商品图案误识别成文本，导致 FP 较多。视觉大模型可以识别更多小字，但也存在文本幻觉。PaddleOCR-VL 1.5 的 Precision 最高、FP 最少，综合结果更适合训练数据生产。

对这个业务来说，Precision 比 Recall 更重要。漏掉商品包装上的部分小字，可能只是损失一部分训练样本；但如果把图案识别成文字，或者输出原图中不存在的文本，错误标注会直接进入训练集，可能强化模型的文字幻觉。

先导集结果可以说：

模型	Precision	Recall	F1
PaddleOCR v5	80.05%	97.02%	87.72%
PaddleOCR-VL 1.5	95.05%	95.36%	95.21%
视觉大模型方案	83.77%	95.70%	89.34%
同时主动补一句，避免被质疑样本太少：

这组结果来自 51 条人工精修的先导集，主要用于快速选型，不把它当成最终无偏结论。如果继续推进，我会扩展到 500 条以上，并按类目、文字大小和贴片类型做分层统计和置信区间分析。

这会显得非常严谨。

5. 面试官可能质疑 GPT 机评怎么办

机评的优点是成本低、迭代快，适合模型版本的初筛，但不能完全替代人工。我在 Prompt 中把业务规则拆成 13～14 个原子维度，要求逐项输出 JSON，以提高可解释性；同时针对白底变灰、文字变模糊、主体占比边界等 Bad Case 迭代 Prompt。更完整的方案应该抽样做人工标注，并计算机评与人工的一致率、Precision、Recall 或 Cohen’s Kappa，再决定机评阈值。

当前有三层证据：第一是各阶段漏斗和人工通过率；第二是 OCR 在人工 GT 上的离线指标；第三是人工标注返回的 Bad Case 类型。更严格的验证应该固定训练配置，只改变数据版本，进行清洗前后模型的 A/B 训练，并在固定 Benchmark 上比较文字准确率、商品一致性和业务可用率。

3. “为什么不是 F1 最高就一定选？”
模型选型需要结合错误成本。对于训练数据构建，错误文本进入数据集的代价往往大于漏掉少量文本，所以 Precision 的业务权重更高。实际选择会综合 Precision、Recall、推理吞吐、部署成本以及不同文字类型的分层表现，而不是机械地只看单一指标。

4. “标注团队培训有什么技术含量？”
难点是把模糊的业务需求转化成可重复执行的判断规则。我把文字分为营销贴片、商品主体文字、背景文字和小字，并明确漏识别、误识别、繁简体、标点、倒立文字等边界条件。同时通过 Case 回收修正规则。如果标注定义不稳定，模型评测和训练数据都会产生系统性噪声。

5. “你的最大不足是什么？”
OCR 选型时的人工精修 GT 规模较小，主要适合快速选型，统计稳定性仍然不足。后续我会扩大样本量，按品类、文字大小和文本区域分层抽样，并报告置信区间；同时计算标注员一致性，减少 GT 自身的噪声。

这个回答比强行辩解更加分。

十、团队背景应该怎么说
不建议在简历里写：

团队有 300 张 B200
团队里有多个人才计划实习生
团队很核心
这些不是你的个人成果，而且具体算力规模可能涉及内部信息。

面试中可以概括成：

所在团队负责京东零售核心商品图生成能力，具备较大规模的算力、训练数据和外部标注资源。我承担的是数据质量控制、模型选型和评测环节。

外包标注团队可以写，因为你确实承担了规则培训和质量反馈；但重点要放在“标注体系和质量闭环”，而不是“管理外包”。

十一、最推荐的最终定位
你的最佳人设不是“训练了大模型”，而是：

懂生成模型训练原理、能够搭建大规模数据生产链路、能够完成模型选型部署和 Benchmark 评测的数据型多模态算法候选人。

这比“假装训练过一次 Qwen”更稳定。算法岗面试中，面试官通常更看重：

是否真正做过完整项目；
是否理解指标和业务目标；
是否能进行 Bad Case 分析；
是否能解释技术取舍；
是否清楚个人贡献边界。
你的经历已经可以覆盖前四项，关键是不要因为强行扩大第五项而损害可信度。
