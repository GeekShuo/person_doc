## 2. 一分钟项目介绍

> 我在腾讯做法院和公安文书的有效性校验，主要处理清晰度、印章和文书类型。这个场景对错误拒单比较敏感，所以我会先明确每类错误的业务代价，再选择模型、规则和复核方式。
>
> 清晰度方面，我把粗粒度判断展开成五级标准，用不可辨文字比例与文字区域锐度辅助预标注，再结合人工复核和 VLM 的 LoRA 训练学习质量等级。印章方面，我融合版面、印章检测与颜色特征，将不确定样本交给更强模型或人工。类型识别则用 OCR 和白名单匹配，针对旋转、错序和错字逐项修复。
>
> 这段工作最有价值的经验，是把模糊的业务要求转成可标注的任务、可评测的指标和可追溯的处理链路。

### 2.1 清晰度检测项目详述

**一句话定位**：把"清晰/模糊"二值判断重定义为锚定业务处理动作的五级质量标准，用规则预标注加速人工确认，再对 Qwen3.5 做 LoRA 后训练学习等级，个人负责从任务定义、数据标注到训练评测的完整链路。

#### 2.1.1 背景与业务约束

输入是法院、公安传入的查询与冻结文书图片，其中部分存在模糊、缺章等问题。难点不在"是否模糊"本身，而在**错误代价不对称**：错误拒绝一份有效法律文书的代价远高于放行一份模糊文书，所以链路设计的第一原则是尽量压低误拦、把模糊样本交给复核而不是直接拒绝。这决定了后面所有取舍——标准要能分级处理、模型输出要能支持排序、边界要可控。

#### 2.1.2 旧方案与其能力边界

旧方案是 XGBoost 二分类（输出清晰/模糊分数），特征三族：

| 特征族 | 维度 | 内容 |
|---|---:|---|
| 图像质量 | 7 | 拉普拉斯方差、对比度、边缘锐度、噪声水平、文字区域占比等 |
| OCR 置信度（RapidOCR） | 22 | 行级均值/最小值/中位数置信度、低置信行比例、置信度分布统计 |
| CLIP 全局编码（v6 新增） | 512 | 冻结 CLIP 的池化语义表征 |


对接业务时暴露三个具体缺口，这是重定义任务的直接动因：

1. **质量排序**：中间段样本分数区分度差，业务无法按质量决定处理方式；
2. **局部模糊** 编码有语义但不对任务、无空间定位；
3. **边界决策**：阈值附近分数抖动，且分数无法回答"差多少、差在哪"。
：整体清楚但关键字段（案号、法院名称）模糊的样本，与整体模糊但关键字段可读的样本处理方式不同，全局聚合统计恢复不了这种局部结构——CLIP
注意口径：双峰输出是二分类的正常现象，不作为旧模型"不好"的证据；二分类也能调阈值，"可调松紧"本身不是换五分类的理由。

但反方向的论证是成立的：**五级训练后按档位切回二分类，机制上可能优于直接二分类**，原因有四：

1. **标签信息量严格更大**：二值标签是五级标签的函数（L≤3 为正），五级标签额外携带每个样本的序数位置，相同样本量下边界区域被刻画得更精确；
2. **二分类浪费正类内部结构**：L1 与 L3 混为同一正类，正类内部排序不参与损失，模型没有理由区分"很清晰"和"勉强清晰"；切档用的是被序数结构整形的期望等级，二分类概率的中间区域则是欠约束的；
3. **边界区域被显式建模而非强行分离**：二分类的阈值附近是最难样本的混合区、梯度主导来源，分数抖动；五分类给边界样本独立档位（L3），切档线落在模型已学到的缓变区，决策更稳；
4. **软标签按序数距离惩罚误差**：L2→L3 与 L2→L4 的错误被区别对待，引导特征沿"模糊程度"单调组织；二分类损失里两者同样不计。

这四点是机制假设而非已验证结论：成立的前提是中间档样本量足够、五级标注噪声可控；要作为面试论断，需同特征、同数据、同切分下"直接二分类 vs 五分类切档"的控制变量消融（对应第 8 节最小矩阵中"原 XGBoost vs 同一 VLM 硬标签"一行，可加一组 XGBoost 五分类切档基线）。

#### 2.1.3 任务重定义：五级标准

与业务方把二值判断展开为五级，等级锚定**业务处理动作**而非纯视觉质量：

- L1/L2 → 自动通过；
- L3 → 边界档，按当时策略决定复核或通过；
- L4/L5 → 拒绝或强制复核。

标注手册要求：无重叠、无遗漏、**关键字段可读性优先于整体观感**，并配边界样例。上线采取保守策略：先只拦 L5，观察复核结果后再逐步扩到 L4——调的是决策区间边界，不是单阈值。

#### 2.1.4 数据与标注流程

```text
13,882 张原始图片（clarity_0809 批次）
    ↓ 规则预标注（见 2.1.5）
    ↓ 人工逐条确认 / 修正
13,133 张人工确认集
    ↓ 按 AppID 切分（防来源泄漏）
9,850 训练 / 3,283 验证（08v1 旧稿记录，需数据 manifest 确认）
```

预标签只决定"标注员先看什么"，不决定"标签是什么"——最终 GT 全部经人工确认。预标签与人工终标的一致率本身是诊断指标：一致率越高越要警惕模型只是在学规则。

#### 2.1.5 预标注规则

核心信号是 OCR 不可辨比例：

```text
line_weight = 0.7 × 字数 + 0.3 × (文本框面积 / 图片面积 × 1000)
unreadable_ratio = 低置信行（OCR 置信度 < 0.8）的权重和 / 全部有效文字行的权重和
```

- ratio ≥ 90% 或平均置信度过低 → 等级 5；
- ratio ≥ 50% 满足附加条件 → 等级 4；
- ratio ≥ 10% → 等级 3；
- 低不可辨比例样本结合平均/最低置信度、文字边缘强度、拉普拉斯方差区分等级 1/2。

两个关键工程处理：

- **红章排除**：按文本框内 HSV 红色像素比例过滤章内文字，避免弯曲印章文字的低置信度拖累整页质量评估；红色正文、浅色章与局部交叠是已知边界样本。
- **OCR 漏检补偿**：严重模糊的文字可能根本未被检测出来，只对检出行计算比例会系统性**高估**文书质量——这是比调阈值更本质的选择偏差。处理方式：Otsu 二值化、轻膨胀、连通域过滤并移除二维码区域，估计 OCR 框外的疑似文字占比；约 0.43 的背景基线与超额 0.15/0.30 上调等级属于当时数据的启发式常数，不跨模板通用。

已知缺口（需回代码核查）：阶段 2 写 ratio < 1%，阶段 1 只覆盖 ≥ 10%，1%–10% 分支未在文稿交代；OCR 置信度同时存在 0–1 与百分制两种写法。

#### 2.1.6 模型训练：Qwen3.5 LoRA 后训练

- 基座 Qwen3.5 视觉语言模型，LoRA rank=8、lr=1e-4、BF16、冻结视觉塔与连接层、step 1200、sqrt 反频率采样（旧稿线索，待日志核实）；
- **软标签**：以人工等级为中心、相邻档递减的平滑分布，注入"相邻等级接近"的序关系先验——普通五分类不会自动获得序关系，这是软标签存在的正当理由；它缓解边界标注噪声，但也可能抹平真差异，需与硬标签对照（待补消融）；
- **损失**：响应文本 token 用 next-token CE、等级 token 用分布 KL
为什么从 XGBoost 换到 VLM——能力阶梯的自然延伸，每一级解决上一级的缺陷：

```text
手工统计（7+22，无语义）
  → +冻结 CLIP（512，有语义但不对任务、无定位）
    → 微调视觉塔（任务适配，无文字推理）
      → 完整 VLM（图文联合推理）
```

#### 2.1.7 消融与结果（旧稿线索待核实）

- **语言塔消融**：只用视觉塔小模型 vs 完整模型，完整模型好 1–2 个点，说明语言部分图文联合推理有、
贡献，且去掉自回归解码能省推理成本。注意口径：这是同一架构、共享预训练的塔内消融，**不是**独立小模型基线——掉点混淆了模型大小与模态输入两个因素，不能用它论证"大模型普遍更好"，对轻量方案也不公平。指标口径（exact accuracy / 等级 MAE / 业务边界错误）待确认。
- 旧口播记录的 99.82% / 98.54% / 65.03% 等比较，未附实验配置与逐样本预测；"组内准确率"与"五级 exact accuracy"是否同一指标待核对。
- 1–3 视为通过、4–5 视为拒单后，**跨业务边界错误**（如 L2→L4）与相邻等级误差（L2→L3）必须分开报告，业务含义不同。

#### 2.1.8 评测口径与待补实验

主指标两项：等级 MAE / 加权 Kappa，加上业务误拦约束下的召回（跨边界错误率）。待补消融按第 8 节规划：硬标签 vs 相邻软标签；有/无 OCR 漏检补偿；VLM vs 独立训练的轻量基线（非共享预训练的视觉塔，或旧 XGBoost 改五分类作序数回归）。所有阈值在开发集选择后冻结到测试集，保存逐样本标签、预测、分数与路由记录。

## 3. 总体链路与系统设计

```text
文书输入 → 文件／页面标准化、方向处理
                 ↓
     清晰度 / OCR与标题 / 版面与印章
                 ↓
        模型结果与业务规则校验
                 ↓
   高置信处理 / 低置信 VLM或人工复核
                 ↓
      错误归因、标签修订、下一轮迭代
```

这是用于讲解的模块关系；真实哪些串行、并行以及哪一步能提前结束，要按线上实现描述。多模块可能命中同一请求，统计总体拦截应以业务请求去重；逐项数量相加不能直接得到整体收益。

"主链路低于 100M、单图低于 1s"只对应轻量印章检测部分，不能扩展成包含 9B 清晰度模型和 VLM 复核的全系统指标。平均延迟也不能替代 P95 或含排队时延。

## 4. 清晰度项目：定义、标签与训练

### 4.1 为什么改变建模方式

旧 569 维 XGBoost 在"清晰/模糊"这个二分类任务本身上是够用的。我拿它对接业务时发现三个具体缺口：

1. 质量排序：业务要按质量决定处理方式，中间段样本的分数区分度差、排序不稳定；
2. 局部模糊：整体清楚但关键字段（案号、法院名）模糊，和整体模糊但关键字段可读，处理方式不同——一个总分表达不了局部结构；
3. 边界决策：阈值附近样本的分数抖动，业务也不知道"差多少、差在哪"。

<!-- 旧 569 维 XGBoost 输出二分类分数，分数接近两端，不适合直接切成五个稳定等级。二分类输出双峰本身正常；需要证明的是它不能充分支持当前业务的质量排序、局部模糊处理或边界决策。 -->

五级标签可以提供更细监督，但普通五分类并不会自动获得序关系。相邻软标签、序数损失或排序约束是否帮助泛化，需要独立评测。二分类概率本来也能调阈值，不能说"只有五分类才能调业务松紧"。

### 4.2 原始规则预标注记录


```text
line_weight = 0.7 × 字数 + 0.3 × (文本框面积 / 图片面积 × 1000)
unreadable_ratio = 低置信行的权重和 / 全部有效文字行的权重和
```

设置低于 80% OCR 置信度的文本框为不可辨候选。比例 ≥90% 或平均置信度过低时标为等级 5；比例 ≥50% 等条件对应等级 4；比例 ≥10% 对应等级 3。低不可辨比例样本再结合平均／最低置信度、文字边缘强度、拉普拉斯方差区分等级 1/2。


红章排除：根据文本框内 HSV 红色像素比例过滤章内文字，减少弯曲印章文字低置信度对整页质量的干扰。红色正文、浅色章与局部交叠可能导致误排，需要作为边界样本。

### 4.3 OCR 漏检造成的选择偏差

严重模糊的文字可能根本未被检测出来。如果只对检出行计算不可辨比例，系统会"只看到剩下的清楚文字"，从而高估文书质量。这是比简单调阈值更值得讲清楚的失败原因。

原方案尝试 Otsu 二值化、轻膨胀和连通域过滤，并移除二维码区域，估计 OCR 框外的疑似文字占比。原记录有约 0.43 的背景基线及超额 0.15/0.30 时上调等级的启发式。它们只适用于当时数据，受边框、Logo、印章和扫描背景影响，不能当跨模板通用常数。

后续可比较"无补偿／固定补偿／按模板或来源校准的补偿"，但这属于待做消融。

### 4.4 软标签到底表达什么

需要区分：多人对同一图片评分的分布、多个模型的评分分歧、以人工等级为中心的固定平滑分布。前两者可以提供某种不确定性信息；固定高斯平滑主要表达相邻等级接近，不能直接声称量化了真实标注方差。

一种候选构造是对等级中心周围分配递减概率并归一化。若按连续分布对五个等级区间积分，要说明边界截断、尾部概率归并方式以及参数来源。原稿的固定 σ²、人工均值方差两种说法需要对应到实际代码。

### 4.5 CE、KL、Closed-set Softmax 与期望评分

对固定目标分布 q 和同一预测分布 p，普通未加权定义满足 `CE(q,p) = H(q) + KL(q||p)`，因此对模型参数梯度等价。旧 05 版曾写"响应文本 token 用 next-token CE、等级 token 用 KL"，这与对同一等级分布重复计算两个损失不同；应核实真实 loss mask、目标和权重。[CE 定义](https://docs.pytorch.org/docs/2.14/generated/torch.nn.CrossEntropyLoss.html)、[KL 定义](https://docs.pytorch.org/docs/2.14/generated/torch.nn.KLDivLoss.html)

如果采用五个等级 token 的 closed-set softmax，要确认每个标签如何分词、是否单 token、取哪个位置的 logits，以及条件归一化后如何处理无效输出。

`score = Σ(k × p_k)` 是期望评分。除非额外用开发集拟合温度、映射或阈值，不能仅凭取期望就叫"概率校准"；等级间距是否适合等距编码也应与标签定义一致。

### 4.6 配置和现有消融数字如何保留

旧口播包含 LoRA rank=8、lr=1e-4、BF16、冻结视觉塔与连接层、step 1200、sqrt 反频率采样，以及 99.82% / 98.54% / 65.03% 等比较。这些没有随材料提供实验配置、逐样本预测或日志，暂列为**旧稿线索待核实**，不能直接整合成已经验证的消融表。

尤其要核对"组内准确率"和"五级 exact accuracy"是否同一指标；1–3 视为通过、4–5 视为拒单后，跨业务边界错误与相邻等级误差不同。如果确有有效文书被分到 4/5，就必须解释它与"Precision 100%"的时间、复核和决策口径差异。

## 5. 印章识别：类不平衡与选择性决策

### 5.1 方法与迭代

自然业务无章少、浅色章难检，整体 Accuracy 容易被大量有章样本主导。方案融合 PP-DocLayout 系列、印章专用检测器与 HSV 颜色先验，并引入不确定路由。旧稿另有 8 块、15% 重叠切分的小章放大策略，使用前核对实际版本。

早期周报：扩充到 1,152 张评估集，其中 116 张真实无章；86 组阈值／组合策略搜索后，同召回下 Precision 从 31.8% 到 55.3%。后续采用新的难例和标注批次，不能直接把前后分数视为同一固定测试集的严格消融。

### 5.2 从历史混淆矩阵重算

旧周报记录：

| 判定 / 真实 | 有章 | 无章 |
|---|---:|---:|
| 判有章 | 10,948 | 6 |
| 判无章 | 0 | 562 |

以"无章"为正类，TP=562、FP=0、FN=6、TN=10,948，总数 11,516：

- Precision = 562/(562+0) = 100%。
- Recall = 562/(562+6) ≈ 98.94%。
- F1 = 2×562/(2×562+0+6) ≈ **99.47%**；旧文稿的 99.37% 为算术不一致。

这个矩阵不含 UNSURE，也没有说明它是复核后的全量结果还是选择后子集。必须补充路由记录再解释自动覆盖率。若这是富集无章的样本集，也不能直接用其 Precision 代表自然业务分布下的表现。

### 5.3 三个容易混淆的指标

```text
自动覆盖率 = 自动给出最终结论的样本数 / 全部样本数
全量无章召回 = 自动或最终系统正确检出的无章数 / 全部真实无章数
子集无章召回 = 子集内正确检出的无章数 / 子集内真实无章数
```

后两者不能交换。报告高置信子集 Precision 时，需要同时交代自动覆盖率、升级 VLM／人工比例及最终系统漏检。

## 9. 高频问题与回答要点

**最大的难点？** 业务错误代价不对称、标签标准存在灰区、算力和人工复核有限。分别对应风险约束、可操作标注标准、选择性路由。避免凭空添加"标注效率提高五倍"等未见记录的结果。

**为什么五分类用软标签？**  预标注规则在小字、手写体上有局限，用评分均值+方差拟合质量分布构造五维软标签，SFT 时 CE+KL 联合训练 + 概率期望校准，避免硬标签噪声导致过拟合。

**为什么不全部用大 VLM？** 根据实际比较解释成本、时延、确定性和长尾能力；规则可以稳定处理的标题与号码无需全量生成式推理，困难样本可以升级。不能用印章轻量路径时延代替全系统时延。
67667
**怎么证明没有误拦？** 只能说明在特定样本、决策口径与复核流程下未观察到误拦。需给样本数、预测拒单数和来源；未知未来请求不受这一观察保证。

**软标签一定更好吗？** 不一定。它可能缓解边界噪声，也可能抹平真差异。应比较远距离误分、长尾表现和业务边界错误。

**级联会不会丢召回？** 会。前级错误拒绝／放行可能让后级无法补救，需记录每级流量、真阳性损失和升级路径，并对全系统评测。

**XGBoost 已经不错，为什么换 VLM？** 先证明它对具体难例缺能力，再比较 VLM、轻量视觉模型、调整规则的质量与成本；模型尺寸本身不是理由。

**如何防止过拟合？** 按来源隔离，比较训练／验证曲线，以业务指标选 checkpoint，控制训练长度；先确认是否标签噪声或分布偏移。旧稿中的具体 step/loss 待日志确认。

**你独立做了哪些？** 准备任务定义、预标注、标注工具、模型训练、规则与路由各自负责的代码和交付物；导师／业务方负责的标准确认和上线环节也明确说明。

**失败经历怎么讲？** 可以讲早期试图切分二分类分数、后续发现需要统一标签标准的过程；具体"一致性 23%""提前一半时间"等数字没有记录就省略。

**DBNet** 原理基于可微二值化（Differentiable Binarization），把二值化阈值嵌入训练，用概率图 + 阈值图 + 二值图三头，解决标准后处理不可导问题；损失对正负样本自适应加权。追问：和 DBNet++/PSENet/FCENet 区别、LCNet 作为 backbone 的取舍。

**版面分析** 讲 LayoutLM 系列或检测式版面分析（你的场景里用了版面/印章检测三路融合）。

**OCR 幻觉怎么处理** 结合你腾讯/京东经历答——行级置信度门控、多源信号交叉验证（标题定位 + 白名单 + 同义词归一 + 自适应模糊匹配）、低置信走 VLM 复核。

### T03｜五档清晰度怎么定义？OCR 不可辨比例、边缘强度、拉普拉斯方差怎么算？

**场次**：[腾讯微信支付风控，2026-09-16][wx] Q9；[字节风控，2026-09-25][bf] Q2。

**我的回答**：微信时按可辨文字比例分档，但口述区间存在空隙；字节时提到 OCR 置信度阈值 0.9、框大小和字符加权，对拉普拉斯的公式不熟，解释成模糊时文字"不那么黑"。

**更好回答**：先区分人工业务标签和自动预标特征。OCR 低置信比例可以按文本框数、字符数或面积加权，但必须说明实际分母；阈值 0.8／0.9 的历史差异要对应版本，不能混用。拉普拉斯为二阶空间导数，常用清晰度代理是 `Var(∇²I)`；边缘强度可用梯度幅值统计，但要以自己的代码定义为准。它们受尺寸、噪声、对比度和 ROI 影响，所以统一预处理并聚焦有效内容区域。五档边界应写成无重叠、无遗漏的标注手册，关键字段可读性优先，OCR 置信度不等于人类可读性真值。[OpenCV 拉普拉斯说明](https://docs.opencv.org/4.x/d5/db5/tutorial_laplace_operator.html)

### T04｜验证集哪里来？GT 是人工还是模型给的？召回怎么量？

**场次**：[09-14 风控一面，公司待核实][fk] Q4；[字节风控，2026-09-25][bf] Q3。

**我的回答**：09-14 说先打标再按 75%／25% 切分，并用历史几千张补充验证；字节时把"漏检率"纠正成 Precision，约万条数据过链路后，对判为有问题的少量样本找产品确认，召回只做了部分抽样。

**更好回答**：把训练预标签、人工确认标签和最终测试 GT 分开。只复核模型判为异常的样本，可以估计这一部分的 Precision，不能计算总体 Recall，因为没有看到漏掉的正例。补做时同时抽样预测正常和预测异常的样本，记录各层抽样概率，经独立人工标注后按权重估计混淆矩阵，并报告区间。切分比例以数据清单为准；相同文书模板、机构、原图衍生版本要防止跨集合泄漏。**历史留存集不自动等于时间外验证集**，必须先证明训练与测试时间边界及样本无重叠。

### T05｜伪标签用在哪一步？与软标签有什么区别？

**场次**：[09-14 风控一面，公司待核实][fk] Q5。

**我的回答**：回答了人工／规则确定类别后，用高斯分布把 1–5 类变成概率，再用于后训练，混在一起解释了标签来源和标签表示。

**更好回答**：伪标签说明标签从哪里来，例如规则或教师模型自动生成；软标签说明监督长什么样，例如五类概率分布。两者是不同维度，人工标签也能被转换成软分布。项目流程是先生成预标签、人工复核，再根据相邻档的不确定性构造归一化目标分布。高斯平滑加入了"相邻类别更接近"的先验，但不等于测出了真实标注者概率，也不能直接称为教师分布蒸馏。平滑宽度需在验证集选择，并与硬标签比较；未做对照就不声称软标签已降低多少误判。

### T06｜为什么 CE + KL？CE 不能学软标签吗？

**场次**：[字节风控，2026-09-25][bf] Q4；[09-14 风控一面，公司待核实][fk] Q5 的事后答案也涉及此处。

**我的回答**：把硬标签高斯平滑后，认为"CE 学不了分布，所以加 KL"。原复盘把这段标为正确，实际上需要改正。

**更好回答**：CE 可以使用概率目标。对同一固定软目标 q、同一预测分布 p，未加类别权重时 `CE(q,p)=H(q)+KL(q‖p)`，因此二者对模型参数的梯度相同。只有作用对象不同，联合使用才可能承担不同功能，例如回答文本的 token CE，加等级位置的分布 KL。我的实际实现需要核对 loss 代码、mask、归一化方式和权重；如果两项只是对同一分布重复计算，就不能包装成两个互补目标。序数关系来自软标签构造或另外的距离／序数目标，不是 KL 本身自动知道类别顺序。[PyTorch CrossEntropyLoss](https://docs.pytorch.org/docs/stable/generated/torch.nn.CrossEntropyLoss.html)

### T07｜为什么二分类改五分类？为什么 XGBoost 双峰就不行？

**场次**：[腾讯微信支付风控，2026-09-16][wx] Q8、Q13。

**我的回答**：五档更贴近连续业务需求，可以灵活调整拦截；XGBoost 二分类分数接近两端，中间档不够稳定。

**更好回答**：五档的价值是更细地表达可读性与标注标准，支持业务选择自动通过、复核和拒绝的范围。二分类本来也能调阈值，因此"可调阈值"不是改五分类的充分理由；但五级训练后按档切回二分类优于直接二分类的四点机制论证见 2.1.2（标签信息量、正类内部结构、边界建模、序数惩罚），可作为正面理由陈述，前提仍是补控制变量消融。分数双峰也不直接证明模型不好，要看排序、校准和目标区间的区分能力。公平比较应包含同一特征下的二分类、五分类／序数建模，以及 VLM 方案，并控制标签和数据切分。我观察到了原方案的边界问题，但缺少控制变量实验时不能把收益单独归因于五档设计或 VLM。

### T08｜五个英文等级词能让模型理解有序关系吗？

**场次**：[腾讯微信支付风控，2026-09-16][wx] Q14。

**我的回答**：选择带语义的英文等级词，借预训练先验帮助模型感知好坏顺序。

**更好回答**：等级词可能提供语义先验，但普通多分类目标不保证"错到相邻档"比"跨四档"受罚轻。软目标在相邻档分配更多概率能表达局部接近；若要显式约束距离，可以考虑累计阈值的序数建模或基于距离的损失。评测除了业务二分类 P/R，还可以看等级 MAE、严重跨档错误率与混淆矩阵。英文词、数字标签、硬标签、软标签分别怎么影响效果，需要消融；现有材料中的"掉 2%"没有可靠对照依据，不作为成果。

### T09｜为什么用 PaddleOCR？有规则了，为什么还需要 VLM 后训练？

**场次**：[腾讯微信支付风控，2026-09-16][wx] Q10、Q11；[字节风控，2026-09-25][bf] Q14 的 OCR 选型部分。

**我的回答**：OCR 选型主要说轻量、工业场景常用；规则对手写字、小众字体、印章、反光等处理不好，VLM 可以结合语义。

**更好回答**：轻量 OCR 适合提取可解释特征和文字，但是否优于通用多模态模型要在同一真实集比较关键字段识别、错误率、延迟、成本及部署条件。规则与 VLM 的作用要说明阶段：规则可以用于预标注，也可以用于线上筛选，这两种不能混讲。VLM 可能结合文字、布局与上下文处理规则难例，但也可能被语义先验误导。要用独立人工 GT 验证这种取舍，不能因为用了大模型就默认更准，也不能在没实现线上分流时声称"只对边界样本跑 VLM"。

### T10｜4.33%→9.84% 是什么？Precision、Recall、误拦怎么区分？

**场次**：[腾讯微信支付风控，2026-09-16][wx] Q5；[09-14 风控一面，公司待核实][fk] Q6。

**我的回答**：微信场次把 9.8% 一度称作误拦，之后用批量人工复核解释 Precision，Recall 只在较小集合估计；09-14 场次把异常第 4／5 类的 Precision 叫作"准确率"。

**更好回答**：先定义无效文书为正类。拦截比例是预测正例数除以全部请求；Precision 是拦截中真实无效的比例；Recall 是所有真实无效中被拦截的比例；FPR 是正常文书中被误拦的比例。还要区分 `1−Precision` 与 FPR，它们分母不同。4.33%→9.84% 本身不能说明质量变好，必须说明同一时间窗、流量、规则和标注口径，且当前材料尚不能确认它是可比线上实测。有限集合零误判只说明这次没观察到，需附 N、错误数和抽样方法。五分类精确匹配率另算，不与业务二分类 Precision 混称。

### T11｜打回之后不再请求，能算有效拦截吗？按 session 分析过吗？

**场次**：[腾讯微信支付风控，2026-09-16][wx] Q6。

**我的回答**：当时没有做 session 分析，表示之后可以考虑。

**更好回答**：不能直接算。停止请求可能是确实不合规，也可能放弃、转线下、换渠道或还没来得及重提。可以按业务对象和请求关联键追踪重提、修正了哪些字段、最终成功与否、处理耗时；设置观察窗口，区分尚未结束的请求。行为序列只能提供弱监督和排查线索，真实性仍需抽样人工核验。对照上线前后或灰度组时还应控制机构和业务类型差异。**这属于未完成的分析方案，不回答成已经有了 session 真值闭环。**

### T12｜电话号码为什么不用大模型？能证明打得通、属于该法院吗？

**场次**：[腾讯微信支付风控，2026-09-16][wx] Q7。

**我的回答**：电话来自结构化字段；异常格式很多，整理成规则；外部强校验接口在成本、权限等条件下难以使用。

**更好回答**：先明确能力边界：规则能验证格式、区号与字段一致性，以及已维护名录中的匹配关系；不能凭字符串证明可接通，更不能证明号码当前归属。对明确模式，确定性规则更可解释、便于回归，未覆盖格式进入复核或补充规则。需要强归属核验时要依赖可靠外部数据或业务核验流程。报告时分别给规则覆盖率、已标注集的误判／漏判和未识别比例，不能把"通过格式检查"说成"号码真实有效"。

### T13｜到底用什么 GPU？为什么不能训练？

**场次**：[腾讯微信支付风控，2026-09-16][wx] Q12。

**我的回答**：P600／P800 等型号说法混乱，并给出了缺乏依据的限制解释。

**更好回答**：这题先报事实：训练和推理分别运行在哪个环境、GPU 型号／数量／显存、采用什么精度和并行方式；不确定就明确回看任务配置。不能训练的原因要区分账号权限、环境依赖、资源配额与显存不足，并给具体错误或限制。若是估算，列出权重、梯度、优化器、激活和缓存的预算，不把估算当成硬件实测。面试前补一张真实资源卡，避免把未知型号替换成另一个猜测型号。

### T14｜3.57% 是什么？样本多少？每天慢慢跑大模型行不行？

**场次**：[腾讯微信支付风控，2026-09-16][wx] Q15。

**我的回答**：把 3.57% 解释为模型判"不清晰"的比例，样本分母和在线／离线口径不够明确。

**更好回答**：当前可核对材料中的 3.57% 是训练数据里的相关类别占比，不能当作 Recall 或线上拦截比例。如果面试时想指的是另一批推理结果，需要拿出该批次的总数、日期和阈值。是否能每日离线慢推，要先问结果何时必须返回：实时阻断受 P95／P99 延迟约束，离线质检可用批处理但仍有吞吐、成本与数据时效约束。比较单位样本成本、日处理量和积压，而不是只说"大模型慢一点也可以"。

### T15｜哪些模块上线了？上线后如何发现误伤和漏召？

**场次**：[09-14 风控一面，公司待核实][fk] Q7。

**我的回答**：按当时口述，文书类型、电话校验已上线，清晰度尚未上线；产品定期抽检，计划先放第 5 档再考虑第 4 档。

**更好回答**：这是 **2026-09-14 当时** 的状态，当前状态需按模块和版本更新。已上线部分分别说明生效范围、回滚方式和反馈来源；清晰度若仍离线，就只报离线结果。发现误伤需要抽查拦截样本，发现漏召还要抽查通过样本，申诉和重提只能补充。影子运行、逐级灰度、监控和回滚是可补方案，不能把原复盘自动补写的 PSI／KS 监控当作已经上线的系统。

图像理解 vs 生成任务差异、视觉 token 效率（对应你接触的 Qwen-Image：Flow Matching、双图条件拼接、CFG 无条件训练机制——JD 提到生成式 AI，这条要能讲）。
