3. Hybrid Search 为什么有必要
推荐回答：

纯向量检索适合语义相似，但对专有名词、编号和精确短语不一定稳定；纯关键词检索精确匹配能力强，但对同义表达和自然语言问题召回不足。因此使用 Hybrid Search 扩大候选集，再通过 Re-ranker 进行细粒度相关性排序。

如果你们实际使用的是 BM25 加 Dense Retrieval，可以直接说；如果不是，不要擅自写 BM25。

4. 个性化检索怎么讲
不同部门和用户拥有不同的关注范围和历史行为。我在检索阶段引入组织级及用户级约束，并针对数据源权重、时效性和用户偏好调整排序策略，从而使同一问题在不同上下文下返回更合适的内容。

注意准备回答：

个性化是在召回前过滤还是召回后重排？
部门权限和用户偏好如何区分？
新用户没有历史数据怎么办？
时效性如何进入排序分数？
5. 长期记忆怎么讲
长期记忆不是把所有历史对话直接拼进上下文，而是从对话中抽取值得长期保存的用户信息，将其向量化存储。在新会话中根据当前问题检索相关记忆，并与短期上下文一起输入模型，从而控制上下文长度并支持跨会话信息保持。

面试官很可能继续问：

什么信息应该写入记忆？
如何避免错误记忆污染后续对话？
记忆更新、覆盖和删除如何实现？
多用户记忆如何隔离？
如何防止召回不相关记忆？
如果你实际没有做这些模块，不要说实现过，只说这是你理解的后续优化方向。

3. 为什么使用多模型投票
推荐回答：

单个教师模型可能存在系统性偏差，尤其是边界样本和隐晦表达。多模型投票可以降低单个模型偶然错误的影响；启发式规则则适合处理格式合法性、标签冲突和明显异常。对于模型间分歧较大的样本，可以过滤、降权或者进入人工复核，而不是直接作为高置信训练数据。

面试官可能问你的投票机制，需要提前确认真实实现：

是多数投票还是置信度加权？
模型输出如何归一化到统一标签？
平票怎么处理？
哪些样本会被过滤？
最终保留率是多少？
是否抽样计算自动标签准确率？
4. 为什么做多轮数据
实际内容安全判断并不总能由单轮输入完成，有些风险依赖前文指代、上下文组合或者连续诱导。多轮数据可以让模型学习上下文依赖，而不是只根据当前一句中的关键词分类。

5. 结构化推理数据怎么讲
不建议过分强调“让模型输出完整 CoT”，可以说：

在 SFT 数据中加入结构化的判断依据，使模型先定位图像和文本中的关键证据，再输出风险类别和处置结果。相比只训练最终标签，这种方式能提升复杂样本的可解释性，并减少模型仅依赖关键词进行判断的问题。

七、SFT 部分怎么讲
推荐表述：

首先使用百万级多轮图文数据对 Qwen3-VL-8B 进行全参数 SFT，使模型学习统一的输入输出格式、风险分类体系以及图文联合判断能力。训练数据中需要重点控制类别分布、正负样本比例、难例比例和多轮长度，否则模型容易偏向高频类别或形成一律拒绝的策略。

面试官很可能问以下内容，建议你把真实参数找出来：

使用多少张卡、什么卡？
Global batch size 是多少？
学习率、warmup ratio、epoch 数是多少？
最大图像分辨率与最大 token 长度是多少？
是否使用 DeepSpeed ZeRO？
全参数 SFT 为什么不选择 LoRA？
训练 loss 是否与实际指标一致？
验证集如何划分？
有没有按数据来源去重，避免 train/test 泄漏？
你不一定要把这些写进简历，但面试前必须准备。

八、GDPO 多目标强化学习怎么讲
这是最容易被深挖的部分。

1. 为什么 SFT 后还需要强化学习
SFT 主要学习训练数据中的标准答案，但模型真实目标包含多个维度，例如既要拦截风险内容，又要避免误判正常内容，还要按照规定格式输出。这些目标很难只通过交叉熵损失直接表达，因此在 SFT 后引入强化学习进行多目标优化。

2. 奖励维度
根据你现有材料，可以分成三类：

风险识别奖励

高风险样本是否正确识别；
风险类别是否正确。
误判或过度拒绝惩罚

正常样本是否被错误拒绝；
边界内容是否被过度判定。
格式遵循奖励

是否输出合法格式；
标签、解释和字段是否完整；
是否包含无关内容。
3. 为什么要做奖励归一化
推荐回答：

不同奖励的数值范围和方差不同。如果直接加权求和，尺度更大的奖励会主导梯度。例如格式奖励可能很容易获得稳定高分，而风险识别奖励更稀疏，训练后模型可能只学会遵循格式，却没有真正提升识别能力。

因此我们对不同奖励进行归一化，再按业务重要性加权，使各个目标在相近尺度上参与优化，从而缓解某个奖励独占优化过程和整体奖励坍塌的问题。

九、面试官最可能质疑的问题
1. “100 万数据如何保证质量？”
推荐回答结构：

第一层是基础规则清洗，包括格式、重复、图像有效性和字段一致性；第二层是大模型自动标注，通过多模型投票减少单模型偏差；第三层是启发式规则处理标签冲突和明显异常；第四层是对低置信及模型分歧样本进行过滤或抽样人工复核。最后还要检查类别、来源和难度分布，避免数据量很大但有效信息重复。

2. “百万数据是不是全部由你完成？”
一定要明确个人边界：

百万级数据是团队链路的总产出。我个人主要负责数据清洗、自动标注策略、某些数据源接入以及质量分析中的具体模块。

如果确实是你一个人搭建的主要链路，可以说：

整体方案和核心代码由我负责，数据资源和算力由团队提供。

不要默认把团队产出全部写成个人产出。

3. “F1 是 Macro 还是 Micro？”
这个必须提前确认。多类别且类别不均衡时，两者区别非常大。

如果是二分类风险拦截 F1，要明确：

将所有风险类别合并成正类计算风险拦截 F1。

如果是多分类 Macro-F1，也要明确说 Macro-F1。

5. “SFT 数据和评测集是否泄漏？”
需要在图像、文本和语义三个层次去重。除精确哈希外，还应通过感知哈希或图像 embedding 处理近重复图片，通过文本归一化和 embedding 检测改写版本，最后按数据来源或时间切分评测集，避免同源模板泄漏。
