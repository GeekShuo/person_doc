## 2. 分类指标与实验设计

### 2.1 必须会写的公式

以“风险／无章／模糊”为正类时，先明确到底选哪一个任务：

```text
Precision = TP / (TP + FP)
Recall    = TP / (TP + FN)
F1        = 2TP / (2TP + FP + FN)
FPR       = FP / (FP + TN)
Accuracy  = (TP + TN) / N
```

Precision 的分母是预测正类，Recall 的分母是真实正类，FPR 的分母是真实负类。F1 不是召回率。审核误拦与生成助手过度拒答需要各自标签定义，不能只改指标名称。

Macro-F1 先算每类 F1 再平均；Micro-F1 汇总计数后计算；Weighted-F1 按类别支持数加权。普通单标签、全类别多分类的 Micro-F1 等于 Accuracy，不能把这条结论扩展到所有多标签设定。

### 2.2 类不平衡时为什么 Precision 会变

若正类占比为 π：`Precision = π·TPR / [π·TPR + (1−π)·FPR]`。在相同 TPR/FPR 下，正类更稀少，Precision 可能下降。主动富集困难正类的评测集适合诊断，但其 Precision 未必代表自然业务。

### 2.3 固定 Recall 怎么比较

使用可排序分数，在开发集选择阈值后冻结到测试集，报告测试集实际 Recall 与 FPR。若只输出离散标签或分数不可比，先比较完整 operating points 或 PR 曲线，不在测试集反复调阈值凑目标。

### 2.4 相对变化与百分点

5%→4%：下降 1 个百分点，相对下降 20%。4.33%→9.84%：增加 5.51 个百分点，相对增加约 127%。业务检出比例提高并不自动证明正确率提高。

### 2.5 消融、A/B 与泄漏

消融希望识别某个因素的作用，因此基座、数据、预算、评测与选择规则要尽可能保持一致。增加训练数据又改算法，无法仅凭最终提升归因给算法。线上 A/B 还需要随机分流、统一时间窗口及合理的统计单位。

泄漏除了完全重复，还包括同一图片的裁剪／压缩版本、同一会话、近似文书模板、同品商品和后续人工规则调优。按这些关联组切分比随机分行更合理；最终测试集不用于样本挖掘、阈值和 checkpoint 选择。

没有对照只能说“采用了方法并得到某结果”。统计推断还要考虑样本相关性、随机种子、错误数量与区间估计。多次评测再挑最好的一次会产生选择偏差。

## 3. SFT、LoRA 与显存

### 3.1 SFT 学什么

对目标响应 token 做条件负对数似然优化。应检查 prompt／padding 是否被正确 mask，多轮对话中哪些轮参与 loss，以及图像 token 和文本截断如何处理。训练 loss 下降不保证业务指标改善，可能来自格式或常见词的拟合。

全参数与 LoRA 的取舍涉及任务差异、数据量、训练预算、优化空间与部署需求。不存在“安全任务一定全参”“LoRA 一定不遗忘”的规则。

### 3.2 LoRA 参数手算
一句话理解 lora:
原模型参数 $W$ 不动，不直接学习一个巨大的 $\Delta W$，而是用两个很小的低秩矩阵 $A,B$ 来表示 $\Delta W$。
#### LoRA 后训出来的参数到底怎么“加”回原模型？

LoRA 并不是把 $A$、$B$ 拼接到 $W$ 上。而是先：

$$
A,B \rightarrow BA \rightarrow \Delta W
$$

再：

$$
W + \Delta W \rightarrow W'
$$

这个问题特别重要。

训练之前：

$$
y = Wx
$$

LoRA 加进去以后，forward 实际变成：

$$
\boxed{y = Wx + \frac{\alpha}{r}BAx}
$$
#### lora节省了多少参数量？
设 $W\in\mathbb{R}^{m\times n}$，增量 $\Delta W=(\alpha/r)BA$，其中 $B\in\mathbb{R}^{m\times r}$、$A\in\mathbb{R}^{r\times n}$。原矩阵参数为 $mn$，LoRA 参数为 $r(m+n)$。$d=4096$、$r=16$ 时，单个方阵原参数 16,777,216，适配器参数 131,072，约为原矩阵的 1/128。这个比例只针对该矩阵，不能直接说全模型显存降低 128 倍。[LoRA 原论文](https://arxiv.org/abs/2106.09685)

要会解释 target modules、rank、alpha、dropout、实际可训练参数量和 adapter 合并。低秩参数减少梯度与优化器状态，但冻结主干仍需要前向计算，训练激活也不自动消失。

### 3.3 显存账与优化

显存分为权重、梯度、优化器状态、激活、临时缓冲与通信开销。常见混合精度 Adam 配置下，每个可训练参数的权重／梯度／FP32 主权重及两个动量合计可粗估为约 16 字节，但具体实现可能不同，这不是“仅优化器状态”的大小。

ZeRO-1 分片优化器状态；ZeRO-2 进一步分片梯度；ZeRO-3 进一步分片参数。Activation checkpointing 用重算换激活显存；梯度累积用多个 microbatch 形成更大的有效 batch。多模态中图像 token、长序列和分辨率分桶也会影响峰值与吞吐。[DeepSpeed ZeRO 文档](https://www.deepspeed.ai/tutorials/zero/)

遇到 OOM 先判断发生在加载、前向、反向还是 optimizer step，再选择对应办法；不要无条件同时缩 batch、缩图片、开 offload，导致不知道代价来自哪里。

### 3.4 遗忘怎么处理

先用固定通用任务与领域任务分别评测；再比较减少学习率／训练步数、混入通用数据、冻结部分模块或参考模型约束等候选方法。混入比例没有通用最优值，不把旧稿中的某个百分比作为默认定律。

## 4. PPO、DPO、GRPO、GDPO

| 方法 | 反馈与训练形式 | 需要讲清的点 |
|---|---|---|
| PPO | 从 rollout 估计优势，裁剪策略更新；常见 RLHF 实现使用 critic | 奖励可来自规则或模型，critic 与 Reward Model 是不同角色 |
| DPO | 常见形式用 chosen/rejected 偏好对和参考策略，直接优化相对偏好 | 通常不需要在该训练阶段拟合显式 RM 或运行在线 rollout；数据偏差仍会影响结果 |
| GRPO | 对同一 prompt 的多条输出用组内奖励构造相对优势 | 不需要单独的 critic；组内奖励全部相同会缺少相对学习信号 |
| GDPO | 多奖励分别归一化再聚合构造优势 | 检查奖励相关性、有效方差、权重与实现；不保证一定优于 GRPO |

DPO 的常见损失写法是：

```text
L = -log sigmoid(β × [log πθ(y+|x)/πref(y+|x)
                      - log πθ(y-|x)/πref(y-|x)])
```

这里比较的是相对于参考策略的偏好对对数概率差。[DPO 原论文](https://arxiv.org/abs/2305.18290)

GDPO 的动机与实现细节见 [原论文](https://arxiv.org/abs/2601.05242) 和 [官方代码](https://github.com/NVlabs/GDPO)。不要把 DPO、GRPO 和 GDPO 当作同一个损失改了名字。

奖励设计回答顺序：明确动作与输出 → 定义正确性／误判／格式等信号 → 检查尺度、相关性和常数奖励 → 在开发集比较权重与约束 → 观察独立业务指标。Reward hacking 是优化代理奖励而没有完成真实目标，不能靠加一个归一化步骤保证消失。

**追问：为什么 RL 可能没有收益？** SFT 已接近上限、奖励噪声、输出缺少多样性、组内优势退化、训练预算不足、目标与评测错位，或者简单阈值调整已能达到同样效果。

**追问：安全样本如何筛？** 可以考虑误杀、漏判、边界分歧和格式问题，但要先去除错标与无法评价的样本。难例不自动适合 RL；知识缺失也可能更适合 SFT。

## 5. Attention、位置编码与推理

### 5.1 Attention 与因果掩码

`Attention(Q,K,V)=softmax(QKᵀ/√d_k + mask)V`。自回归因果掩码阻止当前位置关注未来 token；padding mask 屏蔽无效位置。标准全注意力的序列交互成本随长度呈平方增长。[Transformer 原论文](https://arxiv.org/abs/1706.03762)

手写时说清 `Q:[B,H,Tq,D]`、`K/V:[B,H,Tk,D]`；沿 key 长度轴 softmax；避免忘记缩放、mask 广播和 dtype。高效内核可以避免显式保存完整注意力矩阵，但不能据此声称精确全注意力的所有计算都变成线性。

### 5.2 KV cache、MHA/MQA/GQA

自回归解码缓存历史 K/V，避免每步重新计算它们。MHA 每个 query head 有自己的 K/V head；MQA 共享一组；GQA 按组共享。常见缓存大小近似：

`bytes ≈ 2 × 层数 × batch × 序列长度 × KV头数 × head_dim × 每元素字节数`。

这是标准结构的估算，未包括分页碎片、量化元数据或特殊架构。减少 KV 头数影响缓存和带宽，也可能改变模型质量；prefill 与 decode 的瓶颈不同。[GQA 原论文](https://arxiv.org/abs/2305.13245)

### 5.3 RoPE 与多模态位置

RoPE 对 query/key 的成对维度施加随位置变化的旋转，使点积可以表达相对位置信息。长上下文扩展还涉及频率、训练长度与模型适配，不能只说把位置索引变大即可。[RoPE 原论文](https://arxiv.org/abs/2104.09864)

Qwen3-VL 的官方说明包含 DeepStack 多层视觉特征融合、Interleaved-MRoPE 和时间戳相关设计。面试应结合实际版本讲视觉特征如何进入语言模型；不要把 DeepStack 简化成严格一一对应的“浅层 ViT 只进浅层 LLM”，也不要把所有 Qwen 版本视作相同结构。[Qwen3-VL 官方仓库](https://github.com/QwenLM/Qwen3-VL)

## 6. OCR 与 CTC

OCR 可拆成文本检测、方向处理、文字识别、阅读顺序／版面恢复。文书标题分类还要叠加业务规则。识别不到与识别出不存在的文字是不同错误，应分别计数。

CTC 用于输入与目标长度不同、缺少逐帧对齐的序列学习。对每个时间步输出字符加 blank 的分布，将路径折叠后得到目标字符串，再对所有合法路径概率求和；前向后向动态规划避免枚举全部路径。[PyTorch CTC 文档](https://docs.pytorch.org/docs/2.14/generated/torch.nn.CTCLoss.html)

**折叠顺序：先合并相邻重复标签，再删除 blank。** 以 `-` 为 blank：

- `aa-bb- → a-b- → ab`。
- `a-ab- → a-ab- → aab`，blank 两侧的 a 不应合并。
- 目标 `aa` 至少需要如 `a-a` 的三个时间步。一般 T≥L 只是基本条件，相邻重复目标还需要额外分隔步。

CTC 的局限包括给定输入后的路径时间步分解假设和语言依赖建模限制；可以用更强编码器或解码策略改善。弯曲／二维文字还涉及检测和空间整形，不能把几何问题全部归因于 CTC。

CER 为字符级 `(替换+删除+插入)/GT字符数`；WER 类似但以词为单位。业务上还需要区分关键营销文字、小字和数字字段，不能以一个总体 CER 覆盖所有错误代价。

## 7. 软标签、序数学习、校准与选择性分类

硬标签指定一个类别；软标签是一组目标概率，可以来自人工分歧、教师输出或人为平滑，来源不同，解释不同。序数任务还应评价误差距离，普通 Accuracy 对错一档和错四档同样计错。

对固定 q、同一 p 和普通未加权损失：`CE(q,p)=H(q)+KL(q||p)`。同目标的两项相加不产生两套独立监督；不同 token／不同目标的 CE 与 KL 可以有不同作用。[CE 文档](https://docs.pytorch.org/docs/2.14/generated/torch.nn.CrossEntropyLoss.html)

期望评分 `Σk·p_k` 是把分布变成数值；校准关注置信度与实际正确频率是否一致。温度缩放等参数应在开发集拟合；ECE 受分桶方式影响，Brier score 在二分类中是预测概率与标签的平方误差均值。[校准研究](https://arxiv.org/abs/1706.04599)

选择性分类允许模型拒识或升级处理。要同时报告自动覆盖率、自动子集风险、升级成本和全系统结果；仅通过大幅缩小子集得到高 Precision，不足以证明业务价值。

## 8. RAG、重排、Memory 与 Agent

RAG：解析与切分 → 索引 → 检索 → 重排 → 上下文组装 → 带证据生成。Hybrid Search 组合精确关键词和语义召回，重排改候选顺序；RRF 是一种基于排名的融合方式，不要求原始分数同量纲。

评测按阶段拆：Recall@K 看正确证据是否进入候选，MRR 看首个相关结果的位置，nDCG 处理分级相关性与排名，生成阶段再看证据支持率、回答正确率和任务完成率。长上下文与检索可以组合使用，选型取决于成本、更新与覆盖。

长期记忆需要决定写什么、怎么更新、何时失效、怎样隔离与纠错。保存全部聊天向量不等于解决记忆管理，错误信息会污染后续回答。

Agent Loop：观察 → 规划／选动作 → 调工具 → 读结果 → 更新状态 → 决定继续或结束。重点准备工具 schema、超时与重试、幂等、错误恢复、执行结果验证、状态压缩和预算控制。

Agent 算法效果应比较任务成功率、步骤数、费用和失败类型；使用量只能说明产品采用情况。工具调用工程也不能直接证明做过 Agentic RL；后者需要轨迹、环境反馈、奖励和策略更新。

## 9. 图像生成：Flow Matching、DiT、CFG

Flow Matching 训练时间相关的向量场。对示例线性路径 `x_σ=(1−σ)x_data+σ·ε`，若以 σ 为时间变量，对应目标速度为 `ε−x_data`，可用预测速度与目标速度的平方误差训练；采样时沿约定方向积分。时间参数化改变时目标也要相应变化。[Flow Matching 原论文](https://arxiv.org/abs/2210.02747)

DiT 描述使用 Transformer 处理扩散相关建模的一类网络架构，Flow Matching 描述训练目标／路径框架，CFG 描述条件引导方式，三者是不同层面，不能直接当同类算法排序。[DiT 原论文](https://arxiv.org/abs/2212.09748)

CFG 的常见组合形式为 `v_guided=v_uncond+s(v_cond−v_uncond)`，对应实现需看具体模型。训练中可能通过条件丢弃支持无条件分支；更强引导可能提高条件遵循，也可能损害多样性或产生伪影，不能保证所有维度同时改善。[CFG 原论文](https://arxiv.org/abs/2207.12598)

参考图如何编码与拼接取决于实现；阅读过 Qwen-Image 的训练代码，应能画出文本／图像条件、VAE latent、带噪目标和 loss 的数据流。阅读代码不等于跑过微调实验。

生成评测需覆盖主体一致性、文字、局部结构、背景与业务可用性。VLM judge 要检查人机一致性、模型身份与顺序偏差、提示稳定性；多次生成是否挑最佳也必须统一。

## 10. 手写算法清单

### Quickselect：第 k 大

思路：将第 k 大转成升序下标 `n-k`；选 pivot 分区，只继续目标所在一侧。随机 pivot 的期望时间 O(n)，最坏 O(n²)；三路划分便于处理大量重复值。大小 k 的堆为 O(n log k)，更适合流式输入。

```text
校验 1 ≤ k ≤ n
target = n-k
循环处理 [left,right]：
  选 pivot
  分成 <pivot、=pivot、>pivot 三段
  target 在左段 → 缩小 right
  target 在右段 → 增大 left
  否则返回 pivot
```

练习边界：空数组、k=1/n、全相同、已排序、负数、重复值。求前 k 个有序结果时，选出集合后仍需对这 k 项排序。

### 其他高频题

| 类别 | 练习题 | 必须解释 |
|---|---|---|
| 堆 | TopK、合并 K 个有序链表 | 为什么只保存 k 个元素、堆顶含义 |
| 二分 | 第一个／最后一个满足条件的位置 | 区间约定、终止条件、单调性 |
| 双指针／窗口 | 最长不重复子串、最小覆盖 | 窗口不变量、计数维护 |
| 链表 | 反转、找环、合并 | 指针更新顺序和空节点 |
| 树与图 | 层序、最近公共祖先、拓扑排序 | 访问状态、环、递归深度 |
| 动态规划 | 编辑距离、最长公共子序列 | 状态含义、转移、边界、空间优化 |
| 数值实现 | 稳定 softmax、交叉熵 | 减去最大值、logsumexp、mask |
| PyTorch | Attention、LoRA、分类指标 | shape、dtype、梯度流与边界 |

## 11. 系统设计题与自测

## 13. 真实面试基础题：我的回答与更好回答

“我的回答”是已有文字记录的摘要；明确标为“现场原答未保留”的题目，不反推当时表现。“更好回答”用于复习，涉及项目实验时仍遵守已做／待做的边界。

### G01｜Transformer 整体结构？Decoder 交叉注意力的 Q/K/V 来自哪里？

**场次**：[美团][mt] Q1、Q5。

**我的回答**：现场原答未保留，现有文件为整理后的参考答案。

**更好回答**：原始 Transformer 包含 encoder 和 decoder。Encoder 层有双向自注意力与逐位置 FFN；decoder 层有因果自注意力、对 encoder 输出的交叉注意力与 FFN，各子层结合残差和归一化。交叉注意力的 Q 来自 decoder 当前隐状态，K/V 来自 encoder 输出，再各自经过线性投影。常见 decoder-only LLM 不包含原始 encoder-decoder 的这层交叉注意力，主要做因果自注意力；pre-norm／post-norm、RMSNorm 等是具体架构选择，不能混成原论文同一结构。[Transformer 原论文](https://arxiv.org/abs/1706.03762)

### G02｜QK 点积为什么除以 √dₖ？

**场次**：[美团][mt] Q4。

**我的回答**：现场原答未保留。

**更好回答**：若 q、k 的各维近似独立、均值 0、方差 1，则点积的方差约为 dₖ。维数越大，logit 尺度越大，softmax 更易饱和，梯度变小；除以 √dₖ 将尺度稳定到常数量级。这是基于简化统计假设的解释，不意味着训练中每维始终完全独立或单位方差。追问时写出 `Var(Σ qᵢkᵢ)=Σ Var(qᵢkᵢ)≈dₖ`。[Transformer 原论文](https://arxiv.org/abs/1706.03762)

### G03｜PPO、DPO、GRPO 有什么区别？

**场次**：[美团][mt] Q2。

**我的回答**：现场原答未保留。

**更好回答**：PPO 用采样轨迹和优势估计优化策略，核心有裁剪的代理目标，经典实现通常训练价值函数。奖励可以来自规则或模型，并非必须有奖励模型。DPO 用偏好对直接优化相对参考策略的偏好目标，常规离线形式不需要训练时在线 rollout。GRPO 对同一问题采样多个回答，用组内奖励形成相对优势，省去独立 critic；组内奖励完全相同就缺少相对区分信号。PPO 的 clip 是目标函数设计，**不是对每次参数更新后的概率比或 KL 的硬约束**。选择时看可用监督、奖励可靠性、探索需求与成本，不能只背方法缩写。[PPO](https://arxiv.org/abs/1707.06347)、[DPO](https://arxiv.org/abs/2305.18290)、[GRPO 来源论文](https://arxiv.org/abs/2402.03300)

### G04｜重要性采样解决什么问题？与 PPO 的关系？

**场次**：[美团][mt] Q6。

**我的回答**：现场原答未保留。

**更好回答**：想算目标分布 p 下的期望，却只有 q 的样本时，可用 `E_p[f(x)] = E_q[(p(x)/q(x))f(x)]`；前提是 p 有质量的区域 q 也必须覆盖。比值过大会使方差很高。PPO 用新旧策略的动作概率比构造代理目标，复用旧策略采集的数据，并用裁剪抑制过大的更新激励。不能把 token 级比值称作完整新策略轨迹回报的无偏估计，因为还涉及状态访问分布；裁剪也引入了偏差。这是偏差、方差和训练稳定性的取舍。[PPO 原论文](https://arxiv.org/abs/1707.06347)

### G05｜何时 SFT，何时 RL？有规则奖励为何不直接 SFT？

**场次**：[字节风控，2026-09-25][bf] Q13；[美团][mt] Q3；[字节巨量星图][xl] Q8。

**我的回答**：字节时先说固定标准答案用 SFT、复杂非唯一答案用 RL；追问后提到 teacher forcing、自己的错误前缀，并把 DPO 也归入解决这一问题。另两份文件没有现场原答。

**更好回答**：SFT 利用示范序列，优化目标 token 的似然；RL 让策略生成结果并根据奖励优化期望回报。有标准答案的数学或代码任务也能用 RL，因为验证结果可能比提供最佳生成轨迹更容易。RL 可以接触自己的采样前缀，但不保证消除分布偏移；离线 DPO 也不天然解决这个问题。工程上先用 SFT 建立任务格式和基本能力，再判断可靠奖励与探索是否能带来额外收益。Guard 没有做 SFT／RL 对照，所以目前只能讲采用动机和补做设计，不能声称 RL 必然优于加权 SFT 或阈值调整。[DPO 原论文](https://arxiv.org/abs/2305.18290)

### G06｜LayerNorm 和 BatchNorm 区别、使用场景？

**场次**：[美团][mt] Q9。

**我的回答**：现场原答未保留。

**更好回答**：对 `[B,T,D]` 的常见 Transformer 表示，LayerNorm 通常对每个 token 的 D 维特征计算均值和方差；对 `[N,C,H,W]`，BatchNorm2d 通常按通道在 N/H/W 上统计。BN 默认在训练时使用当前批统计并更新 running statistics，推理时使用累积统计；LN 在训练和推理时都从当前输入的被归一化维度计算统计量。LN 不依赖 batch 中其他样本，适合可变长序列和小 batch。具体统计轴、affine 参数和 BN 的 `track_running_stats` 配置要讲清，不能把默认行为说成所有实现都一样。[PyTorch LayerNorm](https://docs.pytorch.org/docs/stable/generated/torch.nn.LayerNorm.html)、[BatchNorm2d](https://docs.pytorch.org/docs/stable/generated/torch.nn.BatchNorm2d.html)

### G07｜如何评估 SFT 后的遗忘？如何缓解？

**场次**：[字节风控，2026-09-25][bf] Q10，承接 Q7。

**我的回答**：主要回答了缓解：在分布上加 KL 约束或限制参数变化；漏答“怎么评估”。

**更好回答**：先固定基座和训练后 checkpoint、提示模板、解码与评测集，分别测主任务和与部署相关的通用能力，按类别报告分数变化与不确定性；检查是否只在特定长尾或正常输入上退化。能力下降要用任务表现证明，参数距离或表征相似度只能辅助诊断。若确认遗忘，再比较低学习率、早停、冻结部分参数、混入通用回放样本或参考模型约束，观察主任务与通用能力的取舍。我尚未完成系统回归评估，因此不能说通用能力没有退化，也不能把候选缓解措施当作已实施。

### G08｜LoRA 的矩阵形状、参数量和节省比例？

**场次**：[字节风控，2026-09-25][bf] Q11。

**我的回答**：维度表述卡顿后，答出了方阵节省参数量 `d²−2dr`。

**更好回答**：对 `W∈R^(d_out×d_in)`，冻结 W，训练 `A∈R^(r×d_in)`、`B∈R^(d_out×r)`，增量 `ΔW=(α/r)BA`。可训练参数从 `d_out·d_in` 降至 `r(d_in+d_out)`；方阵为 `2dr`，占全参的 `2r/d`，节省比例为 `1−2r/d`。例如 d=4096、r=8，可训练 65,536 个，占原矩阵约 0.3906%。这只是该线性层的可训练参数，基座权重仍须加载，激活等内存也不会按这个比例全部消失。[LoRA 原论文](https://arxiv.org/abs/2106.09685)

### G09｜LoRA 微调后怎么部署？

**场次**：[字节风控，2026-09-25][bf] Q12。

**我的回答**：描述为保存原参数、需要时把 LoRA 插到一层，未说明合并与动态加载的差异。

**更好回答**：固定单任务可以把 `W+(α/r)BA` 合并成部署权重，减少额外低秩分支；多任务或多租户可以共享基座、按请求选择 adapter，但要考虑计算、显存、批处理和切换开销。量化基座的合并需要处理精度与再量化误差，不能认为直接相加永远无损。部署前核对基座版本、target modules、rank、scale 和 tokenizer，并比较合并前后输出及吞吐。是否已用某种 serving 框架，以实际部署为准。[LoRA 原论文](https://arxiv.org/abs/2106.09685)

### G10｜13B 权重多大？4096 隐藏维、40 层、FP16，KV Cache 多大？

**场次**：[腾讯光子，2026-09-14][gz] Q8–Q10。

**我的回答**：KV Cache 回答成“1014×3096”等错误维度，对权重与单 token／整段序列的关系也没说清。

**更好回答**：先问是否 MHA、batch 和序列长度。KV Cache 通式为 `B×T×L×2×n_kv_heads×d_head×bytes`，GQA／MQA 必须使用 KV 头数，不能无条件使用隐藏维。按题设额外假设 MHA、`n_heads×d_head=4096`、B=1：

| 对象 | 计算 | 结果 |
|---|---|---|
| 单 token、单层 KV | `2×4096×2` | 16,384 B = 16 KiB |
| 单 token、40 层 KV | `40×16,384` | 655,360 B = 640 KiB |
| 2048 tokens、40 层 KV | `2048×655,360` | 1,342,177,280 B = **1.25 GiB**，约 1.342 GB |
| 13B FP16 模型权重 | `13×10⁹×2` | **26 GB**，约 24.21 GiB |

权重与 KV 是不同部分，还要加运行时临时张量等开销。常见混合精度 Adam 的粗估可能达到每参数 16 bytes（权重、梯度、主权重、优化器状态合计），13B 约 208 GB，但具体实现可不同，且还未包含激活；不要把 16 bytes 全叫“优化器状态”。原复盘中的 1.28 GB 混用了单位。[GQA 原论文](https://arxiv.org/abs/2305.13245)、[ZeRO 显存组成论文](https://arxiv.org/abs/1910.02054)

### G11｜CTC 怎样解决可变长度输出？

**场次**：[字节风控，2026-09-25][bf] Q14。

**我的回答**：项目使用传统 OCR，但 CTC 没太接触，未答出机制。

**更好回答**：模型输出 T 个时间步的字符分布，字符表增加 blank。CTC 对所有能折叠成目标字符串的路径概率求和，以负对数似然训练；动态规划避免枚举路径。折叠时先合并相邻重复字符，再去 blank。例：`aa-bb- → ab`，但 `a-ab- → aab`，中间 blank 让两个 a 保留下来。输出长度可以小于 T，无需逐帧对齐标注；目标有相邻重复字符时还需要额外 blank 时间步，因此不只是简单的 T≥目标长度。贪心逐帧解码易实现，但不保证得到概率最大的标签序列。[原始 CTC 论文](https://www.cs.toronto.edu/~graves/icml_2006.pdf)

### G12｜Qwen3-VL 的架构与 DeepStack？

**场次**：[字节风控，2026-09-25][bf] Q15。

**我的回答**：不了解 DeepStack；面试官给出类似视觉特征金字塔的提示后仍没展开。

**更好回答**：先讲视觉编码器提取图像／视频特征，再转换到语言模型可处理的表示，与文本共同进入多模态推理。DeepStack 利用视觉编码器不同层级的特征，把它们注入语言模型的相应层，让模型能使用多层次视觉信息。这里的“多层”不能复述成“每一层都注入”，也不能等同于经典 FPN。实际注入位置、层数、张量形状和视频位置编码应结合本人训练的 checkpoint 配置及 forward 代码确认。我使用模型后训练，不意味着我实现或验证了架构创新；尚无个人 DeepStack 消融结果。[Qwen3-VL 官方仓库](https://github.com/QwenLM/Qwen3-VL)

### G13｜什么是数据泄漏？你的项目可能哪里泄漏？

**场次**：[09-14 风控一面，公司待核实][fk] Q8；[虾皮一面补充笔记][sp] 同题。

**我的回答**：主要说测试数据进入训练，以及使用未来时间的信息；补充笔记只有参考答案，没有独立现场回答。原场次的 90%／10% 说法与 Q4 的 75%／25% 还存在口径冲突。

**更好回答**：泄漏是训练或评估利用了部署预测时不该获得的信息，导致结果虚高。文书项目要检查同一文书／模板／机构的近重复跨集合、增强图和原图分散、预处理在全量数据拟合、用测试结果反复调阈值，以及把事后业务状态作为预测特征。先按部署目标选择时间／机构／文书组切分，再仅在训练集拟合处理步骤，验证集调参，最终测试集保留。时间外验证需要明确时间边界；历史文件并不天然是 OOT。切分比例不是泄漏防护的核心，独立性与预测时可得性才是。[scikit-learn 数据泄漏说明](https://scikit-learn.org/stable/common_pitfalls.html#data-leakage)

### G14｜正则化是什么？L1、L2 为什么效果不同？

### G20｜球约束下最小化损失，如何写 KKT？如何投影？

**场次**：[京东零售][jd] Q2。

### G24｜SQL WHERE 与 HAVING 区别？

### G27｜Top-K／第 K 大：堆还是 Quickselect？现场如何写完整？

**场次**：[京东零售][jd] Q5；[字节风控，2026-09-25][bf] Coding。

**我的回答**：京东现场原答未保留；字节时能说快速划分思路，但 C++／Python 写法混用，没写出可运行的完整实现。

**更好回答**：先确认要第 K 大还是 K 个最大值、结果是否有序、是否允许修改输入。流式数据可维护大小 K 的小根堆，时间 O(n log K)、空间 O(K)；数组可 Quickselect，期望 O(n)、最坏 O(n²)，如果还要求 Top-K 内部有序，需再付出 O(K log K)。下例求**第 K 大**，就地修改数组，使用真正的三路划分处理重复元素：

```python
import random

def kth_largest(nums, k):
    if not 1 <= k <= len(nums):
        raise ValueError("k out of range")
    target = len(nums) - k  # 升序下标
    left, right = 0, len(nums) - 1
    while left <= right:
        pivot = nums[random.randint(left, right)]
        lt, i, gt = left, left, right
        while i <= gt:
            if nums[i] < pivot:
                nums[lt], nums[i] = nums[i], nums[lt]
                lt += 1
                i += 1
            elif nums[i] > pivot:
                nums[i], nums[gt] = nums[gt], nums[i]
                gt -= 1  # 换过来的值还未检查，i 不动
            else:
                i += 1
        if target < lt:
            right = lt - 1
        elif target > gt:
            left = gt + 1
        else:
            return nums[target]
```

不变量：`[left,lt)` 小于 pivot，`[lt,i)` 等于 pivot，`(gt,right]` 大于 pivot，中间尚未检查。迭代版辅助空间 O(1)，不含调用者为保留输入而自行复制的数组。讲边界时覆盖 k=1、k=n、全相等、重复值和非法 k。原复盘代码是两路划分，却在描述中称三路，此处已统一。

### G28｜两个有序数组原地合并，为什么从尾部写？

**场次**：[09-14 风控一面，公司待核实][fk] Q19。

**我的回答**：从头部维护最小集合、逐个交换，最后没完成可运行代码。

**更好回答**：先确认 a 已有 m 个有效元素，尾部还有 n 个可写空位，b 有 n 个元素，二者均升序。倒序比较未处理部分的最大值，写入 a 的最右空位，避免覆盖 a 尚未读取的内容。

```python
def merge_sorted(a, m, b, n):
    i, j, write = m - 1, n - 1, m + n - 1
    while j >= 0:
        if i >= 0 and a[i] > b[j]:
            a[write] = a[i]
            i -= 1
        else:
            a[write] = b[j]
            j -= 1
        write -= 1
    return a
```

时间 O(m+n)，额外空间 O(1)。b 耗尽后 a 剩余元素已在正确位置；a 耗尽后继续复制 b。若 a 没有预留容量，先说明输出空间条件变化，不能直接套用同一原地空间结论。

### G29｜最大连续子数组和，如何处理全负数？

**场次**：[京东零售][jd] Q6。

**我的回答**：现场原答未保留。

**更好回答**：令 ending 为“必须以当前位置结束”的最大非空子数组和，则 `ending=max(x,ending+x)`；全局 best 取历次最大值。初始化为首元素，不能设成 0，否则全负输入会错误选择空区间。

```python
def max_subarray(nums):
    if not nums:
        raise ValueError("non-empty subarray required")
    ending = best = nums[0]
    for i in range(1, len(nums)):
        ending = max(nums[i], ending + nums[i])
        best = max(best, ending)
    return best
```

### G30｜先非递减再非递增的数组，求不同元素个数，O(1) 空间？

**场次**：[字节巨量星图][xl] Q10。

**我的回答**：现场原答未保留；现有记录整理了双指针参考思路。

**更好回答**：先确认数组只有一个峰，允许相等。剩余区间仍是单峰，最小值必在两端之一；每轮取两端较小值，只计一次，从左右两边跳过所有该值，再处理下一种值。这样同一值在上升侧和下降侧出现也不会重复统计。

```python
def count_distinct_bitonic(nums):
    left, right, count = 0, len(nums) - 1, 0
    while left <= right:
        value = min(nums[left], nums[right])
        count += 1
        while left <= right and nums[left] == value:
            left += 1
        while left <= right and nums[right] == value:
            right -= 1
    return count
```

两指针各只向内移动，时间 O(n)、辅助空间 O(1)；纯单调、平台峰、空数组也适用。若输入可有多个峰，这个不变量不成立，需使用其他方法。

### G32｜最长连续区间中，低分占比不超过 P%，怎么求？

**场次**：[腾讯微信支付风控，2026-09-16][wx] Coding，原记录保留三轮提示。

**我的回答**：需要面试官依次提示不等式变换、前缀和、候选剪枝／单调与二分，独立建模不熟练。

**更好回答**：先按**本题**定义：1／2 分为低分；这与文书项目中 4／5 档为差档的方向不同。目标是非空连续区间低分占比 ≤P%，无解返回 0。定义 `badᵢ=1[scoreᵢ≤2]`，把约束变成：

`100×Σbadᵢ ≤ P×区间长度`，即 `Σ(100×badᵢ−P)≤0`。

令这些权重的前缀和为 S，则找最大 `j−i`，满足 `i<j` 且 `S[j]≤S[i]`。不能直接用普通滑窗，因为左右移动对约束不具有所需单调性。一个 O(n log n) 答法是维护前缀最大值及其最早位置并二分；进一步可以使用 O(n) 单调栈：

1. 从左到右，只保留 S 严格递增的新高位置作为左端候选。被舍弃的位置，其更早且不小的前缀值能产生至少同样可行、更长的区间。
2. 从右到左枚举 j；只要栈顶 i 满足 `S[i]≥S[j]`，就更新答案并弹出。该 i 第一次匹配到的就是其最远可行右端。

```python
def longest_low_score_ratio(scores, percent):
    # percent 为 0..100 的整数，避免浮点比较误差
    if not isinstance(percent, int) or not 0 <= percent <= 100:
        raise ValueError("percent must be an integer in [0, 100]")
    prefix = [0]
    for score in scores:
        prefix.append(prefix[-1] + (100 if score <= 2 else 0) - percent)

    candidates = []
    for i in range(len(scores)):  # 左端前缀，最大为 n-1
        if not candidates or prefix[i] > prefix[candidates[-1]]:
            candidates.append(i)

    best = 0
    for j in range(len(scores), 0, -1):
        while candidates and candidates[-1] >= j:
            candidates.pop()  # 不满足非空区间 i<j
        while candidates and prefix[candidates[-1]] >= prefix[j]:
            best = max(best, j - candidates.pop())
    return best
```

每个下标最多入栈、出栈一次，时间 O(n)、空间 O(n)。边界：P=100 时所有分数合法；P=0 时寻找最长无低分区间；全是低分且 P<100 时无非空解；空输入返回 0。若 P 是小数，应按题目给定精度统一放大为整数或使用精确有理数。

### G33｜没有游戏项目经验，如何设计挂机／消极游戏识别？

**更好回答**：先说明没有实际游戏项目经验，再给方案。定义可标注的行为事件，区分断线、挂机、消极操作和普通低水平表现，不能凭输赢或低分判定恶意。先用移动、操作频率、离队时长等低成本时序特征建立规则／树模型基线，结合角色、局势和网络状态减少误伤；复杂争议样本再考虑序列模型或多模态复核。举报只是有偏反馈，需人工标注与申诉样本。数据按玩家／对局及时间切分，评估 Precision、漏检、误罚成本和延迟，先影子运行再分级处置。大模型调用频率由预算和实际增益决定，不直接把每几秒调用一次当作可行性证明。
