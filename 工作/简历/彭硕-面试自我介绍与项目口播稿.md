## 2. 三分钟版（技术面 / 主管面，重点讲）

### 第一段｜我是谁 + 能力主线（约 40 秒）

我叫彭硕，华科网安 27 届硕士，本科厦大网安，专业第一。

技术上的话，PyTorch、Transformers、DeepSpeed、vLLM、ms-swift 这些都熟，主要做的是 LLM/VLM 的 SFT 和 RL 后训练。不过我更想先说一下我这三段实习的关系，因为它是有一条线的：

- 京东 AI 安全那段，解决的是**"怎么把模型训出来"**——89 万条多模态 SFT 数据、Qwen3-VL 全参数微调、GDPO 强化学习；
- 京东零售 AIGC 那段，变成**"怎么造可靠的数据、怎么评模型"**——OCR 选型、生成效果 Benchmark；
- 到腾讯风控这段，就变成**"怎么让模型真正变成稳定的业务能力"**了。因为司法场景有个很硬的约束：**误拦一条真实请求，代价比放过一条存疑数据高得多。**

### 第二段｜腾讯项目主推：文书清晰度五级评估（约 90 秒）

**（背景）**腾讯这段我独立负责的是法院、公安传过来的查询和冻结文件，里面有模糊的、没盖章的、类型不合规的、电话号码脏的，日均大概 40 万条。约束是快、便宜、不能有幻觉、不能误拦。

**（问题）**我先讲最有代表性的一个：文书清晰度。原来是一个 569 维特征的 XGBoost 二分类，只输出清晰或模糊两档。它的问题不是说不准，而是**两档本身不够用**：第一，它的分数不符合真实数据的分布；第二，颗粒度太粗，业务没法自己选松紧尺度；第三，卡在边界上的样本特别容易误判。

我去翻了数据分布，发现这个分数是**双峰**的——清晰样本全挤在 0.05 到 1，模糊样本挤在 90 到 99，中间几乎是空的，而且分数跟人眼看到的模糊程度并不单调。

**（关键判断）**所以我当时的判断是：**这不是阈值或概率校准的问题，是任务定义的问题**。二分类损失只要求模型学"清晰和模糊的边界"，没要求它学"同一类里谁更严重"。你再怎么做 Platt Scaling、Isotonic Regression，也只是重新映射已有信息，变不出中间三档的序数结构。所以我就没继续调阈值了，回去重定义任务。

**（为什么是五档）**这里要说清楚：**训练我做的是五分类，但业务最终落地的判定还是"拒绝 / 不拒绝"两类。** 做五档不是为了多输出几档给业务看，而是因为只有把中间这段灰度显性建模出来，业务才能按自己的风险偏好选切分点——今天想严一点就切在 3，想松一点就切在 4，不用我重新训模型。同时档位之间有明确的序关系，边界样本的误判也少了很多。

**（怎么做的）**我把清晰度拆成两个维度：一个是**不可辨文字比例**，决定严重的三档；一个是**可辨区域的锐度**，区分最好的两档。这样能分开两种本质不同的情况——一种是全文轻微发虚但都读得出来，另一种是整体看着还行、但关键信息已经彻底糊了。这两种在业务上完全不是一回事。

数据上我用 OCR 行置信度、文本框面积、拉普拉斯锐度，加上排除红章，做规则预标注，然后自己写了个可视化标注平台做人工复核，拿到 1.3 万张确认图。

这里有个细节：**规则预标注在小字、小众字体、手写体上不准**，所以我用评分的均值和方差去拟合质量分布，构造了五维软标签。原因是 2 档和 3 档之间本来就模糊，用 one-hot 会把相邻档位的轻微分歧当成完全错误。

模型用 Qwen3.5-9B 做 LoRA SFT，把输出限制在五个等级 token 上，closed-set softmax 出分布，CE + KL 联合训练，推理时取概率期望做校准。最后落回业务的时候，取后两档判为模糊、走拒绝，其余通过，所以出口还是两类。当前后两档占比 3.57%，抽检 Precision 100%，零误拦。

### 第三段｜另外两个快速带过（约 40 秒）

还有两个我简单说：

**无印章识别**，难在负样本只占 2%、浅色章漏检。我融合了三路版面/印章检测模型，加上 HSV 红色分割，做成有/无/不确定的三分类，不确定的先切 8 块放大、还不行再交给 VLM 复核。高置信子集 Precision 100%、Recall 98.9%，主链路参数不到 100M，单图不到 1 秒。

**文书类型识别**是 OCR 幻觉、页面旋转、多图横排错序。我用 DBNet + LCNet 做方向检测和标题定位，再叠三层鲁棒匹配——繁简归一化、随长度变化的编辑距离、锚点顺序匹配。准确率从 94.59% 提到 99.99%，单条 0.28 秒。

### 第四段｜收尾（约 20 秒）

这几件事做完，整体拦截率从 4.33% 提到 9.84%，日均拦 3.8 万条。

我自己总结成一句话：**技术路线应该由错误风险、数据吞吐、输出确定性和长尾复杂度一起决定，不是所有问题都该上大模型。**像电话号码校验那个任务，规则可枚举、吞吐又高，我就用正则加地理库，没上模型。

## 2.5 京东 AI 安全部｜可展开版（约 100 秒）

> **什么时候讲**：面试官说"讲讲你在京东那段"、或者"讲一个后训练 / 数据相关的项目"、或者"讲一个你最有成就感的"。如果面试官明确是冲着多模态后训练岗来的，**这段优先级甚至高于腾讯那段**——因为它离岗位 JD 最近。

### 背景（15 秒）

京东 AI 安全部这段是给京东的 AI 对话功能做**多模态安全护栏**，用户发图文过来，要判断有没有涉政、色情、暴力这类风险。我主要负责三块：**风险数据怎么造、审核模型怎么训、以及一个合规数字人智能体**。我重点讲前两块。

### 第一块：89 万条数据是怎么造出来的（40 秒）

**（问题）**最大的挑战其实不在模型，在数据。风险样本天然稀疏、标注又主观，而且**用大模型打标本身就有噪声**——你让 Qwen 标一遍就信它，等于把模型的偏见原封不动喂给下一个模型。

**（冷启动）**我分两步。第一步是冷启动标注：业务数据、开源数据、合成数据先汇总，用 Qwen3-VL-235B 加上多模型投票和规则过滤，把初始标签打出来。

**（降噪——这段是亮点，讲慢一点）**第二步是降噪，这个我觉得是最有意思的。我把数据切成**两个互斥子集**，分别在上面用正负样本重采样训两个模型——一个偏宽松、一个偏严格；然后拿 A 模型去标 B 的数据、B 模型去标 A 的数据，交叉标完再投票聚合。

这里的关键是：**两个模型是在互不相交的数据上训的，如果它们还同时犯错，那大概率不是模型的问题，是这个样本本身就有问题。**争议样本就这么被自动捞出来了。这比"一个大模型自己标、再自己信自己"要可靠得多。

**（形态扩充）**然后我用关键词引导合成加正负样本对照增强，扩出多轮图文对话、单轮图文对、单图这些不同形态，一共产出 89 万条 SFT 数据，覆盖几十类风险场景，而且带**多模态 COT 推理过程**——就是让模型先把判断依据说出来再给结论，这样线上可解释性也好做。

### 第二块：SFT + GDPO 后训练（35 秒）

训练侧我先搭了一个统一的**多轮多模态审核框架**，对 Qwen3-VL 模型组做全参数微调，靠显存管理和混合精度把大规模分布式训练跑起来。数据增强主要是提升指令遵循和灵活性——因为业务策略会变，模型不能只认一种 prompt。

SFT 之后上 GDPO 做多目标强化。这里的核心痛点是**奖励坍塌**：我们要同时优化风险拦截、误杀惩罚、格式遵循三个目标，直接加权求和的话，模型会找捷径——比如为了保拦截率干脆什么都拦，或者为了拿格式分输出一堆废话。GDPO 的做法是把几个奖励的**归一化过程解耦**，各自归一完再聚合，避免某个量纲大的奖励把其他目标全盖掉。最后高风险类目 F1 保持 85% 以上，同时**过度拒绝率降了 37%**。

### 第三块：数字人 Agent（10 秒，一句话带过）

另外还从 0 到 1 做了一个合规数字人智能体，给 CCO 几十个部门用，做政务问答、新闻推送、公文写作、DeepResearch，累计调用 3 万多次。这里主要解决的是**长尾政务知识的幻觉**，用混合检索加重排的两阶段召回，加上长期记忆做跨会话上下文。

### 收尾关联（5 秒）

这段和腾讯那段其实是一脉相承的——**都是在错误代价不对称的场景下做决策**，只不过京东是内容安全，腾讯是司法风控。区别是京东这段我在做"怎么把模型训出来"，腾讯那段在做"怎么让模型变成业务敢用的能力"。

## 3. 高频追问的口语答法

**Q：为什么不直接用一个大模型端到端全做了？**
三个原因。第一是成本，VL 单条要 12.6 秒，OCR 规则路径 0.28 秒，40 万条的量级差两个数量级；第二是确定性，规则能枚举的场景，硬约束比模型概率可靠；第三也是最重要的，误拦成本不对称，司法场景里大模型偶发的幻觉是不可接受的。我的原则是让 AI 待在三个位置：**快速验证候选、处理高信息增益的难例、把人工反馈沉淀成系统能力**。

**Q：Precision 100%，是不是数据太简单 / 是不是过拟合？**
（**这题要诚实，别硬撑**）这个 100% 是有前提的：它是**高置信子集**上最新万条抽检的结果，不是全量全时段。而且这个数字是我那套"只自动处理高置信、不确定就升级"的策略的产物，不完全是模型本身的能力。真要说模型本身的泛化，我还在补独立测试集上的 QWK、MAE、Macro-F1 和概率校准。

**Q：既然最终还是"拒绝/不拒绝"两类，那做五分类的意义是什么？**
（**必考题，一定要答出"业务可调"这一层**）意义有两个。第一是**给业务一个可调的尺度**：二分类只有一个切点，业务想松想紧都得我重训模型；五档把中间灰度显性表达出来了，今天想严就切在 3、想松就切在 4，改的是配置不是模型。第二是**中间档的监督信号反过来让两端更准**：二分类只学边界，边界样本最容易误判，加了序数结构之后模型对"谁更严重"有了排序能力，落在 4、5 档的判断反而更稳。所以五分类是训练侧的建模选择，两类是业务侧的判定出口，这两件事不矛盾。

**Q：软标签具体怎么构造的？为什么不用 one-hot？**
先对每个样本用规则特征算出一个质量分，再用均值和方差拟合出一个五维分布，相邻档位给相邻的概率。不用 one-hot 是因为 2、3 档的边界本身就有争议，one-hot 会把"标 2 还是 3"的轻微分歧当成完全错误，模型会去拟合标注噪声。

**Q：京东那段 GDPO 讲一下？**
多模态审核要同时优化好几个目标——风险要拦住、正常内容不能误杀、输出格式还得遵循。直接加权会有奖励坍塌的问题。GDPO 的做法是把这几个奖励模型的归一化过程解耦开，各自归一再聚合。最后高风险拦截率 F1 保持 85% 以上，过度拒绝率降了 37%。

**Q：奖励坍塌具体是什么表现？为什么不直接调权重？**
表现就是模型会走捷径。我们最初直接加权的时候，模型发现"什么都判风险"最安全，拦截率上去了但正常内容全被误杀；加了误杀惩罚之后它又变成输出很长很空的解释去刷格式分。调权重我们试过，问题是这几个奖励的**量纲和方差不一样**，而且训练过程中分布还在变，手工定的权重很快就失效了——本质上是你在用一个静态系数去追一个动态分布。解耦归一化之后，每个奖励先各自压缩到可比区间再聚合，模型就没法靠刷某一个目标走捷径了。

**Q：89 万条数据，你怎么保证标签是准的？**
三层。第一层是初始标注用 **Qwen3-VL-235B + 多模型投票 + 规则过滤**，不依赖单一模型；第二层是**互斥子集交叉标注**——两个模型在互不相交的数据上训练，再交叉去标对方的数据，同时出错的样本基本就是标签本身有问题的，捞出来单独处理；第三层是**正负样本重采样刻意造出宽松/严格两种倾向**，让分歧显性化，而不是被一个"平均"的模型抹平。争议样本不是丢掉，是拿来定向补数据的。

**Q：为什么一定要带 COT 推理过程？**
两个原因。一是**可解释性**——安全审核的结论是要能申诉、能复盘、能给人审看的，只给一个"风险/安全"的标签，业务没法判断该不该信。二是**训练信号密度**——直接监督一个二分类标签，一条数据只提供一个 bit 的梯度信号；让模型先写判断依据再给结论，等于把专家的决策路径也监督进去了，数据效率高一截。

**Q：数字人 Agent 那段你具体做了什么？**
从 0 到 1 落地，给 CCO 几十个部门用。技术上我觉得值一提的是三点：一是知识问答用 **Hybrid Search + Re-ranking 两阶段召回**，因为政务知识长尾特别严重，纯向量检索会一本正经地编；二是**长期记忆**，把历史会话向量化存起来，跨会话保持上下文；三是 DeepResearch 接了小红书、知乎、B站，能解析图片和视频。最后累计调用 3 万多次。

**Q：京东安全和腾讯风控这两段，你觉得最大的区别是什么？**
京东是**内容安全**，腾讯是**司法风控**，共同点是错误代价都不对称。区别在约束：京东的侧重点是"在保住拦截率的前提下别过度拒绝"，所以我用 RL 去解多目标；腾讯的侧重点是"宁可放过也不能误拦"，且吞吐到了日均 40 万条，逼着我必须做成本分层——能用规则的绝不上模型，能快路径的绝不走 VL。前者是**把模型训好**，后者是**决定在哪用模型**。

**Q：京东零售那段你最大的产出是什么？**
我觉得是评测体系。生成模型的"好不好"很主观，我把服饰、家居扩图拆成主体保真、营销文字、背景衔接、结构透视 14 项原子指标，做成结构化评测。最后内部模型可用率比 Nano Banana Pro 高 7 个点、比 Seedream-5.0-lite 高 12 个点，这才让"选型"这件事有依据。另外 OCR 选型那块，我把推理成本降了两个数量级，接入了几十万级的数据清洗链路。

**Q：讲一个你失败 / 踩坑的经历？**
（**送分题，主动说**）清晰度模型训练时 eval loss 在 step 1200 到最低 0.0757，然后一路涨了 56%，train loss 都快到 0.01 了，典型的过拟合。这个结果反而帮我定位了问题——主要矛盾不是模型拟合能力不够，是数据长尾和标签边界。所以我后面不再堆 epoch 了，改用最佳 checkpoint，补序数评测指标。还有个教训是前期探索不够聚焦，后面应该先建假设树和停止条件。

**Q：你本科是网安，为什么转算法？**
（**按你的两个安全项目接**）其实我没完全转，是安全背景 + 算法结合。华为那个 WebAssembly 性能优化发在 ISSTA（CCF-A），虹服那边我做的 LLM Multi-Agent 自动化渗透测试，还拿了 CVE 编号。这两个让我比较早就在跟模型和 Agent 打交道，后面做多模态安全审核其实是一条很自然的延伸。

## 4. 口径红线（说之前先在心里过一遍）

1. **100% 是高置信子集抽检结果**，别讲成"模型precision 100%"。
2. **日均 3.8 万条是线性估算**（样本比例 × 日均 40 万），不是线上实测去重值。
3. 四类问题有重叠，**3.54 万是分项理论和，不是去重拦截量**。
4. 清晰度 Level 4/5 的 3.57% 占比来自训练集分布，**需要线上自然分布再验证**。
