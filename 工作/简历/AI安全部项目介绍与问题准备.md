## 2. 一分钟项目介绍

> 我在京东 AI 安全部主要做多模态安全模型和企业合规智能体。安全模型面向图文及多轮对话审核，难点是隐晦风险漏判和正常内容误判同时存在，而且自动标注本身有噪声。
>
> 数据侧，我负责风险数据构建相关链路，整合业务、开源与合成样本，通过大参数 VLM、多模型投票和规则校验获取初始标签，再利用互斥子集上的交叉标注定位争议样本，管线产出约 89 万条多模态 SFT 数据。训练侧基于 Qwen3-VL 做 SFT，并引入 GDPO 联合考虑风险判断、正常内容误判和输出格式。
>
> 智能体侧主要做混合检索、重排和长期记忆，支持政务问答与资讯推送。这段经历让我更重视标签标准、错误代价和模型输出的可验证性。

被问 RL 增益时直接补充：“当时没有做完整的 SFT／RL 对照，所以我能说明采用的方法和实现，但目前无法把收益单独归因给 RL。若补实验，我会先比较 SFT、难例继续 SFT 与 GDPO，再比较 GDPO 与 GRPO。”

## 3. 数据链路与技术判断

```text
业务 / 开源 / 合成数据
  → 格式统一、图像有效性检查、去重
  → 教师 VLM 初始标注 + 多模型投票 + 规则校验
  → 在互斥子集上训练、交叉预测
  → 一致样本与争议样本分桶、复核
  → 正负对照与多轮图文扩展
  → 版本化训练数据
```

**为什么交叉标注？** 在一部分数据上训练、对另一部分预测，可以减少直接在训练样本上回标的记忆偏差。仍需按图片来源、会话、模板或近重复组隔离；互斥行号不能保证不存在内容泄漏。

**两个模型都判断一致，就一定是真值吗？** 不一定。相同教师、相似训练分布可能产生相关错误；分歧也是待核查信号，不等于“原标签一定错”或“样本必然争议”。需要人工参照集与按风险类别抽检。

**宽松／严格怎么定义？** 以独立开发集上的风险召回和正常样本误拦表现定义，不凭训练样本配比直接命名。样本比例、损失权重与阈值均可能改变决策倾向；先确认实际采用的办法。

**推理过程数据有什么作用？** 可提供更细的判断依据监督，但生成解释未必忠实，也可能含标签泄漏。若未做“仅标签 vs 标签＋解释”对照，不能宣称推理数据已经提高泛化。线上优先输出可核对的证据、风险类别和处置结果。

**“高质量”如何验证？** 保存每阶段输入／保留量，按来源、类别、难度抽检标签，统计分歧率与错误类型；再在相同训练预算下比较数据版本。数据量与质量分别报告。

### Qwen3Guard 阅读参考

公开报告介绍了自动标注、交叉训练预测、争议标签构建和标签蒸馏。可以借鉴其将边界分歧纳入数据处理的思路；这些是论文方法，具体模型尺寸、配比、实验收益不能自动当成本项目事实。推理时把争议类映射为安全或风险，也与修改整个安全政策定义不同。[Qwen3Guard 原文](https://arxiv.org/html/2510.14276v1)

原材料中“两个模型同时出错说明样本有问题”“训练集上预测必然高置信”“Safe 富集一定更严格”等绝对说法，不再作为标准答案。

## 4. SFT 与 GDPO 应准备到什么深度

### SFT 配置卡：按实际配置填写

| 字段 | 当前可说 / 待补 |
|---|---|
| 模型 | Qwen3-VL；具体尺寸、版本、初始 checkpoint 待核对 |
| 训练范围 | 旧稿称全参数；视觉编码器、连接层、LLM 各自冻结情况待核对 |
| 实际入训数据 | 不直接把 89 万管线产出全部视为入训量；补训练／验证规模及来源比例 |
| 框架和并行 | 具体 ms-swift／DeepSpeed 等版本、ZeRO stage、卡型卡数待核对 |
| 长度与批量 | 图像 token 上限、文本长度、packing、梯度累积、global batch 待核对 |
| 优化器 | 学习率、warmup、epoch、精度、checkpoint 选择依据待核对 |
| RL | prompt 数、每组生成数、温度、最大响应长度、KL 系数、奖励权重待核对 |

**为什么用 RL？** 它允许用完整输出上的反馈调整策略；是否比增加难例、改类别权重或调阈值划算，需要实验。SFT 也可以加入类别权重和多任务监督，不能说它“无法表达多目标”。

**GDPO 与 GRPO 的关键区别？** 在多奖励设定下，典型聚合方式先加权奖励再做组内归一化；GDPO 对各奖励分量分别做组内归一化再聚合，官方实现还包含后续批次归一化。论文关注不同奖励组合映射到相同优势值导致的训练信号分辨率损失。尺度差异、reward hacking 和策略退化是相关但不同的问题。[GDPO 论文](https://arxiv.org/abs/2601.05242)、[官方实现](https://github.com/NVlabs/GDPO)

以下公式是理解算法的示意，实际训练以采用框架的实现为准：

```text
a[i,k] = (r[i,k] - mean_group(r[:,k])) / (std_group(r[:,k]) + eps)
a[i]   = sum_k weight[k] * a[i,k]
A[i]   = batch_normalize(a[i])
```

**奖励函数和奖励模型怎么区分？** 从人工标签判断对错、从 JSON schema 检查格式，属于规则奖励函数；只有使用学习到的评分模型时才称 Reward Model。不要因为有三个奖励就说训练了三个奖励模型。

**奖励拆分的潜在问题是什么？** 同一 prompt 的真实标签固定，正常样本上漏判惩罚可能恒为零，风险样本上误杀惩罚可能恒为零；二分类正确性奖励与错误惩罚可能高度相关。需要检查各分量有效方差、相关性和组内零方差比例，才能解释拆分的价值。

**如何防止只刷格式分？** 设计奖励时避免格式奖励压过错误风险判断；监控每项奖励与独立业务指标。奖励升高但误拦／漏判恶化，说明代理目标和真实任务不一致。权重调整方式属于待验证方案，未做网格搜索就不能说“我们搜索过”。

## 5. 待做的最小对照实验

**状态：实验设计，尚未执行。**

| 组别 | 初始化与变化 | 回答的问题 |
|---|---|---|
| E0 基座 | 原始模型，固定评测提示 | 领域 SFT 相对基座的作用 |
| E1 SFT | 保存的 SFT checkpoint | 所有后续比较的起点 |
| E2 难例继续 SFT | E1 + 人工确认难例 | 简单数据迭代是否已能解决问题 |
| E3 类别权重／阈值 | E1，分别调整损失权重或决策阈值 | 收益是否只是决策偏好变化；两项不要合在一个消融变量里 |
| E4 GRPO | E1 + 与 GDPO 相同的奖励和 RL prompts | 多奖励基线 |
| E5 GDPO | E1 + 相同 prompts、奖励与预算约束 | 奖励归一化方式是否有额外价值 |

先做 E1/E2/E5；有算力再做 E4 与奖励消融。不存在历史 checkpoint 时，先判断能否重训并恢复训练数据版本；不要把不同数据、不同基座的结果拼成消融。

执行要求：

1. 提前冻结独立测试集；开发集用于阈值、奖励权重和 checkpoint 选择。按来源／会话／图片近重复组隔离。
2. 同时保留自然业务分布集和边界压力集；压力集单独报告，不能把人为平衡数据中的 F1 当成线上 F1。
3. 同一任务统一输出解析与格式失败处理。若只有离散标签，没有可排序风险分数，就先报告各 operating point，不能声称实现任意固定 Recall 的比较。
4. 能输出风险分数时，在开发集选取目标召回对应阈值，冻结后报告测试集实际 Recall/FPR；不要在测试集上调阈值来凑完全相同召回。
5. 记录更新步数、采样 token 和 GPU 时间。SFT 与 RL 的训练成本不同，至少报告实际消耗；比较 GRPO/GDPO 时尽量只变归一化方法。
6. 先单种子排查流程，再对有价值的候选使用多个种子；保存逐样本输出，用配对分析评估变化，不只比较两个总分。

## 6. 构造的模拟数据：仅用于理解指标

**下表全部为人工设定的教学算例，不是个人实验结果，也不是对实际算法排名的预测。** 假设 10,000 条样本中有 2,000 条风险、8,000 条正常；各方案恰好检出 1,800 条风险，用不同 FP 展示“召回不变时误拦变化”的含义。这里没有真实样本、模型输出或训练日志。

| 模拟方案 | TP | FN | FP | TN | 风险 Precision | 风险 Recall | 风险 F1 | 正常 FPR |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 模拟 SFT | 1,800 | 200 | 400 | 7,600 | 81.82% | 90.00% | 85.71% | 5.00% |
| 模拟难例继续 SFT | 1,800 | 200 | 360 | 7,640 | 83.33% | 90.00% | 86.54% | 4.50% |
| 模拟 GRPO | 1,800 | 200 | 336 | 7,664 | 84.27% | 90.00% | 87.04% | 4.20% |
| 模拟 GDPO：有利情景 | 1,800 | 200 | 320 | 7,680 | 84.91% | 90.00% | 87.38% | 4.00% |
| 模拟 GDPO：退化情景 | 1,800 | 200 | 440 | 7,560 | 80.36% | 90.00% | 84.91% | 5.50% |

公式：`P=TP/(TP+FP)`；`R=TP/(TP+FN)`；`F1=2TP/(2TP+FP+FN)`；`FPR=FP/(FP+TN)`。

有利情景的 FPR 从 5% 到 4%，是下降 1 个百分点、相对下降 20%；退化情景从 5% 到 5.5%，是相对上升 10%。所有计数和派生指标做过算术核对，**没有运行模型实验**。不为了匹配旧稿“37%”反向编造计数。

如果讲生成助手的过度拒答，还需要“正常问题被错误拒答”的独立标签；这张审核分类混淆矩阵不能直接作为拒答评测。

## 7. 补做实验的预估：用于规划的假设区间

现有材料不足以作有统计依据的性能预测。以下是为预算与停止条件设置的**探索区间**，不是置信区间或文献迁移结果；中心目标也不代表最可能结果。先用小规模试跑替换这些假设。

| 实验 | 可用于规划的有利情景 | 必须同时考虑的无收益／退化情景 | 判断是否值得继续 |
|---|---|---|---|
| 难例继续 SFT | 匹配风险召回时，FPR 相对下降 0–15% | 持平，或相对上升约 10% | 与 RL 相比更省算力且效果相当，就优先简单方案 |
| SFT → GDPO | 可把 FPR 相对下降 10% 设为初轮目标；探索 0–20% 改善 | 可能无改善或相对上升约 10–15% | 独立测试收益、训练成本、通用能力损失一起判断 |
| GRPO → GDPO | 暂不预设胜负；探索 FPR 相对差异在 ±10% 内 | GRPO 更优也完全可能 | 多奖励冲突与组内方差诊断能否解释差异 |
| 交叉标注清洗 | 人工审计标签错误率相对下降 0–20% | 错误率持平，或长尾样本被过度过滤 | 相同数据量／训练预算下是否有下游收益 |
| 输出格式奖励 | 在原本存在格式错误时，合法率增加 0–2 个百分点 | 已接近满分时空间很小；判断能力可能退化 | 格式收益不能抵消风险指标恶化 |

例：若实际 SFT FPR 测到 5%，规划中的 10% 相对下降目标对应 4.5%。先测到基线，再把比例转换为绝对值。原始 FPR 若仅 0.1%，这个目标只相差 0.01 个百分点，需要更多正常样本才能可靠判断。

建议新增评测集先按 1,000–2,000 条做流程试验，正式规模再由错误率、目标差异、风险子类与可用标注预算决定；不能凭“数万条”自动保证统计可信度。

## 8. 企业合规智能体：项目介绍与追问

链路：采集与解析 → 去重／切分 → 关键词与语义检索 → 重排 → 上下文组装 → 带来源回答；长期记忆作为独立可检索信息进入上下文。

| 问题 | 回答重点 |
|---|---|
| 为什么 Hybrid Search？ | 专有名词、文号需要精确匹配，自然语言改写需要语义召回；实际是否 BM25 要看实现 |
| 如何融合？ | 准备实际采用的分数归一化或 RRF、两路候选数、去重方式；没有实现过的只作为备选方案 |
| 重排解决什么？ | 对已召回候选做细粒度相关性判断；候选集缺正确文档，重排无法补救 |
| 幻觉如何定位？ | 分成未召回、排序靠后、切片缺上下文、生成未遵循证据；逐段测而非只改 prompt |
| 个性化与权限是什么关系？ | 权限决定能否访问，偏好影响排序；不能把偏好过滤当权限控制 |
| 长期记忆存什么？ | 有价值且需跨会话复用的信息；说明实际写入、召回、更新、隔离机制 |
| 如何评估？ | 准备检索 Recall@K、排序指标、答案证据支持率、任务成功率和延迟；没有对照就不宣称幻觉下降 |
| Agentic RL 做过吗？ | 当前材料只支持 Agent 工程与安全模型 RL；不能由此推导做过 Agent 工具轨迹训练 |

11. GDPO 是怎么缓解奖励坍塌的？
答：多目标优化中（风险拦截、误杀惩罚、格式遵循）各奖励量纲和梯度尺度差异大，简单加权会导致某一项主导、其他奖励信号坍塌。做法是解耦各维度奖励模型的归一化过程，让每个目标在各自归一化空间内提供有效梯度。最终高风险拦截 F1>85% 的同时过度拒绝率降 37%。可以补充对 GDPO（Group-wise DPO 类算法）原理的理解：组内相对优势排序 + 解耦偏好维度

## 11. 真实面试追问：我的回答与更好回答

2026-09-25 补充。下面的“我的回答”是现有记录摘要，不冒充逐字原话；没有现场回答的文件会单独注明。“更好回答”包含可用表述与补做方案，其中“可以／准备／需要”不表示已经实现。Guard 的 SFT／RL 对照仍未完成，不能引用上面的模拟数据作答。

### A01｜多级投票标签机制为什么合理？怎么证明有效？

**场次**：[京东零售，日期未核实][jd] Q1；[美团大模型，日期未核实][mt] Q7 有数据质量相关追问。

**我的回答**：现场原答未保留。现有文件是事后整理答案，提到强教师、规则、交叉验证、宽松／严格投票与争议复核。

**更好回答**：这套流程的目标是降低人工成本并找到争议样本。教师提供语义判断，规则提供可解释约束，模型间分歧用于筛选难例；训练集内模型回标要用 out-of-fold 预测，避免记住样本。若定义风险为正类，“任一模型判风险就拦截”的规则更严格，通常提高召回但增加误杀；多数票的效果取决于模型误差相关性，不能认为投票必然更准。应在独立人工集比较单教师、规则、投票、投票加人工复核，报告各类 P/R、正常样本误杀率、人工量与单位样本成本。**这些是待补对照，当前不能报提升幅度。**

### A02｜微调数据如何合成？负样本怎么构造？最大瓶颈是什么？

**场次**：[美团][mt] Q7；[腾讯微信支付风控，2026-09-16][wx] Q16。

**我的回答**：美团文件未保留现场回答；微信记录里回答了真实业务数据、公开数据与角色扮演等对抗构造，但场景和“负样本”的定义不够清楚。

**更好回答**：先约定风险为正类，避免把“攻击样本”和“负样本”混用。实际数据工作包括来源清洗、图文配对、风险标签和教师生成的文本说明；基于已有图片生成文本，不等于生成了新图片。当前数据规模使用管线产出约 89 万条的口径，训练实际使用量以 manifest 为准。难点是标签标准和边界一致性：同一表达在新闻报道、引用、讨论与实际违规意图下可能不同。准备成对的正常／风险上下文，并按原图、来源和模板分组切分，防止同源改写泄漏。合成样本是否改善真实业务效果，需要独立真实集验证。

### A03｜隐晦表述、谐音和暗语，模型怎么理解？

**场次**：[腾讯微信支付风控，2026-09-16][wx] Q17。

**我的回答**：提到历史信息、视频帧、Prompt 中的人名／实体等，没有直接讲清暗语识别方法。

**更好回答**：先区分字面线索、上下文含义与最终是否违反具体规则。只匹配暗语词表会误伤正常用法。我会构造同词不同语境的对比样本，结合前后文、图像／视频证据学习判断，并对新出现的表达建立人工确认与数据回流。评测按时间切分，单独留出未见过的暗语和正常同词样本，看召回与误杀。无法从上下文确认时输出不确定或进入复核。**这是补强方案；现有记录不足以证明已经建设了暗语专项数据集或测出收益。**

### A04｜235B 教师是你们微调的吗？学生模型是哪几个？

**场次**：[字节 Data 风控中台，2026-09-25][bf] Q6。

**我的回答**：235B 没有直接微调或部署到在线审核，只用于打标／蒸馏教师；学生口述为 Qwen3-VL 的 8B／4B／2B。

**更好回答**：教师主要提供离线标签和解释，线上学生承担成本和延迟约束下的审核。自己负责的应具体到数据管线、训练脚本／配置与评估。**学生型号按实际 checkpoint 核对后再报**，不要把口述过的不同尺寸直接列成已训练模型矩阵。教师输出也会出错，需要人工审核和独立测试；蒸馏是否有效要与学生基座／仅人工标签训练比较，当前不能凭最终 F1 推出教师的独立贡献。

### A05｜小模型大量 SFT，会不会丢掉通用能力？专用模型还需要管吗？

**场次**：[字节风控，2026-09-25][bf] Q7。

**我的回答**：“不在考虑范围内”，因为训练后只做审核。

**更好回答**：专用审核模型可以接受与部署无关能力的部分变化，但通用语义理解、指令遵循、多模态理解一旦退化，也可能影响长尾风险识别。我当时优先验证了任务指标，没有完成系统的通用能力回归，所以不能断言没有遗忘。补做时会在同一解码配置下比较基座、SFT 和后续 checkpoint，分别看审核主任务、正常复杂样本与相关通用能力，再决定是否引入回放、降低学习率或约束更新。评估细节见通用知识 G07。

### A06｜拦截、误杀、格式三个奖励的权重怎么定？

**场次**：[字节风控，2026-09-25][bf] Q8。

**我的回答**：先说一般调整，被追问后承认主要凭运行经验；没有给出系统搜索或验证依据。

**更好回答**：当时初始权重主要来自经验，这一点应直接说明。更系统的做法是先定义业务约束，例如正常样本误杀率的上限，再在验证集上寻找满足约束时召回更高的配置；同时记录每个奖励的尺度、方差、非零率、梯度／优势分布与格式通过率。候选权重和随机种子固定，最终只在保留测试集上评估。权重变化会影响取舍，不能只挑一个总体 F1。**目前没有完成权重搜索，不应回答成“我们已经网格搜索得到最优权重”。**

### A07｜为什么用 GDPO 而不是 GRPO？格式奖励高就会主导吗？

**场次**：[字节风控，2026-09-25][bf] Q9。

**我的回答**：GRPO 多奖励相加再归一化；格式奖励容易拿高分，压过拦截／误杀奖励，导致模型只学格式；GDPO 先分别归一化。

**更好回答**：标准的多奖励合成方式可以先得到标量奖励，再做组内标准化；GDPO 对各奖励分别做组内归一化后加权，并包含后续归一化处理，减少不同奖励尺度与分布对学习信号的干扰。这里真正要看的是**组内差异、方差、相关性和样本排序**。某项奖励若在同一组中恒定，即使均值很高，中心化后也不提供区分信号；不能用“高分”直接解释主导效应。格式好、业务差也不自动等于 reward hacking，需要日志与样本证明模型利用了奖励漏洞。我的项目采用该方法的动机可以这样解释，但尚未做 SFT／RL 和 GRPO／GDPO 的公平对照，不能声称已证明增益。[GDPO 原论文](https://arxiv.org/abs/2601.05242)

### A08｜如果训练 Agentic RAG，为什么先用 SFT？

**场次**：[美团][mt] Q8。

**我的回答**：现场原答未保留；现有文件是事后参考答案。这也不是已经完成的个人 Agent 训练项目。

**更好回答**：先用高质量轨迹教模型何时检索、如何构造查询、如何引用证据和何时停止，可用 SFT 学习这些动作模式。训练要区分模型动作和环境返回，不能把工具结果当作模型应自主生成的内容来监督。然后用留出的多跳问题检查成功率、证据支持率、调用次数和成本。如果瓶颈仍是长程规划，且能构建可靠任务奖励，再考虑在线探索或偏好优化。SFT 是合理起点，是否“够用”由评测决定，不能只由任务名称决定。

### A09｜低代码平台做了什么？除了配置流程，有没有写代码？最难的点？

**场次**：[字节巨量星图，日期未核实][xl] Q2.1、Q2.2、Q3。

**我的回答**：现场原答未保留。事后材料写有新闻 JSON 拆分、多线程任务、Manager 状态管理、超时重试、去重、TF-IDF／层次聚类和 ES 排序，具体个人代码仍需核对。

**更好回答**：围绕一个实际模块讲“输入—处理—输出—失败恢复—个人代码”。例如新闻处理：平台负责触发和流程编排，服务代码负责批量数据处理与并发任务，按任务状态记录完成、超时和格式错误，再进入去重、聚类与排序。最有价值的是说明自己改了哪个环节、原来怎样失败、怎样定位、修改后有什么可核验的记录。没有延迟／成功率对照就讲已观察到的故障与处理方式，不加编造的提升比例。

### A10｜低代码还是代码，怎么选？竞品调研做过吗？

**场次**：[字节巨量星图][xl] Q2.3、Q2.4。

**我的回答**：现场原答未保留；现有材料未证明做过正式竞品压测。

**更好回答**：我会按迭代速度、定制逻辑、并发和状态管理、可观测性、权限及部署成本选择。简单流程适合平台编排；复杂重试、批处理和可复用业务逻辑适合服务化代码，再作为工具接入。选型要用同一任务比较开发成本、运行成本和维护成本。若当时只体验过产品，就说做过功能体验和方案比较，不说做过完整性能基准测试。

### A11｜多模态聊天输入怎么接入？

**场次**：[字节巨量星图][xl] Q4.1。

**我的回答**：现场原答未保留；材料列的是图片上传、结构化消息和会话管理的参考方案，不能直接认定是个人前后端实现。

**更好回答**：先把图片、文本等转换成模型接口要求的结构化消息，校验文件类型、大小和数量，再由对应预处理器编码。多轮对话保存消息与附件引用，处理上下文截断和附件生命周期；输出与原始输入保持关联，便于定位错误。需要说清自己的边界：调用已有组件，还是实现上传、消息转换、模型适配或状态管理中的哪一项。若被问模型内部，再展开视觉编码器、视觉 token 与语言模型的连接。

### A12｜意图识别和路由怎么做？

**场次**：[字节巨量星图][xl] Q4.2。

**我的回答**：现场原答未保留；材料提到意图分类、槽位提取和路由。

**更好回答**：先定义互斥或可组合的意图集合，再抽取任务必需字段；缺少字段时先澄清，无法判定时走兜底。规则适合明确指令，模型适合表达多样的自然语言。输出用结构化 schema 校验，工具选择还受权限和参数约束。评测需要同时看路由准确率、错误调用成本、兜底率与端到端成功率；模型自己报的“置信度 0.9”不能直接当成校准后的概率。这里的评测框架是补强方案，已有哪部分需查实现。

### A13｜DeepResearch 如何拆查询、异步执行？成本和延迟怎么控制？

**场次**：[字节巨量星图][xl] Q4.3；[腾讯光子，2026-09-14][gz] Q5。

**我的回答**：巨量星图无现场原答；光子复盘中主要提了 OCR／视频转文字，没有讲清多源接入的开销与调度。

**更好回答**：先确认已有实现，当前材料能支持新闻任务拆分和多线程处理，不能直接宣称做了完整动态规划 DAG。若设计 DeepResearch，我会把目标拆成可验证子问题：相互独立的查询受限并发，依赖前置证据的查询串行，按预算限制轮数、来源数和工具调用量。总成本近似是各次模型／工具调用成本之和；总延迟看依赖链的关键路径，再加排队和重试。日志至少记录来源、调用数、token、耗时、超时与证据覆盖率。有这些数据后才能证明缓存、去重和提前停止的收益。

### A14｜OCR 和视频转文字的完整链路是什么？

**场次**：[腾讯光子，2026-09-14][gz] Q6。

**我的回答**：主要说了 OCR 与视频转文字，没有展开处理细节。

**更好回答**：可设计为视频解码、关键帧／场景变化采样、相似帧去重；音轨做 ASR，画面文字做 OCR；按时间戳对齐并保留来源，最后生成带时间定位的结构化摘要。ASR 覆盖语音，OCR 覆盖字幕和屏幕文字，两者不能完全互相替代。需要衡量遗漏的重要事件、文字错误率、摘要证据支持与每分钟视频成本。以上是可展开的设计，只有实际用过的组件才能表述为“我实现了”。

### A15｜RAG 工具怎么构建？分块如何保留文章段落结构？

**场次**：[字节巨量星图][xl] Q4.4、Q5。

**我的回答**：现场原答未保留；材料提供的是离线入库与在线检索参考流程。

**更好回答**：离线保留文档 ID、版本、标题层级、段落位置和权限元数据，优先按语义结构切分，超长段落再限制长度并适当重叠。在线先检索细粒度块，再按需求补父段落或邻接内容，去重并保持原文顺序；不能无条件把所有父文档拼回去。检索侧看证据 Recall@K、排序质量，生成侧看引用是否支持结论。问题来自漏检、切块破坏上下文还是生成不忠实，要分开归因。具体混合检索和 reranker 是否上线，以实际实现为准。

### A16｜长期记忆和短期记忆分别是什么？如何更新？

**场次**：[字节巨量星图][xl] Q4.5；[腾讯光子，2026-09-14][gz] Q7。

**我的回答**：巨量星图无现场原答；光子复盘仅记录“还可以继续优化”，缺少存储和更新细节。

**更好回答**：短期记忆是当前任务中的上下文与状态，长期记忆是跨会话仍需要使用的事实／偏好等信息。设计时说明四件事：什么值得写入、存在哪里、如何检索、何时失效。可选择原文窗口、滚动摘要、结构化字段和向量检索，但不能把参考架构当成已实现功能。冲突不能一律以最新文本为准，要看信息来源、有效时间和用户确认；检索必须隔离用户和权限，并支持删除。总结错误也可能长期传播，因此需要保留证据引用。

### A17｜MCP 原理是什么？调用流程怎样？你做了哪些工具？

**场次**：[字节巨量星图][xl] Q4.6、Q4.7。

**我的回答**：现场原答未保留；材料没有给出可核验的个人 MCP 工具清单。

**更好回答**：MCP 中 host 管理与多个 server 的连接，client 与 server 通信，通过初始化协商能力，再发现和调用工具，例如 `tools/list`、`tools/call`；协议采用 JSON-RPC。server 还可以提供资源和提示模板。实际项目要补充工具名称、输入输出 schema、错误语义、超时和鉴权位置。协议并不自动解决权限或业务正确性。平台工具总数不能算成个人开发量；只讲自己确实实现或接入过的工具。[MCP 架构规范](https://modelcontextprotocol.io/specification/2025-06-18/architecture)

### A18｜大模型总结出错，反思和复盘怎么做？

**场次**：[字节巨量星图][xl] Q4.8。

**我的回答**：现场原答未保留；事后材料提到格式校验、状态管理和重试。

**更好回答**：先把错误分为来源不可靠、证据缺失、抽取错误、归纳错误和输出格式错误。格式问题用 schema 和确定性校验，事实问题把结论绑定到原文证据，缺少证据时降低结论强度或返回无法确认。重试要带明确错误反馈并设次数上限，不能反复让同一个模型“再想想”就当成验证。回流时保存失败输入、证据、输出、版本和错误类别，形成固定回归样本。实际完成了哪些措施和观察到哪些故障，应与代码和日志对应。
