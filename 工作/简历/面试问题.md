一、"这个工作最大的难点和挑战是什么"——推荐回答框架
面试官问这个，不是想听"数据少、模型难训"这种泛泛的话，而是想看你能不能定位到本质矛盾。你在腾讯这个项目的最佳答案不是某个技术点，而是三层难点：

标准回答（腾讯风控项目，约 1.5 分钟版）
这个工作最大的难点不在模型本身，而在三个层面：

第一层是业务约束的矛盾。 法院文书校验的场景，误判一份有效文书的代价远高于放过一份无效文书，所以要求"零误拦"，同时又要尽可能提高拦截率，还要满足单图 3 秒内、低成本的线上约束。也就是说，我不是在优化一个准确率指标，而是在一个"Precision 必须 100%"的硬约束下挤 Recall，这决定了所有技术选型都不能走"大模型端到端一把梭"的路。

第二层，也是最本质的：任务定义本身没有共识。 以清晰度检测为例，"清晰"和"模糊"中间存在大量灰色地带，人的主观判断受先验知识影响，还会自动剔除水印、反光等干扰。我早期拿旧 XGBoost 模型的结果和安管侧对齐，一致性只有 23%。那一刻我意识到：这不是模型问题，是标准问题——标注出来的数据质量必然不高，训练出可用模型无从谈起。所以我做的最关键决策是把任务从二分类重定义为"不可辨文字比例 + 可辨区域锐度"的二维序数五分类，并用 OCR 置信度去锚定一个可操作的标准。

第三层是资源约束下的数据质量。 只有一名标注人员，要支撑数万条训练数据。我通过"规则预标注 + 自研可视化标注平台 + 人工复核分歧样本"的方式，把标注效率提升了 5 倍，并且用序数距离的高斯软标签把标注不确定性显式注入监督信号，最终在拒单口径下做到 Precision 100%。

回头看，最大的收获是：很多模型问题本质是任务定义问题。前期我在 XGBoost 阈值切分上走了弯路，如果更早和业务方对齐标准，能少走一半弯路。

这个答法的好处：有冲突（零误拦 vs 拦截率）、有转折（23% 一致性 → 发现是标准问题）、有决策（重定义任务）、有结果（100% Precision）、有反思（走了什么弯路），正好覆盖面试官想考察的全部维度。

如果被追问"京东那边的难点"（备用）
AIGC 基模组：难点是"评价比生成难"。商品主图生成没有现成标准，要把"主体保真、营销文字、背景衔接"这种主观感受拆成 14 项可打分的原子指标，还要让评测结果能指导模型选型——本质是把模糊的业务审美量化成 Benchmark。
AI 安全部：难点是多目标冲突。安全护栏要"高风险拦得住"和"正常请求不误杀"，这两个目标在 RL 里互相打架，出现奖励坍塌。解法是 GDPO 里把风险拦截、误杀惩罚、格式遵循的奖励归一化解耦，最终在 F1>85% 的前提下过度拒绝率降 37%。
二、各实习高频问题清单 + 回答要点
腾讯（被问概率最高，重点准备）
项目理解类

整个链路为什么要串行、为什么要后校验？ → 输入标准化 → 质量门控 → OCR/版面/检测多源信号 → 后校验输出高置信结论。串行是为了便宜：前置的便宜模块挡掉大部分，贵的模型只处理难例；后校验是"零误拦"的最后一道闸，低置信的全部转人审，宁可漏拦不能误拦。
拦截率 4.33% → 9.84% 怎么算的？ → 分母是日均 38.8 万张传入文书，新增拦截主要来自清晰度拒单（模糊占比 4.3%，是数据漏斗里最大的一块，ROI 最高）+ 印章/类型/电话的补充。日均拦截 38198 条。
为什么不直接用大 VLM 端到端做？ → 实测过：Qwen3-VL-235B 直接给清晰度打分准确率只有 26%（能读出字就判清晰，给不出绝对评分）；且成本、时延不满足 3 秒约束。大模型用在"难例复核"这种低频次高价值环节，主链路控制在 100M 参数量以内。
清晰度检测（最深，必问） 4. 为什么二分类改五分类？ → 三个理由：① 真实数据分布是连续的，中间档让标注更鲁棒；② 分级后可以差异化处置（Level 3 转人审、Level 4/5 拒单），而不是非黑即白；③ 业务规则变化时可以灵活调整拒单口径，不用重训。 5. 为什么用 VLM LoRA 而不是传统分类器？ → 消融实验说话：LLM LoRA 软标签组内准确率 99.82%、前→后跨档仅 1 条；纯视觉头 98.54%、跨档 30 条；硬标签 65.03% exact、跨档 25 条。纯视觉头缺"读字"能力，把整页压成全局特征，还会把印章水印误判为模糊；VLM 能理解"表格线断裂不算模糊"这类语义规则。 6. 软标签怎么设计的？为什么 CE+KL？ → 以预标签等级为中心、σ²≈0.3 的高斯分布构造五维软标签，相邻档各分约 0.14。五档是序数关系不是互斥类别，硬标签会让模型对边界样本过度自信、过拟合预标签噪声。软标签 CE 等价于 KL(q‖p)+const，再加概率期望校准。 7. "Precision 100%"怎么验证的？会不会是测试集太小？ → 主动承认：是在 3283 条测试集 + 两轮人工复核分歧 case 上验证的，上线前还会灰度。重点是拒单口径（Level 4/5）下前→后跨档只有 1 条。另外兜底机制是不确定样本转人审，线上还有 bad case 回流。 8. 训练上有什么细节？ → ms-swift，LoRA rank=8，lr 1e-4，冻结视觉塔和 aligner，BF16；step 1200 已收敛，继续训会过拟合所以早停；Level 4/5 长尾样本（337/84 条）用平方根反频率过采样。

印章 / 文书类型 9. 印章怎么做到 Precision 100% + Recall 98.94%？ → 难点是无印章样本只占 2%（类别极不平衡）+ 浅色章漏检。方案：三路版面/印章检测模型 + HSV 红色分割融合，86 组阈值搜索；关键设计是有/无/不确定三分类，不确定的走 VLM 难例复核——Recall 和 Precision 不是靠一个模型硬扛，是靠"路由"把难例分流。 10. 文书类型 94.59% → 99.99% 提升靠什么？ → 先拆解错误来源：OCR 幻觉、页面旋转、多图横排错序。对应级联链路：DBNet+LCNet 方向检测 → 全文 OCR → 标题定位 → 白名单分类，再加阅读顺序恢复、同义词归一化、自适应模糊匹配。大部分提升来自工程链路而非模型——这点可以主动说，体现你对"准确率来源"的拆解能力。

延伸追问 11. 你独立负责了哪些？导师做了什么？ → 实话实说：任务定义、链路设计、训练、标注平台是自己做的；业务对齐、安管沟通是导师带着做的。 12. 这个项目还有什么不足？ → 用你自己总结里的：① 标签质量仍是瓶颈，计划用模型替代规则做预标、全量回洗重训；② 标准对齐介入太晚，前期试错花了时间；③ 离线完成但线上收益还没验证。主动说不足是加分项。

京东 AIGC 基模组
清洗链路为什么这么设计？多阶段漏斗每一级挡什么？ → 分辨率/清晰度规则挡低质图 → PP-OCR + 文字贴片检测挡文字脏污 → Qwen3-VL 美学评分挡观感差 → 同品匹配构造 Pair。原则：便宜的规则前置，贵的模型后置。
OCR 选型为什么 Precision 优先？ → 用于数据清洗，错留脏文字会污染训练数据（garbage in garbage out），所以 Precision 95.05% 优先于 Recall；推理成本降两个数量级是因为选的小 OCR 模型替代了 VLM。
14 项原子指标怎么定的？ → 从业务 bad case 反推：主体保真、营销文字、背景衔接、结构透视四大类往下拆，每项可独立打分，保证评测结果能定位到具体优化方向。
VLM 横评为什么最终没用 VLM？ → 成本差两个数量级，且 OCR 专用模型在文字场景精度已够用——选型是精度×成本×时延的权衡，不是选最强的。
京东 AI 安全部
GDPO 和 GRPO 的区别？奖励坍塌怎么解？ → 多维奖励（风险拦截、误杀惩罚、格式遵循）量纲和尺度不同，直接加权会让某个奖励主导、其他被淹没；解法是各奖励独立归一化后再聚合。
89 万数据怎么保证质量？ → 互斥子集 + 宽松/严格双模型交叉标注 + 投票聚合，识别争议样本；Qwen3-VL-235B 初始标注 + 规则过滤。
过度拒绝率降 37% 怎么衡量的？ → 在正常请求集上测误杀率，RL 前后对比。
Agent 项目里 Hybrid Search 为什么比纯向量好？ → 政务长尾知识，纯向量召回对专有名词/文号不敏感，BM25 补足精确匹配，Re-ranking 做精排。
通用行为问题
三段实习的关系？ → 用你答辩里的叙事，非常好："京东安全部解决怎么把模型训出来 → AIGC 解决怎么构造可靠数据、怎么评价模型 → 腾讯解决怎么让模型成为稳定业务能力"。
最有成就感的事 / 最大的失败？ → 成就感：拦截率翻倍且零误拦；失败：前期在 XGBoost 阈值上死磕，根因（标准无共识）识别偏晚，一致性只有 23% 才回头——讲成"试错故事"。
你和别人比优势在哪？ → 全链路视角：任务定义 → 数据标准 → 标注平台 → 训练 → 决策路由 → 人审闭环，都独立做过。
给你的核心建议：面试官问"难点"时，千万别答"数据不够""模型效果不好"这种过程性困难，要答结构性矛盾（零误拦 × 高拦截 × 低成本 × 标准无共识），然后讲你怎么定位根因、怎么做取舍。你答辩材料里"在保证不误拦文书的前提下尽可能提高拦截率是最大的挑战"这句已经是标准答案的骨架，把它展开成上面的三层结构即可。
