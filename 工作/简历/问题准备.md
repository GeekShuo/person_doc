正文技能栏写了 DeepSpeed、vLLM，但经历里没有对应证据。如果确实使用，应在这条体现；如果没有深度参与，应从技能栏删除。




1. 什么样的样本需要强化学习？
不是单纯把错题拿来做强化学习，而是选择 SFT 后仍然存在策略权衡、且结果可以被奖励函数可靠评价 的样本。

主要包括三类：

高风险漏判样本：风险表达隐晦，需要结合图像、文字和上下文推理。
正常内容误杀样本：包含风险关键词或相似视觉元素，但实际语义正常。
边界与冲突样本：不同审核目标之间存在权衡，例如提高拦截率后误杀率明显上升。
纯粹的知识缺失、标签错误、极度歧义样本不适合直接做 RL：知识缺失优先补 SFT，错标和歧义样本先清洗或人工复核。

2. 这些样本怎么筛选？
可以这样回答：

我先让 SFT 模型在独立候选集上推理，结合真实标签和模型输出，按照假阴性、假阳性以及格式错误进行分桶。然后优先选择高置信错判、多个模型判断不一致、以及奖励目标冲突明显的样本。人工复核并去除错标、无法判定和重复样本后，作为 RL prompt。训练时针对每个 prompt 采样多条回答，通过组内相对奖励更新模型。

筛选链路可以概括为：

text
SFT 模型推理
→ 按漏判/误杀/格式错误分桶
→ 按置信度、模型分歧度和业务风险采样
→ 人工复核与去重
→ 划分 RL 训练集和独立测试集
→ 在线采样多条 response 计算组内奖励
这里要强调：RL 样本通常是 prompt，response 由当前策略在线生成，不是简单地把 SFT 问答对换个训练方法再训一遍。

3. 怎么证明 RL 比继续做 SFT 有用？
不要说“RL 天生比 SFT 好”，而要说做了受控对比：

我们没有预设 RL 一定优于 SFT，而是从同一个 SFT checkpoint 出发，对比原始 SFT、继续使用难例做 SFT，以及 GDPO 三组实验。使用完全独立、没有进入训练和样本筛选流程的测试集，统一比较高风险 Recall/F1、正常样本通过率、误杀率和格式正确率。只有当 GDPO 在高风险识别提升的同时，误杀没有恶化，或者形成更好的 Pareto 权衡，才认为 RL 有效。

4. 为什么这里 RL 可能比 SFT 更合适？
SFT 学的是对参考答案的 token 级模仿，但安全审核同时涉及漏判、误杀和输出格式等序列级目标，而且这些目标之间存在冲突。GDPO 可以对模型完整输出直接计算多目标奖励，并通过组内比较强化更优策略。因此它的价值不是补充安全知识，而是在已有 SFT 能力上进一步调整决策边界。

一分钟回答版本
我们不是把所有难例都拿去做强化学习。先让 SFT 模型跑独立候选集，按照高风险漏判、正常内容误杀、格式错误和多模型分歧进行分桶，再经过人工复核，去掉错标、重复和本身无法判定的样本。最终选择的是模型已经具备基本判断能力，但在安全性与可用性之间仍然存在策略权衡，而且能够通过标签和格式规则稳定计算奖励的 prompt。训练时每个 prompt 在线采样多条回答，对拦截、误杀和格式奖励分别归一化、加权，再用 GDPO 做组内相对优化。我们也不会直接断言 RL 比 SFT 好，而是从同一 SFT checkpoint 对比难例继续 SFT和 GDPO，在独立测试集上同时观察高风险 F1、Recall、正常通过率和误杀率；只有 GDPO 获得更好的综合指标或 Pareto 权衡，才能证明它有价值。

最关键的是准备好真实的样本数量、筛选比例、消融指标和奖励计算公式，否则面试官继续追问时容易露出空泛。


## 面试口径自查

1. **印章 Precision 100%**：正类为“无印章”，Precision 100% 表示被自动判为无印章的样本均确实无章，且仅限定于高置信自动处理子集，不表述为模型整体准确率 100%；四轮优化依次使用 1,000 条、扩展后的 1,152 条及两批各 1 万条新增数据，最终将无印章 Recall 提升至 98.94%。
2. **文书分类 99.9%**：基于 11,803 条、30 类人工核验数据；面试前确认数据类别分布及其与调参集、测试集的关系。
3. **号码校验**：总量 278,407 条，经异常 Case 回流及业务口径对齐，将判定无效率由初版 21.5% 收敛至 11.7%（32,545 条），降低 9.8 个百分点；区号补全修复 64,991 条（23.3%）。当前属于离线评估和上线收益预估，不表述为已产生线上收益。
4. **高风险识别 F1 > 85%**：面试前确认二分类 F1、Macro-F1 或 Micro-F1 的具体口径。
5. **超 100 万条数据**：明确个人负责的数据清洗、自动标注与质检环节，以及个人产出与团队总产出的边界。
6. **主图人工通过率 86%**：准备好候选数据规模、抽检方法及指标统计口径，不将其表述为相对基线提升。
7. **方转长机评可用率 54.9%**：保留“机评”限定，并主动说明尚未进行人工复核。
8. **腾讯业务背景**：可说明法院、公安等机构向财付通传入查询、冻结类单据，但不提内部平台名称、客户数据细节和算力规模。
重新核对四类高风险指标
1. 无印章 Precision 100%、Recall 98.94%
当前已经限定为“高置信自动处理子集”，这是正确的，但还应确认：

测试集是否独立于阈值调优集；
测试集总量及无章样本量；
“高置信自动处理子集”的覆盖率；
Recall 是全量无章 Recall，还是子集内 Recall；
置信度以下样本如何处理。
这里最有业务价值的数字可能不是“100%”，而是：

在保证无章 Precision 100% 时，自动覆盖了多少请求。

如果有覆盖率，建议一起写。

2. 文书分类准确率 99.9%
需要确认：

11,803 条是否为独立测试集；
是否与规则/阈值调优数据隔离；
30 类是否严重不均衡；
是否存在白名单外类别；
Macro-F1 或尾部类别 Recall 是否同样稳定。
如果只是总体 Accuracy，99.9% 很容易被追问长尾类别表现。

3. 号码“判定无效率由 21.5% 降至 11.7%”
这是目前最需要改写的指标。

招聘方第一眼可能理解为：

系统识别出的无效号码变少了，所以效果下降了。

该数字实际想表达的是通过 Case 回流和业务口径对齐，减少误判或修正规则边界，但当前表述没有证明 11.7% 比 21.5% 更准确。

优先寻找更能证明效果的指标：

无效号码 Precision/Recall；
误杀数下降；
人工抽检准确率；
规则误判 Case 减少；
区号补全后的有效号码恢复量；
人工复核量下降。
在没有准确率类指标前，可以把“修复 64,991 条号码”作为主结果，把 21.5%→11.7% 降为辅助过程信息。

4. 高风险识别 F1 超过 85%
需要补：

指标是二分类 F1、Macro-F1 还是某个高风险类 F1；
SFT 基线是多少；
GDPO 带来了多少增益；
“降低过度拒答”的具体数字；
测试集规模与风险类型分布。
否则面试官无法判断 GDPO 是否真正有效。
