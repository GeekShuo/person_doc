1. 什么样的样本需要强化学习？
不是单纯把错题拿来做强化学习，而是选择 SFT 后仍然存在策略权衡、且结果可以被奖励函数可靠评价 的样本。

主要包括三类：

高风险漏判样本：风险表达隐晦，需要结合图像、文字和上下文推理。
正常内容误杀样本：包含风险关键词或相似视觉元素，但实际语义正常。
边界与冲突样本：不同审核目标之间存在权衡，例如提高拦截率后误杀率明显上升。
纯粹的知识缺失、标签错误、极度歧义样本不适合直接做 RL：知识缺失优先补 SFT，错标和歧义样本先清洗或人工复核。

2. 这些样本怎么筛选？
可以这样回答：

我先让 SFT 模型在独立候选集上推理，结合真实标签和模型输出，按照假阴性、假阳性以及格式错误进行分桶。然后优先选择高置信错判、多个模型判断不一致、以及奖励目标冲突明显的样本。人工复核并去除错标、无法判定和重复样本后，作为 RL prompt。训练时针对每个 prompt 采样多条回答，通过组内相对奖励更新模型。

筛选链路可以概括为：

text
SFT 模型推理
→ 按漏判/误杀/格式错误分桶
→ 按置信度、模型分歧度和业务风险采样
→ 人工复核与去重
→ 划分 RL 训练集和独立测试集
→ 在线采样多条 response 计算组内奖励
这里要强调：RL 样本通常是 prompt，response 由当前策略在线生成，不是简单地把 SFT 问答对换个训练方法再训一遍。

3. 怎么证明 RL 比继续做 SFT 有用？
不要说“RL 天生比 SFT 好”，而要说做了受控对比：

我们没有预设 RL 一定优于 SFT，而是从同一个 SFT checkpoint 出发，对比原始 SFT、继续使用难例做 SFT，以及 GDPO 三组实验。使用完全独立、没有进入训练和样本筛选流程的测试集，统一比较高风险 Recall/F1、正常样本通过率、误杀率和格式正确率。只有当 GDPO 在高风险识别提升的同时，误杀没有恶化，或者形成更好的 Pareto 权衡，才认为 RL 有效。

4. 为什么这里 RL 可能比 SFT 更合适？
SFT 学的是对参考答案的 token 级模仿，但安全审核同时涉及漏判、误杀和输出格式等序列级目标，而且这些目标之间存在冲突。GDPO 可以对模型完整输出直接计算多目标奖励，并通过组内比较强化更优策略。因此它的价值不是补充安全知识，而是在已有 SFT 能力上进一步调整决策边界。

一分钟回答版本
我们不是把所有难例都拿去做强化学习。先让 SFT 模型跑独立候选集，按照高风险漏判、正常内容误杀、格式错误和多模型分歧进行分桶，再经过人工复核，去掉错标、重复和本身无法判定的样本。最终选择的是模型已经具备基本判断能力，但在安全性与可用性之间仍然存在策略权衡，而且能够通过标签和格式规则稳定计算奖励的 prompt。训练时每个 prompt 在线采样多条回答，对拦截、误杀和格式奖励分别归一化、加权，再用 GDPO 做组内相对优化。我们也不会直接断言 RL 比 SFT 好，而是从同一 SFT checkpoint 对比难例继续 SFT和 GDPO，在独立测试集上同时观察高风险 F1、Recall、正常通过率和误杀率；只有 GDPO 获得更好的综合指标或 Pareto 权衡，才能证明它有价值。

最关键的是准备好真实的样本数量、筛选比例、消融指标和奖励计算公式，否则面试官继续追问时容易露出空泛。

# Qwen3Guard 数据预标签方案（多模型交叉打分）

来源：Qwen3Guard Technical Report（arXiv 2510.14276）。本地 `.qwen3guard_report.pdf` 是截断损坏版本，内容以 arXiv 完整版为准。
**面试定位**：这是"业界方法论参照"，必须明确说是阅读/参考所得，最后一定落回自己京东 AI 安全的百万级数据构建实践。不要说成自己做的。

## 一、整体流程（先把这张图背下来）

1. **Prompt 合成**：Self-Instruct，先把安全 policy 拆成细粒度 taxonomy，按类播种生成。两个防捷径技巧：
   - 关键词引导（"bomb / TNT / C4 / black powder"）保证同类内的词汇多样性；
   - **正负配对**（"How to make a bomb" ↔ "How to make a cake"），防止模型把 "make" 这类词学成不安全特征。
2. **Response 收集**：Instruct 模型常规合成 + **base 模型**（Qwen2.5-72B-Base，因为对齐模型几乎不产 unsafe）+ **推理模型**（QwQ / Qwen3 / DeepSeek-R1）收集带 thinking 的回复。
3. **Auto Labeling（预标签）**：多个 Qwen（Qwen2.5-72B-Instruct、Qwen3-235B-A22B）按统一标注指令出初步标签 → **投票聚合**；以少量人工标注样本为参照校准，安全等级在人工验证集上 **F1 > 0.9**；类别 / 拒答标签直接取众数。
4. **训练期数据精修两轮**：
   - **Building Controversial Labels**：数据均分 A / B；每半用不同 Safe/Unsafe 配比训出 **Strict（偏严）** 和 **Loose（偏松）** 两个模型；**交叉标注对方半区**；两模型一致 → Safe/Unsafe，**冲突 → Controversial**。
   - **Label Distillation**：再次对半切，用一半训的模型修正另一半标注，**Qwen3-32B 当 teacher**，滤掉错误标注。Qwen3Guard-Gen-4B 平均 **+0.47 / +1.10（prompt）**、**+0.5 / +0.76（response）**。

## 二、高频追问与答法

**Q1：为什么不直接人工标？**
规模不允许，而且 controversial 这类边界样本人工之间也不一致（kappa 低）。人工只承担两件事：**提供校准参照集** 和 **验证投票结果**，不参与全量标注。

**Q2：为什么用多个模型投票，是堆算力吗？**
不是。投票的目的是**压掉单模型的个体偏置和方差**，让标签稳定；尺度差异（72B vs 235B）只是让成员去相关的手段之一，不是控制对象。

**Q3：Strict / Loose 两个模型是怎么造出来的？**
操纵的是**训练集的 Safe/Unsafe 配比**，不是模型规模。Safe 富集的模型倾向判 Unsafe（Strict），Unsafe 富集的倾向判 Safe（Loose）。配比不是拍脑袋定的，而是按模型在验证集上"最保守 / 最宽松"两种表现**标定**出来的。
> 这句很关键：**两个模型同架构同规模，变的只有数据分布。**

**Q4：为什么必须交叉（训 A 打 B），不能自标？**
在同一批数据上训再在同一批上预测，模型必然记忆式高置信，冲突率趋近 0，"分歧"信号直接消失。切成 A/B 后标注器对被标注数据是**外推**的，它的错误才是真实泛化错误——这就是 out-of-fold / 交叉拟合的标准套路（和 K-fold 造 stacking 特征、confident learning 找错标同源）。

**Q5：冲突样本到底怎么处理？**
分两轮，性质相反，这是最容易被追问糊掉的地方：

| | Step 1 建 Controversial | Step 2 Label Distillation |
|---|---|---|
| 分歧来自 | Strict vs Loose（**故意造的相反偏置**） | 交叉模型 / teacher vs **已有标签** |
| 分歧含义 | 内容本身在边界上，谁都没错 | 原标签错了（噪声） |
| 处理 | **升格为新类别 Controversial，样本保留** | **改标签，或丢弃** |
| 动机 | 边界信息有用，要留 | 噪声有害，要清 |

证据：论文说蒸馏收益来自 "making the decision boundaries for each category **more separable**"——如果删的是边界样本，边界只会更模糊。所以删的是**落在别的类别腹地的错标样本**。
另外 teacher 的**软标签**本身就是降噪：噪声样本上 teacher 概率分散，梯度又小又不极端，等于隐式降权，不一定是显式 if-else 删除。

**Q6：这种多模型聚合，能不能控制审核标准？**
半对半错，答法要分三层：
- 控**标注质量**：能（压方差、降噪声）；
- 控**松紧阈值**：能，但只是**沿已有的一条轴滑动**——产出 controversial 档后，strict（controversial 并入 unsafe）/ loose（并入 safe）变成推理时开关。证据 Table 8：ToxicChat 71.1 → loose 80.9；OpenAIMod 70.2 → loose 80.2；Aegis 86.1 → strict 90.9；
- 控**标准本体**（类别定义、内容维度的政策差异）：**不能**。标准由 policy 文本（prompt 里的 `<BEGIN SAFETY POLICY>`）、taxonomy 和人工验证集定义，ensemble 碰不到。

**Q7：有什么局限？**
- 投票本质是取多数平均，**长尾 / 少数派口径会被抹平**，换来的是一致性和稳定性；
- strict/loose 只是**一维松紧**，表达不了"这个场景禁 A 不禁 B"的多维政策；
- policy 虽在输入模板里理论上可换，但训练数据是按单一 taxonomy 造的，**换 policy 的泛化性论文没验证**；
- 要真正做可配置审核，正路是 **policy 作为条件输入 + 训练时对同一批数据按多套 policy 分别标注**，堆 ensemble 堆不出来。

## 三、迁移到自己项目的说法（这条最重要）

对照简历"京东 AI 安全：百万级数据构建"那条 bullet，可以这样接：

> 我在数据链路里负责的是自动标注、投票聚合和质量过滤。多模型投票是为了压单模型的偏置，聚合结果再按置信度和模型分歧度分桶：分歧大的不丢，单独列为一档边界样本交给人工或后续策略处理；高置信且与标签冲突的判为错标，做修正或剔除。这一点我参考了 Qwen3Guard 的做法——它把"模型间的分歧"直接当成信号，用来定位安全边界（controversial）和清洗噪声（label distillation）。

注意边界问题：明确 100 万条是**团队链路总产出**，个人负责的是其中的自动标注、投票聚合与质量过滤模块（见"面试口径自查"第 5 条）。

## 四、一分钟口播版本

> Qwen3Guard 的预标签分三层。第一层，未标注数据先让多个大模型按统一标注指令各自打初步标签，投票聚合，用少量人工标注样本校准，安全等级在人工验证集上 F1 超过 0.9，类别和拒答取众数。第二层解决"中间地带"：把训练集对半切，每半用不同的 Safe/Unsafe 配比训出偏严和偏松两个模型，再去标另一半——预测一致的定 Safe/Unsafe，冲突的就标成 Controversial；必须交叉而不能自标，是因为模型在自己训练过的数据上永远高置信，冲突信号会消失。第三层是去噪：再对半切，用一半训的模型改另一半的标注，配一个更大的 teacher 做蒸馏修正，4B 上有零点几个点的稳定增益。这里有个关键点：第一轮的冲突是真实边界，要**保留**并升格成新类别；第二轮的冲突是标注错误，要**改掉或丢掉**。另外这套聚合能控制的是标注质量和松紧阈值，控制不了审核标准本身——标准是由 policy 文本、分类体系和人工验证集定义的。

## 五、风险提示

1. 面试官追问"这是你做的吗"——立刻切回：这是公开技术报告的做法，我参考的是它的**数据清洗思路**，我自己在京东做的是 X（数据源、标注策略、质检环节、指标）。
2. 被追问到论文细节（阈值 85%、模型规模、具体配比）时，只说论文有明确写出的数字；**配比和冲突处理规则论文没给细节**，不要编。
3. 最好能准备一个自己项目的对应数字：投票前单模型一致率、投票后人工抽检准确率、边界样本占比、清洗前后下游模型增益。没有这组数字，方法论讲得再漂亮也会被判定为空泛。
