## 阶段 3｜拆成两个项目讲（不要混成一锅）

### 项目一：企业合规智能体

**背景（怎么开场）**
企业内部有大量分散且持续更新的领域知识，不同部门和用户关注的信息又不一样。直接用通用大模型会有三个问题：知识过时、长尾信息召回不足、多轮对话上下文丢失。所以我们搭了一套带**个性化检索**和**长期记忆**的企业智能体。

**整体链路**

```
多源数据采集
    ↓
解析、清洗、去重
    ↓
文档切分与索引更新
    ↓
Hybrid Search
    ↓
Re-ranking
    ↓
上下文组装
    ↓
LLM 生成
    ↓
长期记忆抽取与写入
```

**三个技术点的讲法**

1. **Hybrid Search 为什么必要**：纯向量检索适合语义相似，但对专有名词、编号、精确短语不稳定；纯关键词检索精确匹配强，但对同义表达和自然语言问题召回不足。所以先用 Hybrid 扩大候选集，再用 Re-ranker 做细粒度排序。
   ⚠️ 如果实际用的是 BM25 + Dense Retrieval 就直接说；**不是就别硬说 BM25**。

2. **个性化检索**：不同部门和用户有不同的关注范围与历史行为。我在检索阶段引入组织级和用户级约束，并针对数据源权重、时效性、用户偏好调整排序策略，让同一个问题在不同上下文下返回更合适的内容。

3. **长期记忆**：不是把所有历史对话拼进上下文，而是从对话中**抽取值得长期保存的用户信息**并向量化存储；新会话里按当前问题检索相关记忆，和短期上下文一起送入模型。这样既控制上下文长度，又支持跨会话保持。

### 项目二：多模态安全模型训练（算法含量最高，作为核心项目讲）

**背景（怎么开场）**
通用 VLM 对显式风险内容有一定识别能力，但在**多轮对话、图文组合、隐晦表达、视觉绕过**这些场景下不稳定。而且安全模型容易出两个相反的问题：一类是漏判高风险内容，另一类是对正常内容过度拒绝。所以要构建领域数据，并用 SFT + RL 同时优化"识别能力"和"正常内容可用性"。

**数据生产链路**

```
业务数据 / 开源数据 / 采集数据 / 合成数据
                  ↓
          格式统一与基础清洗
                  ↓
        去重、低质和异常样本过滤
                  ↓
      大参数 VLM 与多个教师模型推理
                  ↓
        聚合投票与启发式规则校验
                  ↓
            低置信样本过滤
                  ↓
        类别与难度分布平衡
                  ↓
        89 万条多轮图文 SFT 数据
```

**四个"为什么"的讲法**

- **为什么多模型投票**：单个教师模型有系统性偏差，尤其在边界样本和隐晦表达上。多模型投票降低单模型偶然错误的影响；启发式规则处理格式合法性、标签冲突和明显异常。分歧大的样本**过滤、降权或进人工复核**，而不是直接当高置信训练数据。
- **为什么做多轮数据**：真实安全判断不总能由单轮输入完成，有些风险依赖前文指代、上下文组合或连续诱导。多轮数据让模型学上下文依赖，而不是只按当前一句的关键词分类。
- **结构化推理数据怎么讲**：不要强调"让模型输出完整 CoT"，改成——在 SFT 数据中加入**结构化判断依据**，让模型先定位图像和文本中的关键证据，再输出风险类别和处置结果。相比只训最终标签，这提升复杂样本的可解释性，也减少模型只靠关键词判断。
- **为什么 SFT 后还要 RL**：SFT 学的是训练数据里的标准答案，但真实目标是多维的（要拦截、要不误杀、要按格式输出），这些很难只用交叉熵表达。

**SFT 怎么讲**
用 89 万条多轮图文数据对 Qwen3-VL 模型组做全参数 SFT，让模型学习统一的输入输出格式、风险分类体系和图文联合判断能力。训练数据要重点控制**类别分布、正负样本比例、难例比例、多轮长度**，否则模型会偏向高频类别，或者形成"一律拒绝"的懒惰策略。

**GDPO 怎么讲**
奖励分三类：风险识别奖励（高风险是否正确识别、类别是否正确）、误判/过度拒绝惩罚（正常样本是否被错拒、边界内容是否被过度判定）、格式遵循奖励（格式是否合法、字段是否完整、有无无关内容）。

核心痛点是**奖励坍塌**：不同奖励的数值范围和方差不同，直接加权求和的话尺度大的奖励会主导梯度——比如格式奖励容易拿稳定高分，风险识别奖励更稀疏，训完模型只学会遵循格式，识别能力没涨。GDPO 的做法是**把各奖励的归一化过程解耦**，各自归一后按业务重要性加权，让各目标在相近尺度上参与优化。

## 阶段 4｜面试官提问清单（一条条准备）

> 每条格式：**问题 → 推荐答法 → 追问预警 / 待确认**。答法只写要点，现场用自己的话说。

### A 组：数据与质量

**Q1　89 万条数据怎么保证质量？**
四层。第一层基础规则清洗（格式、重复、图像有效性、字段一致性）；第二层大模型自动标注，多模型投票减少单模型偏差；第三层启发式规则处理标签冲突和明显异常；第四层对低置信及模型分歧样本过滤或抽样人工复核。最后还要检查类别、来源、难度分布，避免"量很大但有效信息重复"。

**Q2　89 万条是不是全部你一个人做的？**（必考，决定你能不能说"主导"）
**一定要明确个人边界。** 百万级数据是团队链路的总产出。如果链路主要由你搭：说"整体方案和核心代码由我负责，数据资源和算力由团队提供"。如果只负责部分模块：说"我主要负责数据清洗、自动标注策略、部分数据源接入和质量分析"。**不要默认把团队产出写成个人产出。**
→ 待确认：你个人负责的具体模块和量级。

**Q3　F1 是 Macro 还是 Micro？**（必须提前确认）
多类别且不均衡时两者差别非常大。如果是二分类风险拦截 F1，就明确说"将所有风险类别合并为正类计算风险拦截 F1"；如果是多分类 Macro-F1 就明确说 Macro-F1。**不要含糊。**

**Q4　怎么定义"过度拒绝"？**
在正常或可回答样本上，模型错误输出拒绝、风险标签或无法提供正常服务的比例。
`Over-refusal Rate = 正常样本中被错误拒绝的数量 / 正常样本总数`

**Q5　SFT 数据和评测集有没有泄漏？**
需要在图像、文本、语义三个层次去重。除精确哈希外，用感知哈希或图像 embedding 处理近重复图片，用文本归一化和 embedding 检测改写版本，最后按数据来源或时间切分评测集，避免同源模板泄漏。
⚠️ **只说你实际做过的部分**，其余作为改进方案讲。

**Q6　投票机制具体怎么实现的？**
→ 待确认：多数投票还是置信度加权？输出如何归一化到统一标签？平票怎么处理？哪些样本被过滤？最终保留率多少？有没有抽样算过自动标签准确率？
这六个数字别人一问就得答得出来。

**找不到数字时就明说**："完整实验由团队共同维护，我主要负责其中某模块；我能确认最终 F1 超过 85% 和过度拒绝率下降 37%，但不想编造记不准的单项指标。"——这比随口编数字安全得多。


  第一，为什么需要 RL？
  应比较“继续补充难例做 SFT”“调整类别权重／决策阈值”“引入 RL”。如果降低误拦只是改变了决策倾向，需要检查在相同风险召回下是否仍有提升。

  第二，GDPO 的收益来自哪里？
  原论文针对的是多奖励聚合归一化时，不同奖励组合可能得到相同
  advantage、损失训练信号分辨率的问题；官方实现包含各奖励的组内归一化、加权聚合及后续批次归一化。简历只写“缓解奖励坍塌”，还没有说明你在自己的任
  务上观察到了什么。GDPO 论文 (https://arxiv.org/abs/2601.05242)、官方实现 (https://github.com/NVlabs/GDPO)

  可以补：各奖励的变化曲线、组内零方差比例、训练稳定性，以及同等训练预算下与 GRPO 的比较。没有做过相应观察，就写“采用 GDPO 进行多奖励优化”，不
  要直接归因于“解决坍塌”。

  第三，几个奖励是否真的提供不同信号？
  如果任务主要输出安全／风险标签，同一个风险样本上的“误杀惩罚”可能始终为零；正确性和错误惩罚也可能高度相关。你需要解释奖励拆分的必要性，以及如
  何处理同组回答奖励完全相同、没有有效相对学习信号的情况。

  最值得补的一组实验是：

  > SFT 基线、SFT＋难例／类别权重、SFT＋GRPO、SFT＋GDPO，在同一独立测试集、匹配风险召回的条件下比较误拦率。

  另外，“89 万条高质量数据”可以再补一个质量证据：交叉标注前后的人工抽检准确率，或同等训练数据量下的下游收益。这样才能说明清洗策略的贡献。

## 阶段 6｜三段实习怎么串成一条线

| 实习 | 核心定位 | 证明的能力 |
|---|---|---|
| 京东 AI 安全 | VLM 训练与 Agent | RAG、百万级数据、SFT、RL、多目标奖励 |

```

    ├── Agent / RAG / Memory
    ├── 多模态 SFT
    └── GDPO 强化学习

多模态图像生成
    ├── 训练数据治理
    ├── OCR / VLM 模型选型
    ├── 服务部署
```
