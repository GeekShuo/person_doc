# 一面

## 1．自我介绍，项目和论文

**解答**：按“背景—核心能力—代表项目/论文—个人贡献—量化结果—岗位匹配”组织。项目重点说明选型依据、数据与评测、难点和最终收益，只陈述真实经历。

## 2．为什么多头注意力能提升表达能力？

**解答**：多头注意力把 Q、K、V 投影到多个较低维子空间，各头独立计算注意力后拼接并做输出投影。不同头可以学习不同位置关系和特征组合，因此比单个同维度注意力头具有更灵活的表示能力。但“每个头必然对应语法、情感等可解释功能”只是直觉，不是训练约束；头之间也可能冗余。

## 3．为什么使用 RMSNorm？和 LayerNorm 有什么差异？

**解答**：

\[
\operatorname{LN}(x)=\gamma\odot\frac{x-\mu}{\sqrt{\sigma^2+\epsilon}}+\beta,
\quad
\operatorname{RMSNorm}(x)=\gamma\odot\frac{x}{\sqrt{\frac1d\sum_i x_i^2+\epsilon}}。
\]

RMSNorm 去掉均值中心化，很多实现也不用偏置，因此计算更简单；它在许多 LLM 中能保持稳定训练和良好效果。速度提升取决于 Kernel、形状和硬件，不能笼统宣称固定提升 10%～30%，也不能说它对所有模型必然更优。

## 4．KV Cache 怎么工作，为什么对长上下文推理关键？

**解答**：自回归解码时，历史 Token 在每层的 K、V 不会改变，因此缓存它们；生成新 Token 时只计算新位置的 Q/K/V，并让新 Q 与缓存 K/V 做注意力，避免重复计算整个前缀。没有缓存时，生成长度 \(L\) 的解码总注意力计算约为 \(O(L^3)\)；使用缓存后约为 \(O(L^2)\)，单步仍随上下文长度线性增长。代价是 KV Cache 显存近似随层数、序列长度、Batch 和 KV 头数线性增长，长上下文常受显存带宽限制。

## 5．大模型推理加速思路

**解答**：模型侧可做权重/激活/KV 量化、蒸馏、剪枝和采用 GQA/MQA；算子侧使用 FlashAttention、融合 Kernel 和高效矩阵库；系统侧使用 PagedAttention、连续批处理、Prefix Cache、合理调度和张量/流水线并行；解码侧可用投机解码。优化前需区分 TTFT、TPOT、吞吐和显存目标，并在真实输入输出长度及并发下 Benchmark，不存在必须使用某一框架的方案。

## 6．模型微调时遇到过过拟合吗，怎么处理？

**解答**：过拟合表现为训练损失继续下降而验证指标变差；灾难性遗忘则是新任务训练后旧能力下降，二者相关但不等同。可通过增加与去重数据、划分独立验证集、降低学习率或训练轮数、Early Stopping、Weight Decay/Dropout、混合通用回放数据，以及 LoRA 等参数高效方法缓解。LoRA 仍可能过拟合或遗忘，数据配比也不存在固定 80/20 最优值，需用目标与通用能力共同评测。

## 7．算法题：字符串全排列、二叉树序列化与反序列化

**解答**：全排列可用回溯；有重复字符时先排序，并在同一搜索层跳过“前一相同字符尚未使用”的分支。时间复杂度与输出规模同阶，最坏 \(O(n\cdot n!)\)。

二叉树可用前序遍历序列化，空节点写 `#`；反序列化按同样顺序递归消费 Token。必须保留空节点，否则不同树形可能得到相同序列。

```python
class Codec:
    def serialize(self, root):
        out = []
        def dfs(node):
            if node is None:
                out.append("#")
                return
            out.append(str(node.val))
            dfs(node.left)
            dfs(node.right)
        dfs(root)
        return ",".join(out)

    def deserialize(self, data):
        it = iter(data.split(","))
        def dfs():
            value = next(it)
            if value == "#":
                return None
            node = TreeNode(int(value))
            node.left = dfs()
            node.right = dfs()
            return node
        return dfs()
```

## 3．大模型生成内容如何去重过滤？

**解答**：先做规范化与哈希精确去重；文档级近似重复可用字符/词 N-gram 的 MinHash+LSH；段落级可用 SimHash、Embedding 聚类或局部 N-gram 重叠；模板、页眉页脚和高频样板可用规则或 Bloom Filter 辅助过滤。LSH 的同桶只是候选，需要再计算相似度确认；阈值应通过人工样本校准，并检查训练/验证/测试集之间的污染。

## 4．词表很大时，Softmax 有哪些加速实现？

**解答**：训练阶段可使用 Sampled Softmax、NCE、Adaptive Softmax 或 Hierarchical Softmax，避免每步计算全部词表，但它们改变或近似训练目标，需要匹配任务。推理阶段仍常需词表投影，可通过权重共享、量化、Tensor Parallel、融合 Logits/Softmax Kernel，以及只在候选词集合上约束解码优化。对于现代 LLM，词表投影的主要成本往往是隐藏状态乘输出矩阵，不能只讨论 Softmax 分母。

## 5．中文领域 Instruction Tuning 要注意哪些数据问题？

**解答**：关注原生中文表达与翻译腔、简繁体和中英文标点、分词与乱码、事实准确性、文化和地域差异、领域术语、任务与难度分布、隐私版权及合规。数据应精确/近似去重并检查测试污染；安全数据需同时覆盖合理拒答与避免过度拒答；对话模板、角色边界、EOS 和 Loss Mask 必须正确。模型生成数据要经过规则、模型和人工抽检。

## 6．LoRA 和 Prompt Tuning 有何区别，分别适合什么场景？

**解答**：Prompt Tuning 冻结模型，只学习拼接到输入前的连续软提示，参数极少且便于多任务切换，但可能占用有效上下文，在小模型或复杂任务上能力有限。LoRA 在选定线性层学习低秩权重增量，参数仍很少但通常适配能力更强；推理可合并权重，动态多 Adapter 时会有额外调度和计算。具体选择取决于模型规模、任务难度、延迟和多租户需求，不能断言 LoRA 在所有任务上都优于 Prompt Tuning。
