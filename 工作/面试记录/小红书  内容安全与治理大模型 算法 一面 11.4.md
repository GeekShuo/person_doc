+ 为什么大模型训练更喜欢 BF16？

	训练大模型的时候，尤其是反向传播，可能会出现非常大或者非常小的数。
	例如：
	\[ x=100000 \]
	- FP16：超出最大有限值，可能溢出成 Inf。
	- BF16：可以正常表示，不过会有舍入误差。
	- FP32：也可以表示，且更加精确。
	因此，BF16 既能节省显存，又能降低 FP16 的溢出风险，通常更适合现代大模型混合精度训练。
	
+ KV cache的计算方式？
	
	假设一个 Transformer： Hidden Size = 4096 Sequence Length = 2048，BF16 = 2 Bytes 32 层 Transformer，每一个 token 的 一层中的 K 向量长度和 Hidden Size 一致，即 4096，所以整个的 KVcache为 2048x4096x2x32x2=1GB
	以上前提是标准的 MHA 在标准 MHA 中，每一层所有 Attention Head 的 K 向量拼接起来，维度通常等于 Hidden Size，即 4096。V 也是如此。但是现代标准的大模型通常使用 GQA，假设 Q Head 数量为 32，KV Head 数量为 8，每个 Head 维度为 128。则 KVcache 是 MHA 的四分之一，256MB

3.讲讲什么是 GDPO，为什么不用 GRPO，优势是什么 
```
在多奖励强化学习中，传统 GRPO 通常先对多个奖励加权求和，再进行组内标准化。但这种方式可能导致奖励组合坍缩。例如两个 Rollout 的总奖励分别为 (0,1) 和 (0,2) 时，经过标准差归一化，最终都得到相同的 Advantage，丢失了不同程度奖励改进的信息。

GDPO 的改进是先对每个奖励维度独立计算组内 Advantage，再进行加权聚合，最后进行 Batch 级别的尺度归一化。这样既保留了不同奖励维度的相对信息，又避免了奖励数量增加导致优势值尺度失控，从而改善多目标优化的训练信号质量和稳定性。
```

有个小的需要注意的点，在单样本中，每个 token 都会有一个 loss，在同一个 micro batch 内，不同样本的 token 数也不同，是怎么聚合在一起的？不同的 micro batch（多个 gpu 内）是怎么聚合的呢?
首先，单个样本内，通用的是，把 prompt 和 padding 的 token 去掉，只考虑 assistant 回答的 loss，做一个平均。然后不同 batch 内部，有两种方式 1. 不同的 batch 等权，所有的 batch 的 loss 对最终的结果影响比重一样 2. 按照 token 数量加权，把所有 token 的 loss 加在一起，除以所有 token 数量，这样就会导致长回答样本对 loss 的影响大于短回答样本。 这两个方式没有绝对的对错，关键看你希望每个 Token 等权，还是每条审核样本等权。

代码题，计算 a 的 b/c次方 不能直接用 power 函数 
思路 拆分为 a 的 b 次方，然后开 c 次方幂，a的 b 次方就是用快速幂，开 c 次方，就是枚举 x,比较x的 c 次方跟 a^b的大小，然后二分
```python
from collections import defaultdict, deque, Counter
from typing import List, Dict, Set, Tuple, Optional

def quick_power(base: float, exp: int) -> float:
    """快速幂，计算 base^exp，exp是非负整数"""
    result = 1.0
    b = base
    e = exp
    while e > 0:
        if e % 2 == 1:
            result *= b
        b *= b
        e = e // 2
    return result

def m_root(val: float, m: int, eps=1e-6) -> float:
    """二分法求 val 的 m 次方根 val^(1/m)"""
    if val == 0:
        return 0.0
    # 负数情况：m必须是奇数
    neg = False
    if val < 0:
        if m % 2 == 0:
            raise ValueError("负数不能开偶次方根")
        neg = True
        val = -val
    # 确定二分区间
    low, high = 0.0, max(1.0, val)
    while high - low > eps:
        mid = (low + high) / 2
        mid_pow = quick_power(mid, m)
        if mid_pow < val:
            low = mid
        else:
            high = mid
    res = (low + high) / 2
    return -res if neg else res

def solution():
    # 示例输入，你可以改成读取输入
    x = 4
    n = 1
    m = 2
    # x^(n/m) = (x^n)^(1/m)
    xn = quick_power(x, n)
    ans = m_root(xn, m)
    # 保留2位小数
    ans = round(ans, 2)
    print(ans)

if __name__ == "__main__":
    solution()
```
