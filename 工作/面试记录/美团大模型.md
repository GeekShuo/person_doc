## 1. Transformer 结构整体串一遍

**回答：**

Transformer 的输入先经过 Token Embedding 和位置编码，得到每个 Token 的向量表示。原始 Transformer 是 Encoder-Decoder 架构：

1. **Encoder**：每层依次包含多头自注意力和前馈网络 FFN，每个子层外都有残差连接与 LayerNorm。自注意力中，同一份输入分别线性映射为 Q、K、V，计算
   $$
   \operatorname{Attention}(Q,K,V)=\operatorname{softmax}\left(\frac{QK^T}{\sqrt{d_k}}+M\right)V。
   $$
   多头注意力让不同的 Head 学习不同子空间中的关系；FFN 对每个 Token 独立做非线性变换。Encoder 的自注意力通常是双向的，能够看到整个输入序列。
2. **Decoder**：每层包括带因果 Mask 的自注意力、对 Encoder 输出做交叉注意力，以及 FFN。因果 Mask 保证生成第 $t$ 个 Token 时看不到未来 Token。交叉注意力中，用 **Decoder 当前层自注意力子层的输出**线性映射得到 $Q$，用 **Encoder 最后一层对整个输入序列的输出**线性映射得到 $K$ 和 $V$，即
   $$
   Q=H_{dec}W_Q,\quad K=H_{enc}W_K,\quad V=H_{enc}W_V,
   \qquad \operatorname{CrossAttention}=\operatorname{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V。
   $$
   因此，每个 Decoder Token 都用自己的查询 $Q$ 去匹配 Encoder 各输入 Token 的 $K$，再对对应的 $V$ 加权求和，从而读取与当前生成位置最相关的源序列信息；交叉注意力通常不加因果 Mask，只屏蔽 Encoder 输入中的 Padding。
3. **输出层**：Decoder 最后一层隐状态经过线性映射和 Softmax，得到下一个 Token 的概率；推理时自回归地逐 Token 生成，已生成的 K、V 可以放入 KV Cache 复用。

当前主流 LLM（如 Qwen、LLaMA）多采用 **Decoder-Only**：去掉独立 Encoder 和交叉注意力，只堆叠带因果 Mask 的 Transformer Block。工程上常使用 Pre-LN、RoPE、RMSNorm、SwiGLU，以及 MHA/GQA/MLA 等注意力变体。

## 2. 讲讲 PPO、DPO、GRPO

### PPO

PPO 是典型的 Actor-Critic 在线强化学习算法。先用旧策略 $\pi_{old}$ 采样回答，由奖励模型或规则给出奖励，再由 Critic 估计 Value，并通过 GAE 等方法计算优势 $A_t$。Actor 的核心目标为：

$$
L_{PPO}=\mathbb{E}\left[\min\left(r_tA_t,\operatorname{clip}(r_t,1-\epsilon,1+\epsilon)A_t\right)\right],
\quad r_t=\frac{\pi_\theta(a_t|s_t)}{\pi_{old}(a_t|s_t)}。
$$

裁剪概率比可以限制单次策略更新幅度。LLM 的 PPO 通常还包含 Value Loss、熵奖励，以及相对参考模型的 KL 惩罚。优点是能够在线探索；缺点是需要 Actor、Critic、Reference、Reward Model 等多个模型，显存开销大、训练链路复杂且容易不稳定。

### DPO

DPO 使用离线偏好对 $(x,y_w,y_l)$ 直接训练策略，其中 $y_w$ 是偏好回答，$y_l$ 是较差回答。它根据 Bradley-Terry 偏好模型，把奖励优化转化为策略与参考模型之间的分类式目标：提高 chosen 相对 rejected 的对数概率差，同时用参考模型约束策略偏移。

它不需要显式训练 Reward Model，也不需要在线采样和 Critic，训练简单、稳定、省显存；但能力上限受离线偏好数据覆盖范围限制，缺少在线探索，偏好对质量不好时也容易过拟合偏差。

### GRPO

GRPO 可以看作去掉 Critic 的 PPO。对于同一个 Prompt，从旧策略采样一组回答，分别计算奖励，再在组内标准化：

$$
A_i=\frac{r_i-\operatorname{mean}(r)}{\operatorname{std}(r)+\varepsilon}。
$$

然后使用类似 PPO 的概率比裁剪目标，并加入对参考模型的 KL 约束。它以组内相对奖励作为 Baseline，不再单独训练 Value Model，因此显著降低显存和工程复杂度，适合数学、代码、安全审核等能够设计规则奖励或可靠验证器的任务。缺点是每个 Prompt 需要生成多条回答，Rollout 成本较高；组内奖励几乎相同时，优势信号也会变弱。

**一句话区分：**PPO 是“在线采样 + Critic 估计优势”；DPO 是“直接学习离线偏好对”；GRPO 是“在线组采样 + 组内相对奖励替代 Critic”。

## 3. 如何根据业务场景选择 SFT 还是 RL

核心看业务目标是**模仿标准答案**，还是**优化一个可评价但难示范的目标**。

- **优先 SFT**：任务存在明确的标准输出或高质量专家轨迹，例如固定格式生成、分类、信息抽取、工具调用协议、已知工作流模仿。SFT 成本低、训练稳定、迭代快，通常先用于冷启动和建立基本能力。
- **选择 DPO**：很难写出唯一标准答案，但容易比较两个答案谁更好，例如语气、简洁性、有用性等主观偏好；同时已有稳定的离线偏好对，不强求在线探索。
- **选择 PPO/GRPO**：目标是最终结果而不是复现某条标准路径，模型需要自主探索策略，并且奖励可以稳定计算。例如数学答案、代码执行结果、安全拦截、复杂规划。算力紧张且规则奖励可靠时可优先 GRPO；若需要独立 Value 估计、长时序信用分配，可考虑 PPO。

实际一般不是二选一，而是 **SFT 冷启动 → 离线评测定位瓶颈 → 必要时 DPO/GRPO/PPO**。如果 SFT 已达到业务指标，或者奖励函数与线上目标不一致，就不应为了使用 RL 而使用 RL；错误奖励会造成 Reward Hacking，反而损伤基础能力。

**结合我的项目，更严谨的回答是：**SFT 和 RL 的最终业务目标并不矛盾，都是提高风险判断的准确性；“同时优化拦截、误杀和格式”本身也不能证明必须使用 RL，因为这些目标同样可以通过数据重采样、加权交叉熵或多任务 SFT 优化，格式遵循更只是辅助目标。

项目材料将强化学习阶段记为 **GDPO**，但现有记录没有给出其全称、损失函数和训练配置，而且另一份方案材料使用过 GSPO 表述，因此面试前必须以实际代码统一算法名称，不能直接把 GDPO 当作 GRPO。若实际实现属于组内相对优化方法，那么引入它的合理条件是：**SFT 已建立基本推理能力，剩余问题集中在可验证的疑难决策边界，并且同一 Prompt 的多次采样存在可比较差异**。

1. **SFT 主要学习示范轨迹**：它对教师给出的 CoT 和答案做 Token-Level 最大似然。对于隐喻、谐音、视觉偷渡、图文组合、多轮上下文反转等 Case，正确推理路径可能不唯一，高质量 CoT 又很难穷举，继续堆同质数据的边际收益可能降低。
2. **RL 可以比较多条候选路径**：对同一疑难样本采样多条回答，根据最终风险标签、误杀代价和结构合法性计算 Sequence-Level Reward，提高高奖励轨迹的概率，而不要求逐 Token 复刻唯一教师轨迹。
3. **结果相对容易验证**：推理过程难以逐步标注，但最终标签、风险层级和输出格式可以由人工 GT 或规则验证。奖励核心应是分类与业务代价，格式奖励只是保证结果可解析。
4. **可将训练信号集中到边界样本**：从多次采样中筛出结果不稳定的样本，或使用线上 Bad Case 构造高难度 Rollout，比继续重复训练大量简单样本更有针对性。

这些是选择 RL 的方法论条件，不能仅凭现有材料断言项目已经完成了“Base→SFT→RL”的严格消融，或证明 SFT 确已饱和。更准确的表述是：若模型已经偶尔生成正确路径且最终结果可可靠验证，RL 才可能进一步放大正确策略。若采用二值结果奖励且同组所有 Rollout 同分，组内相对优势接近零，应先补高质量推理数据、课程学习或更强基座，而不是直接上 RL。

**论文依据：**

- [GuardReasoner](https://arxiv.org/abs/2501.18492)：先用 Reasoning SFT 建立安全推理能力，再对模型采样结果中“同时存在正确和错误输出”的困难样本做 Hard-Sample DPO。消融中 R-SFT 是主要增益来源，HS-DPO 在其基础上进一步提升约 0.67～0.97 个平均 F1 点，说明偏好优化更适合作为决策边界精修，而不是替代 SFT。
- [Hi-Guard](https://arxiv.org/abs/2508.03296)：在真实多模态审核中使用层级风险路径、Policy-Aligned Reasoning 和 GRPO，以路径感知的 Soft-Margin Reward 区分上层方向错误与深层兄弟类别误判。这比简单的“分类正确记 1 分、错误记 0 分”提供了更细粒度的序列级反馈，与多模态审核项目最直接相关。
- [Deliberative Alignment](https://arxiv.org/abs/2412.16339)：SFT 用于内化安全规范和学习显式推理，RL 再根据最终回答的安全性与有用性校准行为；其结果支持“复杂意图识别需要先推理再决策”，但不能证明隐喻 Case 只有 RL 才能解决。

## 4. QK 相乘后为什么除以 $\sqrt{d_k}$

计算的是：

$$
\operatorname{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)。
$$

假设 Q、K 的各维元素相互独立、均值为 0、方差为 1，那么点积 $q\cdot k=\sum_{i=1}^{d_k}q_ik_i$ 的方差约为 $d_k$，标准差约为 $\sqrt{d_k}$。维度越大，未经缩放的点积绝对值通常越大，Softmax 会过早饱和为接近 one-hot 的分布，使梯度很小、训练不稳定。除以 $\sqrt{d_k}$ 后，点积方差恢复到约 1，使不同 Head 维度下的数值尺度和梯度更稳定。

这里除的是**每个注意力头的 Key/Query 维度 $d_k$**，不是整个模型隐藏维度 $d_{model}$；仅当单头注意力时二者才可能相同。

## 5. Decoder 交叉注意力中的 Q、K、V 分别来自哪里

在 Encoder-Decoder Transformer 中：

- **Q**：来自 Decoder 当前层在 Masked Self-Attention 之后的隐状态；
- **K、V**：来自 Encoder 最后一层的输出，通常分别经过各自的线性投影；
- 含义是 Decoder 用当前生成状态作为 Query，到 Encoder 表示中检索当前最相关的源序列信息。

补充区别：Decoder 的 **Masked Self-Attention** 中 Q、K、V 都来自 Decoder；主流 Decoder-Only LLM 没有独立 Encoder，因此通常也没有这种 Encoder-Decoder Cross-Attention。

## 6. 重要性采样的作用

重要性采样用于：**样本来自行为策略 $q$，但我们希望估计目标策略 $p$ 下的期望**。通过权重修正分布差异：

$$
\mathbb{E}_{x\sim p}[f(x)]
=\mathbb{E}_{x\sim q}\left[\frac{p(x)}{q(x)}f(x)\right]。
$$

在 PPO 中，Rollout 是由旧策略 $\pi_{old}$ 生成的，而参数更新针对新策略 $\pi_\theta$，所以使用概率比

$$
r_t=\frac{\pi_\theta(a_t|s_t)}{\pi_{old}(a_t|s_t)}
$$

对旧策略样本进行校正。这样可以在一次 Rollout 上做若干次更新，提高样本利用率，而不必每更新一步就重新采样。

局限是当目标策略与行为策略差异过大时，权重可能极大或极小，导致估计方差很高，甚至被少数样本主导。因此 PPO 会对 $r_t$ 做 Clip，也常配合 KL 约束控制新旧策略距离。重要性采样只能在行为策略覆盖目标策略支持集时使用，否则缺失区域无法被校正出来。

## 7. 微调数据怎么合成，项目遇到的最大瓶颈是什么

**结合我的多模态安全项目回答：**

数据不是直接让一个大模型批量生成完就训练，而是采用“真实数据打底、教师模型扩充、多模型校验、难例回流”的闭环：

1. **定义任务与标签体系**：先按业务风险类型、是否违规、推理过程和最终输出格式定义样本 Schema，并划分单图、单轮图文、多轮图文等形态。
2. **构建种子数据**：整合脱敏业务样本和开源数据，去重、清洗无效样本，做类别统计，保留一批人工确认的高质量种子和独立测试集。
3. **定向合成与增强**：使用关键词和风险场景模板，以已有图片为视觉条件，引导 Qwen3-VL-235B 生成文本问题、上下文、结构化判断依据和标签；对少数类、隐晦表达、视觉偷渡等长尾场景重点扩充，并构造正负对照样本，避免模型仅凭关键词判断。Qwen3-VL 是理解型 VLM，这里不能表述为它生成了新图片。
4. **自动标注与过滤**：结合多个模型投票、启发式规则、格式校验和一致性检查，过滤低置信、答案矛盾、图文不匹配以及模板味过重的样本。
5. **交叉标注降噪**：把数据划成互斥子集，通过正负样本重采样训练宽松和严格判别模型，再对另一子集交叉标注并投票聚合，用模型分歧识别争议样本。
6. **抽检与难例回流**：人工重点复核低置信、模型分歧和线上 Bad Case；训练后按错误类型归因，再定向补充下一轮数据。最新简历口径为超 100 万条多模态 SFT 数据；旧材料曾记录 89 万条，若是项目中期与最终规模，应在面试中说明阶段关系，否则必须统一口径。

**最大瓶颈不是数据量，而是标签质量和决策边界。** 安全场景中类别长尾明显，隐晦违规样本语义模糊，而且“风险拦截”和“避免误杀”天然冲突。单教师模型会产生幻觉和系统性偏差，简单扩量会把噪声同步放大。我的处理重点因此是：用互斥子集交叉标注减少自训练确认偏差，用宽松/严格模型和多模型投票暴露边界样本，再把争议样本交给人工复核。面试前还需确认测试集是否严格独立、数据计数单位，以及 100 万是团队总产出还是个人负责链路的最终产出。

## 8. 如果训练 Agentic RAG 能力，为什么第一阶段通常用 SFT 就够了

**先说明事实边界：**现有项目材料能确认我参与了 Hybrid Search、重排、Elasticsearch/向量记忆、DeepResearch 和工作流建设，但没有记录我用 SFT 训练过“何时检索、查询改写、工具选择和停止”等 Agent 能力。因此下面是训练方案理解，不能包装成已经完成的个人实验。

如果已有高质量标准轨迹，Agentic RAG 的冷启动本质上接近行为克隆：轨迹给出了状态、工具调用、参数、Observation 和最终答案，SFT 通过最大化正确轨迹似然，先让模型学会基本协议和动作模式。

第一阶段优先 SFT 的原因有四点：

1. **动作空间受约束**：工具集合和参数 Schema 明确，模型首先需要学会合法调用，而不是在开放环境中盲目探索。
2. **流程可由工程兜底**：权限、检索、重排、重试和状态流转可由状态机控制，模型重点负责意图、查询、工具选择和结果组织。
3. **示范轨迹可验证**：强模型或人工产生轨迹后，可以真实执行工具，并用格式规则和人工抽检过滤错误轨迹；直接学习正例更稳定、便宜。
4. **RL 的奖励归因困难**：最终答案同时受召回、重排、工具执行和生成影响。只看最终结果容易使模型通过少检索、投机格式等方式 Reward Hacking。

“SFT 够用”不等于 RL 永远无用。若后续变成长链路规划，标准轨迹难以穷举，而成功率、调用成本、时延和证据质量可以可靠自动验证，就可以在 SFT 冷启动后再用 GRPO/PPO 优化整条轨迹。判断标准是：**不会按协议完成标准动作时先用 SFT；已经会做但策略不够优、确实需要探索时再考虑 RL。**

若要把它作为个人实验陈述，必须补齐轨迹数量和来源、工具 Schema、错误轨迹过滤方式，以及 Base/SFT 在工具选择准确率、参数 Exact Match、检索召回和端到端成功率上的对照。

## 9. LayerNorm 和 BatchNorm 有什么区别，分别在哪些场景使用，作用是什么

### 共同作用

两者都是归一化方法，主要作用是稳定中间特征的数值分布，改善梯度传播，使模型可以使用更合适的学习率并加快收敛。它们通常还包含可学习的缩放参数 $\gamma$ 和平移参数 $\beta$，因此不会简单地把网络表达能力限制为固定的零均值、单位方差。

### BatchNorm

对于 CNN 中形状为 $[N,C,H,W]$ 的输入，BatchNorm 通常对每个通道 $C$，在 Batch 维和空间维 $N,H,W$ 上统计均值与方差：

$$
\hat{x}=\frac{x-\mu_B}{\sqrt{\sigma_B^2+\epsilon}},
\qquad y=\gamma\hat{x}+\beta。
$$

- **依赖 Batch 中的其他样本**：同一样本的输出会受到当前 Batch 组成影响。
- **训练和推理行为不同**：训练时使用当前 Mini-Batch 的统计量，并维护滑动平均；推理时使用训练阶段累计的 Running Mean 和 Running Variance。
- **适用场景**：主要用于 CNN 等视觉模型。图像同一通道具有较稳定的统计意义，而且通常能使用足够大的 Batch。
- **局限**：Batch 很小时均值和方差估计不稳定；变长序列、在线推理或分布式训练中也较麻烦，不同设备还可能需要 SyncBatchNorm。

### LayerNorm

对于一个 Token 的隐藏向量 $x\in\mathbb{R}^{d_{model}}$，LayerNorm 在该样本自身的特征维度上计算均值和方差：

$$
\mu=\frac{1}{d_{model}}\sum_{i=1}^{d_{model}}x_i,
\qquad
\sigma^2=\frac{1}{d_{model}}\sum_{i=1}^{d_{model}}(x_i-\mu)^2。
$$

- **不依赖其他样本**：每个 Token 根据自己的隐藏维独立归一化。
- **训练和推理行为一致**：都直接使用当前样本的统计量，不需要维护滑动均值和方差。
- **适用场景**：Transformer、RNN 和大语言模型，尤其适合 Batch 较小、序列长度不一致以及自回归逐 Token 推理的场景。
- **局限**：它不会利用 Batch 统计带来的正则化效果；在部分 CNN 任务中，效果可能不如 BatchNorm。

### 核心区别

| 维度 | BatchNorm | LayerNorm |
|---|---|---|
| 归一化范围 | 同一通道跨样本、跨空间位置 | 单个样本或 Token 的隐藏特征维 |
| 是否依赖 Batch | 依赖 | 不依赖 |
| 训练与推理是否一致 | 不一致，推理使用滑动统计量 | 一致 |
| 对 Batch Size 是否敏感 | 敏感，小 Batch 不稳定 | 基本不敏感 |
| 典型应用 | CNN、较大且稳定的 Batch | Transformer、RNN、LLM |

**面试一句话总结：**BatchNorm 是“同一特征跨样本归一化”，适合大 Batch 的 CNN；LayerNorm 是“同一样本跨特征归一化”，不依赖 Batch，因此更适合变长序列和 Transformer。Transformer 不常使用 BatchNorm，主要因为序列长度和 Batch 统计不稳定，而且自回归训练、推理阶段需要一致且不依赖其他样本的行为。

补充：现代 LLM 常使用 **RMSNorm**。它不减均值，只根据均方根进行缩放，计算更简单；实践中通常能取得与 LayerNorm 相近或更好的稳定性和效率。
