## 二、虾皮 · 风控算法面试（2026-09-14 14:58）

### 1. 开场与自我介绍

（开头有短暂的音频调试，面试官说明需要安装防作弊插件，随后正式开始。）

**面试官：** 先做个简单的自我介绍，讲讲你的项目和实习经历做了什么。

**候选人：** 面试官你好，我叫彭硕，目前在华中科技大学网络空间安全学院读硕士，是保研上来的；本科毕业于厦门大学信息学院，专业第一，获得过国家奖学金。我求职方向是算法工程师、风控算法方向，有三段比较相关的实习经历：

1. **京东 AI 安全部（CCO 体系）**：负责京东 AI 对话功能的安全护栏，做数据构建、微调以及后续的优化。
2. **京东零售 AIGC 部生成模型机组**：做商品主图生成等方向，主要负责数据清洗、数据构建和评测体系搭建。
3. **腾讯 CDG 策略模型中心**：独立负责法院、公安传来的 PDF 公文有效性校验，拦截率从 4.3% 上升到 9% 左右，每天处理的违规单据平均在 4 万左右。

**面试官：** 你过去做的大多数都是 OCR 相关的？

**候选人：** 第一段在京东 AI 安全部是内容审核方向，第二段和第三段主要跟 OCR 相关。我个人想做的方向主要是风控大模型的应用，其他方向也可以考虑。

### 2. 项目深挖：腾讯 CDG 公文有效性校验

**面试官：** 针对你最近的项目展开讲讲：业务背景是什么？要解决的问题是什么？用了什么方法？最后达成什么效果？

**候选人：** 我们在腾讯 CDG 主要是微信支付的风控部门，对微信钱包里的转账做欺诈检测。法院、公安部门会传过来一些图片或 PDF，里面有账号名、电话号码等字段信息，我们需要校验单据是否有效。因为监管（商务部）要求保护用户隐私，法院、公安也不能随便查——如果传来的是错误的警官证或者错误的盖章，我们不能把用户信息直接给他们。而且每天传来的文书数量非常多，大概 37 万左右。

业务上有几个硬约束：第一，成本要低；第二，不能有幻觉——不能把没问题的文书判成有问题，误伤成本非常高，法院、公安会觉得我们没有配合他们的工作；第三，响应速度要快。

我把任务做了拆分，找投入产出比最高的部分，最终拆出清晰度检测、电话号码校验、标题是否有问题、是否有盖章等几个子任务。大部分 case 是没问题的，但边缘 case 很难判断，比如没有章、又很糊——十个人看，五个人觉得清、五个人觉得糊，我们要保证这部分判断不出错。

清晰度这块，之前有一个机器学习二分类小模型（XGBoost），特征主要是锐度、对比度、高斯模糊等，颗粒度比较粗；我构造了一批困难样本，它在这批样本上准确率非常低。原因一是信息量少，二是真实样本并不是二分类问题。

我把任务重新定义为五分类：不是根据整图的综合特征判定，而是把关键信息切出来，看 OCR 能辨别出多少比例作为重要指标；先用 OCR 指标分三档，再用图像综合特征补充，总共五类，用规则做预标签。规则预标签更可控，但也有新问题：字体非常小、手写体、图像比较灰等情况，规则或小模型判断不了，需要用大模型。直接用大模型加提示词做图像分类效果很差，因为大模型的预训练里没有学过「清晰度」这件事。

所以方案是：用 OCR 规则预标签构造样本，再做后训练。考虑到标准人员很少（只有一位产品经理），不可能做大量人工标注，所以先用规则预标签，再让产品去 check 有问题的样本。训练时做了标签平滑：把人工标注的不确定性用高斯分布平滑到相邻类别，输出不再是单一类别而是属于第 1 到第 5 类的概率分布，用 KL 散度做优化。最终精准率基本 100%，召回在测试集上超过 60%。

**面试官：** 验证集是在人工打标的样本上做验证吗？

**候选人：** 先打标一批样本，按 75%/25% 拆成训练集和测试集；另外对几千张历史样本也做了测试，精准率都是 100%。

**面试官：** 你提到的伪标签用在什么阶段？

**候选人：** 在后训练阶段。比如人工标注加规则确定它属于第四类或第五类，但标注本身有不确定性，就做标签平滑——按高斯分布曲线确定它属于第五类和第四类的概率各是多少，不是 0/1 的关系。样本加上属于各类别的概率分布，给大模型做后训练。

**面试官：** 你这里的准确率，是要求模型预测的类别必须预测对吗？

**候选人：** 也不是完全按 1 到 5 类来判。实际使用时，前三类算清晰样本，后两类算有问题。最后准确率判的是第四类、第五类（判为有问题）的精准率。

**面试官：** 项目现在处于离线状态还是已经上线？

**候选人：** 上线了一部分。像公文类型、电话号码校验这类精准率和召回都比较高，已经上线。清晰度做得比较晚、也最复杂，还没有使用。

**面试官：** 上线后怎么发现有误伤和漏过？

**候选人：** 产品那边会定期抽检，大概每周抽一万条样本做测试。分成五类也考虑到了这点：第五类判错的概率最小，第四类稍高，第三类分得不是特别清。所以预期上线时先上第五类，效果好再上第四、五类。最关键的指标是精准率，召回要求没那么高。

### 3. 基础题

**面试官：** 什么是数据泄露？你这些项目里什么地方可能存在数据泄露？

**候选人：** 简单说就是测试集里的样本在训练集中已经出现过，导致指标虚高、过拟合，模型泛化能力差，在没见过的样本上效果差很多。比如时间序列任务中，预测某个指标却用了它之后时间段的数据作为输入，这也算信息泄露。具体到项目里：训练集和测试集切分定义不准，比如切了 90% 训练、10% 验证；或者没做去重，一万条样本切 75%/25%，但测试集和训练集里有重复样本，那测试集上很多样本模型已经见过了。

**面试官：** 什么是正则化？L1 和 L2 有什么直观区别？

**候选人：** 模型参数越多，在固定训练集上效果越好，但新数据上效果差、会过拟合。正则化就是损失函数里的惩罚项：既要求预测误差小，也要求参数量不要太大。L1 是各个参数绝对值之和，L2 是参数平方后再求和。

**面试官：** 模型输出风险分之后，阈值应该怎么选？

**候选人：** 通常要同时考虑精准率和召回率。在不同阈值下分别看精准率和召回率，画出曲线：如果要求精准率比如卡在 80%，就看这时候召回率是多少、阈值应该卡在哪里；如果对精准和召回没有特别明确的要求，就看 F1 值最大的点对应的阈值。

**面试官：** 逻辑回归、决策树、随机森林的主要区别是什么？

**候选人：** 共同点都是用于分类任务（二分类或多分类）。逻辑回归输入可以是线性或非线性的数值类型，通过损失函数拟合各输入参数，使误差最小。决策树一般是非线性的，通过一系列条件判断的组合来做决策，比如判断西瓜熟不熟，看大小、味道、颜色三个指标，每个指标对应一个分类，相当于近似一个流程式的判断。随机森林相当于给这些不同的判断加上分值，做一个加权组合。

### 4. Python、SQL 与概率题

**面试官：** Python 里浅拷贝和深拷贝有什么区别？

**候选人：** 浅拷贝只复制地址。比如链表或集合，复制后修改复制出来的值，原来的数据也会相应改变。深拷贝相当于在新内存空间里新开一块地方，把参数都复制过去，新旧数据之间的操作互不影响。

**面试官：** 什么是生成器？什么时候生成器比 list 更适合？

**候选人：** 生成器通常在函数里用 `yield` 语句，每次调用产生一个值返回。如果数据是确定的，可以直接放在 list 里把数据全取回来；如果数据需要先处理一遍再输出，或者输入数据在不断变化，就适合用生成器。

**面试官：** SQL 里 `where` 和 `having` 有什么区别？

**候选人：** 这个我接触得比较少，`where` 用得比较多，`having` 用得比较少，具体区别一时想不起来。

**面试官：** 袋子里有三个红球、两个蓝球，不放回连续抽两个球，两个都是红球的概率是多少？

**候选人：** 枚举所有情况一共 20 种，第一次红球、第二次也是红球的有 6 种，6/20 = 3/10。

### 5. 数据分析题

**面试官：** 什么是分层分析？为什么不能只看全局指标？

**候选人：** 比如看准确率，样本可能不均衡——99% 是负样本，规则把所有样本都判成负样本，全局准确率就是 99%，但正样本全错了。所以要拆分成小样本群分开看、再分析问题。

**面试官：** 为什么平均值有时候不够？你会补充看哪些统计量？

**候选人：** 因为可能有离群点，特别大或特别小，会拉高或拉低均值。还要看众数、中位数、方差。

**面试官：** 有两个广告渠道，怎么判断两个渠道转化率的差异是否值得重视？

**候选人：** 假设两个渠道的转化率服从高斯分布，看它们各自样本里的均值和方差，推断出分布，再看两个分布之间的差异。如果差值出现的概率比较小，可能确实是两个渠道转化率不一样；如果差异出现的概率比较大，可能只是一些干扰项或小误差导致的。

### 6. 代码题与反问

**面试官：** 出一道代码题：有数组 a 和数组 b，尽量用最优方案。（候选人表示时间到了，思路有但代码有 bug。）

**候选人：** 最简单的方案是先合并再快排，复杂度 n log n。另一种思路能到 O(n)：维护两个指针，先把数组变形块，第一个指针指向开头，另一个指向 b 的第一个位置；维护第一个指针及其之前的元素都是整个数组中最小的，然后看 b 的当前值与它相比，如果更大就交换，不断把指针往后移。

**面试官：** 你有什么要问我的？

### 2. 业务深挖：查询冻结单据校验

### 3. 后训练与清晰度五分类

**面试官：** 模型后训练时，输入和样本标签是什么样子？

**候选人：** 几个任务里，有些用已有的小模型，调配置、调阈值就能有比较好的效果；真正做后训练的是清晰度任务。本来要判断文书清晰还是模糊，之前 mentor 做的是 XGBoost 二分类小模型，但在边缘 case 上效果非常差。真实样本不是简单的清晰/模糊，很多是有点糊或比较清晰，任务定义本身不该是二分类。

我把它转成五分类：一是更符合数据分布；二是产品可以灵活调阈值，比如只拦截最模糊的，或稍微有点模糊的；三是训练效果更好。

标签定义上，从 OCR 可辨识度角度定了两个指标：文字可辨别比例、可辨别文字的对比度和锐度（拉普拉斯方差），据此分成五档：可辨比例大于 95% 为第一、第二类（再用拉普拉斯方差区分）；50%-90% 为第三类；10%-40% 为第四类；小于 10% 为第五类。

先用百度的小 OCR 模型（不到 1B 参数，工业界用得很多）输出每个文本框的置信度，加上一些规则组合打五分类预标签，再人工复核。小模型在一些异常 case 上不准：字非常小、藏文/蒙古文、手写体、印章里的字、反光光晕等，这些需要大模型来判断（预训练过的大模型有相关知识）。所以先用小模型规则打标、人工复核后，用 Qwen2.5-3B 原生多模态模型做后训练。

**面试官：** 把 mentor 的 XGBoost 二分类推广成五分类（特征不变、数据改成五分类）效果会怎样？

**候选人：** 我一开始也探索过二分类能不能行。那时没有用数据重新训，只是把 XGBoost 的二分类结果按阈值切成五档，效果比较差。后来因为硬件限制——监管不让用英伟达卡，只能用国产卡（昆仑星 P600/P800），训练 3B 模型非常困难，算子缺失，所以后来又要回到用小模型做五分类。

**面试官：** 你用 Qwen2.5-3B 时，是把语言层去掉、只用视觉层训练？

**候选人：** 对，完整模型九百多兆，去掉语言层只用视觉层，准确率比完整模型差 2% 左右。那些异常 case（蒙古文、反光等）只有用语言模型才能判断出来。

**面试官：** 简历里写「将五分类中后两位判为模糊，占比 3.57%」怎么理解？

**候选人：** 就是把 3.57% 的样本判为模糊样本。每批一万条。多模态大模型直接推理根本判断不了清晰度，必须做微调。

**面试官：** 这个「文字可辨别比例」依赖 OCR 模型，如果图片很清晰但写的是模型不认识的文字（手写体、英文、希腊字母），模型识别不出来，就会误判为不清晰？

**候选人：** 是有可能。但 OCR 模型成本低、参数几百兆，先用来打标，把判成后三类的样本再交给产品确认。

**面试官：** 既然规则（拉普拉斯方差 + OCR 识别率）效果也不错，为什么还要 SFT 或训练大模型？

**候选人：** 规则打标在细节 case 上有问题需要校正，比如印章里的字看不清导致置信度低；我们也试过加小模型去除印章干扰，但比较困难，所以直接用大模型，参数比 P600 大、提供的知识更多。

**面试官：** XGBoost 输出概率呈双峰，你用什么分数做 cutoff 评估？

**候选人：** 我建了一个标注平台预览数据，不断试。发现即使 A 的打分比 B 高，A 的清晰度实际上更差，这不是切分阈值能解决的。

**候选人：** 训练时让模型输出英文 token：excellent、good、fair、bad，以及一个表示特别差的词。利用大模型原有的语义，模型就能学到这些类别之间的顺序关系。

### 4. 大模型护栏（京东 AI 安全部）

**面试官：** 京东实习时做的大模型护栏，想解决什么场景问题？

**候选人：** 京东 AI 主站的对话功能（客服、导购），用户会发一些敏感图片，比如涉政、暴力、涉黄等，监管要求模型不能产生有害输出。比如有人发一张敏感图片，再问一句带有侮辱性的问题，如果模型对齐没做好就可能输出有问题的内容。我们要做的是提前检测出这类风险。

**面试官：** 这种负样本怎么来？

**候选人：** 构造上要覆盖单轮纯图片和多轮对话。用户可能在多轮对话中前面都没问题，最后一轮突然把前面提到的东西和贬义词关联起来。纯图片从公开数据集和业务方提供的数据集里找敏感图片，也构造「图片 + 简单问题」（比如「这个图片讲什么」）。另外公司内部有做提示词检测的部门，他们提供角色扮演、忘掉身份、指定网络指令等策略，我们把这些提示词也做扩充，用来构造数据。

**面试官：** 涉政类隐晦表达（比如暗语、谐音描述）怎么让模型理解？

**候选人：** 数据上主要依赖业务方的历史数据，也会从视频平台上的敏感内容关键帧、封面构建数据集。SFT 阶段在提示词里会明确告诉模型需要识别的敏感类别和判定标准（比如特定标志、特定事件，以及特定人物的负面形象等），让模型做判断。

### 5. 算法题

题目是：给定一个数组，找出最长的连续子数组，使得其中「坏」元素的占比不超过 p%（类似 LeetCode 428 题的变体）。面试官提示不限时间复杂度，可以优化。

**面试官提示思路：** 把「坏」元素赋值为 100−p，「好」元素赋值为 −p，则区间和 ≤ 0 等价于满足占比条件。问题转化为求最长的子数组使区间和 ≤ 0。再转化为前缀和：求最大的 r−l，使 S[r] ≤ S[l]。可以维护前缀和的单调递增序列（起点候选），枚举右端点后二分查找。若 l1 在 l2 左边且 S[l1] > S[l2]，则 l2 永远不可能成为更好的起点，可剔除。

**候选人：** 做什么方向最难、最有挑战性？

**面试官：** 难在数据很多，怎么把一笔交易的风险归因到具体的人。从付款角度很难预测下一个行为序列——今天在京东买东西，明天线下消费。我们更多从收款角度看：这个收款方做什么生意。难点在于大量沟通引流都在微信之外，微信只是支付渠道，这里面掺杂着很多正常用户——你在京东买东西也不会在微信里聊，这种支付异常可能和黑产、灰产很像，很难做。还是要从本质画像（商户或收款号）入手，通过历史行为序列去刻画。

**候选人：** 日常工作中，技术研究（模型训练、数据构造）和对接业务方需求的时间占比大概多少？

**面试官：** 产品上新产品要过风控、安全评估，让他们把数据带上来；一旦带了之后，后面怎么拦、不拦都是我们自己的事，客诉和欺诈指标也由我们自己背。日常更多是漏检分析：有些是可拦可不拦的边缘 case（比如清晰模糊之间），有些是历史策略遗留问题；如果大批量爆发，可能是有漏洞或缺某种数据去刻画本质行为，这时就要补数据。长期工作涉及模型训练和样本定义。现在更像 research agent 的方式——跟大模型对话、定问题、开实验。问题定义反而更花时间，比如你们从二分类扩展到五分类；剩下的实验在 AI 辅助下很快能把代码写好。更多时间要花在「为什么要做这件事」上。

**候选人：** 招候选人时更青睐哪种类型？

**面试官：** 首先看能不能把自己做的事情讲清楚、讲得有道理。校招生就看能不能讲清实习场景、场景里比较困难的地方，以及自己针对难点做了什么，或者效果不好的原因是什么。并不指望校招生解决非常复杂的问题，关键看有什么想法、尝试过哪些思路，这样能看出在更多数据或前人工作的基础上他能不能做得更好。另一方面是基础和聪不聪明，这个没有统一标准——面试就像找对象，看眼缘，恰好某个闪光点和面试官契合就推荐下一轮。后面还有老板面、交叉面，不同面试官角度不同。进不进也有运气成分，四轮五轮下来本身是个概率问题，碰到不喜欢的面试官也不一定是能力不行。

## 五、某风控中台 · 一面（录音标题：宝乐二街 5-14 号）

> 面试官开场说明自己是该风控团队的第一位面试官；从对话内容看，部门支持抖音相关业务（社区安全、电商、生活服务等），疑似字节跳动 Data 风控中台。

### 1. 开场与自我介绍

（录音开头候选人正在低声复述清晰度任务中高斯分布平滑、KL 散度优化的要点，并调试设备。）

**候选人：** 我叫彭硕，来自华中科技大学网络空间安全专业，在读硕士，保研上来的；本科就读于厦门大学信息学院，专业第一，获得过国家奖学金、优秀三好学生等荣誉。目前求职方向是风控领域的大模型，有三段实习经历：

1. **京东 CCO AI 安全部**：负责京东 AI 对话功能的多模态安全护栏，参与一百万条风险数据构建，在千问 3-VL 模型组上做 SFT 后训练和 GDPO 强化学习优化。
2. **京东零售 AIGC 机组**：负责商品主海报图、logo 及扩图任务的生成，做数据构建和生成模型评测体系搭建。
3. **腾讯 CDG 策略与模型中心**：独立负责法院、公安每天几千万条查询单据，针对缺章、电话号码不合规、印章类型等问题，设计了一套可解释、低误拦、低幻觉、低成本的有效性校验链路，日拦截率从 4% 提升到 9% 左右，每天拦截约 3.8 万条，极大减轻了人工压力。

### 2. 项目细节提问

**面试官：** 腾讯这段写的是你建立了五级质量标准，OCR 不可辨比例、边缘强度、拉普拉斯方差和漏检率分别是怎么算出来的？

**候选人：** OCR 不可辨比例：调用一个小的专用 OCR 模型，它不仅输出 OCR 结果，还会对每个检测到的文本框输出一个置信度。比如框的精度小于 0.9，就认为这个文字无法判断；再结合框的大小、框内字数做加权，就能得到整份文书里大概多少文字能辨别、多少不能。

拉普拉斯方差：具体公式没有细看（用的是 OpenCV），原理是比较边缘和背景像素之间的差异。黑色或白色像素差异大说明清晰；模糊文书的文字像素值和背景差异不大，就不容易辨别，以此来给清晰度分档。

漏检率：我简历里写的其实是精准率。数据量每天几十万，测试时取一万条，过一段时间再取一批。有问题的样本占比不到 5%，对这部分做人工标注（找产品同学标），来保证精准率；召回只做抽样看一部分，这个任务对召回要求不高。

**面试官：** SFT 时结合了 CE 和 KL，为什么不是只用 CE？

**候选人：** 通常 SFT 只用 CE，保证每个 token 是确定的标准答案。但这个任务的预标签有误差，人工复核时也有主观范围——同一个人看同一份文书，有人认为属于第二类，有人认为第三类或第四类。我们通过标签平滑（高斯分布）得到软标签：标准答案不是一个固定 token，而是不同 token 的概率分布。只用 CE 没法学习这种概率分布，所以用 CE + KL 散度联合训练。五级标签是 excellent、good、fair、bad 等。

**面试官：** 印章识别你用了三路模型信号，分别解决什么问题，怎么融合？

**候选人：** 一开始我以为这任务比较简单：用 HSV 颜色空间加连通性（把断裂的章拼成圆）就能检测红章。但真实样本里很多是「潘金章」，不是红色，有绿色、黄色等；有的章非常小，有的有背景反光或彩色墨水干扰，只用颜色或形状容易误判。

后来调研发现百度有几百兆的开源版面识别模型，专门检测表格、抬头、标题、印章。不同模型有的激进、有的保守。我标了大约 1000 条含困难样本的数据集，把百度两个模型的打分加上颜色形状信号作为三路信号，测了几百个阈值组合，先保精准再保召回。还有一些极小的印章（跟汉字差不多大）怎么调阈值都识别不出来：分值低的直接判无章、高的判有章，中间模糊的交给 27B 千问模型，识别得比较准。任务总耗时要求在 3-5 秒内，原小模型链路不到 1 秒，把困难 case 交给大模型成本上也是可以接受的。

**面试官：** 京东这边你调的是 235B 模型吗？

**候选人：** 不是，那个任务要求成本低、速度快，235B 肯定不行。我们用的是 Qwen2.5-32B（MoE）这类，蒸馏放在千问 3-VL 的 8B/4B/2B 模型上。

**面试官：** 这么大量的数据做 SFT，会不会把小模型的通用能力全干掉了？

**候选人：** 不在我们考虑范围内——训完之后这个模型只负责这一个审核任务。

**面试官：** 你设计了三个奖励（拦截、误杀、格式奖励），权重怎么调？

**候选人：** 靠实验跑出来的经验比例。

**面试官：** 为什么用 GDPO 而不是 GRPO？

**候选人：** GRPO 是先对奖励相加、再做归一化。训练刚开始时，格式遵循奖励就能拿到很高的分数，而风险拦截、误判这些奖励很低。直接相加归一化后，模型长期训练只会去追求容易拿高分的格式遵循，忽略核心的拦截效果，也就是奖励 hacking。GDPO 避免了这个问题。

### 3. 算法题

**面试官：** 如果大量数据做 SFT 后，要判断它对通用知识的遗忘程度，你会怎么设计指标评估？又怎么减缓这个问题？

**候选人：** 如果要兼顾任务能力和通用能力，可以在 SFT 或强化学习训练时，把更新后模型和原模型的参数差异作为损失（用 KL 散度），也就是加一个惩罚项，让更新后模型的概率分布和初始模型相近。

**面试官：** 有点像 PPO 里每一步要限制相对 reference model 的偏离程度。下一个问题：计算 LoRA 能节省多少参数。假设矩阵输出维度是 h，rank 是 r。

**候选人：** 如果是二维矩阵，原来参数量是 h²，LoRA 是 2hr，节省 h² − 2hr。

**面试官：** LoRA SFT 部署时，外挂参数怎么处理？

**候选人：** 保存时会把原始参数也放到文件夹里；用到 LoRA 时，把外挂参数插入到对应层里，先经过主干层再送到下一层时插入。

**面试官：** 什么时候用 SFT，什么时候用强化学习？

**候选人：** SFT 适用于问题比较固定、有标准答案、输入输出固定、不需要探索的场景，本质是教师强制——让模型照着答案学。强化学习适用于复杂推理、没有标准答案的任务，比如写作文，或者风控里需要给出判断依据的场景；它不告诉模型标准答案，只对回答做比较、设计规则奖励。

**面试官：** 如果奖励是规则奖励，跟 SFT 有什么区别？

**候选人：** SFT 是教师强制的：推理时假设前面的 token 都按 SFT 的输入数据产生，但真实任务里没有标准答案，后面的 token 会根据前面可能错误的答案继续输出。强化学习（比如 GRPO）对每个回答都做奖励，让模型根据自己的历史回答做回归，训练会更稳定。

**面试官：** CTC 怎么解决 OCR 可变长度输出的问题？

**候选人：** 这个我没有太接触过。

**面试官：** 千问 3-VL 的整体框架了解吗？deep stack 是怎么做的？

**候选人：** 大概了解。deep stack 是在 LLM 每一层的输入都把图片特征注入进去，有点像传统 CV 里的特征金字塔（FPN）。

**面试官：** 不完全是先在第一步做图像塔和文字塔再拼接。它的基础架构是图像隐点和文字隐点在一起计算，但在图片特征处理上会做切分，抽取不同层的特征分别给到 LLM 的不同层。

**面试官：** 最后做一道 coding 题：给定一个长度为 n 的无序数组，找第 k 大的数，不能做完整排序，直接返回第 k−1 的下标。

**候选人：** （用 C++ 写，语法有些混淆，没完全调通。）思路是做快排的切分，只对前 k 个数继续排序，在排序过程中输出。
