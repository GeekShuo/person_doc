1.你在京东这个多模型审核项目中，训练过程有没有遇到什么难点和坑，怎么处理的
```
我们在做多模态内容安全审核的 SFT 训练时，遇到过一个比较有代表性的 Loss 设计问题。

**最开始的现象是，训练 Loss 一直在下降，但是高风险类别的 Recall 提升不明显，尤其是一些隐喻、图文组合类的 Badcase，仍然存在漏报。**

一开始我们怀疑是长尾类别的数据覆盖不够，后来在分析 Badcase 的时候，发现不同样本的标注回答长度差异比较大。

比如，有些样本只有简短的风险等级和原因，而有些样本包含很长的解释文本。进一步检查损失函数发现，原来的实现直接使用了 CrossEntropy 的 Mean Reduction，相当于对一个 Batch 内所有有效 Token 求平均。

**问题在于，我们的核心业务目标是判断每张图片的风险等级，而不是让回答越长的样本在训练中占据越大的权重。**

举个例子，如果一条样本有 20 个有效 Token，另一条有 100 个，那么原来的 Loss 聚合方式就会给后者分配五倍的 Token 权重。

所以我们做了一次对照实验，把 Loss Reduction 从 Token-level Mean 改成了 Sample-level Mean，也就是先对每条样本内部的 Token Loss 求平均，再对 Batch 中的样本求平均。

同时检查了梯度累积和多卡训练的归一化方式，保证最终每条样本具有相同的权重。

在这个假设案例中，修改后整体 Accuracy 有小幅改善，高风险 Recall 从 76.2% 提升到 83.5%，漏报率有了比较明显的下降。

**这件事让我意识到，SFT 不仅仅是数据质量和训练超参数的问题，Loss 的聚合方式也需要与最终的业务评价指标对齐。尤其在多模态审核这种回答长度差异较大的任务中，默认的 Token-level Mean 不一定是最适合的优化目标。**



Q1：为什么改成 Sample-level Mean，高风险 Recall 就会提高？

不能说改了就必然提高。合理的解释是：如果原先长答案样本与类别、难度等因素存在相关性，Token-level Mean 会隐式改变样本权重。修改后，这种长度引入的权重偏差被消除，可能改善原本被低估的样本群体。需要通过长度分桶和消融实验验证。

Q2：既然分类最重要，为什么不直接提高分类 Token 的 Loss 权重？

这是很好的进一步优化方向。Sample-level Mean 解决的是样本之间的权重问题，而分类 Token 加权解决的是样本内部不同输出字段的重要性问题。两个设计可以组合，但应分别做消融实验。

Q3：你怎么确认不是类别不均衡造成的问题？

需要同时检查类别分布、各类别回答长度、分桶 Recall，并保持采样策略不变进行对照。如果高风险类别本身数量就非常少，还需要考虑类别重采样或 Class-weighted Loss，不能把所有问题归因于 Token Mean。
```

2.如果防止灾难性遗忘？
```
我认为防止 SFT 灾难性遗忘，首先应该考虑的是通用数据 Replay，而不是默认引入 KL 散度。

因为 Replay 和 KL 的目标存在区别。Replay 使用正确标注，通过交叉熵让模型继续学习通用任务，既能保留旧能力，也有机会改善原模型的错误。

KL 则属于输出分布层面的正则化，让微调模型在通用场景下保持接近基座模型。它的优势在于可以利用没有人工标签的通用输入以及原模型的软概率分布，但同时也可能保留原模型的错误。

所以对于我们的多模态审核项目，我会先通过领域与通用数据混合 SFT，配合双维度验证集和 Early Stopping，观察是否存在能力退化。

如果通用能力仍然明显下降，再考虑引入基座模型作为 Teacher，在通用图文样本上增加 KL 约束，并通过消融实验验证实际收益。

另外，我不会在审核任务上盲目施加强 KL，因为基座模型可能本身不具备足够的复杂风险识别能力，过强的 KL 反而会影响新任务学习，尤其是高风险样本召回。

最终我们不是简单追求模型参数变化小或者 KL 小，而是希望在通用能力尽量不下降的前提下，最大化审核领域的有效性能。
```
