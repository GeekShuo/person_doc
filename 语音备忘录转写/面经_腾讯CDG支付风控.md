#### Q5 · 你说的伪标签用在哪一步？ ✅
**我的回答**：用在后训练阶段。人工 + 规则确定类别后，考虑到标注者的不确定性，不把它当 0/1 硬标签，而是按高斯分布给出**属于 1~5 类各自的概率**，作为样本标签去训练。
**更优回答**：正确，这就是**标签平滑 + 软标签蒸馏**的思路。可补：① 为什么不用硬的 argmax——因为相邻档之间本身就没有清晰边界，硬标签会把标注争议注入噪声；② 为什么用 KL 而不是 CE——CE 只看真实类，KL 能拟合完整分布、保留类间序关系（**序数分类 ordinal classification**，五类有天然顺序，理想情况还应加上序数损失）。

#### Q9 · 什么是正则化？L1 和 L2 的直观区别？ ⚠️
**我的回答**：模型参数越多越容易过拟合，正则化就是在损失里加惩罚项限制参数规模；L1 是参数绝对值之和，L2 是平方和。
**更优回答**：差一口气，要把**为什么 L1 会稀疏**讲出来：
- **L1**：`λΣ|w|`，梯度是常数 `λ·sign(w)`，约束域是菱形，等高线容易在**顶点**相切 → 部分权重精确变 0 → **自带特征选择**，适合高维稀疏；
- **L2**：`λΣw²`，梯度 `∝ w`，越接近 0 推力越小 → 权重**均匀收缩但不为 0**，模型更平滑，抗共线性；
- 概率视角：L1 ↔ 拉普拉斯先验，L2 ↔ 高斯先验；
- 补一句：**数据增强、dropout、early stopping、权重衰减**也是正则化手段（weight decay 在 Adam 下 ≠ L2，这点常被追问）。

#### Q10 · 模型输出风险分后，阈值怎么选？ ✅

**更优回答**：正确，再加业务视角三件事：① 用**成本函数**选而非只靠 F1：`总成本 = 漏损金额 × FN + 审核/打扰成本 × FP`；② **分层定阈值**：不同渠道、新老用户、不同金额区间用不同阈值（对应上一题的分层分析）；③ 上线后用 **PSI** 监控分布漂移，阈值需随漂移动态调整。

#### Q11 · 逻辑回归、决策树、随机森林的主要区别？ ⚠️
**我的回答**：逻辑回归用均方误差拟合各输入参数（这里说错了，见左）；后两者是非线性的，决策树按条件逐级判断（举了挑西瓜的例子），随机森林是给不同判断加权重再投票。**回答散、且有硬伤**。
**更优回答**：
- **逻辑回归**：线性模型 + sigmoid 输出概率，优化的是**对数似然（交叉熵）不是 MSE**；可解释性强（权重方向即业务含义），对量纲敏感需分箱/归一化 + 人工做特征交叉；高维稀疏下仍是工业界主力（配合 WOE 编码 + PSI 监控）。
- **决策树**：轴平行切分，天然做特征交互、免归一化；但方差大，数据微调树结构就变，易过拟合（需限深/剪枝/叶节点最小样本）。
- **随机森林**：Bagging（bootstrap 抽样 + 随机特征子集）**降方差**，OOB 可作验证集，自带特征重要性；不易过拟合但推理慢、可解释差（需 SHAP）。
- 顺带提：**GBDT/XGBoost/LightGBM 是 Boosting，降偏差**，表格数据上通常优于 RF，风控里主流是 LR 打底 + GBDT 提效。

#### Q12 · Python 浅拷贝和深拷贝的区别？ ✅
**我的回答**：浅拷贝只复制地址，改副本原对象也会变；深拷贝在新空间完整复制，两者互不影响。
**更优回答**：核心对了，补三点：① `b = a` 只是**起别名**；② `a[:]`、`list(a)`、`copy.copy()` 都是**浅拷贝**——只复制最外层容器，内层嵌套对象仍共享，所以改嵌套列表的内层还是会影响原对象；③ `copy.deepcopy()` 递归复制，靠 memo 字典处理循环引用。经典坑：`[[0]] * 3` 三个元素是同一个列表。

#### Q13 · 什么是生成器？什么时候比 list 更合适？ ⚠️
**我的回答**：函数里用 `yield`，每次调用产出一个值；如果输入数据需要先处理一遍或者数据在变化，就用生成器。
**更优回答**：后半句没踩到点上。核心是**惰性求值 + O(1) 内存**：`yield` 让函数挂起并保留现场，每次 `next()` 才执行到下一个 yield。**适合的场景**：① 大文件按行读；② 流式数据 / 网络 / 日志管道；③ 无限序列；④ 大数据管道式串联（生成器表达式）。**代价**：只能遍历一次、不能随机访问、长度未知。对比 list：list 一次性占内存但可重复随机访问——**数据量能装下内存就用 list，装不下或只需单次流式处理就用生成器**。

#### Q14 · SQL 里 WHERE 和 HAVING 的区别？ ❌
**我的回答**：直接说"我可能接得比较少，WHERE 用得多，HAVING 好像用得少，永远记不过来。"
**正确回答**：
- `WHERE` 在 `GROUP BY` **之前**过滤**行**，**不能**用聚合函数；
- `HAVING` 在 `GROUP BY` **之后**过滤**分组**，**可以**用 `COUNT/SUM/AVG`；
- 例：`SELECT dept, COUNT(*) c FROM t WHERE status=1 GROUP BY dept HAVING c > 10`；
- 执行顺序：`FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT`。
> 风控/数据岗必考题，"用得少"不能作为答案。

#### Q16 · 什么是分层分析？为什么不能只看全局指标？ ✅

#### Q18 · 两个广告渠道，怎么判断转化率差异是否值得重视？ ⚠️
**我的回答**：把两个渠道的转化率看成高斯分布，比较均值和方差，看它们联合分布中"差异出现"的概率——概率小就认为真的有差异，概率大就认为只是噪声干扰。
**更优回答**：直觉对了，但缺规范表述，面试官不会买账。**正确姿势是双比例 z 检验**：
```
H0: p_A = p_B
z = (p̂_A - p̂_B) / sqrt( p̄(1-p̄)(1/n_A + 1/n_B) )
```
① 算 **p 值** 与显著性水平 α（0.05）比较，或看 **置信区间是否跨 0**；② 必须同时看**效应量**（相对提升多少）——样本量极大时微小差异也会显著，所以要提前定义 **MDE（最小可检测效应）**；③ 这是 AB 实验，需保证**随机分流、实验前锁定指标、样本量预估（power analysis）、不中途偷看（peeking）**。

#### Q19 · 代码题：给定数组 a 和数组 b（合并有序数组） ❌ 全场最大失分
**我的回答**：讲了思路——维护两个指针，保持 a 的头部始终为已排好序的最小集合，遍历 b 逐个比较交换；最后以"时间到了、代码稍微有点 debug 不出来"收场，**没有写出可运行代码**。
**正确回答**：合并两个有序数组的最优解是**从尾部开始的双指针**，O(m+n) 时间、O(1) 额外空间（从尾往头写，避免覆盖 a 中未处理的元素）：
```python
def merge(a, m, b, n):
    i, j, k = m - 1, n - 1, m + n - 1
    while j >= 0:
        if i >= 0 and a[i] > b[j]:
            a[k] = a[i]; i -= 1
        else:
            a[k] = b[j]; j -= 1
        k -= 1
    return a
```
> 关键点：为什么从尾部写（`i` 在头部会被覆盖）；为什么 `while j >= 0` 就够了（`a` 剩下的本来就在位）。建议把双指针、滑动窗口、堆/topK、二分、LRU 刷到白板可写。
