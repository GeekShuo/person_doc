
##1. 这份文档回答什么

一个号码字符串进来，什么情况判有效（最终是否有效=True）、什么情况判无效（False）。

- 输入：CSV 文件，默认取第 1 列为法院名称、第 3 列为电话（可用环境变量 NAME_COL / PHONE_COL 改列号）。空电话行直接丢弃，不产生结果行。
- 处理链：process_contact.py（阶段 1，提取号码 + 第一轮判定）→ fix_areacode.py（阶段 2，补区号 + 区号一致性 + 出最终结论）。
- 结论列：fix_areacode.py 输出的 最终是否有效 是唯一结论，只有 True / False，不留空。

总原则：判无效必须 100% 准确，能放过的都放过。 只要号码本身可用，即使格式脏、缺区号、带分机，都尽量判有效；只有确认不是可用号码，才判无效。

## 8.备注

### 规则 9 的关键修正

条件不依赖库的 is_valid 结果。phonenumbers.parse("2395104","CN") 会把前 3 位 023 当成重庆区号猜出 FIXED_LINE/True，但这不是录入者填的区号——后续 number_areacode() 会得到 023、geocoder 得到"重庆市"，与法院所在地冲突被误判无效（实测 341 行被这样误杀）。只要原串是无区号本地号形态（7/8 位且不以 0 开头），一律标 LOCAL_NO_AREA_CODE，由第二阶段按法院所在地补真正的区号，不采信库猜测的区号。

> 注：无区号的 SHARED_COST（如 87996397）与 UNKNOWN 的 8 位本地号形态完全相同，同样按本地号处理；带区号的 SHARED_COST（如 07682396220）早期曾保留 SHARED_COST_SUSPECT 纠正，现已删除，按库判有效放行（见 §3 的 SHARED_COST 说明）。

### 规则 5 的案号关键词

（民初、执保、财保、保全裁定、刑初、行初、立案）会命中"号码+案号备注"的字段。v2.1 加了判别：如果字段含可解析号码（任意位置）且不是纯案号（没有 (20XX) + 案由 + 号 的完整结构），则提取号码继续走正常流程，不整条丢弃。

号码提取规则（PHONE_IN_TEXT_RE）：

- 区号开头（0\d{2,3}+本地号）和手机号开头（1[3-9]+9位）：前面允许中文（如 财保13800138000、执保0835-3236605），但不能是数字；
- 纯本地号（[2-9]+6~7位）：前面不能是中文（防止从案号中间截取数字段，如 民初27259号 中的 27259）；
- 号码后面允许中文（如 0835-3236605执保冻结），但不能是数字。

### > **SHARED_COST 处理的最终形态（v2.1 后期调整）

**：早期版本曾对"带区号、非 400/800、非白名单"的 SHARED_COST 号码做 SHARED_COST_SUSPECT 反方向纠正（库判有效、强制判无效，如 07682396220），命中 41 行。这是全系统唯一一条"库判有效反而判无效"的规则，与"能放过的都放过"总原则相悖，已删除——这 41 行现按库判定放行判有效。保留的仅有：0+区号+白名单短号（如 0755-96110）被库错标 SHARED_COST 时改标 SERVICE_LINE 放行。

### 本地号第一位不能是 0（v2.1 新增）

fix_areacode.validate() 在校验补全区号后的号码时，如果分离出的本地号第一位是 0，直接判 False。

为什么需要：phonenumbers 对"区号 + 第一位为 0 的本地号"判定不一致——075501234567 判 True（错误），037202395104 判 False（正确）。判 False 的还会被 validate() 的放宽规则救回 True。统一在前缀层面拦截，保证本地号必须以 1-9 开头。

分离方法：按区号第二位判断区号长度（d[1] 为 1/2 → 3 位区号如 010/021，否则 4 位如 0372/0755），与 _areacode_from_raw 一致。

例子：05583093 推断区号 0558 → 拼接 055805583093 → 本地号 05583093 第一位 0 → 判无效。

### 脏数据修复的 4 条硬约束（v2.1 收紧）

阶段 2 的 repair_messy() 会结合法院区号从脏串中切号码。v2 版本过于激进，把大量根本无法修复的内容判成了"修复成功"，v2.1 加了 4 条约束，命中任一条即放弃修复、判无效：

|   |   |   |   |
|---|---|---|---|
|#|约束|拒绝的内容|说明|
|1|单段数字长度 > 12 位|209734403722097344、0373716690905660580187、36600630991-3631189|一个完整国内固话最多 4 位区号 + 8 位本地号 = 12 位。超过必然不是单个电话号码，实测大量为 18 位身份证号（330381199206236134、140502198911242519）、银行卡号、多号无分隔粘连|
|2|字段含明显非电话特征|91341621MA2UYQPM3D（统一社会信用代码）、35,322.4900（金额）、http://146.0.250.57/portal/login.do（网址）、０02882677880（全角数字）|判据：含拉丁字母、千分位/小数金额、全角数字，或"统一社会信用代码/账号/卡号/身份证"等字样|
|3|同一切法档内候选不唯一|0373716690905660580187 曾切出 03730373716、037371669090、03737166909、037303737166 四个互相冲突的号码|切法不唯一 = 无法确定录入者原意，不猜|
|4|兜底截取只允许"数字量刚好够一个号码"|079+32617034 曾被截成 0516+0793261（区号与原串无关）、152476+14999→04761524761|兜底档（直接截前 7/8 位）最不可信，限制 数字长度 ≤ 区号位数 + 本地号位数|

另外切法按可信度分三档，取第一档有唯一有效解的：

|   |   |   |
|---|---|---|
|档位|切法|例子|
|0（最可信）|串中已能识别出区号，去掉区号后取本地号|00834-5201650 → 0834+5201650|
|1|串本身就是纯本地号|0258352383|
|2（兜底猜测）|直接截前 7/8 位当本地号|61620770372 → 0372+6162077|

同时修正了区号重复的 bug：0854862265 前 3 位恰好是区号 0854 的无零形式 854，v2 会拼成 0854+0854862；v2.1 对已含区号的串不再重复拼接，这类残缺号（区号 + 6 位）改判无效。
