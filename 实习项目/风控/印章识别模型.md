印章检测链路 (Seal Detection Pipeline)

适用: 公安/法院法律文书印章有无判定
一、链路总览
三阶段级联架构，逐步消解不确定样本：
输入文档 (PDF/JPG/PNG)
    │
    ▼
┌──────────────────────────────────────────────┐
│ Stage 1: 三模型三分类 (seal_classify_online)   │
│  下载 → 渲染全部页 → 逐页跑 3 模型 → v5 规则    │
│  PP-DocLayoutV2 + PP-DocLayout-L + seal_det   │
│  + HSV 颜色 blob 检测                          │
│  输出: HAS_SEAL / NO_SEAL / UNSURE / ERROR    │
│  (高长宽比 H/W>2.0 自动分块推理)               │
└──────────────┬───────────────────────────────┘
               │ NO_SEAL + UNSURE 进入二阶段
               ▼
┌──────────────────────────────────────────────┐
│ Stage 2: 8块切分 (run_0804.py --stage 2)      │
│  每页切 8 块(15%重叠) → 每块重跑三模型         │
│  找回整页缩放导致漏检的小印章                   │
└──────────────┬───────────────────────────────┘
               │ 仍 UNSURE
               ▼
┌──────────────────────────────────────────────┐
│ Stage 3: VLM 多页判定 (run_vlm_unsure_0804_v2)│
│  渲染全部页 → 每批 5 页发 VLM → 逐页判定       │
│  任一页有印章 → HAS_SEAL; 全无 → NO_SEAL      │
└──────────────┬───────────────────────────────┘
               ▼
  合并 combined_results.json → review_server 人工审核

三、三个模型的必要性
|模型|架构|参数量|作用|实测贡献|
|-|-|-|-|-|
|PP-DocLayout-L|RT-DETR-L, 640x640|32.3M|版面检测(23类含seal)|主力: 承担 98.5% HAS_SEAL 检出|
|PP-DocLayoutV2|RT-DETR+PointerNet, 800x800|53.1M|版面检测+阅读顺序|补充: 0.2% 独立检出 + 交叉验证降低漏检|
|PP-OCRv4_server_seal_det|ResNet+FPN(PSE), 动态输入|28.5M|印章弯曲文本检测|辅助: 1.3% 中分区间(0.12~0.25)的颜色/圆度确认|
|detect_color_seal_blobs|OpenCV HSV (非模型)|-|红/蓝/黄彩色斑块检测|辅助: 与 seal_det 共同提供中分确认信号|


classify_v5 决策规则 (为什么需要多信号):

|条件|判定|
|-|-|
|V2≥0.25 或 L≥0.25|HAS_SEAL (高分直接判)|
|V2/L∈[0.12,0.25) + seal_det或颜色blob确认|HAS_SEAL (中分需辅助)|
|V2/L<0.15 + seal_det全否决 + 无blob|NO_SEAL (hard_no/soft_no)|
|其他|UNSURE → 进入 Stage2/3|

七、已知问题与改进方向
1. ERROR 45 个: 全部为空白 PDF (结构合法但内容为空), 属数据源问题
2. V2/L 模型 46% 分歧率: 两模型检测标准不一致, layoutL 为主力
3. 0727 送达回执类误检: layout 对"此联交协助查询单位"回执页系统性误检 (黑色文字被判为印章特征)
4. 端到端融合 (见 MODEL_ANALYSIS.md): 无框标注场景下推荐伪标签自训练 — layoutL 已对 99.9% HAS_SEAL 检出框(即使低分), 可作伪标签迭代微调
